## 1. 역할 정의서 (1차)

| 역할 | 책임 |
| --- | --- |
| 애플리케이션 아키텍트 (AA) | 설계 Baseline·코드·OM 초안·검증 증적의 **최종 A** |
| 업무 개발자 | AI 초안 보완, 구현, 로컬 검증 — **R** |
| AI / Model Studio | 초안·골격 생성 — R의 보조 (승인 권한 없음) |
| 프레임워크팀 | 표준 구조·금지패턴 — **C** |
| PMO | 일정·범위 공유 — **I** (설계 Baseline) |
| 운영 | OM 반영 시 — **C** (해당 시) |

## 2. 산출물별 RACI

| 산출물 | R | A | C | I |
| --- | --- | --- | --- | --- |
| 설계 Baseline | 업무 개발자 (+AI 초안) | **AA** | 프레임워크팀 | PMO |
| 코드·Mapper | 업무 개발자 (+AI 골격) | **AA** | 프레임워크팀 | — |
| OM 초안 | 업무 개발자 | **AA** | 운영(해당 시) | — |
| 로컬 검증 증적 | 업무 개발자 | **AA** | — | — |

## 3. AI 생성물 승인 Workflow

```text
1. 설계 정보 입력 (사람)
2. AI 초안 생성
3. 개발자 보완·정리 (R)
4. AA 승인 (A)  ← Architecture Gate
5. (승인 후) 코드·문서·OM 초안 생성
6. 개발자 보완·로컬 검증 (R)
7. AA 승인 (A)
8. 다음 단계(통합/배포 절차 — M16)
```

## 4. Architecture Gate 운영기준 (최소)

AA가 승인 전에 확인:

1. SoT(소스)와 설계 불일치가 `현재 구현 / 목표 / Gap`으로 구분됐는가  
2. M1 사람 유지 항목(Timeout·TX·오류 / Rule / SQL 성능)이 미승인 상태로 넘어가지 않았는가  
3. 금지 패턴(업무 Controller, Service→Mapper 직호출, 타 업무 테이블 직접 참조)이 없는가  
4. M0 제외(배치·Gateway 신규)를 침범하지 않았는가  

## 5. 예외 승인

- 긴급 예외 절차: **미확정** (필요 시 AA가 한시 승인 + 사후 기록)  
- AI 단독 승인: **금지**
