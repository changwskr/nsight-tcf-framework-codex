## 1. 선도개발 계획

| 차수 | 대상 | 대표 거래 |
| ---: | --- | --- |
| 1차 (선도) | 단일 테이블 조회 | `AV.Sample.inquiry` / `AV_SAMPLE` / 화면 1 |
| 2차 | CRUD 한 세트 | create / update / delete 추가 (M2) |
| 이후 | 권장 로드맵 | 다중테이블·Rule → … → 배치(제외와 충돌 시 스킵) |

## 2. 1차 검증 시나리오

- 템플릿 입력(화면·거래·프로그램·SQL·추적성) 가능  
- 메타모델 ServiceId 1건 표현 (M12)  
- 문서 골격·초안 생성 (M13: 골격만 승인 없이 사용)  
- Baseline AA 승인 후 코드 경로 (기존 inquiry)  
- 자동 Gate ①~③ + 수동 POST 증적 (M15)  
- Drift·재생성 보호 (Rule/Timeout/SQL 성능)

## 3. 성공·중단 기준

**성공 (1차)**

- M0 KPI: 조회 1건을 설계→(생성)→검증 절차로 문서화·실행 증적  
- AA Baseline·코드 사용 승인  
- 금지 패턴 없음  

**중단 / 보류**

- SoT(소스)와 템플릿이 화해 불가한 Drift  
- Timeout·Rule·SQL 성능을 AI가 자동 승인하려는 시도  
- Gateway/배치 범위 침범  

**2차(CRUD) 착수 조건**

- 1차 성공 기준 충족  
- CUD ServiceId·화면 이벤트 Baseline 준비

## 5. 단계적 확산계획

```text
1차 조회 선도 → 2차 단일 CRUD → (이후) 다중테이블·Rule
→ 도메인 연동 → 타 WAR·외부 → Timeout·오류·보상 심화
→ 배치·파일은 M0 제외로 본 방법론 1차 범위 밖
```
