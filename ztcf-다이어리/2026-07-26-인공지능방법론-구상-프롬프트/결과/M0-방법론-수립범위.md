## 1. 방법론 목적서

NSIGHT-TCF-FRAMEWORK에서 **화면·테이블 기반 CRUD 거래 한 세트**(조회·등록·변경·삭제)를  
설계 → (이후 단계에서 정의할) 생성 → 검증까지 **반복 가능한 절차**로 문서화하는  
AI·LLM SI 개발방법론의 1차 범위를 확정한다.

코드 생성부터 시작하지 않는다. 기준·범위·KPI를 먼저 잠근다.

## 2. 적용범위 정의서

| 항목 | 확정 내용 |
| --- | --- |
| 방법론 유형 | 화면·테이블 기반 **CRUD 개발** |
| 최초 적용 단위 | CRUD 거래 한 세트 (inquiry / create / update / delete) |
| 참조 Baseline | `av-service` / 현재 구현 `AV.Sample.inquiry`·`AV_SAMPLE` — CUD는 **목표(설계 예시)**, 현행 소스에 없을 수 있음 |
| 포함 (1차) | 화면 이벤트, 표준 전문, Handler~Mapper, SQL, CUD 규칙·검증, 로컬 검증 절차 |
| 제외 (1차) | 배치·파일 처리, Gateway 신규 라우팅 |
| 보류 (미확정) | 신규 업무 WAR 신설, 타 WAR·외부 연계 |

## 3. 대상 사용자 정의

| 역할 | 1차 대상 여부 | 비고 |
| --- | --- | --- |
| 업무 개발자 | 예 | CRUD 패턴 재현 |
| 애플리케이션 아키텍트 | 예 | 범위·Gate 승인 |
| AI·방법론 설계자 | 예 | 본 문서 작성·유지 |
| PMO·품질 | 설계 예시 | 상세 RACI는 M4 |
| 운영·DevOps | 부분 | Gateway/배치는 제외이므로 1차 비중 낮음 |

## 4. 방법론 성공 KPI

| KPI | 판정 |
| --- | --- |
| CRUD 한 세트를 설계→생성→검증까지 반복 가능한 절차로 문서화 | **채택 (필수)** *(개정: 조회 1건 → CRUD 세트)* |
| 화면–ServiceId–프로그램–SQL–테이블 추적표 완성 | 미확정 (M1 이후 후보) |
| OM·Timeout·거래로그를 완료 정의에 포함 | 미확정 (M15와 연결) |
| 신규 개발자 재현성 | 미확정 |

## 5. 기대 효과 (잠정)

- CRUD 표준화로 설계서 작성 부담·반복 구현 비용을 줄인다.  
- `av-service`를 SoT로 삼되, 현행은 조회만 있으므로 CUD는 방법론 목표로 명시한다.  

(정량 목표: 미확정)

## 6. Gap / 주의 (사실)

- `AV.Sample.inquiry`의 OM Catalog 등록 여부는 이후 단계에서 재확인.  
- CUD Handler·ServiceId·화면 이벤트는 현행 `av-service`에 **없을 수 있음** → 현재 구현 vs 목표 표준으로 구분.  
- M1의「사람 유지 판단」(Timeout·Rule·SQL 성능)은 CUD에도 동일 적용.
