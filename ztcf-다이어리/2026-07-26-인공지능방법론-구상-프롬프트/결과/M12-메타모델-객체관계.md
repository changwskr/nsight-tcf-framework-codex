## 1. 모델 범위

| 항목 | 확정 |
| --- | --- |
| 기본 단위 | ServiceId 1건 = 개발모델 1개 |
| CRUD 세트 | 모델 4개 + Screen이 ServiceId 목록으로 연결 |
| 테이블 | 시범 1개(`AV_SAMPLE`) — 거래 모델이 Table 참조 |
| 외부연계 | 1차 미포함 (보류) |

## 2. 논리 메타모델 (1차 채택 객체)

Project, BusinessArea, Domain, Screen, ScreenEvent, UseCase,  
ServiceId, TransactionCode, RequestModel, ResponseModel,  
DTO, ProgramComponent, Rule, Table, Column, Mapper, SqlStatement,  
OperationalPolicy, TestCase, DeploymentUnit, Artifact, Evidence, Decision

1차 약화/보류: ExternalInterface, SecurityPolicy 상세, ChangeRequest 워크플로

## 3. 필수 관계

```text
Project → BusinessArea → Domain(AV/Sample)
  ├ Screen → ScreenEvent → ServiceId (1..n)
  ├ UseCase → ServiceId
  ├ ProgramComponent
  └ Table (AV_SAMPLE)

ServiceId
  ├ RequestModel / ResponseModel
  ├ Handler / Facade / Service / Rule / DAO / Mapper / SQL
  ├ OperationalPolicy (Timeout 등)
  └ TestCase
```

## 4. 식별자 규칙

| 객체 | 식별자 |
| --- | --- |
| ServiceId | `{업무코드}.{Domain}.{action}` 예: `AV.Sample.inquiry` |
| Artifact | Artifact ID (M11 공통 메타) |
| SQL | Mapper Namespace + SQL ID |
| 테이블 | 물리 테이블명 |

## 5. 버전·호환·상태 (최소)

| 항목 | 방침 |
| --- | --- |
| 버전 | Artifact.version |
| As-Designed vs As-Built | Drift 검증 대상 (M14·M15) |
| 상태 전이 | 초안 → 검토 → Baseline승인 → 생성 → 검증 → 완료 (상세는 M14) |

## 6. 시범 인스턴스 (설계 예시)

| 모델 | ServiceId |
| --- | --- |
| M-inq | `AV.Sample.inquiry` |
| M-crt | `AV.Sample.create` *(명칭 미확정)* |
| M-upd | `AV.Sample.update` *(명칭 미확정)* |
| M-del | `AV.Sample.delete` *(명칭 미확정)* |
| Screen | 위 4개 ServiceId 참조 |
