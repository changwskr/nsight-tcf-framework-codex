## 1. 정상 처리 흐름 (채택)

```text
화면 이벤트
→ 표준 요청 전문
→ (1차) JWT Filter 경로 — Gateway 신규는 제외
→ OnlineTransactionController  (/av/online)
→ TCF.process()
→ STF.preProcess()
→ TimeoutExecutor
→ TransactionDispatcher  (serviceId → Handler)
→ TransactionHandler → Facade → Service → Rule → DAO → Mapper → DB
→ ETF
→ 표준 응답
→ 거래로그·감사로그
```

시범 Endpoint: `POST /av/online`  
ServiceId 패턴: `AV.Sample.{inquiry|create|update|delete}`

## 2. 적용 판정

| 항목 | 판정 |
| --- | --- |
| 공통 OnlineTransactionController | **전체 적용** (목표·시범 기준) |
| ServiceId Dispatcher | **전체 적용** |
| 업무별 Controller | **금지** |

## 3. 계층별 책임표

| 계층 | 책임 |
| --- | --- |
| Handler | ServiceId 진입, Facade 호출 |
| Facade | 트랜잭션 경계 |
| Service | 업무 오케스트레이션 |
| Rule | 검증·업무 규칙 (사람 승인 — M1) |
| DAO | Mapper 위임 |
| Mapper/SQL | 데이터 접근 (성능은 사람 승인 — M1) |

## 4. 허용·금지 호출 규칙

**허용**

- 화면 → tcf-ui 중계 → `/av/online`
- Handler → Facade → Service → Rule → DAO → Mapper

**금지**

- 업무 모듈 `entry/web` Controller
- Service → Mapper 직호출
- 타 업무 DAO·Mapper·Table 직접 참조 (M6)

## 5. 오류·Timeout·Rollback (골격)

| 흐름 | 1차 방침 |
| --- | --- |
| 업무 오류 | Rule/Service에서 표준 오류코드 → ETF |
| Timeout | NFR-02 + TimeoutExecutor (수치 미확정) |
| Rollback | Facade 트랜잭션 롤백; DB·OM은 코드 롤백만으로 부족할 수 있음 |

## 6. 현재 구현 vs 목표

| 항목 | 현재 | 목표 |
| --- | --- | --- |
| inquiry 경로 | 존재 | 유지 |
| create/update/delete | 없음 | 동일 실행구조로 추가 |
| Gateway | 1차 제외 | 제외 유지 |
