## 1. 배포 경계

| 항목 | 확정 |
| --- | --- |
| 경계 | 업무코드별 WAR |
| 시범 WAR | `av.war` |
| Context Path | `/av` |
| Gradle 모듈 | `av-service` |
| 로컬 포트 | 8101 (`BusinessModuleDefinitions` — 사실) |

## 2. 논리 아키텍처·모듈 구성

```text
[플랫폼]
  tcf-core / tcf-web / tcf-util …
[업무]
  av-service  (시범)
[UI 중계]
  tcf-ui  →  bootRun: :8101/av/online  또는  Tomcat: :8080/av/online
[제외 1차]
  Gateway 신규 라우팅, 배치·파일 (M0)
```

## 3. 패키지·계층 (목표 = 현재 av-service)

```text
com.nh.nsight.marketing.av
  entry/handler → facade
  application/service → rule → dto
  persistence/dao → mapper → dto
  (+ client / config / support 필요 시)
```

의존성 규칙:

- 업무 모듈 → `tcf-core`, `tcf-web` (허용)
- Service → Mapper 직호출 **금지**
- 타 업무 DAO·Mapper·Table 직참조 **금지** (M6)
- 업무 `entry/web` Controller **금지**

## 4. 현재 구현 vs 목표

| 항목 | 현재 구현 | 목표 표준 |
| --- | --- | --- |
| WAR·패키지·조회 계층 | 존재 | 유지 |
| CUD 계층 | 없음 | 동일 패키지 규칙으로 추가 |
| Gateway | 1차 제외 | 제외 유지 |
| JWT | 플랫폼 필터 경로 존재 | 상세는 미확정 |

## 5. 배포·장애 경계

- 장애 단위: `av` context / `av-service` JVM(bootRun) 또는 공유 Tomcat 내 `av` WAR  
- 롤백: WAR + (해당 시) DB·OM — 코드만으로 부족할 수 있음 (M16에서 상세)
