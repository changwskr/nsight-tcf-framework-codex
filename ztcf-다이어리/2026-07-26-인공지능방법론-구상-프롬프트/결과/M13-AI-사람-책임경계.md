## 1. 원칙

```text
AI는 설계를 대신 결정하지 않는다.
AI는 확인된 설계정보를 반복 가능한 코드·문서·검증으로 변환한다.
```

승인 없이 사용 가능: **문서 골격만**.  
그 외(코드, OM, 완성 설계서, CRUD 전체)는 **AA 승인 후** 사용.

## 2. AI 자동화 범위표

| 대상 | AI | 사람 | 비고 |
| --- | --- | --- | --- |
| 문서 골격 | 생성·사용 가능 | 보완 | 승인 없이 사용 허용 |
| 설계서 초안(핵심 6종) | 생성 | AA 승인 후 사용 | M10·M1 |
| DTO·Handler·Mapper 골격 | 생성(목표) | AA 승인 후 사용 | 승인 전 사용 금지 |
| 표준 CRUD 전체 | 생성(목표) | AA 승인 필수 | ③ 채택 안 함 |
| OM 초안 | 생성 가능 | AA 승인 | |
| Rule 본문·SQL 성능 | 골격만 | **사람 필수** | M1 |
| Timeout·TX·오류 정책 | 초안 | **사람 필수** | M1·M7 |

## 3. 사람 승인 필수 (고정)

업무 규칙, 데이터 소유권, 트랜잭션 경계, Timeout·Retry,  
SQL 성능·인덱스, 권한·개인정보·감사(해당 시),  
배포·롤백, 최종 운영 승인, **모든 코드·OM의 AA A**

## 4. 생성 소유 / 수동 소유

| 생성 소유 (AI→개발자 R) | 수동 소유 (덮어쓰기 금지) |
| --- | --- |
| 문서 골격, 템플릿 반복 필드 | Rule 로직·메시지 |
| Handler/DTO/Mapper **초안** (승인 후) | 손댄 비즈니스 로직 |
| 추적성 매트릭스 초안 | Timeout·인덱스·소유권 결정값 |

## 5. 재생성 보호정책

1. `수동`·`보호` 표시 구간은 재생성으로 덮지 않는다.  
2. Baseline 승인 전 코드 머지 금지 (M4).  
3. 문서 골격만 승인 없이 workspace에 둘 수 있다.  
4. 사실(현재 Model Studio 능력)과 목표(CRUD 생성)를 섞어 쓰지 않는다.
