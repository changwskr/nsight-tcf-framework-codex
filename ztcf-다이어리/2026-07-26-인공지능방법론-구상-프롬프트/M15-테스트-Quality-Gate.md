## 이 단계에서 얻는 것

“완료”를 **증적과 Gate**로 정의한다. 컴파일 성공만으로 끝내지 않는다.

## 지금 이 질문을 붙여 넣으세요

```text
M00을 적용한다. 결과/M0~M14를 인용한다.
코드·최종방법론 본문은 쓰지 마라. 질문 1개씩.
컴파일 성공만으로 완료 처리하지 마라.

생성된 코드의 완료 여부를 어떤 수준까지 자동으로 검증할까요?

① 컴파일
② 단위테스트
③ 구조·명명 검증
④ DB·거래 통합테스트
⑤ 배포·운영검증까지

다음 검증 범주를 이 방법론의 Gate로 재정의하라.

모델: 필수값, 중복 ID, 참조 무결성, 소유권, 상태 전이, 미승인 항목
코드: Gradle Build, 패키지, 계층 의존성, 금지 Import, ServiceId 중복,
      Handler 등록, Mapper↔XML, SQL ID, 테스트 실행
정합성: 화면이벤트↔ServiceId↔Handler↔Facade↔Service↔Rule↔DAO↔Mapper↔SQL·Table
        ↔OM↔Timeout·거래통제↔테스트↔거래로그·감사로그
런타임: bootRun, 표준 POST, 정상/업무오류/시스템오류, Timeout, Rollback,
        중복요청, 권한 부족, 로그 추적, DB 결과
증적: Commit ID, 모델/문서 버전, 빌드·테스트 결과, 실행 로그,
      요청·응답, DB 검증, OM 등록, 배포 Artifact

단계 산출물(결과/M15-테스트-Quality-Gate.md):
- Quality Gate 정의서
- 자동검증 규칙
- 테스트 시나리오
- 완료 증적 기준
- Gate 실패 처리절차

확정 후 「다음 단계(M16)로 갈까요?」만 물어라.
```

## 단계 산출물

- Quality Gate 정의서
- 자동검증 규칙
- 테스트 시나리오
- 완료 증적 기준
- Gate 실패 처리절차

## 통과 기준

- 자동 검증 상한(①~⑤)이 확정되어 있다.  
- 완료 증적 목록이 체크리스트로 있다.
