## 이 단계에서 얻는 것

화면부터 DB까지 **한 건의 온라인 거래 흐름**과 허용·금지 호출 규칙을 확정한다.

## 지금 이 질문을 붙여 넣으세요

```text
M00을 적용한다. 결과/M0~M8을 인용한다.
코드·최종방법론 본문은 쓰지 마라. 질문 1개씩.
아래 기준 흐름을 현재 저장소와 대조하라.

기준 흐름:
화면 이벤트 → 표준 요청 전문 → Gateway 또는 JWT Filter
→ OnlineTransactionController → TCF.process() → STF.preProcess()
→ TimeoutExecutor → TransactionDispatcher → TransactionHandler
→ Facade → Service → Rule → DAO → Mapper → DB/외부연계
→ ETF → 표준 응답 → 거래로그·감사로그

질문:
현재 업무 요청은 공통 OnlineTransactionController와 ServiceId Dispatcher를 통해 처리됩니까?

① 전체 적용
② 일부 업무만 적용
③ 업무별 Controller 혼재
④ 아직 구현되지 않음

확인할 내용:
표준 Endpoint, 요청·응답 전문, ServiceId 형식, 거래코드, Header,
인증 문맥, 거래통제, Timeout, 중복요청, 트랜잭션 경계,
오류 변환, 거래로그, 감사로그

단계 산출물(결과/M9-표준-거래-실행구조.md):
- 정상 처리 흐름
- 오류 처리 흐름
- Timeout 흐름
- Rollback 흐름
- 계층별 책임표
- 허용·금지 호출 규칙

확정 후 「다음 단계(M10)로 갈까요?」만 물어라.
```

## 단계 산출물

- 정상·오류·Timeout·Rollback 흐름
- 계층별 책임표
- 허용·금지 호출 규칙

## 통과 기준

- 한 줄 정상 흐름이 확정되어 있다.  
- 금지 호출 규칙(업무 Controller, Service→Mapper 직호출, 타 업무 테이블 직접 참조)이 명시되어 있다.
