# II.3.1.5 유지보수성(maintainability) — 작업지시

## 1. 도입 전 안내말

이 디렉터리는 원문 목차 **`II 아키텍처 결정요인 도출 > II.3 품질 요구사항 > II.3.1 품질 속성 분류 > II.3.1.5 유지보수성(maintainability)`**를 독립 작업 단위로 전환한 공간이다. 원문에 기재된 2008년 기술과 조직 조건은 역사적 기준선으로 보존하고, 현재 값이나 현대화 제안으로 자동 치환하지 않는다.

| 목차 코드 | `II.3.1.5` |

| 책임 | A: SA / R: 품질·아키텍처 담당 / C: 전 영역 아키텍트·업무·운영 / I: PMO·개발·QA |

### 목적
ISO/IEC 9126의 유지보수성 관점에서 측정 가능한 품질 시나리오와 수용 기준을 정의한다.

### 적용범위
- 해당 목차의 원문 내용과 관련 표·그림
- 관련 요구사항, 제약, 구성요소, 인터페이스, 배포·운영 정보
- 하위 목차가 있는 경우 하위 산출물의 통합·검토·승인

### 선행조건
- 원문 기준선과 현재 현행자료의 기준일·버전을 구분한다.
- 사실, 가정, 제안, 미결정 사항을 서로 다른 상태로 관리한다.
- 담당자와 승인자를 지정한다.

## 3. IN — 준비할 입력자료

1. 업무 중요도
2. 품질속성 후보
3. 자극·환경·대상·응답
4. 측정 지표·임계치
5. 우선순위·시험방법

입력 예시는 [`IN/예시_입력.md`](./IN/예시_입력.md)를 사용한다. 실제 자료는 예시 파일을 덮어쓰지 말고 날짜·버전을 붙여 추가한다.

## 4. 수행해야 되는 일

1. 품질속성을 구체적인 시나리오로 변환한다.
2. 자극·환경·대상·응답·응답측정값을 작성한다.
3. 정상·피크·장애 조건의 수용 기준을 정한다.
4. 검증 방법과 증적 위치를 정의한다.
5. 상충하는 품질속성의 우선순위와 trade-off를 기록한다.

## 5. OUT — 작성할 산출물

1. 품질속성 시나리오
2. 측정지표·수용기준표
3. 우선순위·trade-off 기록
4. 시험 시나리오
5. 증적 목록

산출물 예시는 [`OUT/예시_산출물.md`](./OUT/예시_산출물.md)를 참고한다. 최종본은 작성자·검토자·승인자와 기준일을 명시한다.

## 6. 책임 경계와 RACI

- **Accountable**: 위 표의 A 역할이 최종 기준선과 예외를 승인한다.
- **Responsible**: R 역할이 자료 수집, 분석, 작성, 결함 조치를 수행한다.
- **Consulted**: C 역할이 업무·데이터·기술·보안·운영 영향도를 검토한다.
- **Informed**: I 역할이 승인된 결과와 변경 영향을 전달받는다.

## 7. 품질 Gate

- [ ] 원문 사실, 현재 확인값, 설계 제안, 미확정 가정을 구분하여 표시했는가?
- [ ] 모든 표·그림·식별자가 관련 산출물과 양방향으로 추적되는가?
- [ ] 정상뿐 아니라 오류·Timeout·장애·복구 상황을 포함했는가?
- [ ] 책임 조직, 승인자, 변경·폐기 절차가 명확한가?
- [ ] 각 요구가 정량 측정 가능하고 시험환경·판정기준이 명확한가?
- [ ] 상충 품질속성의 우선순위와 허용 trade-off가 승인되었는가?

## 8. 변경·호환성·폐기 관리

1. 원문 기준은 수정하지 않고 별도 `현재값`, `목표값`, `폐기대상` 상태를 둔다.
2. 변경 시 영향 목차, 관련 그림·표, 구성요소, 인터페이스, 시험 항목을 갱신한다.
3. 기술 버전, 수치, 범위, 책임 변경은 ADR 또는 변경승인 기록을 남긴다.
4. 폐기 항목은 대체 항목, 전환일, 데이터·인터페이스 호환 기간을 명시한다.
