# II.2.2.2 데이터베이스 서버 환경 — 작업지시

## 1. 도입 전 안내말

이 디렉터리는 원문 목차 **`II 아키텍처 결정요인 도출 > II.2 제약사항 > II.2.2 기술적 제약사항 > II.2.2.2 데이터베이스 서버 환경`**를 독립 작업 단위로 전환한 공간이다. 원문에 기재된 2008년 기술과 조직 조건은 역사적 기준선으로 보존하고, 현재 값이나 현대화 제안으로 자동 치환하지 않는다.

## 2. 문서 개요

| 항목 | 내용 |
|---|---|
| 원문 | 워커힐 NGS(차세대 시스템) 소프트웨어 아키텍처 정의서 v1.0 |
| 목차 코드 | `II.2.2.2` |
| 제목 | 데이터베이스 서버 환경 |
| 원문 논리 페이지 | 16 |
| 작업 경로 | `II 아키텍처 결정요인 도출 > II.2 제약사항 > II.2.2 기술적 제약사항 > II.2.2.2 데이터베이스 서버 환경` |
| 책임 | A: DA / R: DBA·데이터아키텍트 / C: SA·AA·TA·업무 / I: 개발·QA·운영 |

### 목적
원문 기준 통합 DB는 Informix Dynamic Server v10, 문자셋은 US7ASCII이며 Oracle·Informix·MS SQL 유지 DB 의존성을 함께 조사한다.

### 적용범위
- 해당 목차의 원문 내용과 관련 표·그림
- 관련 요구사항, 제약, 구성요소, 인터페이스, 배포·운영 정보
- 하위 목차가 있는 경우 하위 산출물의 통합·검토·승인

### 선행조건
- 원문 기준선과 현재 현행자료의 기준일·버전을 구분한다.
- 사실, 가정, 제안, 미결정 사항을 서로 다른 상태로 관리한다.
- 담당자와 승인자를 지정한다.

## 3. IN — 준비할 입력자료

1. 제약 원문·근거
2. 영향 대상
3. 강제/협의/가정 구분
4. 위험·완화책
5. 유효기간·재검토 조건

입력 예시는 [`IN/예시_입력.md`](./IN/예시_입력.md)를 사용한다. 실제 자료는 예시 파일을 덮어쓰지 말고 날짜·버전을 붙여 추가한다.

## 4. 수행해야 되는 일

1. 데이터베이스 서버 환경의 목적과 범위를 원문 근거로 확정한다.
2. 입력자료를 사실·가정·제약·미결정 사항으로 구분한다.
3. 정상 흐름과 오류·Timeout·장애 흐름을 함께 설계한다.
4. 대안과 trade-off를 비교하고 결정근거를 기록한다.
5. 산출물 간 추적성, 운영성, 보안성, 테스트 가능성을 검증한다.

## 5. OUT — 작성할 산출물

1. 데이터베이스 서버 환경 기준서/설계서
2. 관련 표·구성도·흐름도
3. 결정사항·ADR
4. 검증 체크리스트·증적
5. 변경·승인 이력

산출물 예시는 [`OUT/예시_산출물.md`](./OUT/예시_산출물.md)를 참고한다. 최종본은 작성자·검토자·승인자와 기준일을 명시한다.

## 6. 책임 경계와 RACI

- **Accountable**: 위 표의 A 역할이 최종 기준선과 예외를 승인한다.
- **Responsible**: R 역할이 자료 수집, 분석, 작성, 결함 조치를 수행한다.
- **Consulted**: C 역할이 업무·데이터·기술·보안·운영 영향도를 검토한다.
- **Informed**: I 역할이 승인된 결과와 변경 영향을 전달받는다.

- [ ] 모든 표·그림·식별자가 관련 산출물과 양방향으로 추적되는가?

- [ ] 제품명·버전·라이선스·지원종료·환경별 차이가 실제 인벤토리와 일치하는가?
- [ ] 단일 장애점과 용량·복구 조건이 시험 가능한가?

## 8. 변경·호환성·폐기 관리

1. 원문 기준은 수정하지 않고 별도 `현재값`, `목표값`, `폐기대상` 상태를 둔다.
2. 변경 시 영향 목차, 관련 그림·표, 구성요소, 인터페이스, 시험 항목을 갱신한다.
3. 기술 버전, 수치, 범위, 책임 변경은 ADR 또는 변경승인 기록을 남긴다.
4. 폐기 항목은 대체 항목, 전환일, 데이터·인터페이스 호환 기간을 명시한다.
