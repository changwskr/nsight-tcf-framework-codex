# II.1.13 업무지원시스템 — 작업지시

## 1. 도입 전 안내말

이 디렉터리는 원문 목차 **`II 아키텍처 결정요인 도출 > II.1 비즈니스 요구사항 > II.1.13 업무지원시스템`**를 독립 작업 단위로 전환한 공간이다. 원문에 기재된 2008년 기술과 조직 조건은 역사적 기준선으로 보존하고, 현재 값이나 현대화 제안으로 자동 치환하지 않는다.

## 2. 문서 개요

| 항목 | 내용 |
|---|---|
| 원문 | 워커힐 NGS(차세대 시스템) 소프트웨어 아키텍처 정의서 v1.0 |
| 목차 코드 | `II.1.13` |
| 제목 | 업무지원시스템 |
| 원문 논리 페이지 | 13 |
| 작업 경로 | `II 아키텍처 결정요인 도출 > II.1 비즈니스 요구사항 > II.1.13 업무지원시스템` |
| 책임 | A: 업무책임자 / R: BA·업무아키텍트 / C: SA·DA·연계·보안 / I: 개발·QA·운영 |

### 목적
업무지원시스템의 업무 범위, 사용자, 핵심 기능, 데이터, 타 시스템 연계와 조직 책임을 확정한다.

### 적용범위
- 해당 목차의 원문 내용과 관련 표·그림
- 관련 요구사항, 제약, 구성요소, 인터페이스, 배포·운영 정보
- 하위 목차가 있는 경우 하위 산출물의 통합·검토·승인

### 선행조건
- 원문 기준선과 현재 현행자료의 기준일·버전을 구분한다.
- 사실, 가정, 제안, 미결정 사항을 서로 다른 상태로 관리한다.
- 담당자와 승인자를 지정한다.

## 3. IN — 준비할 입력자료

1. 업무 프로세스·기능 목록
2. 사용자·조직·권한 정보
3. 핵심 데이터·기준정보 목록
4. 연계 시스템·인터페이스 목록
5. 현행 문제·TO-BE 요구
6. 정량 품질 목표

입력 예시는 [`IN/예시_입력.md`](./IN/예시_입력.md)를 사용한다. 실제 자료는 예시 파일을 덮어쓰지 말고 날짜·버전을 붙여 추가한다.

## 4. 수행해야 되는 일

1. 업무 목적과 사용자 여정을 기준으로 기능을 구조화한다.
2. 핵심 엔터티·기준정보·거래정보의 생성·조회·변경 책임을 식별한다.
3. 타 시스템 호출과 제공 인터페이스를 정리하고 동기/비동기 방식을 결정한다.
4. 권한·감사·개인정보·오류·병행운영 요구를 명세한다.
5. 기능 요구를 품질 요구와 아키텍처 구성요소에 추적 연결한다.

## 5. OUT — 작성할 산출물

1. 업무지원시스템 요구사항 명세서
2. 업무 기능·사용자·데이터 매트릭스
3. 시스템 연계 목록
4. 권한·감사·품질 요구 목록
5. 아키텍처 추적성 표

산출물 예시는 [`OUT/예시_산출물.md`](./OUT/예시_산출물.md)를 참고한다. 최종본은 작성자·검토자·승인자와 기준일을 명시한다.

## 6. 책임 경계와 RACI

- **Accountable**: 위 표의 A 역할이 최종 기준선과 예외를 승인한다.
- **Responsible**: R 역할이 자료 수집, 분석, 작성, 결함 조치를 수행한다.
- **Consulted**: C 역할이 업무·데이터·기술·보안·운영 영향도를 검토한다.
- **Informed**: I 역할이 승인된 결과와 변경 영향을 전달받는다.

## 7. 품질 Gate

- [ ] 원문 사실, 현재 확인값, 설계 제안, 미확정 가정을 구분하여 표시했는가?
- [ ] 모든 표·그림·식별자가 관련 산출물과 양방향으로 추적되는가?
- [ ] 정상뿐 아니라 오류·Timeout·장애·복구 상황을 포함했는가?
- [ ] 책임 조직, 승인자, 변경·폐기 절차가 명확한가?
- [ ] 기능별 사용자·데이터·연계·권한·품질 요구가 누락 없이 연결되는가?
- [ ] 다른 시스템과 중복되는 기능·데이터 소유권 충돌이 해소되었는가?

## 8. 변경·호환성·폐기 관리

1. 원문 기준은 수정하지 않고 별도 `현재값`, `목표값`, `폐기대상` 상태를 둔다.
2. 변경 시 영향 목차, 관련 그림·표, 구성요소, 인터페이스, 시험 항목을 갱신한다.
3. 기술 버전, 수치, 범위, 책임 변경은 ADR 또는 변경승인 기록을 남긴다.
4. 폐기 항목은 대체 항목, 전환일, 데이터·인터페이스 호환 기간을 명시한다.
