# IV.1.4.3 Batch 파일 수신 — 작업지시

## 1. 도입 전 안내말

이 디렉터리는 원문 목차 **`IV 아키텍처 수립 > IV.1 Runtime View > IV.1.4 대외 인터페이스 > IV.1.4.3 Batch 파일 수신`**를 독립 작업 단위로 전환한 공간이다. 원문에 기재된 2008년 기술과 조직 조건은 역사적 기준선으로 보존하고, 현재 값이나 현대화 제안으로 자동 치환하지 않는다.

## 2. 문서 개요

| 항목 | 내용 |
|---|---|
| 원문 | 워커힐 NGS(차세대 시스템) 소프트웨어 아키텍처 정의서 v1.0 |
| 목차 코드 | `IV.1.4.3` |
| 제목 | Batch 파일 수신 |
| 원문 논리 페이지 | 37 |
| 작업 경로 | `IV 아키텍처 수립 > IV.1 Runtime View > IV.1.4 대외 인터페이스 > IV.1.4.3 Batch 파일 수신` |
| 책임 | A: 연계아키텍트 / R: 인터페이스 개발·운영 / C: SA·AA·업무·보안 / I: QA·DBA |

### 목적
Batch 파일 수신의 시작 조건, 전문/파일 계약, 처리 순서, Timeout·재처리·오류 흐름과 운영 추적 기준을 정의한다.

### 적용범위
- 해당 목차의 원문 내용과 관련 표·그림
- 관련 요구사항, 제약, 구성요소, 인터페이스, 배포·운영 정보
- 하위 목차가 있는 경우 하위 산출물의 통합·검토·승인

### 선행조건
- 원문 기준선과 현재 현행자료의 기준일·버전을 구분한다.
- 사실, 가정, 제안, 미결정 사항을 서로 다른 상태로 관리한다.
- 담당자와 승인자를 지정한다.

## 3. IN — 준비할 입력자료

1. 송·수신 시스템
2. 전문/파일 레이아웃
3. 프로토콜·포트·문자셋
4. Timeout·재시도·중복 처리
5. 오류코드·ACK/NAK
6. 운영·재처리 절차

입력 예시는 [`IN/예시_입력.md`](./IN/예시_입력.md)를 사용한다. 실제 자료는 예시 파일을 덮어쓰지 말고 날짜·버전을 붙여 추가한다.

## 4. 수행해야 되는 일

1. 시작·종료 조건과 메시지/파일 상태를 정의한다.
2. 인코딩·길이·필수값·검증·변환 규칙을 정의한다.
3. 정상, 업무오류, 시스템오류, Timeout 흐름을 작성한다.
4. 재시도·중복·순서·재처리 정책을 결정한다.
5. 거래ID·파일ID·로그·모니터링 항목을 연결한다.

## 5. OUT — 작성할 산출물

1. 연계 흐름도/시퀀스
2. 전문·파일 계약서
3. 오류·재시도·재처리 정책
4. 운영 로그·모니터링 기준
5. 연계 테스트 케이스

산출물 예시는 [`OUT/예시_산출물.md`](./OUT/예시_산출물.md)를 참고한다. 최종본은 작성자·검토자·승인자와 기준일을 명시한다.

## 6. 책임 경계와 RACI

- **Accountable**: 위 표의 A 역할이 최종 기준선과 예외를 승인한다.
- **Responsible**: R 역할이 자료 수집, 분석, 작성, 결함 조치를 수행한다.
- **Consulted**: C 역할이 업무·데이터·기술·보안·운영 영향도를 검토한다.
- **Informed**: I 역할이 승인된 결과와 변경 영향을 전달받는다.

## 7. 품질 Gate

- [ ] 모든 표·그림·식별자가 관련 산출물과 양방향으로 추적되는가?
- [ ] 정상뿐 아니라 오류·Timeout·장애·복구 상황을 포함했는가?
- [ ] 책임 조직, 승인자, 변경·폐기 절차가 명확한가?
- [ ] 송·수신 양측 계약, 문자셋, 길이, ACK/NAK, 재처리 기준이 합의되었는가?
- [ ] 중복·순서역전·부분실패·재전송 시 데이터 정합성이 보장되는가?

## 8. 변경·호환성·폐기 관리

1. 원문 기준은 수정하지 않고 별도 `현재값`, `목표값`, `폐기대상` 상태를 둔다.
2. 변경 시 영향 목차, 관련 그림·표, 구성요소, 인터페이스, 시험 항목을 갱신한다.
3. 기술 버전, 수치, 범위, 책임 변경은 ADR 또는 변경승인 기록을 남긴다.
4. 폐기 항목은 대체 항목, 전환일, 데이터·인터페이스 호환 기간을 명시한다.
