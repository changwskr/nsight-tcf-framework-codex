# IV.3 Allocation View — 작업지시

## 1. 도입 전 안내말

이 디렉터리는 원문 목차 **`IV 아키텍처 수립 > IV.3 Allocation View`**를 독립 작업 단위로 전환한 공간이다. 원문에 기재된 2008년 기술과 조직 조건은 역사적 기준선으로 보존하고, 현재 값이나 현대화 제안으로 자동 치환하지 않는다.

## 2. 문서 개요

| 항목 | 내용 |
|---|---|
| 원문 | 워커힐 NGS(차세대 시스템) 소프트웨어 아키텍처 정의서 v1.0 |
| 목차 코드 | `IV.3` |
| 제목 | Allocation View |
| 원문 논리 페이지 | 52 |
| 작업 경로 | `IV 아키텍처 수립 > IV.3 Allocation View` |
| 책임 | A: SA / R: 담당 아키텍트·분석가 / C: 업무·개발·데이터·보안·운영 / I: PMO·QA |

### 목적
논리 구성요소를 서버·소프트웨어·소스·배포 단위에 배치한다.

### 적용범위
- 해당 목차의 원문 내용과 관련 표·그림
- 관련 요구사항, 제약, 구성요소, 인터페이스, 배포·운영 정보
- 하위 목차가 있는 경우 하위 산출물의 통합·검토·승인

### 선행조건
- 원문 기준선과 현재 현행자료의 기준일·버전을 구분한다.
- 사실, 가정, 제안, 미결정 사항을 서로 다른 상태로 관리한다.
- 담당자와 승인자를 지정한다.

## 3. IN — 준비할 입력자료

1. 논리 구성요소 목록
2. 서버·네트워크·스토리지 정보
3. 제품·버전·라이선스
4. 소스·빌드·패키징 구조
5. 이중화·용량·운영 요구
6. 환경별 차이

입력 예시는 [`IN/예시_입력.md`](./IN/예시_입력.md)를 사용한다. 실제 자료는 예시 파일을 덮어쓰지 말고 날짜·버전을 붙여 추가한다.

## 4. 수행해야 되는 일

1. 하위 목차별 IN 자료의 완전성과 최신성을 점검한다.
2. 하위 산출물 사이의 용어·식별자·범위·수치 정합성을 검토한다.
3. 미결정 사항을 ADR/Risk/Gap으로 등록하고 담당자와 기한을 지정한다.
4. 통합 그림·표·인덱스를 작성하여 하위 산출물로 추적 가능하게 연결한다.
5. 검토·승인 결과를 기록하고 다음 단계 진입 여부를 판단한다.

## 5. OUT — 작성할 산출물

1. 하위 산출물 통합 인덱스
2. 통합 요약·구성도
3. 미결정·Risk·Gap 목록
4. 검토 의견 및 조치 결과
5. 승인된 Baseline

산출물 예시는 [`OUT/예시_산출물.md`](./OUT/예시_산출물.md)를 참고한다. 최종본은 작성자·검토자·승인자와 기준일을 명시한다.

## 6. 책임 경계와 RACI

- **Accountable**: 위 표의 A 역할이 최종 기준선과 예외를 승인한다.
- **Responsible**: R 역할이 자료 수집, 분석, 작성, 결함 조치를 수행한다.
- **Consulted**: C 역할이 업무·데이터·기술·보안·운영 영향도를 검토한다.
- **Informed**: I 역할이 승인된 결과와 변경 영향을 전달받는다.

## 7. 품질 Gate

- [ ] 원문 사실, 현재 확인값, 설계 제안, 미확정 가정을 구분하여 표시했는가?
- [ ] 모든 표·그림·식별자가 관련 산출물과 양방향으로 추적되는가?
- [ ] 정상뿐 아니라 오류·Timeout·장애·복구 상황을 포함했는가?
- [ ] 책임 조직, 승인자, 변경·폐기 절차가 명확한가?
- [ ] 산출물이 다음 단계의 입력으로 직접 사용 가능한 수준인가?

## 8. 변경·호환성·폐기 관리

1. 원문 기준은 수정하지 않고 별도 `현재값`, `목표값`, `폐기대상` 상태를 둔다.
2. 변경 시 영향 목차, 관련 그림·표, 구성요소, 인터페이스, 시험 항목을 갱신한다.
3. 기술 버전, 수치, 범위, 책임 변경은 ADR 또는 변경승인 기록을 남긴다.
4. 폐기 항목은 대체 항목, 전환일, 데이터·인터페이스 호환 기간을 명시한다.
