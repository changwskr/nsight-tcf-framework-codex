# 1. 도입 전 안내말

결론부터 말하면, **DAVIS CODER가 사내 인터넷이 없는 상태에서 처음부터 학습한 것은 아닐 가능성이 매우 높습니다.**

대부분의 사내 LLM 개발지원 도구는 다음 구조로 동작합니다.

```text
외부의 대규모 GPU 환경
  ↓
방대한 문서·소스코드로 기본 LLM 사전학습
  ↓
명령 수행·코딩 능력을 추가 학습
  ↓
완성된 모델 파일을 회사 내부로 반입
  ↓
사내 GPU 서버에 설치
  ↓
인터넷 없이 추론·코드 생성 수행
```

즉, **학습은 과거에 외부에서 이루어졌고, 현재 사내에서는 학습된 결과를 실행하고 있는 것**입니다.

공개형 LLM은 사전학습·지시학습이 완료된 모델 가중치를 내려받아 별도 서버에서 실행할 수 있습니다. Meta도 Llama 모델을 사전학습 모델과 지시 미세조정 모델로 배포하며, 모델 가중치를 내려받아 자체 환경에서 사용할 수 있다고 설명합니다. ([메타 AI][1])

---

# 2. 학습과 사용은 서로 다른 과정이다

LLM에서는 다음 두 과정을 명확히 구분해야 합니다.

| 구분      | 의미                                         |                      인터넷 필요 여부 |
| --------- | -------------------------------------------- | ------------------------------------: |
| 사전학습  | 대량의 문서와 코드로 모델 능력을 만드는 과정 | 학습자료 확보 단계에서 필요할 수 있음 |
| 미세조정  | 명령 수행, 코딩, 대화 능력을 강화            |                      사전에 수행 가능 |
| 사내 설치 | 완성된 모델 파일을 GPU 서버에 배치           |                    설치파일 반입 필요 |
| 추론      | 사용자의 프롬프트를 받아 답변 생성           |                      인터넷 없이 가능 |
| RAG 검색  | 사내 문서·소스 저장소에서 관련 내용을 검색   |                     사내망만으로 가능 |
| 추가학습  | 사내 데이터로 모델 가중치를 다시 조정        |                    인터넷 없이도 가능 |

Hugging Face의 공식 문서에서도 모델과 설정 파일을 미리 내려받아 두면 방화벽 또는 완전한 오프라인 환경에서 모델을 실행할 수 있다고 설명합니다. ([허깅페이스][2])

# 3. LLM의 지식은 어디에 들어 있는가

LLM은 일반적인 데이터베이스처럼 다음 구조로 지식을 저장하지 않습니다.

```text
질문: Java에서 NullPointerException이 발생하는 이유
  ↓
DB에서 해당 문서 검색
  ↓
저장된 답변 반환
```

기본 LLM은 학습 과정에서 문장, 개념, 코드 구조 사이의 통계적 관계를 **수십억 개의 숫자, 즉 모델 가중치에 압축해 저장**합니다.

비유하면 다음과 같습니다.

```text
수많은 책과 소스코드를 읽은 개발자
  ↓
책을 매번 다시 찾아보지 않더라도
  ↓
기억하고 있는 패턴과 원리를 조합하여 답변
```

LLM 내부에서는 대략 다음 과정이 수행됩니다.

```text
사용자 프롬프트
  ↓
문장을 Token 단위로 변환
  ↓
학습된 모델 가중치로 문맥 분석
  ↓
다음에 올 가능성이 높은 Token 계산
  ↓
Token을 하나씩 생성
  ↓
답변·코드 완성
```

따라서 인터넷이 없어도 다음과 같은 일반적인 질문에 답할 수 있습니다.

- Java와 Spring 사용법
- SQL 작성
- 오류 원인 분석
- 클래스와 메서드 생성
- 테스트 코드 생성
- 소스 리팩터링
- 설계 패턴 설명
- 주석과 문서 작성

이러한 내용은 모델이 사전에 학습한 언어·코드 패턴에 이미 반영되어 있기 때문입니다.

# 4. 다양한 프롬프트를 이해하는 이유

단순히 많은 문서를 읽었다고 해서 사용자의 명령을 잘 수행하는 것은 아닙니다.

일반적으로 코딩 LLM은 다음 세 단계의 능력을 갖습니다.

## 4.1 기본 사전학습

방대한 자연어와 소스코드를 학습합니다.

```text
Java
Python
JavaScript
SQL
HTML
Spring
알고리즘
기술문서
질문과 답변
코드 주석
오류 메시지
```

이 단계에서 언어, 코드 문법, 일반적인 개발 패턴을 익힙니다.

## 4.2 Instruction Tuning

다음과 같은 형태의 데이터로 추가 학습합니다.

```text
명령: 이 Java 코드를 리팩터링하라.
응답: 개선된 코드와 변경 이유

명령: 이 오류를 분석하라.
응답: 원인, 확인 방법, 수정 코드

명령: 고객 조회 CRUD를 작성하라.
응답: Controller, Service, DAO, SQL
```

Instruction Tuning은 처음 보는 자연어 명령에도 대응하는 능력을 크게 높이는 것으로 연구되어 왔습니다. ([arXiv][3])

## 4.3 코드 특화 학습

일반 LLM에 다음 능력을 강화할 수 있습니다.

- 코드 자동완성
- 코드 생성
- 코드 설명
- 오류 수정
- 단위 테스트 생성
- 여러 파일 간 의존성 분석
- 자연어 요구사항을 코드로 변환

따라서 사용자가 표현을 조금씩 다르게 하더라도, 학습했던 명령과 코드 패턴을 조합하여 비슷한 작업을 수행할 수 있습니다.

# 5. DAVIS CODER가 사내 소스까지 이해하는 이유

DAVIS CODER가 일반적인 Java 지식뿐 아니라 **회사의 실제 프로젝트 구조나 사내 프레임워크까지 어느 정도 이해한다면**, 다음 기능이 추가되어 있을 가능성이 큽니다.

## 5.1 프롬프트에 현재 소스를 함께 전달

IDE에서 열어 놓은 파일이나 선택한 코드를 LLM에 함께 보냅니다.

```text
사용자 질문
+ 현재 열려 있는 Java 파일
+ 관련 Interface
+ 오류 메시지
+ 프로젝트 설정
  ↓
LLM 요청
```

LLM이 사내 프로젝트를 사전에 학습하지 않았더라도, 요청할 때 소스가 같이 전달되면 내용을 분석할 수 있습니다.

## 5.2 사내 소스 인덱싱

도구가 사내 Git 저장소를 미리 읽어 다음 정보를 색인할 수 있습니다.

```text
클래스명
메서드명
패키지 구조
호출 관계
설정 파일
Mapper XML
SQL
문서
테스트 코드
```

사용자가 질문하면 관련 파일을 찾아 LLM에 제공합니다.

```text
질문
  ↓
사내 코드 검색
  ↓
관련 파일 5~20개 선택
  ↓
질문과 검색 결과를 LLM에 전달
  ↓
답변 생성
```

이 방식을 일반적으로 **RAG, Retrieval-Augmented Generation**이라고 부릅니다. RAG는 사전학습 모델의 내부 지식과 외부 문서 검색 결과를 함께 이용하는 방식입니다. ([arXiv][4])

중요한 점은 **RAG는 대개 모델을 다시 학습시키는 것이 아니라, 질문할 때 필요한 자료를 찾아 넣어 주는 방식**이라는 것입니다.

## 5.3 사내 규칙 프롬프트

DAVIS CODER 관리자나 공급사가 다음과 같은 지침을 사전에 설정했을 수도 있습니다.

```text
- Java 21을 사용한다.
- Spring Boot 3.x를 사용한다.
- Controller → Service → DAO 구조를 따른다.
- MyBatis를 사용한다.
- 사내 보안코딩 기준을 적용한다.
- 테스트 코드를 함께 작성한다.
```

사용자는 이 숨겨진 시스템 프롬프트를 보지 못하지만, 매 요청마다 자동으로 적용될 수 있습니다.

## 5.4 개발 도구 연계

LLM이 직접 다음 도구를 호출할 수도 있습니다.

```text
파일 검색
소스 읽기
정규식 검색
컴파일
테스트 실행
오류 로그 조회
Git 변경 비교
정적 분석
```

이 경우 LLM 자체의 지식뿐 아니라, **도구가 제공하는 실제 결과를 바탕으로 답변**하기 때문에 훨씬 정확해집니다.

# 6. 사내에서 전혀 학습하지 않았을 수도 있다

많은 사용자가 다음을 혼동합니다.

```text
사내 코드를 잘 이해한다.
=
사내 코드로 모델을 학습했다.
```

반드시 그렇지는 않습니다.

다음 세 가지는 완전히 다른 방식입니다.

| 방식             | 모델 가중치 변경 | 특징                                |
| ---------------- | ---------------: | ----------------------------------- |
| 프롬프트 Context |        변경 없음 | 현재 파일이나 질문 내용을 함께 전달 |
| RAG              |        변경 없음 | 사내 문서·소스를 검색하여 함께 전달 |
| Fine-tuning      |           변경됨 | 사내 데이터로 모델 자체를 추가 학습 |

실무에서는 비용과 관리 난이도 때문에 먼저 다음 구조를 사용합니다.

```text
오픈 LLM
+ 사내 소스 검색
+ IDE Context
+ 사내 개발표준 Prompt
+ 컴파일·테스트 도구
```

이것만으로도 상당히 유용한 코딩 도구를 만들 수 있습니다.

Fine-tuning은 특정 출력 형식이나 반복 작업을 모델에 강하게 익혀야 할 때 추가로 적용합니다. 이미 사전학습된 모델의 가중치를 특정 작업에 맞게 조정할 수 있지만, 모델 능력 손실과 운영 복잡성도 고려해야 합니다. ([메타 AI][5])

# 7. 인터넷 없는 회사에서 모델을 어떻게 반입했는가

일반적으로 다음 중 하나입니다.

```text
[방법 1]
외부에서 모델 파일 다운로드
→ 보안 검사
→ 저장매체 또는 반입 절차
→ 폐쇄망 서버에 설치

[방법 2]
공급사가 모델과 실행환경이 포함된 서버를 납품
→ 사내망에 설치

[방법 3]
외부 개발망에서 모델·패키지를 준비
→ 내부 Artifact Repository로 이관
→ 폐쇄망에서 배포

[방법 4]
사내 GPU에서 추가 Fine-tuning
→ 사내 데이터만 사용
→ 완성된 모델을 내부에서 운영
```

인터넷이 없더라도 다음 파일이 사내 서버에 존재하면 실행할 수 있습니다.

- 모델 가중치 파일
- Tokenizer
- 모델 설정 파일
- 추론 엔진
- Python 또는 C++ Runtime
- GPU Driver와 CUDA
- 임베딩 모델
- 사내 문서 Vector DB
- IDE Plugin 또는 Web UI

즉, 인터넷은 **모델을 사용하는 데 필수적인 것이 아니라, 모델·패키지·업데이트를 가져오는 경로 중 하나**입니다.

# 9. 인터넷이 없을 때 나타나는 한계

오프라인 LLM은 일반 지식과 코딩 능력은 유지하지만 다음 정보는 자동으로 알 수 없습니다.

| 구분            | 한계                                               |
| --------------- | -------------------------------------------------- |
| 최신 기술       | 모델 학습 이후 출시된 버전이나 기능을 모를 수 있음 |
| 사내 최신 소스  | RAG·IDE 연계가 없으면 알 수 없음                   |
| 실시간 장애     | 로그나 서버 상태를 전달하지 않으면 알 수 없음      |
| 최신 보안취약점 | 내부 취약점 DB가 갱신되지 않으면 모름              |
| 실제 실행 결과  | 컴파일·테스트 도구를 호출하지 않으면 추측에 불과   |
| 정확성          | 자연스러운 문장으로 틀린 코드를 생성할 수 있음     |

따라서 다음 관계를 기억해야 합니다.

```text
LLM이 자신 있게 답변한다.
≠ 답변이 사실이다.

코드가 그럴듯하다.
≠ 컴파일된다.

컴파일된다.
≠ 업무적으로 맞다.

테스트가 성공한다.
≠ 운영 기준을 만족한다.
```

# 10. 회사에 확인해야 할 질문

DAVIS CODER의 실제 구성을 알고 싶다면 담당 조직이나 공급사에 다음을 요청하면 됩니다.

| 확인 항목     | 질문                                                |
| ------------- | --------------------------------------------------- |
| 기반 모델     | 어떤 오픈 LLM과 버전을 사용하는가                   |
| 학습 이력     | 사전학습 모델인가, 사내 Fine-tuning을 했는가        |
| 사내 지식     | Git·Confluence·설계서를 RAG로 검색하는가            |
| 소스 전달     | IDE의 어떤 파일이 서버로 전송되는가                 |
| 외부 통신     | 추론 서버의 외부 통신이 완전히 차단되어 있는가      |
| 저장 정책     | 프롬프트와 소스코드를 저장하는가                    |
| 재학습 여부   | 사용자 입력이 자동으로 학습에 사용되는가            |
| 모델 업데이트 | 새 모델과 보안패치는 어떤 절차로 반입하는가         |
| 권한 통제     | 사용자별 접근 가능한 저장소가 분리되는가            |
| 생성 검증     | 컴파일·테스트·보안검사를 자동 수행하는가            |
| 감사          | 누가 어떤 소스를 질의했는지 기록되는가              |
| 라이선스      | 기반 모델과 학습 데이터의 기업 사용 조건은 무엇인가 |

특히 반드시 확인해야 할 것은 다음 세 가지입니다.

```text
1. 내 프롬프트와 소스가 모델 재학습에 사용되는가?
2. 사내 소스가 다른 사용자에게 노출될 가능성이 있는가?
3. 서버가 정말 외부로 통신하지 않는다는 증적이 있는가?
```

# 11. NSIGHT 관점의 판단

DAVIS CODER를 NSIGHT-TCF-FRAMEWORK 개발에 사용하려면 단순한 범용 코딩 LLM보다 다음 구조가 중요합니다.

```text
NSIGHT 설계서
+ 실제 TCF 소스
+ ServiceId 인벤토리
+ 화면·거래·프로그램·SQL 추적성
+ 패키지·명명규칙
+ 정상 구현 예제
+ 금지 구현 예제
+ Architecture Gate
  ↓
DAVIS CODER RAG와 개발규칙으로 등록
```

이렇게 구성하면 DAVIS CODER는 단순히 Java CRUD를 만드는 도구를 넘어 다음 역할을 수행할 수 있습니다.

- NSIGHT 표준 Handler·Facade·Service·Rule·DAO·Mapper 생성
- ServiceId와 Handler 등록 누락 검출
- 화면 정의와 프로그램 간 정합성 검사
- Mapper SQL과 테이블 영향 분석
- 명명·패키지·계층 위반 탐지
- 단위·통합 테스트 생성
- 프로그램 설계서 자동 생성
- 코드와 설계서 차이 분석

# 12. 시사점

## 핵심 판단

DAVIS CODER가 인터넷 없이 동작하는 이유는 다음 한 문장으로 정리할 수 있습니다.

```text
외부에서 이미 학습을 마친 LLM의 지식이
모델 파일 안에 숫자 형태로 저장되어 있고,
회사는 그 모델을 내부 서버에서 실행하기 때문이다.
```

그리고 사내 프로젝트를 잘 이해한다면 다음 기능이 결합되어 있을 가능성이 큽니다.

```text
기본 LLM 지식
+ 현재 IDE 소스
+ 사내 문서·소스 RAG
+ 개발표준 Prompt
+ Build·Test 도구
```

따라서 **사내에서 인터넷이 없다는 것과 LLM이 지식을 가지고 있다는 것은 모순이 아닙니다.**

인터넷은 지식 그 자체가 아니라, 모델을 학습시키거나 모델·자료를 갱신하는 수단입니다. 이미 학습된 모델은 오프라인에서도 사용할 수 있습니다.

# 13. 마무리말

LLM을 사람에 비유하면 이해하기 쉽습니다.

```text
인터넷이 연결된 LLM
= 책을 읽어 본 전문가가 필요할 때 외부 자료도 검색하는 상태

인터넷이 없는 LLM
= 이미 많은 책과 코드를 공부한 전문가가
  기억과 사내 자료만으로 답하는 상태
```

다만 그 전문가는 매우 많은 것을 알고 있으면서도, 때로는 모르는 내용을 그럴듯하게 만들어 말합니다. 따라서 DAVIS CODER의 결과는 **초안과 개발 가속 수단**으로 활용하고, 컴파일·테스트·정적 분석·아키텍처 검증을 반드시 통과시키는 방식으로 운영해야 합니다.
