# 좋은 프롬프트와 잘못된 프롬프트

## 잘못된 예시

```text
NSIGHT 방식으로 고객 조회 프로그램을 만들어줘.
```

문제점:

- 실제 기준 모듈이 없다.
- ServiceId가 없다.
- 테이블과 데이터 소유권이 없다.
- 권한·Timeout·감사가 없다.
- 테스트와 완료기준이 없다.
- 실제 소스 확인을 요구하지 않는다.

## 권장 예시

```text
P0 공통 마스터 프롬프트를 적용한다.

IC 업무의 고객 기본정보 조회 거래를 개발하라.

업무코드: IC
도메인: Customer
ServiceId: IC.Customer.selectBasic
거래코드: IC-INQ-0010
화면 이벤트: IC-CUS-0010-E01
테이블: IC_CUSTOMER_BASIC
조회조건: CUSTOMER_NO
Timeout: 3초
감사대상: Y
필요권한: IC_CUSTOMER_INQUIRY

기준 모듈은 현재 Branch의 ic-service 내
정상 운영 조회 거래로 선정하라.

구현 전에 기준 거래의 Handler 등록방식,
Facade 트랜잭션, DAO·Mapper 구조,
OM 등록과 테스트 패턴을 분석하여 보고하라.

그 후 Request·Response DTO,
Handler·Facade·Service·Rule·DAO·Mapper,
SQL, 테스트, HTTP 호출 예시와
화면–ServiceId–프로그램–SQL 추적성 매트릭스를 작성하라.

clean build, bootRun, 표준 POST 호출,
DB 결과와 GUID·TraceId 로그까지 검증하라.
```
