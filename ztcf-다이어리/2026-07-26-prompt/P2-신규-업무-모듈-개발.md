# P2 — 신규 업무 모듈 개발 프롬프트

사용: `P0` + `P2` + 업무코드·도메인·테이블·화면정보  
최소 입력: [가이드-입력정보-최소세트.md](./가이드-입력정보-최소세트.md) § 신규 업무 개발

```text
[P2 신규 업무 모듈 개발 작업]

NSIGHT-TCF-FRAMEWORK에 다음 신규 업무 모듈을 추가하라.

[업무 입력정보]

업무코드: {예: AV}
업무명: {예: 자산평가}
영문 도메인: {예: AssetValuation}
Gradle 모듈명: {예: av-service}
WAR명: {예: av.war}
Context Path: {예: /av}
온라인 Endpoint: {예: POST /av/online}
기준 모듈: {예: eb-service}
최초 ServiceId: {예: AV.AssetValuation.inquiry}
거래코드: {예: AV-INQ-0001}
처리유형: {INQUIRY/CREATE/UPDATE/DELETE/EXECUTE}
DB 테이블·View: {입력}
조회·변경 조건: {입력}
응답 필드: {입력}
권한·감사 요건: {입력}
목표 bootRun 포트: {입력}

코드를 생성하기 전에 다음을 먼저 수행하라.

1. settings.gradle의 모듈 등록방식 확인
2. 루트 build.gradle의 업무 모듈 관리방식 확인
3. 기준 업무 모듈의 실제 디렉터리와 패키지 구조 확인
4. NsightWarBootstrap 상속 방식 확인
5. Handler의 serviceId() 또는 serviceIds() 등록 방식 확인
6. Mapper Scan과 Component Scan 방식 확인
7. Profile과 포트 구성 확인
8. Gateway Route 등록 방식 확인
9. OM Service Catalog 등록 방식 확인
10. 기존 포트·ServiceId·거래코드 중복 확인

분석 결과를 먼저 표로 보고한 후 구현하라.

구현 범위:

- Gradle 모듈 등록
- build.gradle
- 메인 Application
- Handler
- Facade
- Service
- Rule
- DAO
- Mapper Interface
- Mapper XML
- Request·Response·Criteria·Result DTO
- application-local/dev/prod 설정
- schema.sql 또는 설계 예시
- 단위·통합 테스트
- 표준 HTTP 요청 샘플
- OM 등록 초안
- Gateway Route 초안
- README와 실행 방법

완료 검증:

- clean build 성공
- 단위테스트 성공
- bootRun 성공
- 포트 충돌 없음
- POST /{업무코드}/online 호출 성공
- ServiceId가 정확한 Handler로 연결
- Mapper SQL 실행 성공
- 표준 응답 확인
- 오류·Timeout 응답 확인
- GUID·TraceId·ServiceId 로그 확인
- WAR 산출물 확인

실제 DB 정의가 없는 경우 운영 SQL을 추측하지 말고
local Profile 전용 '설계 예시'로만 작성하라.
```
