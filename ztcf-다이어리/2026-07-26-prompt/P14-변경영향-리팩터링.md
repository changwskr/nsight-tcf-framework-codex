# P14 — 변경 영향·리팩터링 프롬프트

사용: `P0` + `P14` + 변경 대상·호환성·중단 가능시간

```text
[P14 변경 영향 및 리팩터링 작업]

다음 변경 요청의 전체 영향을 분석하고
안전한 리팩터링 계획을 작성하라.

변경 대상: {클래스/ServiceId/패키지/테이블/설정/모듈}
변경 내용: {내용}
변경 이유: {이유}
목표 버전: {버전}
호환성 요구: {요구}
중단 가능시간: {시간}

다음 영향을 정방향·역방향으로 분석하라.

- 화면·이벤트
- ServiceId·거래코드
- Handler·Facade·Service·Rule
- DAO·Mapper·SQL
- DB 객체
- 다른 도메인·업무 WAR
- Gateway Route
- JWT Audience·권한
- OM Service Catalog
- Timeout·거래통제
- 거래로그·감사로그
- 테스트
- CI/CD
- 배포·Rollback
- 운영 Runbook

다음 대안을 비교하라.

- 즉시 변경
- 호환 Adapter 유지
- 신규 Version 병행
- Feature Toggle
- 데이터 Migration
- 점진적 전환
- 기존 기능 폐기

변경 계획에는 다음을 포함하라.

1. 현행 Baseline
2. 영향 객체 목록
3. 호환성 전략
4. 단계별 변경 순서
5. 코드·DB·설정 Migration
6. 회귀테스트
7. 배포 순서
8. Rollback
9. 운영 관찰기간
10. 폐기 조건
11. 완료 증적

기존 인터페이스를 삭제하거나 이름을 변경하기 전에
소비자와 운영 기준정보를 반드시 확인하라.
```
