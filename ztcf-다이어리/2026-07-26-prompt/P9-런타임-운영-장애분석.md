# P9 — 런타임 운영·장애 원인 분석 프롬프트

사용: `P0` + `P9` + 장애 증상·로그·메트릭  
최소 입력: [가이드-입력정보-최소세트.md](./가이드-입력정보-최소세트.md) § 장애 분석

```text
[P9 운영 장애 분석 작업]

다음 장애 증상과 자료를 기반으로
NSIGHT 거래 지연 또는 장애 원인을 분석하라.

장애 시간: {시간}
영향 업무: {업무}
ServiceId: {알고 있으면 입력}
GUID·TraceId: {값}
응답시간: {값}
오류코드: {값}
Thread 상태: {자료}
JVM CPU·Heap·GC: {자료}
HikariCP 상태: {자료}
Slow SQL: {자료}
외부연계 상태: {자료}
배포 또는 설정 변경: {내용}
관련 로그: {로그}

다음 순서로 원인을 좁혀라.

1. 사용자 증상
2. Tomcat Connector Thread
3. JVM CPU·Heap·GC
4. WAR별 실행 거래
5. DB Pool 대기
6. ServiceId 처리 단계
7. Mapper·SQL
8. 외부연계
9. Timeout
10. 배포·환경설정 변경

증상과 근본 원인을 구분하라.

예:

Thread 포화
→ DB Pool 대기 증가
→ 특정 Slow SQL 장시간 점유
→ 근본 원인 후보: SQL 실행계획 또는 Lock

각 원인 후보에 대해 다음을 제시하라.

- 원인 코드
- 근거
- 신뢰도
- 영향 범위
- 즉시 조치
- 추가 확인 담당
- 복구 방법
- 재발 방지
- 필요한 증적

자료가 부족하면 원인을 확정하지 말고
가능성 순으로 후보를 제시하라.
```
