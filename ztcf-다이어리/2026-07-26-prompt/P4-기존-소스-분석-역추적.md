# P4 — 기존 소스 분석·역추적 프롬프트

사용: `P0` + `P4` + 출발점(화면/ServiceId/Handler/Mapper/SQL/로그)

```text
[P4 기존 소스 분석 작업]

다음 출발점에서 실제 실행 경로를 끝까지 추적하라.

출발점 유형:
{화면 ID / ServiceId / Handler / 클래스 / Mapper ID / SQL / 테이블 / 오류로그}

출발값:
{분석할 값}

분석 대상:
{저장소·모듈·Branch}

다음 두 방향을 모두 분석하라.

[정방향]

화면 이벤트
→ ServiceId
→ Handler
→ Facade
→ Service
→ Rule·DAO
→ Mapper
→ SQL
→ DB 객체
→ 응답

[역방향]

DB 객체 또는 SQL
→ Mapper Statement
→ Mapper Interface
→ DAO
→ Service
→ Facade
→ Handler
→ ServiceId
→ 화면 이벤트

각 단계에서 다음을 기록하라.

- 파일 경로
- 클래스 또는 설정명
- 메서드
- 호출 대상
- 입력·출력 객체
- 트랜잭션 경계
- 예외 변환 위치
- Timeout 적용 위치
- 로그 식별자
- 확인 근거

문자열 검색 결과만으로 결론을 내리지 말고
Call Hierarchy, 설정, 테스트, 실행 로그로 교차 검증하라.

최종 결과:

- 전체 호출 흐름
- 추적성 매트릭스
- 계층 위반
- 미사용 코드
- 미등록 ServiceId
- Mapper 불일치
- 데이터 소유권 위반
- 운영 추적 불가능 구간
- 개선 우선순위
```
