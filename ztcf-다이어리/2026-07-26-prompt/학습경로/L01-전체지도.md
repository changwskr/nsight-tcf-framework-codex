## 이 단계에서 얻는 것

저장소의 **모듈 지도**를 머릿속에 한 장으로 넣는다.  
이후 “어느 폴더를 열지”를 헤매지 않게 된다.

## 왜 이 순서인가

거래 흐름(L02)을 보기 전에, `tcf-core` / `tcf-web` / 업무 WAR / Gateway / OM이  
**어디에 있고 누가 누구를 의존하는지** 알아야 한다.

## 지금 이 질문을 붙여 넣으세요

```text
P0 + P1을 적용한다. 구현·개선안은 내지 말고 "현행 지도"만 그려라.

대상: 현재 Branch의 nsight-tcf-framework 전체
목적: 학습용 아키텍처 맵 작성

다음만 수행하라.

1. settings.gradle / 루트 build.gradle / README를 근거로
   프레임워크 JAR, 인프라 WAR, 업무 WAR, 도구 모듈을 표로 분류하라.
2. 의존 방향(tcf-util → … → 업무)을 ASCII 한 장으로 그려라.
3. bootRun 포트와 WAR context path가 문서/설정에 어떻게 나타나는지
   대표 모듈 5개만 예시로 보여라. (추측 금지, 근거 경로 명시)
4. "모듈러 모놀리스 + 다중 WAR"가 이 저장소에서 구체적으로 무엇을 뜻하는지
   3문장으로 정리하라.
5. 학습자가 다음에 반드시 열어볼 파일 10개를 우선순위와 함께 추천하라.

금지: Gap 개선 로드맵, 리팩터링 제안, 새 모듈 설계.
출력: 표 + ASCII + 파일 목록만.
```
