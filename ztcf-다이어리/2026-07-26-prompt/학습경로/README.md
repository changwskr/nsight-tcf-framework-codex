# TCF-FRAMEWORK 지식 흡수 학습 경로

목적: `P0`~`P15` 작업 프롬프트를 **실행 순서**가 아니라,  
우리가 만든 NSIGHT-TCF를 **가장 잘 이해하도록** 재배열한 **질의 학습 경로**입니다.

## 사용법

1. 아래 단계를 **번호 순서대로** 진행한다.
2. 각 단계 파일의 **「지금 이 질문을 붙여 넣으세요」** 블록을 Cursor 채팅에 그대로 붙인다.
3. 답변을 받은 뒤 **「자기 점검」** 질문에 스스로 답할 수 있으면 다음 단계로 간다.
4. 막히면 해당 단계의 `관련 프롬프트`만 추가로 붙인다. 순서를 건너뛰지 않는다.

## 왜 이 순서인가

```text
원칙(어떻게 볼 것인가)
  → 지도(무엇이 있는가)
  → 한 건의 거래 흐름(어떻게 흐르는가)
  → 업무 모듈 해부(어디에 무엇을 쓰는가)
  → 데이터·SQL(무엇이 저장되는가)
  → 추적성(요구~운영이 어떻게 이어지는가)
  → 우리가 만든 샘플로 검증(av/eb)
  → 보안·용량·장애(운영 시야)
  → 품질·배포(완료 증적)
  → 신규 모듈·자동화·변경(지식을 다시 쓰는 단계)
```

작업용 라이브러리 `P1→P2→P3…`는 **할 일 목록**이고,  
이 학습 경로는 **이해 순서**입니다. (먼저 Gap 분석·신규모듈부터 하면 맥락이 비어 학습 효율이 떨어집니다.)

## 완료 정의

전 단계를 마치면 다음을 **설명 없이 소스만 보고** 말할 수 있어야 한다.

1. 한 HTTP 요청이 어느 클래스들을 지나 DB까지 가는가  
2. 새 업무 WAR를 만들 때 무엇을 복제하고 무엇을 금지하는가  
3. ServiceId 하나가 화면·Handler·OM·로그를 어떻게 묶는가  
4. “코드가 생겼다”와 “완료”의 차이(증적)가 무엇인가
