## 이 단계에서 얻는 것

SSO · tcf-jwt · Gateway · 업무 WAR · STF · OM의 **책임 분리**를 이해한다.  
업무 코드에 인증을 때려 넣는 유혹을 차단한다.

## 왜 이 순서인가

거래·모듈·추적을 안 뒤에 보안을 얹어야 “필터를 어디에 둘지”가 보인다.  
처음부터 JWT만 보면 업무 흐름과 분리되어 암기만 된다.

## 지금 이 질문을 붙여 넣으세요

```text
P0 + P7을 적용한다. 보안 설계서를 장황하게 쓰지 말고, 책임 경계와 실제 모듈 매핑에 집중하라.

1. README와 모듈 구조를 근거로 다음 역할표를 채워라.
   SSO | tcf-jwt | Gateway | 업무 WAR Filter | STF | 업무 Rule | tcf-om
   각 칸: 하는 일 / 하지 않는 일 / 관련 모듈 경로(확인된 것만)
2. Access Token 발급~Gateway 검증~업무 진입의 정상 흐름을 단계 번호로 그려라.
3. Gateway 미경유·만료·위조·권한변경 시나리오를 "어디가 막아야 하는지"로만 답하라.
4. 토큰을 URL·로그·localStorage에 넣으면 안 되는 이유를 NSIGHT 운영 관점으로 적어라.
5. 학습자가 다음에 열어볼 파일 8개(jwt/gateway/web filter/om)를 우선순위로 추천하라.

미확인 항목은 미확정. 코드 수정 금지.
```
