**선행:** [L09](./L09-용량-장애.md)

## 이 단계에서 얻는 것

“코드가 생겼다”가 아니라 **Gate와 증적**으로 완료를 정의한다.  
학습의 종착점이 구현이 아니라 **판정 능력**임을 고정한다.

## 왜 이 순서인가

무엇을 만들었는지(L01~L09) 안 뒤에야  
무엇을 검증·배포·롤백해야 하는지 의미가 생긴다.

## 지금 이 질문을 붙여 넣으세요

```text
P0 + P10 + P11을 적용한다. 파이프라인 YAML을 새로 만들지 마라.
학습용 "완료 판정 카드"를 만들어라.

1. P0 완료 판정 항목을 이 저장소 언어로 재해석한 체크리스트를 작성하라.
   (설계-소스 일치, ServiceId-Handler, OM, Timeout, Mapper 일치, 테스트, POST 성공, 로그 추적, Rollback, 금지패턴)
2. Quality Gate 7종(Source/Architecture/SQL/Security/Integration/Deployment/Operation)마다
   "이 저장소에서 무엇을 보면 통과로 볼지" 예시 1개씩. (없으면 미확정)
3. bootRun 검증과 ztomcat/WAR 배포 검증의 차이를 표로 비교하라.
4. Rollback이 코드만 되돌리면 부족한 경우(DB, OM, Gateway Route)를 나열하라.
5. 초보가 "완료"라고 착각하는 순간 5가지와, 그때 던질 반문 1개씩을 적어라.

출력은 체크리스트와 표 위주. 장문 Runbook 금지.
```

## 읽을 자료 / 열 파일

- `tcf-cicd`, `tcf-scripts`, `ztomcat`
- 루트 README 이중 배포 설명
- P0 완료 판정 절

## 자기 점검

1. 단위테스트 green만으로 Operation Gate를 통과시킬 수 있는가?  
2. GUID가 로그에 없으면 왜 완료가 아닌가?  
3. OM 미등록 상태로 화면 데모 성공은 완료인가?  

## 통과 기준

- 완료/미완료를 증적 언어로 판정할 수 있다.
