# P3 — 화면·테이블 기반 CRUD 개발 프롬프트

사용: `P0` + `P3` + 화면 이벤트·입출력·테이블 정의

```text
[P3 CRUD 거래 개발 작업]

다음 화면과 테이블 정보를 이용하여
NSIGHT-TCF 표준 CRUD 거래를 설계하고 구현하라.

[화면 정보]

화면 ID: {화면 ID}
화면명: {화면명}
화면 이벤트 ID: {이벤트 ID}
이벤트명: {조회/등록/변경/삭제}
입력 필드: {필드 목록}
출력 필드: {필드 목록}
화면 성공 처리: {내용}
화면 오류 처리: {내용}

[거래 정보]

업무코드: {코드}
도메인: {도메인}
ServiceId: {ServiceId}
거래코드: {거래코드}
처리유형: {유형}
Timeout: {초}
멱등성 필요 여부: {Y/N}
감사 대상 여부: {Y/N}
필요 권한: {권한}

[데이터 정보]

테이블 또는 View: {DB 객체}
PK: {기본키}
조회조건: {조건}
변경컬럼: {컬럼}
필수값: {필수값}
정렬기준: {기준}
페이징: {방식}
동시성 통제: {낙관적 Lock/비관적 Lock/없음}

반드시 다음 순서로 처리하라.

1. 화면 이벤트와 ServiceId 관계 정의
2. Request·Response 계약 정의
3. 입력 Validation과 업무 Rule 분리
4. 데이터 소유권 확인
5. 트랜잭션 경계 결정
6. Handler–Facade–Service–Rule–DAO–Mapper 설계
7. SQL과 영향 행 수 처리
8. 정상·중복·동시·오류·Timeout 흐름 정의
9. 코드 구현
10. 테스트와 추적성 산출물 작성

금지사항:

- 업무별 Controller 생성
- Handler에 업무 로직 작성
- Service에서 Mapper 직접 호출
- Rule에서 DB 또는 외부 시스템 호출
- DAO에서 업무 규칙 수행
- Mapper에 업무 판단 작성
- 다른 업무 도메인의 테이블 직접 변경
- 예외 무시 또는 빈 응답 반환
- UPDATE·DELETE 영향 행 수 미확인

산출물:

- 화면 이벤트–ServiceId 매핑
- 거래설계서
- 프로그램설계서
- DTO 정의
- Mapper·SQL 정의
- 테스트 시나리오
- HTTP 요청·응답 예시
- OM 등록정보
- 변경 영향 목록
```
