# 03. 선택 가이드

## 1. 의사결정 트리

```text
Q0. ztcfbook(책) 장을 프레임워크 출처로 집필·갱신하나?
  YES → tcf-harness-exe-집필  (+ Claude /harness)
  NO  ↓

Q1. pdmp-service 코드를 지금 고쳐야 하나?
  YES → tcf-harness-exe-pdmp  (+ Claude /harness)
  NO  ↓

Q2. PDMP 계약/역할 핸드오프만 점검·문서화하나?
  YES → tcf-harness-pdmp
  NO  ↓

Q3. 하네스/에이전트팀 설계·검증이 목적인가?
  YES → tcf-harness-world
  NO  ↓

Q4. 새 프로젝트에 Claude /harness 시드를 심나?
  YES → tcf-harness-framework 복사 후 CLAUDE.md 채우기
  NO  ↓

Q5. 수동 Gate·상태원장·CLI 장기 자동화가 필요한가?
  YES → tcf-harness (+ 필요 시 tcf-harness-prompt)
```

|------|------|--------|

| ztcfbook-m / -h 미러 | `exe-집필` + 에디션 승인 | base와 동시 무단 개편 |

| 12문항 요건·승인 Gate CLI | `tcf-harness` | Claude phase와 이중 SoT 없이 병행 |

## 3. SoT(Source of Truth) 규칙

| 관심사 | SoT |
|--------|-----|
| PDMP 런타임 코드 | `pdmp-service` (향후 `pdmp-fw` 분리 시 FW JAR) |
| PDMP 계약 문서 | `tcf-harness-pdmp/docs` |
| PDMP 실행 증적(phase) | `tcf-harness-exe-pdmp/phases` |
| 책 원고 | `ztcfbook` / `ztcfbook-m` / `ztcfbook-h` |
| 책 집필 증적(phase) | `tcf-harness-exe-집필/phases` |
| 책 사실 근거 | 코드 → zman/znsight-man/zarchitecture → 기존 책 → 다이어리 |
| 메타 역할 계약 | `tcf-harness-world/agents` |
| 다이어리/의사결정 | `ztcf-다이어리` |

계약 문서와 실행 증적이 어긋나면: **코드(`pdmp-service`) → 실행 증적 갱신 → 계약 문서 갱신** 순으로 맞춘다.  
책과 출처가 어긋나면: **코드/매뉴얼 → 장 수정 → (승인 시) -m/-h 미러** 순으로 맞춘다.

## 4. Claude `/harness` vs 채팅 에이전트

| | `/harness` (exe-pdmp / exe-집필) | Cursor/일반 채팅 |
|--|----------------------|------------------|
| phase 파일 | 강제·누적 | 선택 |
| step 러너 | `execute.py` | 없음 |
| 승인 게이트 | 스킬/커맨드 내 규칙 | 대화 의존 |
| 적합한 작업 | CRUD·안정화·다단계 / 장 집필 | 짧은 점검·설명 |

둘을 섞을 때: 채팅에서 구현·집필해도 **phase 증적은 해당 exe 패키지에 남길지** 합의한다.
## 5. 하지 말 것

- `tcf-harness-pdmp`를 열어두고 `pdmp-service`를 “계약 검증” 명목으로 마음대로 수정
- `world` 시뮬레이션 결과를 실제 PDMP 커밋으로 착각
- `framework` 플레이스홀더 CRITICAL을 채우지 않은 채 프로덕션 작업
- Java `tcf-harness` 상태원장과 Claude `phases/`를 같은 작업 ID로 이중 관리 (충돌)
