# 02. 패키지 상세

저장소 루트 기준 경로: `nsight-tcf-framework/<패키지>/`

---

## 1. `tcf-harness`

**유형**: Java 21 · Spring Boot CLI 실행 하네스  
**역할**: 요건→분석→설계→구현→테스트를 Markdown/JSON/로그/Diff와 **수동 승인 Gate**로 통제

### 핵심 기능

- 고정 12문항 대화형 요건 수집
- 단계별 Markdown 산출물 + 모든 단계 수동 승인
- 전용 브랜치 `harness/{작업ID}-{기능명}`
- DAVIS CODER / Codex CLI / 사내 LLM 어댑터
- 테스트 실패 최대 3회 자동 수정 루프
- `.harness/state`(JSON), `.harness/audit`(JSONL)

### 주요 경로

| 경로 | 역할 |
|------|------|
| `harness/prompts/` | 마스터·단계 프롬프트 |
| `harness/templates/` | 산출물 골격 |
| `harness/schemas/` | 상태·계약 스키마 |
| `docs/work-items/` | 작업별 기록 |
| `src/` | CLI 구현 |

### 검증

```bash
./gradlew test
./gradlew check
sh scripts/offline-smoke-test.sh
```

### 상태 메모

장기 게이트형 자동화의 “엔진” 후보. PDMP 일상 구현은 현재 Claude exe 축이 더 가볍다.

## 2. `tcf-harness-prompt`

**유형**: 프롬프트/템플릿 패키지 (Java `src` 없음)  
**역할**: `tcf-harness`와 동일한 프롬프트·문서 계약을 **경량으로** 제공

### 구성

- `AGENTS.md`, `ARCHITECTURE.md`
- `harness/prompts/`, `harness/templates/`, `docs/`

### 사용

Java CLI를 돌리지 않고 **프롬프트만** 다른 에이전트/IDE에 이식할 때.

---

## 3. `tcf-harness-framework`

**유형**: Claude Code `/harness` **빈 템플릿**  
**역할**: 새 프로젝트에 붙여 넣을 시드 (플레이스홀더 `CLAUDE.md`)

### 구성

| 경로 | 역할 |
|------|------|
| `.claude/commands/harness.md` | `/harness` 슬래시 커맨드 |
| `skills/harness/` | phase 생성·실행 스킬 |
| `scripts/execute.py` | step 러너 |
| `docs/` | 설계 문서 |

### 사용

```text
1) 패키지 복사
2) CLAUDE.md 기술스택·CRITICAL 규칙 채우기
3) phases/ 에 작업 단계 작성
4) Claude에서 /harness 실행
```

## 4. `tcf-harness-world`

**유형**: Codex 메타 하네스  
**역할**: **에이전트 팀·스킬 자체를** 설계·검증 (비즈니스 앱 구현이 1차 목적 아님)

### 구성

| 경로 | 역할 |
|------|------|
| `AGENTS.md` | 패키지 범위 규칙 |
| `agents/` | Analyst, Builder, QA 역할 계약 |
| `skills/harness/SKILL.md` | 하네스 설계 메타 스킬 |
| `skills/harness/orchestrator-sample/` | Analyst→Builder→QA 샘플 |
| `scripts/verify-codex-harness.*` | 검증 진입점 |
| `tests/` | 오프라인 수락 테스트 |

### 흐름

```text
요청 → Analyst(요건·완료기준) → Builder(구현산출물) → QA(추적성·증적) → 통과/제한수정
```

### 검증

```powershell
.\tcf-harness-world\tests\test-verifier.ps1 -Mode All
.\tcf-harness-world\scripts\verify-codex-harness.ps1
.\tcf-harness-world\skills\harness\orchestrator-sample\scripts\run-simulation.ps1
```

## 5. `tcf-harness-pdmp`

**유형**: PDMP **계약 문서** Codex 하네스  
**역할**: `pdmp-service` 계약을 문서화·검증. **대상 프로젝트 소스를 수정하지 않음**

### 강제하는 계약

- `mpcoa8888`형 Controller→Service→DAO→MyBatis
- `@TcfTransaction`, JWT, MyBatis 바인딩, H2 vs Oracle 한계
- Analyst / Builder / Security Reviewer / QA 핸드오프

### 시작점

1. `docs/pdmp-architecture.md`
2. `docs/workflow.md`
3. `agents/` 역할 계약

### 검증

```powershell
.\tcf-harness-pdmp\tests\test-pdmp-harness.ps1 -Mode All
.\tcf-harness-pdmp\scripts\verify-pdmp-harness.ps1
```

대상 빌드는 별도:

```powershell
.\pdmp-service\gradlew.bat test
.\pdmp-service\gradlew.bat war
```

## 7. `tcf-harness-exe-집필`

**유형**: 책 **목차 구동 집필** Claude/Cursor 하네스  
**역할**: `TOC.md`/`toc.json` 항목 단위로 NSIGHT-TCF-FRAMEWORK를 읽어 `../ztcfbook` 장을 집필

### 핵심 파일

| 경로 | 역할 |
|------|------|
| `TOC.md` / `toc.json` | 집필 단위 SoT (장+부록 ~47) |
| `chapters/{id}/TASK.md` | 항목별 에이전트 브리프 |
| `chapters/{id}/IN|OUT` | 출처 메모 · 핸드오프 |
| `scripts/sync_toc_chapters.cjs` | 목차·워크스페이스 동기화 |
| `skills/book-chapter-agent` | 항목 오케스트레이터 |

### 실행

```text
TOC의 CH-03-… 집필 실행해줘
```

```powershell
cd tcf-harness-exe-집필
node .\scripts\sync_toc_chapters.cjs
.\tests\test_codex_harness.ps1 -Mode Contracts
```
