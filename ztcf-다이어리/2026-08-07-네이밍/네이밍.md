# PDMP Naming Convention Guide

## 개요

이 문서는 PDMP 프로젝트의 소스 코드 명명 규칙을 정의합니다. 모든 개발자는 이 규칙을 준수하여 코드를 작성해야 합니다.

기존 소스를 참고하지 말고 서비스(컨트롤러,서비스, resources, meta dto 등등)을 생성합니다.

## 0. 애플리케이션 그룹체계

### 애플리케이션 그룹 (대구분)

- **MP**: 애플리케이션 그룹 코드

### 애플리케이션 (업무구분)

| 코드 | 업무구분    |
| ---- | ----------- |
| CO   | 공통        |
| IC   | 통합고객    |
| MS   | 미니 상품몰 |
| SA   | 상담판매    |

### 세부업무구분

| 코드 | 세부구분 |
| ---- | -------- |
| A    | 상담     |
| B    | 고객     |

## 1. 서비스 ID 규칙

### 구성

```text
[대구분 2자][업무구분 2자][세부업무구분 1자][식별번호 4자][식별자 2자]
```

### 구성 요소

- **대구분 코드 (2자)**: `MP`
- **업무구분 코드 (2자)**: `CO`, `IC`, `MS`, `SA`
- **세부업무구분 코드 (1자)**: `A`, `B`
- **식별 번호 (4자)**: 화면 번호 또는 `Z` + 일련번호(3자)
- **식별자 (2자)**: 구분(1자) + 순번(1자)

### 구분자

| 구분 | 의미   |
| ---- | ------ |
| S    | 조회   |
| C    | 등록   |
| U    | 수정   |
| D    | 삭제   |
| A    | 혼합   |
| R    | 레포트 |

### 순번

- 숫자: `0-9`
- 알파벳: `A-Z` (숫자 범위 초과 시)

### 작성 예시

- 조회: `mpcoa0000s0`
- 등록: `mpcoa0000c0`
- 수정: `mpcoa0000u0`
- 삭제: `mpcoa0000d0`
- 혼합: `mpcoa0000a0`
- 레포트: `mpcoa0000r0`
- 화면 없음: `mpcoaZ000s0`

## 2. 패키지 명명 규칙

### Java 소스 파일

```text
src/main/java
```

기본패키지:

```text
nhnis.{대구분소문자}.{업무구분소문자}.{세부업무구분소문자}
```

서브패키지:

```text
controller, dao, dto, service
```

전체 경로 예시:

```text
controller: [project home]/src/main/java/nhnis/{대구분소문자}/{업무구분소문자}/{세부업무구분소문자}/controller/[대구분소문자][업무구분소문자][세부업무구분소문자][식별번호-4자리]Controller.java

service: [project home]/src/main/java/nhnis/{대구분소문자}/{업무구분소문자}/{세부업무구분소문자}/service/[대구분소문자][업무구분소문자][세부업무구분소문자][식별번호-4자리]Service.java

dao: [project home]/src/main/java/nhnis/{대구분소문자}/{업무구분소문자}/{세부업무구분소문자}/dao/[대구분소문자][업무구분소문자][세부업무구분소문자][식별번호-4자리]DAO.java

dto: [project home]/src/main/java/nhnis/{대구분소문자}/{업무구분소문자}/{세부업무구분소문자}/dto/{서비스 ID}DTO[입출력구분].java

meta dto: [project home]/meta/nhnis/{대구분소문자}/{업무구분소문자}/{세부업무구분소문자}/dto/{서비스 ID}DTO[입출력구분].dto
```

### 중요: 파일명 규칙

- **Controller, Service, DAO**: `[대구분][업무구분][세부업무구분][식별번호 4자리]`만 포함 (서비스 구분자 제외)
  - 예: `mpcoa0000Controller.java`, `mpcoa0000Service.java`, `mpcoa0000DAO.java`
- **DTO**: 전체 `[서비스 ID]` 포함 (식별번호 + 구분자 + 순번)
  - 예: `mpcoa0000s3DTOin.java`, `mpcoa0000s3DTOout.java`, `mpcoa0000s3DTOsub0.java`

### 서비스 ID 구조 예시 (`mpcoa0000s3`)

- `mp`: 대구분 (소문자)
- `co`: 업무구분 (소문자)
- `b`: 세부업무구분 (소문자)
- `0000`: 식별번호 (4자리 숫자)
- `s`: 구분자 (조회=S, 등록=C, 수정=U, 삭제=D, 혼합=A, 레포트=R)
- `3`: 순번 (0-9, A-Z)

### 파일명 적용 예시

| 항목       | 파일명 설명                                     |
| ---------- | ----------------------------------------------- |
| Controller | `mpcoa0000Controller.java` — 식별번호(0000)까지 |
| Service    | `mpcoa0000Service.java` — 식별번호(0000)까지    |
| DAO        | `mpcoa0000DAO.java` — 식별번호(0000)까지        |
| DTOin      | `mpcoa0000s3DTOin.java` — 전체 서비스 ID 포함   |
| DTOout     | `mpcoa0000s3DTOout.java` — 전체 서비스 ID 포함  |
| DTOsub     | `mpcoa0000s3DTOsub0.java` — 전체 서비스 ID 포함 |

예시 패키지:

```text
nhnis.mp.co.a.controller
nhnis.mp.co.a.service
nhnis.mp.co.a.dao
nhnis.mp.co.a.dto
```

## 3. Controller 클래스

### 파일명 규칙

#### 기본 규칙

```text
[대구분소문자][업무구분소문자][세부업무구분소문자][식별번호-4자리]Controller.java
```

클래스명 구성:

```text
mp + co + a + 0000 + Controller.java
```

클래스명에는 고정 문자열 `Controller`를 사용하며, 서비스 구분은 메소드 레벨의 Annotation으로 처리합니다.

| 구분 | 의미       |
| ---- | ---------- |
| S0   | 조회       |
| C0   | 등록       |
| U0   | 수정       |
| D0   | 삭제       |
| A0   | 혼합       |
| R0   | 레포트(RD) |

### 예시

- `mpcoa0000Controller.java` (단일 컨트롤러)
- 조회: `mpcoa0000s0()`
- 등록: `mpcoa0000c0()`
- 수정: `mpcoa0000u0()`
- 삭제: `mpcoa0000d0()`
- 혼합: `mpcoa0000a0()`
- 레포트: `mpcoa0000r0()`

### import 문

```java
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RestController;

import lombok.extern.slf4j.Slf4j;
import nhnis.fw.commons.resolver.RequestBody;
```

### 통합 컨트롤러 규칙 (동일 식별번호 서비스 통합)

동일한 식별번호(예: `0000`)를 가지며 구분자(X1, X2, X3 등)만 다른 서비스들이 여러 개 존재하는 경우, 하나의 통합 컨트롤러로 관리합니다.

```text
[대구분(2자리)][업무구분(2자리)][세부업무구분(1자리)][식별번호(4자리)]Controller.java
```

예시:

- `mpcod0000Controller.java` (`mpcod0000x1`, `mpcod0000x2`, `mpcod0000x3` 통합)
- `mpcoa0000Controller.java` (`mpcoa0000s0`, `mpcoa0000s1`, `mpcoa0000s2` 통합)

### 어노테이션

- `@RestController` 사용 (클래스 레벨)
- `@RequestMapping` 사용 금지 (클래스 레벨)
- `@PostMapping` 사용 (메소드 레벨, 경로: `/{서비스 ID}`)
- `@RequestBody` 사용 (입력 파라미터, `nhnis.fw.commons.resolver.RequestBody` 임포트)
- `@Slf4j` 사용 (로깅)

### 메소드 규칙

- 파라미터: `@RequestBody [서비스 ID]DTOin input`
- 반환 타입: `[서비스 ID]DTOout`
- 예외: `throws Throwable`
- 로깅: 시작/종료 로그 포함 (`▷▷▷▷▷▷▷▷▷▷`)
- **메소드 주석 필수**: Javadoc 형식의 주석 반드시 포함
- **날짜 자동 설정**: 모든 주석의 날짜는 생성/수정 당일 날짜로 설정 (`YYYY.MM.DD` 형식)
- **통합 컨트롤러 내 메소드**: 각 서비스 ID에 해당하는 메소드를 별도 추가

### 메소드 주석 형식

```java
/**
 * @description : [기능 설명]
 * @method : [서비스 ID]
 * @author : ${name}
 * @param : input - [입력 파라미터 설명]
 * @return : [서비스 ID]DTOout - [반환값 설명]
 * @throws : Throwable - 예외
 * @date : ${date}
 */
@PostMapping("/{서비스 ID}")
public [서비스 ID]DTOout [구분자](@RequestBody [서비스 ID]DTOin input) throws Throwable {
    log.info(">>>>>>>> [서비스 ID] Controller Start!");
    [서비스 ID]DTOout output = [대구분(2자리)][업무구분(2자리)][세부업무구분(1자리)][식별번호(4자리)]Service.[서비스 ID](input);
    log.info(">>>>>>>> [서비스 ID] Controller End!");
    return output;
}
```

### 통합 컨트롤러 적용 기준

- **적용**: 동일한 업무/화면의 서비스 (X1, X2, X3 또는 S0, S1, S2 등)가 2개 이상인 경우
- **미적용**: 단일 서비스, 다른 식별번호를 가진 서비스

예시:

- `mpcoa0000X1`, `mpcoa0000X2`, `mpcoa0000X3` → `mpcoa0000Controller` (통합)
- `mpcoa0002S2` (단일) → `mpcoa0002Controller` (개별)
- `mpcoa0000X1`, `mpcoa0001X2` (식별번호 다름) → 각각 별도 컨트롤러

## 2. meta .dto 파일

### 규칙

- dto 클래스와 동일한 쌍으로 생성되어야 함

### 파일 생성 위치 규칙

```text
[project home]/meta/nhnis/{대구분소문자}/{업무구분소문자}/{세부업무구분소문자}/dto/{서비스 ID}DTO[입출력구분].dto
```

### 파일명 규칙

```text
[서비스 ID]DTO[입출력구분].dto
```

### 입출력 구분

| 구분 | 의미    |
| ---- | ------- |
| in   | 입력    |
| out  | 출력    |
| io   | 입/출력 |

### 작성 예시

- 입력: `mpcoa0000S0DTOin.dto`
- 출력: `mpcoa0000S0DTOout.dto`
- 입/출력: `mpcoa0000S0DTOio.dto`
- 레포트 입력: `mpcoa0000R0DTOin.dto`
- 레포트 출력: `mpcoa0000R0DTOout.dto`

### Sub DTO 클래스 (GRID 처리용)

#### 파일명 규칙

```text
[서비스 ID]DTOsub[순번].dto
```

#### 파일 구성 요소

| 순서 | 항목      | 설명                                             | 예시               |
| ---- | --------- | ------------------------------------------------ | ------------------ |
| 1-5  | 서비스 ID | 대구분 + 업무구분 + 세부업무 + 식별번호 + 식별자 | `mpcoa0000S0`      |
| 6    | DTO       | 고정 문자열                                      | `DTO`              |
| 7    | Sub       | 고정 문자열                                      | `Sub`              |
| 8    | 순번      | 숫자(0-9) 또는 알파벳(A-Z)                       | `0`, `1`, `A`, `B` |
| 9    | 확장자    | 고정                                             | `.dto`             |

#### 용도

- GRID 처리를 위한 하위 DTO 클래스
- 메인 DTO에서 참조하는 상세/자식 데이터용
- 여러 개의 Sub DTO를 사용하여 GRID 컬럼 구성

#### 작성 예시

- `mpcoa0000S0DTOsub0.dto`
- `mpcoa0000S0DTOsub1.dto`
