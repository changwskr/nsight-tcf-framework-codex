# 02. 설계재료 · 품질속성

원문: 「2. 아키텍처 설계방법」 전반

## 1. 요리 비유 — 재료부터

요리를 하려면 먼저 **싱싱한 재료**를 모은다.  
아키텍처라는 요리를 만들 때 가장 먼저 모을 재료 = **비기능 요구사항**.

소프트웨어가 가져야 할 요소:

| 구분 | 아키텍처와의 관계 |
|------|-------------------|
| 기능 요구사항 | 아키텍처 설계에 **세부 기능은 거의 영향 없음** (상위 수준이면 충분) |
| 비기능 요구사항 | 아키텍처를 만드는 **핵심 재료** |

→ 상위수준 요구사항 + **비기능 요구사항**으로 아키텍처를 만든다.

비기능 ≈ **품질** + **제약사항**.

## 2. 기능 vs 비기능

### 기능 (Function)

- 수학의 **함수**: INPUT이 있으면 반드시 OUTPUT.
- 예: 1+1 → INPUT 1, OUTPUT 2, 과정은 SUM.

### 비기능 / 품질

- 예: 로그인은 되는데 첫 화면이 **10초** 만에 뜸 → 기능은 되나 **품질(성능) 불만족**.
- 구분 기준: **INPUT/OUTPUT 정의의 변화 여부**.
- 표현: 기능은 동사적, 품질은 **부사적** 표현이 많은 편 → 품질을 찾기가 어렵다.

참조 표준: **ISO/IEC 25010** (소프트웨어 품질 특성).

기능은 INPUT/OUTPUT이 분명해 모델링이 쉽고, 비기능은 정의가 어려워 **모델링이 어렵다**.

## 3. 품질속성 시나리오 (6요소)

비기능 요건을 먼저 모델링한 뒤 아키텍처 모델링으로 간다.  
품질속성 시나리오 구성 요소(원문):

| 요소 | 의미 |
|------|------|
| Stimulus | 시스템에 적용되는 조건 |
| Response | Stimulus에 의한 결과 |
| Source of the stimulus | Stimulus를 발생시키는 원인 |
| Environment | Stimulus 발생 시 외부 요인 |
| Artifact stimulated | 영향받는 산출물 |
| Response measure | 결과를 **수치화**한 지표 |

참고 문헌(원문 언급): **『소프트웨어 아키텍처 이론과 실제』**  
→ 품질속성 시나리오를 만드는 것이 **제일 중요**.

## 4. 수강신청 예시 (가용성·성능 시나리오)

> 자극의 원천이 되는 수강생이 수강신청 시스템에 **동시에 1,000명** 요청할 경우,  
> 수강신청 완료시간이 **3초 이내**여야 하고, **한 번도 다운되지 않아야** 한다.

추가로 모은 비기능 예:

- 웹브라우저 **IE 10.0 이상**, 모바일로도 수강신청 가능  
- 권한 있는 직원만 접근  
- 수강신청 데이터 **주 1회 백업**

이런 시나리오를 모아 **비기능 요구사항 모델링** → 이해관계자와 매핑 → **아키텍처 설계전략**으로 이어진다.
