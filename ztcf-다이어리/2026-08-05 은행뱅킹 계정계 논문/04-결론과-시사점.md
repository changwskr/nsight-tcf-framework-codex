# 04. 결론과 시사점

원문: Ⅴ. 결론 (+ 향후 과제)

## 1. 논문 결론

- 계정계에 **원장보정 프로세스**를 적용해 과목별 처리·업무 적용을 확인.
- **D-1 / 00:00 현시점** 기준 **배치볼륨 원장** 확보를 시뮬레이션으로 입증.
- 기존: 일자변경 시 중단을 **필연**으로 보고 **시간 단축**에 집중.
- 본 설계: 중단을 **원천 배제** → **24시간 무중단** 금융서비스에 만족할 결과.

## 2. 향후 과제 (원문)

| 방향 | 내용 |
|------|------|
| 관점 전환 | 계좌중심 → **고객중심** |
| 상품화 | 계정중심 서비스 → **상품 Parameter화** |
| 구조 | 시스템중심 → **프로세스 통합·자동화** |
| 환경 | Static → **flexible**, OPEN 시스템 |
| 허브·UI | Biz-hub, 사용자 중심 UI, 기술한계 극복 연구 지속 |

## 3. 핵심 개념 치트시트

| 용어 | 의미 (본 논문 맥락) |
|------|---------------------|
| 원장보정 | 복제본에서 익영업일 변경분을 되감아 **00:00 마감 이미지**를 만드는 것 |
| 원장보정로그 | DBIO가 남긴 INSERT/UPDATE **Before Image** 로그 |
| Center Cut | 배치·대량 결과를 온라인/코어 경로로 반영하는 방식 |
| 내부 DR | 운영원장 복제본; 다시 백업·배치용으로 분기 |
| SI (Shadow Image) | 디스크 볼륨 복제·Resync/Split |
| D-1 / 전영업일 | 일자변경 직전 영업일 마감 원장 |
| MSCB | 프레임워크 시스템 제어 블록(일자·거래·배치·Center cut) |
| Temp Mode | 일자변경 구간 임시 제어 모드(시뮬레이션 Job) |

## 4. TCF / PDMP 다이어리 관점 메모

본 논문은 **코어뱅킹 인프라·일자변경·원장 복제** 층이다. `pdmp-service`/TCF 앱 층과는 다르다. 다만 개념적으로 맞닿는 점:

| 논문 | 로컬/현대적 대응 메모 |
|------|------------------------|
| 온라인과 배치 **서버·원장 분리** | OLTP와 배치/보고 경로 분리, 운영 DB 직접 대량갱신 지양 |
| Before Image 보정로그 | 감사·이벤트소싱·CDC와 유사한 “변경 전 스냅샷” 사고 |
| Center Cut / FTP 반영 | 배치 결과를 통제된 채널로만 운영원장에 반영 |
| 00:00 시점 정합성 | 영업일·처리일·원장 기준시각을 트랜잭션 메타로 명확히 둘 필요 |
| 무중단 일자변경 | 앱의 `@TcfTransaction`/헤더의 **영업일·처리유형**과 인프라 일자절체 정합 |

상세 실행 계약은 `tcf-harness-pdmp`·`pdmp-service` 문서를 SoT로 두고, 본 폴더는 **계정계 원장·무중단 배경지식**으로 쓴다.
