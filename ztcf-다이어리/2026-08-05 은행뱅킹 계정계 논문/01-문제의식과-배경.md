# 01. 문제의식과 배경

원문: Ⅰ. 서론 (+ 표1, 그림1)

## 1. 계정계 온라인 Transaction 형태

| 구분 | 예시 |
|------|------|
| 대면 | 영업점 방문, 텔러·단말 거래 |
| 비대면(고객) | 자동화기기, 인터넷/텔레/모바일 뱅킹 |
| 비대면(센터 발생) | DLB(Delayed Batch, 지연갱신) + OS Middleware Utility |
| 배치→코어 | 배치서버를 단말 형태로 두고 코어뱅킹 서버에 전송 처리 |

모든 온라인 거래는 **장애 대비·회계 작업**을 위해 통상 **24:00(00:00) 정각 시점 데이터 확보**가 절대 요건이다.  
현실적으로 이 시간대에 은행 **온라인 계정계 서비스가 일시 중단**된다.

카드승인 등 일부는 **FEP + 대행승인**으로 계정계와 다른 방식으로 24시간 제공 가능.

## 2. 특정 A은행 운영 실태 (예시)

무정지(24×365)를 표방해도 세부적으로는:

| 구간 | 내용 |
|------|------|
| 매일 00:00∼00:30 | 온라인 일자변경, 회계 Count shift, 시스템 테이블 Dynamic save, 비인계 테이블 init, 업무 배치 → **약 30분** 코어 온라인 중단 |
| 매주 월요일 00:00 | 온라인 프로세스 **완전 Terminate** 후 01:00 재기동 → **1시간 이상** 중단 |
| 화∼일 | Middleware/Program/DB 프로세스 **No-Terminate**, 00:00 종료·00:30 재기동 → **30분 이상** 중단 |

월요일 Terminate 시간대 작업 예:

- VALTAB (Validation Table)
- SIBGEN (System Information Base Generation)
- 코어·주변기기(디스크, 멀티호스트 XPC 공유메모리 등) 프로세스 Set-up

## 3. 국내 은행 서비스 중단시간 (표 1, 평일 00:00 전후)

| 은행(익명) | 중단시간 | 동시간대 주요작업 |
|------------|----------|-------------------|
| 신◯은행 | 약 1분 40초 | 일자변경 전후 최소한 거래수행 |
| 하◯은행 | 약 2분 | 동일 |
| 우◯은행 | 약 15분 | 동일 |
| IB◯◯업은행 | 5∼7분 | 동일 |
| N◯◯협은행 | 약 30분 | 일자변경 후 여신업무 배치 |
| K◯◯민은행 | 약 15분 | 일자변경 전후 최소한 거래수행 |

중단 시간 차이는 **메인프레임/유닉스, 프레임워크, 업무 프로세스 구성** 차이에서 비롯.

## 4. 왜 00:00 전영업일 원장이 필수인가

00:00의 **전영업일자 원장(시점정보)** 은 다음에 쓰인다.

- 원가결산, 회계 정합성 Cross Check
- 일일 데이터 검증, 각종 결산
- 후선/정보계 **EDW** 적재용 데이터 생성
- 장애 대비 **원장 백업**

DB 처리는 원장 정합성 유지를 위해 **Commit**으로 종료되는 것이 일반적이다.

## 5. 논문이 겨냥한 문제

| As-Is | To-Be (논문 목표) |
|-------|-------------------|
| 일자변경 구간 온라인 **중단**(수분~1시간+) | **1초도 중단 없는** 온라인 |
| 중단 시간 단축에 집중하던 기존 접근 | 중단을 **원천 배제**하는 원장보정 아키텍처 |
| 배치·백업이 코어 온라인과 경합 | 배치/백업을 **복제·분리 원장**에서 수행 |
