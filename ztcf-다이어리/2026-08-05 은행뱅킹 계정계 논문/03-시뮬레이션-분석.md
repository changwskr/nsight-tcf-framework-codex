# 03. 시뮬레이션 분석

원문: Ⅳ. 시뮬레이션 분석

## 1. 환경구축 · 사전준비 (4.1)

목표: 표1과 같은 일자변경 시간대에도 **1초 중단 없는** 온라인 + **D-1 원장 이미지** 확보.

구현 수단:

- 코어 DB 볼륨 복제: **SI (Shadow Image)**  
- 원장보정: **프레임워크 솔루션** (+ 응용/동적모듈 변경)

큰 수순: **배치볼륨 동기화 → 온라인일자 변경·배치볼륨 복제 → 원장보정 → 배치 DB 기동**

### 사전준비 Job (5개, 순차)

1. 배치 DB 정지  
2. 배치 볼륨그룹 Varyoff  
3. 배치 볼륨그룹 Export  
4. 배치 복제 (SI Resync)  
5. 전일자 기동 배치

## 3. 원장 정합성 · 접근제한 (4.3)

| 주제 | 방식 |
|------|------|
| 계정계↔정보계 정합성 | 일반적 Delete 허용/앱 직접 로그와 달리 **DBIO**로 정합성 유지 |
| 계정계 원장 접근 | 거래 중 생성된 **갱신 Key·내역**을 통해서만 갱신 |
| 배치→운영 반영 | 필요 시 결과를 코어로 **FTP** 후 원장 업데이트 |

---

## 4. 결과 평가 · 조치 (4.4)

| 이슈 | 내용 |
|------|------|
| 일치 | 계리 **Count shift** 합산은 일치 |
| 불일치 | 표준화 보정로그 적용오류, 금융망 **과목코드 착오**(대외계·카드 등 오적용) → 거래내역·계좌원장 불일치 |

조치:

- 업무별 보정로그 재조정 → 배치서버에서 **정지(마감) 이미지** 보정 확보  
- 이자·세금 등 **원가 대상 파일**을 코어로 전송  
- Count shift는 정지 이미지 기준으로 이자계산·결산 사전검증에 반영
