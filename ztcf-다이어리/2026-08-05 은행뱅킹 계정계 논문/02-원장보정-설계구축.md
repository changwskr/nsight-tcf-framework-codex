# 02. 원장보정 설계구축

원문: Ⅱ. 업무 설계분석, Ⅲ. 원장보정 설계구축

## 1. 업무 구분과 수신 요건 (Ⅱ)

금융업무 ≈ **계정계**(여신·수신 등) + **정보계**(영업점 후선, EDW 등).

수신업무 주요 요건설계 방향:

1. 기능 중심 원장 구성 · 프로세스 통합  
2. 대고객 편의기능 확대  
3. 유지보수 편의성  
4. 원화/외화예금 통합  
5. Multi Currency  
6. 퇴직연금 자산관리 ↔ 수신 통합  

→ 요구불·저축성·신탁·퇴직연금 자산관리를 **하나의 원장으로 통합** 검토 (유사성·유지보수·시장 유연성).

---

## 2. 설계 개요 (3.1)

| 원칙 | 내용 |
|------|------|
| 00:00 시점정보 | 원가결산·당일 배치에 사용. 디스크 복제로 **배치서버**에 전송 |
| 야간 배치 | **운영 DB 원장을 직접 갱신하지 않음** |
| 계리·원장 반영 | **Center Cut** 또는 배치 결과를 코어 운영서버로 **FTP** 후 업데이트 |
| 복제 구조 | 운영원장 → 내부 DR → (백업용 / 배치파일용) 재복제 |

선행 조건:

1. 전일자 원장 이미지 보존 → 코어 DB 장애 시 즉시 복구  
2. 대량 백업·야간 배치가 코어/타 시스템에 영향 없이 병행  
3. 백업·배치 지연이 코어 운영에 미치는 영향 최소화  

---

## 3. 설계 방안 (3.2)

- 디스크 복제 솔루션 + **원장보정 아키텍처**로 일자변경 시에도 **다과목 24×365** 업무 연속성 보장.
- DBA는 논리/물리 설계 이력·변경관리로 **구축상태 ↔ 문서** 일치 유지.
- 대응 변경: 테이블 추가, 분리/합병/삭제·컬럼 변경, 무결성/제약 변경.
- 온라인과 **독립된 배치시스템**, **이중화 서버**로 작업 순차 수행.

---

## 4. 시스템 구축 요지 (3.3)

일자변경 **전/후**에 **원장보정로그**를 생성하고, H/W Mirroring 종료 후 보정하여 **전영업일 마감 이미지** 확보.

이미지 확보 코어 구성의 시간축 (그림 2·4 요지):

| # | 내용 |
|---|------|
| ① | 온라인 원장 ↔ 내부 DR **항상 동기화** |
| ② | 일자변경 **3시간 전(21:00)** 부터 내부 DR ↔ 백업/배치원장 동기화 |
| ③ | 일자변경용으로 내부 DR과 백업/배치원장 **분리(Split)** |
| ④ | 원장보정로그로 **배치원장 보정** |
| ⑤ | 배치 DB 기동 후 배치 Job |
| ⑥ | 백업 DB 기동 후 **VTL** 백업 |

---

## 5. D-1(전영업일) 원장 확보 (3.4)

- 응용 프레임워크 **동적 모듈 교체(무중단 모듈)** + 디스크 복제 + 원장보정 아키텍처.
- 온라인은 중단 없이, 일자변경·백업 이미지·배치용 **D-1 마감 이미지** 확보.

주요 처리 흐름 (그림 3):

1. 영업일자 변경과 동시에 **익영업일 거래**에 대해 원장보정로그 시작  
   - DBIO에서 INSERT/UPDATE/DELETE 시 **Before Image**를 보정로그에 저장  
2. 코어 DB ↔ 배치 DB 디스크 복제 종료 및 **Split**  
3. 원장보정로그 생성 종료  
4. 배치원장에 로그로 보정 → **전영업일 정적원장** 확보  

---

## 6. 보정원장 처리절차 (3.5) — 시간대

| # | 절차 |
|---|------|
| ① | 앱과 무관하게 **H/W Mirroring** 시작 |
| ② | 일자변경과 동시에 익영업일 거래 **보정로그** 생성 |
| ③ | Mirroring 종료 = 보정로그 생성 종료 |
| ④ | 확보 원장에 보정로그 **보정 처리** |
| ⑤ | 매일 **21:00 이후** 본원장↔복제원장 동기화 (백업·배치 볼륨) |
| ⑥ | **00:00** 영업일자 변경, 백업·배치원장 분리 |
| ⑦ | 변경시점 거래는 보정로그로 보정 |

이 동안 **코어 온라인은 무중단**. 백업원장에서 백업, 배치시스템에서 배치 수행.

---

## 7. 원장보정 방법 (3.6.1)

- **온라인 서버 ≠ 배치 서버** 분리.
- D-1 마감 이미지 대상 배치는 배치서버에서 → 주·야간 배치가 코어 서비스에 영향 없음.

| 시점 | 단계 |
|------|------|
| 변경 전 | ➊ 21:00~ 백업·배치 원장 동기화 · ➋ 보정로그 테이블 초기화 |
| 변경 시점 | ➌ 온라인→보정로그 반영 · ➍ 내부DR과 백업/배치 **Split** |
| 변경 후 | ➎ 보정로그 반영 완료 · ➏ Split로 백업/배치 원장 생성 → 전일자 배치원장 확보 |

---

## 8. 보정 데이터 처리방법 (3.6.2)

일자변경 이후 **익영업일 변경분**의 Before Image를 DBIO가 보정로그에 저장.

| # | 처리 |
|---|------|
| ➊ | 보정용 로그 Table 삭제(초기화) |
| ➋ | UPDATE 거래: 테이블별 **Before Image** 저장 |
| ➌ | INSERT 거래: 테이블별 로그 저장 |
| ➍ | 분리된 백업원장으로 배치서버 DBMS Start |
| ➎ | UPDATE분: 배치원장에서 동일키 **삭제 후** 로그 내용 INSERT (= Before로 되돌림) |
| ➏ | INSERT분: 배치원장에서 동일키 **삭제** (= 익일 신규분 제거) |
| ❼ | 확보된 최종(시점) 이미지로 결산 등 **대량 배치** |

직관: 배치 쪽 복제본에서 **익영업일 변경을 되감아** 00:00 직전(=전영업일 마감) 상태를 만든다.
