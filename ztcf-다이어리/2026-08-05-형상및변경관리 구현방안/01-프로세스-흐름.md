# 01. 프로세스 흐름

출처: [형상및변경관리-구현방안-검토.png](./형상및변경관리-구현방안-검토.png)

## 1. 전체 흐름 (좌→우)

```text
[요구사항관리]          [변경·설계]           [형상·개발]              [변경·검증]                 [이관·운영]
서비스요청 → 요건정의 → 영향도분석 → 분석/설계 → CM Package 생성
                                              → IT개발 → 단위/통합테스트
                                              → 3자테스트 → 인수테스트 → (이관의뢰)
                                              → 이관/배포 → 운영 → CM Package 종료
```

## 2. 서버 환경

| 환경 | 단계 | 비고 |
|------|------|------|
| (요청·설계, 서버 전) | 서비스요청 ~ CM Package 생성 | 요건·영향도·설계 |
| **개발 Server** | IT 개발, 단위/통합 테스트 | 형상관리(소스 반입/반출) |
| **Staging Server** | 3자 테스트, 인수테스트 | 변경관리 중심 |
| **운영 Server** | 이관/배포, 운영 | 장애/문제관리·ITSM |

## 3. 단계별 역할·활동

### 3.1 요구사항관리

| 단계 | 주체 | 활동 |
|------|------|------|
| 서비스요청 (개발/변경) | 사용자 / 현업 | 요청 제기 |
| 요건정의 | AM | 요건 정의·조정 |
| 영향도 분석 | 아키텍트 | 변경 영향도 평가, 아키텍처 검토 |

### 3.2 변경관리(설계) → CM Package

| 단계 | 주체 | 활동 |
|------|------|------|
| 분석/설계 | PM | 아키텍처 검토, **구축방안 정의** |
| **CM Package 생성** | (프로세스 게이트) | 변경 단위 패키지 개시 |

### 3.3 형상관리 · 개발 Server

| 단계 | 주체 | 활동 |
|------|------|------|
| IT 개발 | 개발자 | 구현, **소스코드 Check-in / Check-out** |
| 단위/통합 테스트 | 개발·테스트 | 개발Server에서 검증 |

### 3.4 변경관리 · Staging Server

| 단계 | 주체 | 활동 |
|------|------|------|
| 3자 테스트 | 변경관리자, 전담 테스터 | 독립 검증 |
| 인수테스트 | 사용자/현업, AM 지원 | 인수 확인 |
| (이관의뢰) | AM 등 | 운영 이관 요청 |

### 3.5 이관/배포 · 장애/문제관리 · 운영 Server

| 단계 | 주체 | 활동 |
|------|------|------|
| 이관/배포 | 변경관리자 | 운영 반영 |
| 운영 | 운영 조직 | 가동 |
| **CM Package 종료** | (프로세스 게이트) | 패키지 라이프사이클 종료 |
| 장애/문제관리 | ITSM·통합관제 연계 | 운영 이슈 |

## 4. 역할 요약

| 역할 | 주요 구간 |
|------|-----------|
| 사용자 / 현업 | 서비스요청, 인수테스트 |
| AM | 요건정의, 인수 지원, 이관의뢰 |
| 아키텍트 | 영향도 분석, 아키텍처 검토 |
| PM | 분석/설계, 구축방안 정의 |
| 개발자 | IT 개발, 소스 반입/반출 |
| 전담 테스터 | 3자 테스트 |
| 변경관리자 | 3자~이관/배포 감독·실행 |

## 5. CM Package 라이프사이클

```text
생성 (분석/설계 직후)
  → 개발·단위/통합 (개발Server, 형상관리)
  → 3자·인수 (Staging, 변경관리)
  → 이관/배포·운영 (운영Server)
  → 종료
```

하나의 개발/변경 요청에 대응하는 **관리·이관 단위**로 본다.
