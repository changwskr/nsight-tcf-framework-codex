# 02. 시스템 계층

출처: [형상및변경관리-구현방안-검토.png](./형상및변경관리-구현방안-검토.png)

도식 하단은 **프로세스 위를 받치는 시스템·도구 레이어**다.

## 1. 기반·횡단 시스템

| 시스템 | 범위 | 역할 |
|--------|------|------|
| **iQMS** | 서비스요청 ~ 운영 전 구간 | 통합 품질/프로세스 기반 (전 라이프사이클) |
| **PMS** | 영향도 분석 ~ 이관/배포 부근 | **산출물 등록** (프로젝트·산출물 관리) |

```text
iQMS  ════════════════════════════════════════════ (전 구간)
PMS      ────────────────────────────── (산출물 등록)
```

## 2. 형상관리 vs 변경관리 (시스템)

| 시스템 | 주 구간 | 핵심 기능 |
|--------|---------|-----------|
| **형상관리** | 개발Server · IT 개발 | 소스 Check-in/out, **소스코드점검** |
| **변경관리** | 단위/통합 이후 ~ 이관/배포 | Staging·운영으로의 **승격·이관** 통제 |

구분 원칙:

- **형상관리** = “무엇을 만들었는가”(소스·구성품 버전)
- **변경관리** = “어디에 올리는가”(환경 이동·승인·배포)

## 3. 단계별 지원 도구

| 도구 | 사용 단계 | 용도 |
|------|-----------|------|
| 사전협의 | 서비스요청 초기 | 사전 협의 |
| 영향도분석 시스템 | 영향도 분석 | 현행 아키텍처 확인 |
| 모델링 시스템 | 분석/설계 | 현행 아키텍처 확인, **모델 등록** |
| 형상관리 | IT 개발 | 소스 반입/반출, 소스코드점검 |
| 변경관리 | 테스트 ~ 이관 | 환경 승격·변경 통제 |
| 테스트 도구 | 단위/통합 · 3자 · 인수 | 테스트 수행·기록 |
| ITSM / 통합관제 | 운영 | 장애·문제·관제 |

## 5. 도식상 관리 영역 라벨 (상단)

슬라이드 상단 배너에 나타난 관리 영역:

1. 요구사항관리  
2. 변경관리 (설계·CM 생성 측)  
3. 형상관리 (개발)  
4. 변경관리 (테스트·이관 측)  
5. 이관/배포관리  
6. 장애/문제관리  

동일 이름 **「변경관리」**가 설계 초반과 Staging 이후 양쪽에 걸쳐 있다.  
구현 시 모듈은 하나여도, **게이트(CM 생성 / 이관 / 종료)** 는 구분하는 편이 안전하다.
