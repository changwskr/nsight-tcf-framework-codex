## 이 단계에서 얻는 것

테이블·컬럼·PK

## 유도 원칙 (필수)

1. **테이블 정보가 이미 있으면** (원장·이전 결과·업무 확정값·기준소스에서 테이블명·PK를 안다)  
   → **직접 입력**으로 진행한다. 전략(기존/신규/확장) 질문은 생략하고  
   `c04.tableInfo=1`, `c04.tableMode=0 — 직접입력(정보확정)`, `c04.tableName`, `c04.pk` 를 확정한다.
2. **테이블 정보가 없으면**  
   → **기존 방식**을 유지한다. 전략(기존 사용 / 신규 생성 / 확장)을 고른 뒤  
   테이블명·PK를 하나씩 확정한다 (`c04.tableInfo=2`).
3. 업무코드(BC)와 테이블 접두어는 일치시킨다. (예: AV → `AV_…`, LN → `LN_…`)  
   기준소스 테이블명을 그대로 복사하지 말고, 대상 BC에 맞게 정규화한다.

## 분기 후 질문 (1개씩)

### A) 1번(정보 있음)을 고른 경우

```text
테이블명은? (확정값을 직접 입력. 예: AV_CUSTOMER_CONTACT)
```

```text
PK 컬럼은? (확정값을 직접 입력. 예: CONTACT_ID)
```

원장: `c04.tableMode=0 — 직접입력(정보확정)` 으로 기록.

### B) 2번(정보 없음)을 고른 경우 — 기존 방식

```text
CRUD 대상 테이블 전략은?

1. 기존 테이블 사용
2. 신규 테이블 생성
3. 기존 테이블 확장
4. 아직 결정되지 않음
```

이어서 테이블명·PK·(필요 시) 컬럼을 하나씩 확정.

## 추가 확인 (질문 1개씩)

기존: 테이블명·컬럼·PK·인덱스·논리삭제·건수 등을 하나씩.  
신규: 저장 필수 업무항목 → 식별자/속성/상태/감사컬럼 구분.  
소유 도메인 일치(방법론 M6). 감사컬럼 없으면 [설계 예시]로 REG_/UPD_/DEL_YN 등 제안.
