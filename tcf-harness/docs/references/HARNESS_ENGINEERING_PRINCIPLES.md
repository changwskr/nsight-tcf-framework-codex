# 참고 문서 반영 원칙

사용자가 제공한 「하네스 엔지니어링: 에이전트 우선 세계에서 Codex 활용하기」를 본 프로젝트의 설계 참고자료로 사용했다.

## 반영한 핵심 원칙

1. 사람은 코드 작성보다 환경·의도·피드백 루프를 설계한다.
2. `AGENTS.md`는 거대한 매뉴얼이 아니라 짧은 문서 지도다.
3. 저장소 내부의 Markdown·계획·스키마·로그를 기록 시스템으로 취급한다.
4. 에이전트가 읽을 수 없는 외부 지식은 실행 시 사실상 존재하지 않는 것으로 본다.
5. 문서만으로 통제하지 않고 구조적 테스트·린터·상태 Gate로 불변조건을 강제한다.
6. 로그·메트릭·실행결과를 에이전트가 읽을 수 있는 피드백으로 제공한다.
7. 에이전트 자율성은 테스트·검증·복구 루프가 시스템에 인코딩된 범위에서만 높인다.
8. 아키텍처 드리프트와 기술부채는 정기적으로 탐지하고 작은 단위로 정리한다.

## MVP 적용과 유보

| 원칙 | MVP 적용 | 후속 고도화 |
|---|---|---|
| 저장소 지식 기록 | Markdown·JSON·JSONL | 문서 신선도 자동 점검 |
| 단계별 실행계획 | 작업별 디렉터리 | 계획 품질 점수 |
| 기계적 통제 | 상태 Gate·3회 제한 | ArchUnit·커스텀 린터 |
| 에이전트 가독성 | stdout·stderr·Diff | 로그·Metric·Trace 질의 |
| 격리 | 전용 Branch | Git Worktree별 실행환경 |
| 정리 프로세스 | 수동 위험·기술부채 기록 | 주기적 doc-gardening·refactor agent |
