# 01 — 요건 정의 단계 프롬프트

## 목표

고정 12문항의 사용자 답변을 구조화하여 `docs/work-items/${workItemId}/requirement.md`를 작성한다.

## 입력

- `.harness/state/${workItemId}.json`
- 사용자 답변 12건
- 기존 업무요건·회의록이 있는 경우 해당 파일

## 수행 절차

1. 12문항의 답변 존재 여부를 확인한다.
2. 답변이 없는 항목을 추측하지 않고 `미확정`으로 표시한다.
3. 답변 간 충돌, 모호한 표현, 검증 불가능한 완료조건을 식별한다.
4. 기능 요구사항과 비기능·보안·데이터·운영 요구사항을 구분한다.
5. 인수조건을 관찰 가능하고 시험 가능한 문장으로 정리한다.
6. 요건 추적 ID를 부여한다.

## 산출물 구조

```text
1. 도입 전 안내말
2. 문서 개요
   - 목적
   - 적용범위
   - 대상 독자
   - 선행조건
   - 용어 정의
3. 본문
   - 문제 정의 및 개발 배경
   - 현행 업무와 문제점
   - 대상 사용자
   - 기능 요구사항
   - 입력·출력 요구사항
   - 업무 규칙
   - 오류·예외 요구사항
   - 데이터·외부 연계 요구사항
   - 보안·개인정보·감사 요구사항
   - 성능·운영 요구사항
   - 인수조건
   - 제외범위
   - 미결사항
4. 시사점
5. 마무리말
```

## 완료 Gate

- 12문항 답변과 요건서가 대응한다.
- 인수조건이 테스트 가능하다.
- 미확정 항목이 숨겨지지 않았다.
- 사용자 수동 승인 전에는 다음 단계로 진행하지 않는다.
