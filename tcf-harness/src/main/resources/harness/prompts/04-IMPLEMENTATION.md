# 04 — 구현 단계 프롬프트

## 목표

승인된 `design.md`와 `execution-plan.md`에 따라 현재 작업 브랜치에서 최소 범위로 구현하고 `implementation-result.md`를 작성한다.

## 구현 원칙

1. 구현 전에 Git 상태와 Branch가 상태원장과 일치하는지 확인한다.
2. 테스트를 먼저 작성하고 예상한 이유로 실패하는지 확인한다.
3. 실패 테스트를 통과하는 최소 구현을 작성한다.
4. 설계에 없는 기능이나 광범위한 리팩터링을 추가하지 않는다.
5. 기존 아키텍처·패키지·명명·로그·예외 표준을 따른다.
6. 생성·수정·삭제 파일과 Git Diff를 보존한다.
7. 설계 충돌이 발견되면 구현을 중단하고 변경요청을 작성한다.

## 금지사항

- 기준 브랜치 직접 수정
- 자동 Commit·Push·Merge
- 테스트 삭제·비활성화
- 예외 무시 또는 오류를 정상으로 변환
- 비밀정보 하드코딩
- 승인 범위 밖의 DB·API 계약 변경

## 구현 결과서

```text
1. 구현 개요
2. 적용한 승인 설계
3. 변경 파일 목록
4. 프로그램별 변경 내용
5. 설정·DB·연계 변경 내용
6. 테스트 우선 구현 기록
7. 실행 명령과 결과
8. Git Diff 요약
9. 미구현·미확정 사항
10. 위험과 후속 조치
11. 사용자 검토 항목
```

## 완료 Gate

- 컴파일 또는 기본 정적검증이 성공한다.
- 설계된 테스트가 존재한다.
- 변경 범위가 승인 설계와 일치한다.
- 구현 결과서와 Diff가 생성된다.
- 사용자 수동 승인 전 테스트 단계로 이동하지 않는다.
