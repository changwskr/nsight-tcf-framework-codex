# ZDocs GitHub Wiki 게시 설계

## 목표

`zdocs-1`과 `zdocs-2`의 Markdown 문서를 기존 NSIGHT TCF Framework GitHub Wiki에 독립된 문서군으로 게시한다. 기존 Wiki 페이지를 덮어쓰지 않고, 원본 저장소의 파일과 기준 커밋을 추적할 수 있어야 한다.

## 게시 범위

- `zdocs-1`의 Markdown 65개를 게시한다.
- `zdocs-2`의 Markdown 27개를 게시한다.
- 총 92개 Markdown 파일만 Wiki 페이지로 변환한다.
- `zdocs-1`의 DOCX 22개는 Wiki 저장소에 올리지 않는다.
- `zdocs-1`의 JSON 1개는 Wiki 페이지나 첨부 파일로 올리지 않는다.
- Markdown에서 DOCX 또는 JSON을 참조하면 고정 Source Baseline의 GitHub 원본 링크로 변환한다.

## 페이지 이름과 색인

- 통합 진입점은 `ZDocs-Index`로 한다.
- 문서군별 진입점은 `ZDocs-1-Index`, `ZDocs-2-Index`로 한다.
- `zdocs-1` 페이지에는 `ZDOC1-` 접두어를 사용한다.
- `zdocs-2` 페이지에는 `ZDOC2-` 접두어를 사용한다.
- 하위 디렉터리 경로를 페이지명에 포함해 같은 파일명의 충돌을 방지한다.
- 파일명은 GitHub Wiki가 안정적으로 처리할 수 있도록 경로 구분자를 하이픈으로 바꾸되, 한글과 의미 있는 영문 이름은 보존한다.
- README 파일은 해당 디렉터리 또는 문서군의 색인 역할을 유지한다.

## 변환 규칙

각 Wiki 페이지에는 다음 정보를 제목 바로 아래에 추가한다.

- 문서군: `zdocs-1` 또는 `zdocs-2`
- Source Baseline 전체 커밋 SHA
- 원본 Markdown 파일 링크
- 실제 구현과 차이가 있을 때 구현 검증과 승인된 아키텍처 의사결정을 우선한다는 주의 문구

링크는 다음과 같이 변환한다.

1. 게시 대상 Markdown을 가리키는 상대 링크는 대응하는 `ZDOC1-*` 또는 `ZDOC2-*` Wiki 링크로 변환한다.
2. 게시하지 않는 DOCX, JSON과 기타 파일 링크는 Source Baseline의 GitHub `blob` 링크로 변환한다.
3. 저장소의 다른 디렉터리를 가리키는 링크도 Source Baseline의 절대 GitHub 링크로 변환한다.
4. 외부 HTTP 링크와 문서 내부 앵커는 보존한다.
5. 해석할 수 없거나 원본 대상이 존재하지 않는 링크는 자동으로 추측하지 않고 검증 결과에 기록한다.

## 기존 Wiki 통합

- `Home`에 ZDocs 통합 색인 링크와 문서군 설명을 추가한다.
- `_Sidebar`에는 `ZDocs-Index`, `ZDocs-1-Index`, `ZDocs-2-Index`만 추가한다.
- 92개 상세 페이지를 Sidebar에 모두 나열하지 않는다.
- 기존 ZArchitecture와 아키텍처 의사결정 문서군은 수정하거나 이름을 바꾸지 않는다.
- 원격 Wiki에 병행 변경이 있으면 강제 푸시하지 않고 rebase로 보존한다.

## 보안과 내용 보존

- 비밀번호, 토큰, 개인키, Access Key와 명백한 운영 Secret을 게시하지 않는다.
- 보안 후보 문자열은 문맥을 확인한다. 설정 키 이름이나 마스킹된 예시는 보존하고 실제 자격증명은 삭제 또는 비식별화한다.
- 사설 IP, 내부 호스트, JDBC URL은 공개 Wiki 노출 위험을 검토한다. 실제 운영 접속정보로 판단되면 일반화하고 원본 파일 위치만 기록한다.
- 원본의 기술 설명은 임의로 요약하거나 재해석하지 않고 가능한 한 보존한다.

## 검증 기준

게시 전후 다음 조건을 모두 확인한다.

- 생성된 상세 페이지가 정확히 92개다.
- 통합 및 문서군 색인 3개가 존재한다.
- 생성 페이지 이름이 기존 Wiki 페이지와 충돌하지 않는다.
- 깨진 내부 Wiki 링크가 0건이다.
- 게시 페이지에 `./` 또는 `../` 상대 링크가 남지 않는다.
- 92개 페이지 모두 동일한 Source Baseline과 원본 파일 링크를 가진다.
- 코드 펜스가 모든 페이지에서 균형을 이룬다.
- 실제 Secret과 개인키 패턴이 0건이다.
- DOCX와 JSON 파일이 Wiki Git 저장소에 새로 추가되지 않는다.
- 로컬 Wiki 작업 트리가 clean이고 로컬 HEAD와 원격 Wiki HEAD가 일치한다.

## 오류 처리와 롤백

- 변환 중 이름 충돌, 링크 해석 실패 또는 보안 위험이 발견되면 푸시 전에 중단한다.
- 원격 변경으로 push가 거절되면 원격을 가져와 rebase하고 전체 검증을 다시 실행한다.
- 게시 커밋은 단일 목적 커밋으로 구성해 필요하면 GitHub Wiki 저장소에서 해당 커밋을 되돌릴 수 있게 한다.

## 완료 조건

사용자가 GitHub Wiki의 `ZDocs-Index`에서 두 문서군을 탐색할 수 있고, 92개 Markdown 페이지가 원본 추적성과 정상 링크를 유지하며 공개되어야 한다. DOCX와 JSON은 Wiki 저장소에 포함되지 않아야 한다.
