# PDMK AS-IS 아키텍처 상세 정의서 Word 제작 설계

## 목적

현재 저장소의 `pdmk-fw`, `pdmk-service`, `pdmk-ui` 구현을 개발자와 아키텍트가 이해하고 검증할 수 있는 상세 Word 아키텍처 정의서로 작성한다.

## 독자와 범위

- 주 독자: PDMK 업무 개발자, 프레임워크 개발자, 애플리케이션·솔루션 아키텍트
- 범위: 현재 저장소에서 확인되는 AS-IS 구현과 설정
- 제외: TO-BE 구조, 개선 로드맵, 목표 아키텍처, 구현되지 않은 기능을 사실처럼 기술하는 내용
- 구현과 기존 문서가 불일치하면 소스 코드와 실행 설정을 우선한다.

## 근거 자료

- `pdmk-service/docs/PDMK_아키텍처_정의서.md`를 설명 구조의 기준으로 사용한다.
- 세 모듈의 Java 소스, Mapper XML, YAML, Gradle 파일, 샘플 요청 및 테스트를 교차 검증한다.
- 기존 보조 문서는 용어와 배경 설명에만 사용하며 중복 또는 계획성 내용은 제외한다.

## 문서 구조

1. 표지, 문서 정보, 목차
2. 아키텍처 개요와 시스템 범위
3. 시스템 컨텍스트와 물리·논리 구성
4. `pdmk-fw`, `pdmk-service`, `pdmk-ui` 책임과 내부 패키지
5. 모듈 의존성과 금지 방향
6. 서비스 ID, URL, 요청·응답 전문 및 DTO 계약
7. UI Relay부터 Controller, Service, DAO, Mapper까지의 거래 흐름
8. Filter, Interceptor, Aspect, Resolver와 TCF/STF/ETF 실행 구조
9. Context, MDC, 예외 및 응답 조립
10. DataSource, H2/Oracle, MyBatis와 트랜잭션
11. 인증·인가, JWT, CORS 및 외부 연동
12. 거래 로그, 이미지로그 및 SQL 로그
13. 설정, 기동, 포트, 빌드 및 배포 산출물
14. API·클래스·설정·테이블 인덱스
15. AS-IS 제약과 확인 범위

## 시각 설계

- 문서 프리셋: `compact_reference_guide`
- 첫 페이지: `editorial_cover`
- 용지: Letter 세로, 상하좌우 1인치, 본문 폭 6.5인치
- 본문: Calibri 11pt, 1.25줄, 문단 뒤 6pt
- 제목 색상과 표 머리글은 프리셋의 청색·청회색 계열만 사용한다.
- 시스템 컨텍스트, 모듈 의존관계, 거래 시퀀스, 데이터 흐름은 고해상도 이미지로 삽입한다.
- 표는 고정 DXA 폭과 반복 머리글을 사용하고 설명 열에 충분한 폭을 배정한다.
- 머리글에는 문서명, 바닥글에는 문서 상태와 페이지 번호를 표시한다.

## 검증 기준

- AS-IS 근거가 없는 목표·권장·예정 표현이 없어야 한다.
- API, 포트, 클래스명, 설정 키와 의존관계는 소스와 일치해야 한다.
- 목차와 제목 계층이 Word 스타일로 구성되어야 한다.
- 모든 표와 다이어그램이 잘림 없이 렌더링되어야 한다.
- `render_docx.py`로 전 페이지 PNG를 생성하고 100% 기준으로 시각 검토한다.
- 최종 산출물은 DOCX 하나만 전달한다.
