| 항목 | 내용 |
| ---- | ---- |
| 대상 | `pdmk-om` (운영관리 샘플 앱, port 8081) |
| 기준일 | 2026-08-08 |
| 참조 | `tcf-om` Handler 도메인, `znsight-man/15-업무코드-Context-WAR.md`, `znsight-man/43-Cache-사용-기준.md` |

---

## 1. 목적

`pdmk-om`은 **업무 WAR(`pdmk-service`)과 분리된 운영관리 원장**이다.  
온라인 거래가 의존하는 **기준정보·정책·통제·증적**을 OM에서만 등록·변경·조회하고, 업무 서비스는 이를 소비한다.

본 요건서는 “무엇을 만들 것인가”를 정의한다. 테이블명·컬럼·ServiceId 최종값은 설계 단계에서 확정한다(임의 확정 금지).

---

## 2. 범위와 원칙

### 2.1 In Scope

| 구분 | 내용 |
| ---- | ---- |
| 기준정보 CRUD | 카탈로그·코드·정책의 조회/등록/수정/삭제 |
| 운영 통제 | 거래 허용/차단, Timeout, Cache 갱신 |
| 증적·감사 | 이미지로그·감사로그·변경이력 조회 |
| 권한·메뉴 | OM 화면/기능 접근 통제 (샘플 수준) |
| UI 연동 | `pdmk-ui`(또는 향후 om-ui)에서 OM API 호출 |

### 2.2 Out of Scope (1차)

| 구분 | 이유 |
| ---- | ---- |
| 고객·상품 등 업무 원장 | 업무 WAR 책임 |
| CI/CD·배포 파이프라인 실연동 | `tcf-om` Deploy/Batch는 후순위 |
| 다중 WAS 실시간 Cache 동기화 완전체 | 로컬+TTL+수동 Evict로 시작 |
| TCF `OM.*` Handler 경로 완전 이식 | PDMK는 commons(`POST /서비스ID`) 유지 |

### 2.3 공통 원칙

1. **원장은 DB, Cache는 가속 계층** — 업무 데이터는 캐시하지 않는다.
2. **OM만 기준정보를 변경** — `pdmk-service`에 기준정보 수정 API를 두지 않는다.
3. **변경 시 즉시 또는 명시적 Evict/Reload** — Timeout·거래통제·카탈로그·오류코드.
4. **모든 변경은 감사 가능** — 누가/언제/무엇을/이전값·이후값.
5. **ServiceId는 OM 업무코드로 시작** — 목표: `omcoa*` (B안). 당분간 `mkcoa*` 혼용 허용 시 문서에 명시.
6. **PDMK 실행 경로** — Filter → Interceptor → BizPrePostAspect → Controller → Service → DAO.

## 3. 현재 Gap (확인된 사실)

| 항목 | 현재 `pdmk-om` | 목표 |
| ---- | -------------- | ---- |
| 앱 정체성 | Boot 8081, H2 `mem:pdmk-om` | 유지 |
| 관리정보 원장 | 이미지로그(`TB_FW_IMAGE_LOG`) 조회·삭제만 | §4 도메인 확대 |
| Service Catalog | 없음 | OM에서 등록·조회 |
| Timeout / 거래통제 | FW에 정책 테이블 연동 없음(또는 미사용) | OM 원장 + 업무/FW 소비 |
| 공통코드·오류코드 | yml/정적 위주 | OM DB 원장 + Cache |
| 권한·메뉴·세션 | JWT 샘플 수준 | OM 사용자·기능권한 |
| 패키지 | `nhnis.mk` / `mkcoa*` | 추후 `nhnis.om` / `omcoa*` (B안) |

## 4. 관리정보 도메인 요건 (무엇을 만들 것인가)

참조 표준: `tcf-om`의 Handler 도메인. PDMK-OM은 동일 **업무 의미**를 샘플로 재현한다.

### 4.1 P0 — 핵심 운영 기준정보 (최우선)

#### OM-REQ-001 Service Catalog (서비스 카탈로그)

| 항목 | 요건 |
| ---- | ---- |
| 목적 | 허용 ServiceId(거래) 원장. 미등록 거래 차단·라우팅·로그의 기준 |
| 주요 속성(설계 예시) | serviceId, 업무코드, 거래명, 사용여부, HTTP path/메서드, 설명, 등록/변경일시 |
| 기능 | 목록조회, 상세, 등록, 수정, 삭제(논리삭제 권장), 사용여부 토글 |
| 소비처 | Interceptor/STF 전처리, UI 거래 카탈로그, Timeout·거래통제 FK |
| 검증 | 등록된 ID만 호출 가능 / 미등록 시 표준 오류 |

#### OM-REQ-002 Timeout Policy (타임아웃 정책)

| 항목 | 요건 |
| ---- | ---- |
| 목적 | 서비스(또는 그룹)별 처리 제한시간 |
| 주요 속성(설계 예시) | serviceId 또는 정책키, timeoutMs, 적용채널, 사용여부 |
| 기능 | 조회/등록/수정/삭제, Catalog 연동 검증 |
| 소비처 | 외부연계 Timeout, (향후) TimeoutExecutor |
| 검증 | 정책 변경 후 다음 거래부터 반영(캐시 Evict 포함) |

#### OM-REQ-003 Transaction Control (거래통제)

| 항목 | 요건 |
| ---- | ---- |
| 목적 | 거래 허용·차단·점검(서비스×채널×점×사용자 등 조건) |
| 주요 속성(설계 예시) | serviceId, channel, branch, userId(또는 `*`), controlType(ALLOW/DENY/MAINT), 사유, 유효기간 |
| 기능 | 조회/등록/수정/삭제, 즉시 반영 |
| 소비처 | STF/Interceptor 전처리 |
| 검증 | DENY 시 업무 진입 전 차단 + 표준 오류코드 |

#### OM-REQ-004 Error Code / Message (오류코드·메시지)

| 항목 | 요건 |
| ---- | ---- |
| 목적 | 표준 오류코드·메시지 원장 (현재 `exceptionCode.yml` 보완/대체) |
| 주요 속성(설계 예시) | errorCode, locale, message, severity, 사용여부 |

| 소비처 | GlobalExceptionHandler, 업무 BizException |
| 검증 | 코드 변경 후 응답 메시지 일치 |

#### OM-REQ-005 Image / Transaction Log 운영 (이미지·거래로그)

| 항목 | 요건 |
| ---- | ---- |
| 목적 | 요청/응답 전문·GUID 추적 운영 화면 (현 `mkcoa8888` 확장) |
| 기능 | 조건검색, 상세(요청/응답 CLOB), 삭제(권한·기간 제한), 보관주기 정책(후속) |

## 8. 데이터·연동 요건

```text
[원장] pdmk-om DB
   ↑ CRUD (운영자 via pdmk-ui → pdmk-om)
   ↓ 배포/기동 시 Seed + Cache Load
[소비] pdmk-fw / pdmk-service
   - Catalog 존재 여부
   - Timeout ms
   - 거래통제 ALLOW/DENY
   - 오류메시지
```

| ID | 요건 |
| -- | ---- |
| OM-INT-01 | 업무 앱은 OM DB를 **직접 쓰지 않음**(조회는 공유 DB 또는 복제/캐시 API 중 택1 — 설계 결정) |
| OM-INT-02 | 로컬 샘플: 단일 H2 또는 OM H2 + service는 파일/시드 복사 중 하나 명시 |
| OM-INT-03 | Catalog 미등록 ServiceId는 업무 Interceptor에서 거부(옵션 스위치) |

## 10. 인수 기준 (Definition of Done)

Phase 1 완료 시:

1. OM에서 ServiceId 등록 없이 업무 호출 시 차단(스위치 ON 기준).
2. Timeout·거래통제 변경 후 Evict되고, 다음 요청에 반영.
3. 오류코드 변경이 예외 응답 메시지에 반영.
4. 이미지로그에서 GUID로 요청/응답 전문 조회.
5. Catalog/Timeout/통제 변경 시 감사로그 1건 이상 기록.
6. `compileJava` / 샘플 거래 호출 / 로그에 ServiceId·GUID 추적 가능.

## 12. 권장 착수 순서 (실무)

1. **Service Catalog** — 다른 정책의 부모 키  
2. **거래통제** — 운영 체감 큼  
3. **Timeout** — 연계/장시간 거래  
4. **ErrorCode** — 운영 메시지 통일  
5. **이미지로그 OM 정리** — 기존 자산 승격  
6. **Audit + Cache Evict** — 변경 안정성
