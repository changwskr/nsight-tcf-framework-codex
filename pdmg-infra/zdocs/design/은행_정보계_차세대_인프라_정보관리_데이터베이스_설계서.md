# 1. 도입

본 DB는 단순 서버 인벤토리가 아니라, 화면설계서의 관리 흐름을 저장·검증·제안 Export 가능한 **Architecture Repository + CMDB** 이다.

```text
현행 인벤토리 → 업무·App 연결 → 서버군·자산 → MW/DB/Network
  → HA/DR·용량·보안 → 라이선스·비용 → 7R·Wave → Checklist·Gate → 제안서
```

핵심 추적성:

```text
biz_system → application → server_group → server_asset
                → middleware_install / db_instance / network_endpoint
                → asset_relation / app_interface
                → availability / capacity / security
                → license / cost / migration / gate·checklist
```

---

# 2. 설계 원칙

| 원칙 | 적용 |
|---|---|
| 서버 ≠ 서버군 | Node Spec은 `server_asset`, 산정·HA·DR·Scale은 `server_group` |
| AS-IS / TO-BE 분리 | 현행 자산과 `migration_plan` 목표 플랫폼을 분리 |
| 코드 표준화 | IaaS/PaaS/SaaS, Bare Metal, Tier, 7R, Lifecycle → `code_*` |
| Bare Metal 3중 의미 | `SERVICE_MODEL` / `RUNTIME_BASE` / `ASSET_KIND` 분리 (화면 §29) |
| 확장 조사항목 | 유형별 항목은 `survey_*` + `asset_attr`(EAV) |
| 다형성 프로파일 | HA/용량/보안은 `target_type_cd` + `target_id` |
| 품질 Gate | 등록 완료 ≠ 승인. `gate_result` / `checklist_result` |
| 감사·증적 | `change_log` / `evidence_file` (화면 §34 보완) |

## 5.3 서버군·자산

### `server_group` — INF-310

산정·HA·DR·Scale의 **기본 단위**.

| 그룹 | 컬럼 |
|---|---|
| 식별 | group_id, group_name, system_id |
| 분류 | tech_role_cd, service_model_cd, deploy_model_cd, runtime_base_cd, env_cd, tier_cd |
| 노드 | node_active_cnt, node_standby_cnt, node_dr_cnt |

| 처리량 | peak_tps, target_tps, concurrent_users, scale_mode_cd |
| 기타 | status_cd, survey_template_id |

### `server_asset` — INF-320/330

관리대장 1행. Asset Kind에 따라 SaaS/Cloud는 Compute 탭 비활성(화면 §34.6).

| 그룹 | 주요 컬럼 |
|---|---|
| 식별 | asset_id, asset_name, group_id, system_id, asset_kind_cd |
| 분류 | tech_role_cd, service_model_cd, deploy_model_cd, runtime_base_cd, env_cd, tier_cd |
| 위치 | datacenter_cd, cloud_provider_cd, region_cd, az_cd, rack_id, host_cluster, vm_id |
| Compute | cpu_socket, physical_core, vcpu, memory_gb, swap_gb |
| Storage | local_disk_gb, san_gb, nas_gb, object_storage_gb |
| OS/Runtime | os_name, os_version, os_eol_date, runtime_java, runtime_other |
| 조직 | owner_org_id, ops_org_id, owner_person_id |
| 상태 | status_cd, survey_template_id |

### Lifecycle (`status_cd`)

```text
DISCOVERED → VALIDATING → CONFIRMED → TARGET_DEFINED
  → MIGRATION_PLANNED → MIGRATED → RETIRED
```
