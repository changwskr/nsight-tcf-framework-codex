# 1. 도입

서비스 계층은 화면의 사용자 행위와 DB의 영속 모델을 **거래(serviceId)** 단위로 연결한다.

```text
UI (INF-xxx)
  → POST /{serviceId}  + 표준 전문(hdr_nhnis + dto)
    → TCF (OnlineTransactionController)
      → Handler → Facade(@Transactional) → Service → DAO/Mapper
        → pdmg_infra 테이블 / View
```

목표는 CRUD 나열이 아니라 다음을 거래로 제공하는 것이다.

```text
조사 등록 · 관계 연결 · 비기능 검증 · 전환 계획 · Gate 판정 · 제안 Export
```

# 2. 아키텍처

## 2.1 호출 흐름 (TCF ON)

```text
DefaultFilter / ServicePreventionInterceptor
  → OnlineTransactionController
    → TcfFacade → OnlineTimeoutExecutor → TransactionDispatcher
      → {Program}Handler
        → {Program}Facade   ← 트랜잭션 경계 (rdwTransactionManager)
          → BizPrePostAspect
            → {Program}Service   ← 업무 검증·조립
              → {Program}DAO     ← MyBatis
```

| 계층 | 책임 | 금지 |
|---|---|---|
| Handler | serviceId 분기, Facade 호출 | DB·업무규칙 |
| Facade | DTO 변환, `@Transactional` | 복잡한 업무 if |
| Service | 검증, 페이징, Map 조립, DAO 호출, change_log | 자체 TX |
| DAO | SQL ID = serviceId_메서드 | 업무 분기 |
| Controller | TCF OFF 호환만 | TCF ON과 동시 활성 금지 |

## 2.2 표준 전문

```json
{
  "hdr_nhnis": {
    "sys_comm": {
      "rms_svc_c": "ifina3100S0",
      "scid": "INF-320",
      "optr_eno": "E0000001",
      "tr_brc": "10001"
    }
  },
  "dto": { }
}
```

- `rms_svc_c` = serviceId (필수, 라우팅 키)
- `scid` = 화면 ID (권장, 감사·ImageLog)
- 응답: 업무 DTO 또는 `{ PROC_CNT, RSLT_CD, RSLT_MSG }`

## 2.3 결과 코드 관례

| RSLT_CD | 의미 |
|---|---|
| 0000 | 성공 |
| 0001 | 필수값/입력 오류 |
| 0002 | 중복 |
| 0003 | 미존재 |
| 0004 | 코드/FK 오류 |
| 0005 | 정합성 위반 (Tier1 HA 없음 등) |
| 0006 | 권한 부족 |
| 0009 | 기타 업무 거부 |

# 3. 네이밍

## 3.1 serviceId (11자+)

```text
[대구분2][업무2][세부1][식별4][구분1][순번1]
   if      in     a    3100     S/C/U/D   0
```

| 구간 | 값 | 의미 |
|---|---|---|
| 대구분 | `if` | infra (pdmg-infra) |
| 업무 | `in` | inventory / architecture |
| 세부 | `a` | 공통축 |
| 식별 | 화면 정렬 번호 | 2100=시스템, 3100=자산, 3110=서버군 … |
| 구분 | S/C/U/D/E/V | 조회/등록/수정/삭제/실행(배치)/검증 |
| 순번 | 0 | 기본 |

파일럿만 예외: `ifina1999*` → `TB_IF_SERVER_PILOT`  
정규 자산은 `ifina3100*` → `server_asset`

## 3.2 프로그램·패키지

| 구분 | 규칙 | 예 |
|---|---|---|
| Program | `ifina` + 식별4 | `ifina3100` |
| Handler | `{program}Handler` | `ifina3100Handler` |
| Facade/Service/DAO | 동일 prefix | `ifina3100Service` |
| DTO | `{serviceId}DTOin/out/Sub0` | `ifina3100S0DTOin` |
| Mapper XML | `rdw.infra.in.a/{program}-ORA.xml` | |
| 패키지 | `nhnis.infra.in.a.{entry\|application\|dto\|persistence\|config}` | |

도메인 세분이 커지면 `nhnis.infra.in.a` 유지하되 Program 단위로 클래스 분리 (mgcoa9000 방식).

# 5. 공통 서비스 규칙 · 업무 룰

> 화면 §28·§34, DB §8, 요구사항 `REQ-F-804`/`REQ-C-*` 를 Service 계층에 고정한다.  
> 룰은 **Hard(저장 거부)** / **Soft(경고·Gate FAIL)** 로 구분한다.

## 5.1 조회 (S0)

| 항목 | 규칙 |
|---|---|
| 페이징 | `pageNo`≥1, `pageSize` 기본 10·최대 100. 초과 시 100으로 clamp 또는 `0001` |
| 출력 | `Sub0[]` + `totalCount` / `totalPages` / `size` |
| TX | `@Transactional(readOnly=true)` |
| 정렬 | 기본 `updated_at DESC` 또는 업무키 ASC (Program별 명시) |
| 상태 필터 | Lifecycle·`active_yn` 미지정 시 Active 위주(RETIRED 제외) 권장 |

## 5.2 등록/수정/삭제 (C0/U0/D0)

| 항목 | 규칙 |
|---|---|
| TX | Facade `rollbackFor = Exception.class` (`rdwTransactionManager`) |
| 감사 | 성공 시 `change_log` 기록 (Service 동기 우선, async는 후속) |
| 삭제 | 마스터·맵핑은 Soft Delete 또는 `status_cd=RETIRED` 권장. 물리 DELETE는 미사용 코드·미연결 행만 |
| 멱등 | 동일 자연키 C0 재호출 → `0002` (중복). U0는 존재 필수 → 없으면 `0003` |
| 부분실패 | 단건 거래는 all-or-nothing. 일괄(C0 다건)만 `partialOk` 옵션 |

## 5.3 검증 (V0)

| 항목 | 규칙 |
|---|---|
| 부작용 | **DB 변경 금지**. 평가 결과만 반환 |
| 응답 | `{ violations[{ ruleId, severity, target, message }], warnCount, errorCount }` |
| 사용처 | `ifina3400V0`(업로드), `ifina6100V0`(Tier1), `ifina6200V0`(N-1/DR), `ifina8200V0`(Wave) |
| 저장 연동 | C0/U0는 내부에서 동일 Rule을 호출. Hard 위반 시 커밋 전 abort |

## 5.4 실행 (E0)

| 항목 | 규칙 |
|---|---|
| 용도 | Export, Pilot→정규 이관, 대량 반영 |
| Timeout | FW OnlineTimeout 상향 또는 Job ID 즉시 반환 후 비동기 |
| 응답 | `{ jobId, status, downloadUri? }` 또는 동기 소량 이관 시 `PROC_CNT` |

## 5.5 룰 엔진 배치

```text
{Program}Service
  → InfraIntegrityValidator   ← 공통 Hard/Soft
  → {Domain}Rule (선택)       ← Program 전용 (예: AssetKindRule, WaveConflictRule)
  → DAO
```

| 클래스 | 책임 |
|---|---|
| `InfraIntegrityValidator` | ID/IP/코드/FK/Tier1/라이선스/RETIRED 맵핑 등 공통 |
| `AssetKindRule` | SaaS/Cloud compute ignore, Bare Metal 3축 일관성 Soft |
| `UploadValidationRule` | Excel row → `E_*` 오류코드 |
| `GateEvaluationRule` | Checklist 미완·프로파일 누락 → Gate PASS 불가 |
| `WaveConflictRule` | critical edge의 Wave 불일치 |

패키지: `nhnis.infra.in.a.application.support` (또는 `.rule`)

## 5.6 심각도 · 결과코드 매핑

| severity | 저장(C/U/D) | V0 | Gate | RSLT_CD |
|---|---|---|---|---|
| HARD | 거부 | errorCount++ | — | `0005` (입력=`0001`, 중복=`0002`, 코드/FK=`0004`) |
| SOFT | 허용(+경고 목록) | warnCount++ | CONDITIONAL/FAIL 후보 | `0000` + `warnings[]` |
| INFO | 허용 | 참고 | — | `0000` |

메시지 본문: `RSLT_MSG` = `[ruleId] 사용자메시지`  
다건 위반 시 첫 HARD를 `RSLT_*`에, 나머지는 `violations[]`에 실어 UI가 전부 표시.

# 12. 시사점

1. **거래 단위 = 화면 행위**이지 테이블 단위가 아니다. (예: 자산 상세 S1은 여러 테이블)
2. **서버군 서비스(ifina3110)** 가 용량·전환·Gate의 허브가 된다.
3. 파일럿 `ifina1999`는 UX·TCF 검증용이며, 본구현은 `ifina3100`으로 수렴한다.
4. V0(검증)·E0(실행)을 CRUD와 분리해야 일괄등록·Gate·Export가 깔끔하다.
5. **룰은 Rule ID로 고정**한다. 화면 문구·DB 제약·RSLT_CD가 흔들려도 `RL-*`가 추적 키가 된다.
6. Tier1 HA 등은 **저장 Soft / Gate Hard** 이원화로 조사 속도와 품질 Gate를 동시에 만족한다.
7. `InfraIntegrityValidator` + Domain Rule + `change_log` 로 화면 §28·§34를 서비스에 고정한다.
