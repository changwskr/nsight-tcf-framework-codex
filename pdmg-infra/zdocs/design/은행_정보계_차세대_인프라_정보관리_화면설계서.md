# 1. 도입 전 안내말

본 화면의 목적은 단순한 서버 자산 CRUD가 아니다.

사용자는 다음 흐름으로 현행 인프라를 조사하고, 차세대 목표 아키텍처와 전환계획까지 관리할 수 있어야 한다.

```text
현행 인벤토리
  ↓
업무·Application 연결
  ↓
서버군 분류
  ↓
서버/VM/Container/Cloud 자산 등록
  ↓
Middleware·DB·Network·Interface 연결
  ↓
HA·DR·보안·용량 검증
  ↓
라이선스·비용 분석
  ↓
7R·Migration Wave 계획
  ↓
Checklist·Architecture Gate
  ↓
제안서/현황판
```

핵심 관리축은 다음이다.

```text
업무 시스템
  ↕
Application
  ↕
Server Group
  ↕
Server Asset
  ↕
Middleware / DB / Network
  ↕
Dependency / Interface
  ↕
Availability / Security / Capacity
  ↕
License / Cost
  ↕
Migration
  ↕
Checklist / Gate
```

# 2. 화면 설계 원칙

| 원칙 | 적용 기준 |
|---|---|
| 서버와 서버군 분리 | 개별 자산과 용량·HA 산정 단위를 분리한다. |
| AS-IS와 TO-BE 분리 | 현행 자산 정보와 목표 플랫폼·전환계획을 다른 영역에서 관리한다. |
| 코드 기반 선택 | 서비스모델, 배포모델, 실행기반, Tier 등은 코드 마스터를 사용한다. |
| 관계 우선 | Application-Server-DB-Interface 의존성을 화면에서 연결한다. |
| 상태 가시화 | DISCOVERED → VALIDATING → CONFIRMED → TARGET_DEFINED → MIGRATION_PLANNED → MIGRATED → RETIRED를 표시한다. |
| 조사 템플릿 적용 | 서버군 유형에 맞춰 동적 조사항목을 추가 표시한다. |
| 품질 Gate 연결 | 단순 등록 완료가 아니라 Checklist와 Gate 통과 여부를 함께 보여준다. |
| 운영·제안 공용 | 운영자가 자산을 관리하고 제안팀이 TO-BE·전환·비용을 관리할 수 있어야 한다. |
