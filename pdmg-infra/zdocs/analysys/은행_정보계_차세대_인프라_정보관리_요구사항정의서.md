# 1. 배경 및 목적

## 1.1 배경

은행 정보계 차세대 제안·구축 시 서버를 `서버명/CPU/Memory/OS/IP` 수준으로만 조사하면  
IaaS·PaaS·SaaS·Bare Metal 배치, HA/DR, 용량, 라이선스, 전환 Wave를 결정할 수 없다.

현행 Excel 인벤토리는 일회성이며, 업무·Application·의존관계·품질 Gate와 단절된다.

## 1.2 목적

다음을 하나의 Architecture Repository / CMDB로 관리할 수 있어야 한다.

```text
현행 인프라 조사
→ 업무·Application·서버군·자산 연결
→ Middleware/DB/Network/Interface
→ HA·DR·용량·보안
→ 라이선스·비용
→ 7R·Migration Wave
→ Checklist·Architecture Gate
→ 제안서용 현황 Export
```

## 1.3 성공 기준 (요약)

| ID | 성공 기준 |
|---|---|
| SC-01 | 서버와 서버군을 분리해 용량·HA를 **군 단위**로 산정할 수 있다 |
| SC-02 | 업무→App→Group→Asset→DB/IF 추적성이 UI·거래·DB에서 단절 없이 유지된다 |
| SC-03 | Checklist·Gate 없이 “등록 완료”만으로 승인되지 않는다 |
| SC-04 | 제안서 핵심 10대 표를 시스템에서 Export할 수 있다 |
| SC-05 | `pdmg-service`와 동일한 TCF 거래 사상(`serviceId` + 표준 전문)으로 제공한다 |

# 2. 적용 범위

## 2.1 In Scope

- 은행 정보계 중심 인프라 조사·아키텍처·전환 정보 관리
- Bare Metal / VM / Container / K8s / Cloud Managed / SaaS 자산
- WEB·WAS·API·MW·DB·Cache·MQ·Batch·File·Analytics·AI·Monitoring·Security·DevOps 서버군
- Private/Public/Hybrid Cloud 및 On-Premise
- 운영자·아키텍트·PMO·제안 담당자용 관리 UI 및 온라인 거래 API
- MySQL(`pdmg_infra`) 정규 스키마 + 로컬 H2 파일럿(`ifina1999`)

## 2.2 Out of Scope (초기)

- 계정계 코어뱅킹 실시간 거래 처리
- 자동 Discovery Agent의 전면 구축 (배치/업로드 우선)
- CSP 콘솔과 양방향 동기화
- 상세 재무 ERP 연동 (비용은 Snapshot 수준)
- 멀티테넌트 SaaS 제품화
