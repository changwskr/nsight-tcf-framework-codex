# 출력 로그 흐름

실제 코드 기준 한 건 거래의 로그 순서입니다.  
`[TX-FLOW]` 는 `PdmkTxFlowLog` / Aspect 가 남기는 메서드 진입·탈출 로그입니다.

```text
[TX-FLOW][시작] DefaultFilter.doFilter
│
├─ [TX-FLOW][시작] ServicePreventionInterceptor.preHandle
│    [시스템 선처리] 시작 ===============================================
│    [시스템 선처리] GUID: ...
│    [온라인전문][요청][원문] ===============================================
│    [요청전문] {"hdr_nhnis":{...},"dto":{...}}
│    [TX-FLOW][시작] ImageLogHandler.preImagelog
│    [TX-FLOW][종료] ImageLogHandler.preImagelog
│    [시스템 선처리] 종료 ===============================================
├─ [TX-FLOW][종료] ServicePreventionInterceptor.preHandle
│
├─ [TX-FLOW][시작] RequestBodyArgumentResolver.resolveArgument
├─ [TX-FLOW][종료] RequestBodyArgumentResolver.resolveArgument
│
├─ [TX-FLOW][시작] mkcoa8888Controller.mkcoa8888S0     ← PdmkBizTxFlowAspect
│    [TX-FLOW][시작] BizPrePostAspect.before
│      [업무 선처리] 시작 ===============================================
│      [업무 선처리] GUID: ...
│      [업무 선처리] 서비스: ...
│      [업무 선처리] 호출: ...
│      [업무 선처리] BRC: ...
│      [업무 선처리] 종료 ===============================================
│      [업무처리] 시작 ===============================================
│    [TX-FLOW][종료] BizPrePostAspect.before
│
│    ▷▷▷▷▷▷▷▷ mkcoa8888 Controller Start!
│    [TX-FLOW][시작] mkcoa8888Service.mkcoa8888S0
│      ▶▶▶▶▶▶▶▶ mkcoa8888S0 Service Start!
│      [TX-FLOW][시작] mkcoa8888DAO.mkcoa8888S0_S0_count
│      ... SQL ...
│      [TX-FLOW][종료] mkcoa8888DAO.mkcoa8888S0_S0_count
│      [TX-FLOW][시작] mkcoa8888DAO.mkcoa8888S0_S0
│      ... SQL ...
│      [TX-FLOW][종료] mkcoa8888DAO.mkcoa8888S0_S0
│      ▶▶▶▶▶▶▶▶ mkcoa8888S0 Service End! - Total: N
│    [TX-FLOW][종료] mkcoa8888Service.mkcoa8888S0
│    ▷▷▷▷▷▷▷▷ mkcoa8888 Controller End!...
│
│    [TX-FLOW][시작] BizPrePostAspect.after
│      [업무처리] 종료 ===============================================
│      [업무 후처리] 시작 ===============================================
│      [업무 후처리] 결과 DTO
│      {"..."}
│      [업무 후처리] 종료 ===============================================
│    [TX-FLOW][종료] BizPrePostAspect.after
├─ [TX-FLOW][종료] mkcoa8888Controller.mkcoa8888S0
│
├─ [TX-FLOW][시작] ResponseBodyArgumentResolver.beforeBodyWrite
│    [시스템 후처리] 시작 ===============================================
│    [온라인전문][응답][원문] ===============================================
│    {"hdr_nhnis":{...},"dto":{...}}
│    [시스템 후처리] 종료 ===============================================
├─ [TX-FLOW][종료] ResponseBodyArgumentResolver.beforeBodyWrite
│
├─ [TX-FLOW][시작] ServicePreventionInterceptor.postHandle
├─ [TX-FLOW][종료] ServicePreventionInterceptor.postHandle
│
├─ [TX-FLOW][시작] ServicePreventionInterceptor.afterCompletion
│    [TX-FLOW][시작] ImageLogHandler.postImagelog
│    [TX-FLOW][종료] ImageLogHandler.postImagelog
├─ [TX-FLOW][종료] ServicePreventionInterceptor.afterCompletion
│
[TX-FLOW][종료] DefaultFilter.doFilter
```

## 검증 결과 (코드 대조)

| 항목 | 문서(수정 전) | 실제 코드 | 결과 |
|------|---------------|-----------|------|
| 전체 순서 (Filter→Interceptor→업무→응답→afterCompletion) | 위와 동일 | Spring MVC + AOP 순서와 일치 | 일치 |
| `[TX-FLOW]` 문구 | `preHandle 시작` 등 접미사 있음 | `[TX-FLOW][시작] Class.method` 만 출력 | 문서 과잉 → **문서 수정** |
| 시스템 선/후·요청/응답 전문 | 있음 | Interceptor / ResponseBodyAdvice | 일치 |
| 업무 선처리 진행 로그 | `GUID / 서비스 / 호출 / BRC` 한 줄 | **4줄**로 각각 출력 | 문서 단순화 → **문서 수정** |
| Controller/Service/DAO 이름 | `(Controller 메서드)` 플레이스홀더 | `mkcoa8888Controller.mkcoa8888S0` 형태 | **문서에 예시 반영** |
| ImageLog pre/post TX-FLOW | 있음 | `PdmkFwTxFlowAspect` | 일치 |
| BizPrePostAspect before/after TX-FLOW | 있음 | 수동 enter/leave | 일치 |

## 참고

- 거래 시작 시 `SystemPreProcessor` 앞에 **라인피드 5개**(`PdmkTxLog.txGap()`)가 붙습니다.
- `RequestBodyArgumentResolver` 는 `@nhnis.fw.commons.resolver.RequestBody` 사용 시에만 호출됩니다. (현재 `mkcoa*` Controller 사용 중)
- DAO 호출이 여러 개면 `[TX-FLOW]` 가 호출 횟수만큼 반복됩니다.
