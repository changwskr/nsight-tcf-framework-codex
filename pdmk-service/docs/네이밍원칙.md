# PDMK 네이밍 원칙

> **기준 소스:** `pdmk-service` (`src/main/java/nhnis/mk`)  
> **정본(최신·원칙 적용):** [MK-NAMING_CONVENTION.md](./MK-NAMING_CONVENTION.md)  
> **기준 샘플:** `mkcoa8888` (`S0` 조회 + `D0` 삭제)

이 문서는 PDMK에서 **무엇을 어떻게 이름 붙이는지**를 빠르게 파악하기 위한 **요약**이다.  
**본 요약과 CONVENTION이 다르면 CONVENTION을 따른다.**

---

## 한눈에 보기

```text
서비스 ID   mkcoa8888S0
패키지      nhnis.mk.co.a.{controller|service|dao|dto}
클래스      mkcoa8888Controller / Service / DAO
애노테이션  @Slf4j + @RestController / @Service / @RDWMapper
DTO         mkcoa8888S0DTOin / DTOout / DTOSub0  (필요 시 DTOio)
URL         POST /mkcoa8888S0
SQL ID      mkcoa8888S0_S0  (= DAO 메서드명)
Mapper XML  rdw.mk.co.a/mkcoa8888-ORA.xml   (DB구분: ORA|MYS|MSS)
```

호출 흐름:

```text
pdmk-fw ServicePreventionInterceptor
  → BizPrePostAspect (nhnis.mk.co.common)
    → Controller (nhnis.mk.co.a.controller)
      → Service (nhnis.mk.co.a.service)
        → DAO (nhnis.mk.co.a.dao)
          → Mapper XML (rdw.mk.co.a/*.xml)
```

## 1. 기본 원칙

| 원칙 | 설명 |
| ---- | ---- |
| 서비스 ID 중심 | URL, 메서드명, DTO, SQL ID가 같은 서비스 ID로 연결된다 |
| 업무 경로 = 패키지 | Java 패키지에 대구분·업무·세부업무를 넣는다 (`nhnis.mk.co.a`) |
| 식별번호 단위 클래스 | Controller/Service/DAO는 식별번호까지 (구분자 S/C/U/D/A/R 제외) |
| DAO 메서드 = SQL ID | 이름 불일치 금지 |
| TCF 전문 스타일 | `DataObject` + `DTOin`/`DTOout`(·`DTOio`), `POST /서비스ID` |
| REST 금지 | `/api/.../list`, `DtoIn`/`Dao` 스타일 사용하지 않음 |

## 3. 서비스 ID

### 구조

CONVENTION §3.2 기준 (길이 합 = 서비스 ID 전체):

```text
[대구분2][업무2][세부1][식별번호4][구분자1][순번1]
   mk      co     a      8888       S       0
```

→ `mkcoa8888S0`

| 구분 | 길이 | 예 | 설명 |
| ---- | ---: | -- | ---- |
| 대구분 | 2 | mk | 애플리케이션 그룹 |
| 업무구분 | 2 | co | CO, IC, MS, SA |
| 세부업무 | 1 | a | A, B |
| 식별번호 | 4 | 8888 | 화면번호 또는 일반번호 |
| 구분자 | 1 | S | S/C/U/D/A/R |
| 순번 | 1 | 0 | `0~9`, 초과 시 `A~Z` |

### 구분자

| 코드 | 의미 |
| ---- | ---- |
| S | 조회 |
| C | 등록 |
| U | 수정 |
| D | 삭제 |
| A | 혼합 |
| R | 리포트 |

### 예시

| 용도 | 서비스 ID |
| ---- | --------- |
| 이미지로그 조회 | `mkcoa8888S0` |
| 이미지로그 삭제 | `mkcoa8888D0` |
| 안내항목 목록 | `mkcoa5530S0` |
| 영업팁 목록 | `mkcoa9999S0` |
| (규칙 예) 등록/수정/혼합/리포트 | `mkcoa0000C0` / `U0` / `A0` / `R0` |
| (규칙 예) 화면번호 | `mkcoaZ0000S0` |

## 5. 클래스·파일 명명

### Controller / Service / DAO

파일명에는 **식별번호까지**만 쓴다. 구분자(S/C/U/D/A/R)는 넣지 않는다.

| 구분 | 패턴 | 예 | 애노테이션 |
| ---- | ---- | -- | ---------- |
| Controller | `mkcoa{식별}Controller` | `mkcoa8888Controller` | `@Slf4j` + `@RestController` |
| Service | `mkcoa{식별}Service` | `mkcoa8888Service` | `@Slf4j` + `@Service` |
| DAO | `mkcoa{식별}DAO` | `mkcoa8888DAO` | `@RDWMapper` |

동일 식별번호의 여러 서비스는 **하나의 Controller**로 통합한다.  
식별번호가 다르면 Controller를 분리한다.

```text
mkcoa8888S0 + mkcoa8888D0  →  mkcoa8888Controller
```

### DTO

서비스 ID **전체**를 포함한다.

| 구분 | 패턴 | 예 |
| ---- | ---- | -- |
| 입력 | `{서비스ID}DTOin` | `mkcoa8888S0DTOin` |
| 출력 | `{서비스ID}DTOout` | `mkcoa8888S0DTOout` |
| 입·출력 | `{서비스ID}DTOio` | 입출력을 한 타입으로 쓸 때 (CONVENTION §8.1). **현재 샘플 미사용** |
| 목록행(GRID) | `{서비스ID}DTOSub{순번}` | `mkcoa8888S0DTOSub0` |

- `com.ims.superspring.dto.DataObject` 상속
- Getter/Setter, `clone`, `toString`, `getFieldPropertyMap` 구현
- 필드명: camelCase (`guid`, `pageNo`, `totalCount`)
- Sub 순번: `0~9`, 초과 시 `A~Z`
- Sub 목록 필드명은 클래스명과 맞춘다 (예: `mkcoa8888S0DTOSub0`)

## 6. Controller 규칙

```java
@Slf4j
@RestController
public class mkcoa8888Controller {

    @PostMapping("/mkcoa8888S0")
    public mkcoa8888S0DTOout mkcoa8888S0(
            @RequestBody mkcoa8888S0DTOin input) throws Throwable { … }

    @PostMapping("/mkcoa8888D0")
    public mkcoa8888D0DTOout mkcoa8888D0(
            @RequestBody mkcoa8888D0DTOin input) throws Throwable { … }
}
```

| 항목 | 규칙 |
| ---- | ---- |
| 클래스 `@RequestMapping` | **금지** |
| URL | `POST /{서비스ID}` |
| `@RequestBody` | `nhnis.fw.commons.resolver.RequestBody` (dto 노드 바인딩) |
| 메서드명 | 서비스 ID와 동일 |
| 예외 | `throws Throwable` (CONVENTION §5.4) |

요청 Body:

```json
{
  "hdr_nhnis": { "sys_comm": { … } },
  "dto": { … }
}
```

local에서는 `{"dto":{…}}` 만으로도 가능하다.

## 7. Service / DAO / SQL ID

### Service

- 패키지: `nhnis.mk.co.a.service`
- `@Slf4j` + `@Service`
- 메서드명 = 서비스 ID
- 시그니처: `public {서비스ID}DTOout {서비스ID}({서비스ID}DTOin input) throws Exception`

```java
public mkcoa8888S0DTOout mkcoa8888S0(mkcoa8888S0DTOin input)
        throws Exception { … }
```

### DAO

- 패키지: `nhnis.mk.co.a.dao`
- `@RDWMapper`
- 입력: `Map<String, Object>` / 출력: `List<Map<String, Object>>` 또는 `int`
- 예외: `throws Exception`

### SQL ID (= DAO 메서드명)

```text
[서비스ID]_[DML][순번]
[서비스ID]_[DML][순번]_count
```

| 예 | 의미 |
| -- | ---- |
| `mkcoa8888S0_S0` | 목록 조회 |
| `mkcoa8888S0_S0_count` | 건수 |
| `mkcoa8888D0_D0` | 삭제 |

DML: `S` 조회 · `C` 등록 · `U` 수정 · `D` 삭제 · `A` 혼합  
순번: `0~9`, 초과 시 `A~Z`

Mapper XML에서는 `parameterType` / `resultType`을 명시한다 (단순·동적 조회 시 `java.util.HashMap`).

## 8. MyBatis Mapper

### 위치

```text
src/main/resources/rdw.[대구분].[업무].[세부]/
```

```text
src/main/resources/rdw.mk.co.a/
  mkcoa8888-ORA.xml
  mkcoa5530-ORA.xml
  mkcoa9999-ORA.xml
```

### 파일명 / DB구분 / namespace

```text
파일     : [대구분][업무][세부][식별4]-[DB구분].xml
예       : mkcoa8888-ORA.xml
namespace: nhnis.mk.co.a.dao.mkcoa8888DAO
스캔     : classpath*:rdw.*/*.xml
MapperScan: nhnis.mk.**.dao
```

| DB구분 | DB |
| ------ | -- |
| ORA | Oracle (현재 샘플) |
| MYS | MySQL |
| MSS | MS SQL Server |

SQL·Alias·성능 작성 표준은 CONVENTION §12~§13을 따른다.

## 10. 변수·주석

- Java 변수: camelCase (`guid`, `serviceId`, `totalCount`, `pageNo`)
- DB 키워드·오브젝트: 대문자
- 테이블 Alias: `T1`, `T2`, `T3` / 컬럼 Alias: `AS` 사용
- 날짜: `YYYY.MM.DD`

간략형 클래스 주석(샘플과 동일):

```java
/**
 * 이미지로그 조회/삭제 Controller.
 *
 * @since 2026.08.07
 */
```

파일·메서드 상세 주석 템플릿은 CONVENTION §15를 본다.

## 11. 새 프로그램 체크리스트

1. 대구분 / 업무 / 세부 / 식별번호 / 기능(S·C·U·D·A·R) / 순번 결정  
2. 서비스 ID 생성 → 예: `mkcoa8888S0`  
3. 파일 생성:

```text
controller/mkcoa8888Controller.java   (@Slf4j @RestController)
service/mkcoa8888Service.java         (@Slf4j @Service)
dao/mkcoa8888DAO.java                 (@RDWMapper)
dto/mkcoa8888S0DTOin.java
dto/mkcoa8888S0DTOout.java
dto/mkcoa8888S0DTOSub0.java           ← 목록/GRID이면
resources/rdw.mk.co.a/mkcoa8888-ORA.xml
```

4. 검증:

- [ ] 패키지 `nhnis.mk.co.a.*`
- [ ] `@PostMapping("/서비스ID")`, 클래스 `@RequestMapping` 없음
- [ ] Controller `throws Throwable` / Service·DAO `throws Exception`
- [ ] DAO 메서드명 = SQL ID
- [ ] Mapper `namespace` = DAO FQCN
- [ ] 리소스 경로 `rdw.mk.co.a/`, 파일명 `*-ORA.xml`(또는 MYS/MSS)

워크플로우 상세는 CONVENTION §16을 본다.

## 12. 하지 말 것

| 금지 | 이유 |
| ---- | ---- |
| `/api/mk/co/a/.../list` REST URL | TCF 서비스 ID URL만 사용 |
| `DtoIn` / `Dao` / `ListResponseDto` | 표준은 `DTOin` / `DAO` / `DTOout` |
| Controller에 `S0` 등 구분자 포함 | 식별번호 단위로만 |
| DAO 메서드 ≠ SQL ID | MyBatis 매핑 깨짐 |
| 업무 경로 없는 패키지 (`nhnis.mk.controller`) | `co.a` 등 세그먼트 필수 |

## 참고

- **충돌 시:** [MK-NAMING_CONVENTION.md](./MK-NAMING_CONVENTION.md) 우선.
- 공통 FW 모듈명 `pdmk-fw`, 로그 유틸 `PdmkTxLog` 는 FW 공유 식별자로 유지한다.
- meta `.dto` 파일은 **현재 PDMK에서 사용하지 않는다.** (필요 시 CONVENTION §17)
- SQL 포맷·주석 템플릿·성능·생성 워크플로우는 CONVENTION §12~§18을 본다.
