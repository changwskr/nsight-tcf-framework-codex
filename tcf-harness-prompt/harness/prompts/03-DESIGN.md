# 03 — 설계 단계 프롬프트

## 목표

승인된 요건과 분석서를 바탕으로 구현 가능한 목표 설계와 테스트 기준을 정의하고 `docs/work-items/${workItemId}/design.md` 및 `execution-plan.md`를 작성한다.

## 설계 절차

1. 문제와 제약을 다시 확인한다.
2. 최소 2개의 실현 가능한 대안을 비교한다.
3. 선택 기준, 결정, 포기한 대안과 영향을 기록한다.
4. 목표 구성요소와 책임 경계를 정의한다.
5. 정상·오류·Timeout·장애 흐름을 정의한다.
6. 데이터, 상태, 트랜잭션, 연계 계약을 정의한다.
7. 보안, 개인정보, 감사, 로그 기준을 정의한다.
8. 테스트 시나리오와 자동 품질 Gate를 설계한다.
9. 실제 변경 파일 단위의 실행계획을 작성한다.

```text

5. 요구사항과 제약조건
6. 설계 원칙
7. 대안 비교 및 의사결정
8. 목표 아키텍처
9. 표준 형식
10. 구성요소 및 속성
11. 책임 경계와 RACI

13. 오류·Timeout·장애 흐름
14. 정상 예시
15. 금지 예시
16. 연계 규칙
```

## 실행계획 필수 항목

- 변경 파일의 정확한 경로
- 파일별 책임과 변경 이유
- 선후관계
- 테스트 우선 구현 순서
- 실행 명령과 기대 결과
- 롤백 방법
- 수동 확인 항목

## 완료 Gate

설계가 요건과 분석을 모두 추적하고, 구현자가 추가 추정 없이 작업할 수 있어야 한다. 사용자 수동 승인 전 구현을 금지한다.
