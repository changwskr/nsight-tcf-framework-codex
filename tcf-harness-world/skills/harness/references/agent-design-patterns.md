# Codex 에이전트 팀 설계 패턴

## 순차 파이프라인

앞 역할의 산출물이 다음 역할의 필수 입력일 때 사용한다. Analyst → Builder → QA가 대표적이다. 각 단계는 입력 파일 존재와 완료 상태를 확인한 뒤 시작한다.

## 독립 병렬 작업

공유 파일을 수정하지 않고 결과를 나중에 통합할 수 있는 작업에만 사용한다. 작업별 소유 파일, 완료 기준과 충돌 처리자를 먼저 지정한다. 사용자 또는 상위 지침의 에이전트 사용 허가가 필요하다.

## 검토 루프

QA가 재현 절차, 기대 결과, 실제 결과와 담당 역할을 기록한다. 수정 요청은 결함 범위를 넘지 않으며 같은 원인이 반복되면 무한 재시도하지 않는다.

## 역할 계약 형식

모든 역할은 핵심 역할, 입력, 출력, 작업 원칙, 오류 처리, 협업을 설명한다. 다른 역할이 내부 구현을 읽지 않고도 역할을 사용할 수 있어야 한다.
