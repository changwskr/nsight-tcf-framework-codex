# Harness — Codex Agent Team Architect

## 목적

프로젝트의 기존 지침과 구조를 분석해 필요한 역할만 설계하고, 역할 간 입력·출력·실패 계약을 명시하며, 검증 가능한 오케스트레이션을 만든다.

## 실행 단계

1. 적용 범위의 `AGENTS.md`, 기존 `agents/`, `skills/`, 테스트와 문서를 읽는다.
2. 기존 역할과 스킬의 중복, 책임 경계와 변경 드리프트를 확인한다.
3. 각 역할의 입력, 출력 파일, 완료 기준, 오류 처리와 협업 대상을 정의한다.
4. 순차 의존성과 독립 작업을 구분한다. 사용자 또는 상위 지침이 허용한 독립 작업만 `spawn_agent`로 배정한다.
5. 실행 중인 에이전트에는 `send_message`, 완료된 에이전트의 추가 작업에는 `followup_task`를 사용한다.
6. `wait_agent`로 결과를 수집하고 명시적 산출물과 QA 증거를 확인한다.
7. 실패는 담당 역할과 최소 수정 범위로 되돌리고, 변경 이력과 검증 결과를 기록한다.

## 필수 산출물

- 범위가 지정된 `AGENTS.md`
- `agents/{role}.md` 역할 계약
- 필요한 `skills/{name}/SKILL.md`와 로컬 references
- 오케스트레이터 입력·출력 표와 실패 처리
- 재현 가능한 검증 명령

## 설계 규칙

- 역할 하나에는 주요 책임 하나만 둔다.
- 암묵적 대화 상태 대신 파일 경로와 구조화된 작업 메시지를 사용한다.
- 독립적이지 않은 작업을 병렬화하지 않는다.
- 에이전트 생성 권한을 하네스 자체가 확대하지 않는다.
- 사용자 파일을 기본적으로 보존하고 재시도 횟수를 제한한다.
