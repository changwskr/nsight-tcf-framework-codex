# 프로그램 예외 처리 방법

PDMG 업무 프로그램(`Service` 등)의 **표준 예외**는 `BizException`이다.  
메시지·조치문구는 `exceptionCode.yml`에 두고, FW `GlobalExceptionHandler`가 응답 `result`로 조립한다.

관련: [35.에러코드 설정방법.md](./35.에러코드 설정방법.md)

---

## 1. 원칙

| 구분 | 방법 |
|------|------|
| 업무 오류 (검증·권한·데이터 없음 등) | `throw new BizException("코드"[, 인자…])` |
| 메시지를 코드에 하드코딩 | **금지** (yml에 등록) |
| try/catch 후 삼키기 | **금지** (필요 시 이력만 남기고 다시 throw) |
| `NhBaseException` / 자체 Advice | PDMG 온라인 표준 아님 |

---

## 2. 처리 흐름

```text
Service: throw new BizException("MP0404")
  → (TX) rollback
  → GlobalExceptionHandler (pdmg-fw)
  → exceptionCode.yml 조회 (본문 + 조치)
  → NH_NIS_ERR_DTO
  → ResponseBodyArgumentResolver
  → { "hdr_nhnis": …, "result": { stdErrCode, stdErrMsgCntn, addMsgContents, … } }
```

HTTP는 보통 **500** (타임아웃은 **504** `FW_TIMEOUT`).

---

## 3. 코드에서 던지기

```java
import nhnis.fw.exception.BizException;

// 코드만
throw new BizException("MP0401");

// 메시지 템플릿 {0} 치환
throw new BizException("MP0410", "상품코드");
```

샘플: `mgcoa9001Service` — 중복 시 `MP0409`, 미존재 시 `MP0404`, 필수값 `MP0401`.

### catch가 필요할 때

```java
try {
    // …
} catch (BizException e) {
    // 예: 로그인 실패 이력만 남기고
    history.recordFail(e.getCode());
    throw e;   // 반드시 재던짐
}
```

## 4. 에러코드·조치 등록

`src/main/resources/exceptionCode.yml`

```yaml
nhnis:
  exception:
    MP0404: "요청한 데이터를 찾을 수 없습니다."
  exception-action:
    MP0404: "조회 조건을 확인하거나 데이터가 존재하는지 확인하세요."
```

`application.yml`:

```yaml
spring:
  config:
    import: classpath:exceptionCode.yml
```

변경 후 **재기동**.

---

## 5. 응답 result 주요 필드

| 필드 | 출처 |
|------|------|
| `stdErrCode` | `BizException` 코드 |
| `stdErrMsgCntn` | `nhnis.exception.*` |
| `addMsgContents` | `nhnis.exception-action.*` (조치메시지) |
| `errType` | `BIZ` |
| `errClassName` / `errFileName` / `errMethodName` / `errLineNo` | 스택(`nhnis.*`)에서 Handler가 채움 |

---

## 6. FW가 직접 내는 예외 (업무에서 throw하지 않음)

| 코드 | 상황 |
|------|------|
| `FW_TIMEOUT` | 온라인 타임아웃 초과 |
| `FW_OVERLOADED` | Worker 풀/큐 포화 |
| `E9999` | Handler 미지원 serviceId 등 |
