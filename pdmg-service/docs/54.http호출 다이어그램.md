# PDMG HTTP 호출 텍스트 다이어그램

## 1. 전체 HTTP 호출 구조

```text
┌──────────────────────┐
│ 사용자 브라우저      │
└──────────┬───────────┘
           │
           │ GET http://localhost:8090
           ▼
┌────────────────────────────────────┐
│ pdmg-ui : 8090                     │
│                                    │
│ · HTML / CSS / JavaScript 제공     │
│ · 화면 구성정보 제공               │
│ · 거래 목록 제공                   │
│ · 업무·JWT 서비스 호출             │
└──────────┬─────────────────┬───────┘
           │                 │
           │ 업무 요청       │ 인증 요청
           ▼                 ▼
┌──────────────────────┐   ┌─────────────────────────┐
│ pdmg-service : 8080  │   │ pdmg-jwt : 8110         │
│                      │   │                         │
│ · 업무 거래 처리     │   │ · 로그인               │
│ · TCF 처리           │   │ · 토큰 발급·갱신       │
│ · DB 트랜잭션        │   │ · 토큰 폐기            │
└──────────┬───────────┘   │ · JWKS 제공            │
           │               └────────────┬────────────┘
           ▼                            │
┌──────────────────────┐                ▼
│ 업무 데이터베이스    │      ┌──────────────────────┐
└──────────────────────┘      │ JWT 관리 DB          │
                              └──────────────────────┘
```

## 7. TCF 표준 온라인 호출

`nhnis.fw.tcf.enabled=true`인 경우의 호출 흐름입니다.

```text
pdmg-ui
   │
   │ POST http://localhost:8080/online
   │
   │ Header
   │   Authorization: Bearer {Access Token}
   │
   │ Body
   │   hdr_nhnis.sys_comm.rms_svc_c = mgcoa5530S0
   ▼
pdmg-service / pdmg-fw
   │
   ▼
DefaultFilter
   │
   ▼
ServicePreventionInterceptor
   │
   ▼
OnlineTransactionController
   │
   ▼
TcfFacade
   │
   ├─ STF 시스템 선처리
   │
   ▼
TransactionDispatcher
   │
   ├─ rms_svc_c 읽기
   ├─ Service ID 확인
   └─ 담당 Handler 검색
   │
   ▼
mgcoa5530Handler
   │
   ▼
mgcoa5530Facade
   │
   │ 트랜잭션 BEGIN
   ▼
mgcoa5530Service
   │
   ▼
DAO → Mapper → DB
   │
   │ 정상: COMMIT
   │ 예외: ROLLBACK
   ▼
BizPrePostAspect 업무 후처리
   │
   ▼
ETF 시스템 후처리
   │
   ▼
표준 HTTP 응답
```

## 8. TCF 비활성화 직접 호출

`nhnis.fw.tcf.enabled=false`인 경우입니다.

```text
pdmg-ui
   │
   │ POST /mgcoa5530S0
   ▼
DefaultFilter
   │
   ▼
ServicePreventionInterceptor
   │
   ▼
mgcoa5530Controller
   │
   ▼
mgcoa5530Facade
   │
   │ 트랜잭션 BEGIN
   ▼
mgcoa5530Service
   │
   ▼
DAO → Mapper → DB
   │
   ├─ 정상: COMMIT
   └─ 예외: ROLLBACK
   │
   ▼
HTTP 응답
```

Controller가 Service를 직접 호출하는 경우에는 다음과 같이 됩니다.

```text
Controller
   │
   ▼
Service
   │
   ▼
DAO → DB
```

이 경우 Facade의 `@Transactional`을 지나지 않으므로 트랜잭션이 적용되지 않을 수 있습니다.

## 9. 서버 중계 방식

일부 화면은 브라우저가 `pdmg-service`를 직접 호출하지 않고 `pdmg-ui` 서버를 거쳐 호출할 수 있습니다.

```text
브라우저
   │
   │ POST http://localhost:8090/api/relay/mgcoa5530S0
   ▼
PdmgUiApiController
   │
   ▼
TransactionRelayService
   │
   ├─ TransactionCatalog 조회
   ├─ 대상 URL 생성
   │      └─ http://localhost:8080/mgcoa5530S0
   └─ Spring RestClient 실행
   │
   ▼
pdmg-service
   │
   ▼
업무 처리
   │
   ▼
TransactionRelayService
   │
   ├─ HTTP Status
   ├─ 처리시간
   ├─ 대상 URL
   └─ Response Body
   │
   ▼
RelayResult
   │
   ▼
브라우저
```

## 13. HTTP 타임아웃

```text
pdmg-ui
  │
  │ Fetch + AbortController
  │ 제한시간: 10초
  ▼
pdmg-service
  │
  │ pdmg-fw TimeoutExecutor
  │ 제한시간: 기본 5초
  ▼
업무 Service / DB
```

시간 관계:

```text
0초        pdmg-ui 요청 시작
 │
 ├─ 5초    pdmg-fw 업무 타임아웃
 │          └─ OnlineTimeoutException
 │
 └─ 10초   pdmg-ui HTTP 대기 타임아웃
            └─ Fetch Abort + UI_TIMEOUT
```

서버 타임아웃을 UI 타임아웃보다 짧게 설정해야 서버의 표준 오류 응답을 UI가 받을 수 있습니다.

## 15. 전체 호출 순서 요약

```text
화면 접속
  → pdmg-ui 정적 리소스 로딩
  → 환경설정·거래 목록 조회
  → pdmg-jwt 로그인
  → Access/Refresh Token 발급
  → UI 세션에 토큰 저장
  → 업무 요청 전문 생성
  → Authorization Header에 Access Token 설정
  → pdmg-service 호출
  → pdmg-fw JWT·거래 통제·시스템 선처리
  → Handler → Facade → Service → DAO → DB
  → Commit 또는 Rollback
  → 시스템 후처리
  → 표준 HTTP 응답
  → pdmg-ui 화면 표시
```

현재 소스에서는 일반 업무 호출용 `service-client.js`가 `Authorization` 헤더를 넣지 않습니다. JWT 인증을 실제 활성화하려면 다음 형태로 보완해야 합니다.

```javascript
headers: {
    "Content-Type": "application/json;charset=UTF-8",
    "Accept": "application/json",
    "Authorization": `Bearer ${accessToken}`
}
```
