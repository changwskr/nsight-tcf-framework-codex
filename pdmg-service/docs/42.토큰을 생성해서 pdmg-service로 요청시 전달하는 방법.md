# 토큰을 생성해서 pdmg-service로 요청 시 전달하는 방법

## 요약

1. **pdmg-jwt**에서 Access Token 발급 (`mgjwa1000C0`)
2. **pdmg-service** 호출 시 HTTP 헤더  
   `Authorization: Bearer {accessToken}` 로 전달
3. **local 프로파일**에서는 `DefaultFilter`가 JWT 검증을 **생략**한다

요약
발급: pdmg-jwt POST /online + mgjwa1000C0 → dto.accessToken
전달: pdmg-service 요청 헤더
Authorization: Bearer {accessToken}
local: DefaultFilter가 JWT 검증을 생략 → 지금 전문 테스트는 토큰 없이도 동작
주의
pdmg-jwt는 RS256, service JwtProvider는 HS256(jwt.secret)이라 non-local에서 그대로 쓰면 401이 날 수 있습니다. 정합은 문서 §4에 적어 두었습니다.

## 1. 토큰 발급 (pdmg-jwt)

### 엔드포인트

```text
POST http://localhost:8110/online
Content-Type: application/json
```

### 요청 예 (로그인)

```json
{
  "hdr_nhnis": {
    "sys_comm": {
      "std_gbl_id": "임의의-GUID",
      "rms_svc_c": "mgjwa1000C0",
      "scid": "WEBTOP",
      "optr_eno": "admin01",
      "tr_trm_ipadr": "127.0.0.1",
      "tr_sysid": "PDMG-UI",
      "sync_dsc": "S",
      "std_tgrm_rqr_rsp_dsc": "Q",
      "tr_dtm": "20260811"
    }
  },
  "dto": {
    "userId": "admin01",
    "password": "nsight01!"
  }
}
```

### 응답에서 사용할 필드

```json
{
  "dto": {
    "accessToken": "eyJ...",
    "refreshToken": "...",
    "tokenType": "Bearer",
    "expiresIn": 900,
    "jti": "..."
  }
}
```

UI: pdmg-ui JWT 로그인(`mgjwa1000C0`) → sessionStorage에 `accessToken` 저장.

갱신: `mgjwa1000U0` + `refreshToken`.

## 2. pdmg-service로 전달

### HTTP 헤더

```http
POST /mgcoa5530S0 HTTP/1.1
Host: localhost:8080
Content-Type: application/json;charset=UTF-8
Authorization: Bearer eyJ...accessToken...
```

Body는 기존과 동일 (`hdr_nhnis` + `dto`).

### curl 예

```bash
TOKEN="eyJ..."   # pdmg-jwt 로그인으로 받은 accessToken

curl -s -X POST "http://localhost:8080/mgcoa5530S0" \
  -H "Content-Type: application/json;charset=UTF-8" \
  -H "Authorization: Bearer ${TOKEN}" \
  -d '{"hdr_nhnis":{"sys_comm":{"std_gbl_id":"...","rms_svc_c":"mgcoa5530S0",...}},"dto":{...}}'
```

### 검증 주체 (pdmg-service)

`DefaultFilter` (non-local):

1. `Authorization` 헤더 존재 + `Bearer ` 접두어
2. `JwtProvider.validate(token)`
3. `JwtProvider.isAccessToken(token)` (`type` claim == `ACCESS`)
4. subject → `request.setAttribute("ssoId", …)`

## 3. local 프로파일 (현재 개발 기본)

```yaml
spring.profiles.active: local
```

`DefaultFilter`는 **`local`이면 JWT 검사를 하지 않는다.**  
→ Access Token 없이도 `POST /{serviceId}` 가능.

전문 테스트 UI(`online-single.js` / `service-client.js`)도 현재 **Authorization 헤더를 붙이지 않는다.**

---

## 4. 주의 (알고리즘 정합)

| 구분                       | 현황                                         |
| -------------------------- | -------------------------------------------- |
| pdmg-jwt 발급              | **RS256** (JWKS), claim에 `type=ACCESS` 없음 |
| pdmg-service `JwtProvider` | **HS256** (`jwt.secret`), `type=ACCESS` 필요 |

non-local에서 pdmg-jwt Access Token을 그대로 넣으면 **검증 실패(401)** 할 수 있다.  
운영 연동 시 다음 중 하나가 필요하다.

- service가 JWKS(RS256)로 검증하도록 맞추거나
- jwt 발급 claim/`JwtProvider` 검증 규칙을 통일하거나
- local처럼 개발 환경에서는 검증 생략
