# Controller 아키텍처 텍스트 다이어그램

## 1. 전체 Controller 구조

PDMG에는 두 가지 Controller 진입 방식이 있습니다.

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│                        HTTP 요청 / Controller 진입                          │
└─────────────────────────────────────┬────────────────────────────────────────┘
                                      │
                         nhnis.fw.tcf.enabled
                                      │
                    ┌─────────────────┴─────────────────┐
                    │                                   │
                    ▼                                   ▼
             TCF 활성화=true                     TCF 비활성화=false
                    │                                   │
                    ▼                                   ▼
       OnlineTransactionController                업무 Controller
              POST /online                    POST /{Service ID}
                    │                                   │
                    ▼                                   ▼
       TransactionDispatcher                    Business Facade
                    │                                   │
                    ▼                                   ▼
         TransactionHandler                    Business Service
                    │
                    ▼
           Business Facade
```

권장 구조는 다음과 같습니다.

```text
TCF ON
└─ OnlineTransactionController → Handler → Facade

TCF OFF
└─ 업무 Controller → Facade
```

## 2. TCF ON Controller 구조

```text
사용자 / pdmg-ui
      │
      │ POST /online
      │ Authorization: Bearer {Access Token}
      │ Content-Type: application/json
      ▼
DefaultFilter
      │
      ├─ JWT 검증
      ├─ GUID 생성
      ├─ Request Body 캐싱
      └─ ServiceContext 생성
      │
      ▼
ServicePreventionInterceptor
      │
      ├─ 요청 전문 확인
      ├─ Service ID 확인
      └─ 거래 통제
      │
      ▼
┌──────────────────────────────────────────────────────────────────┐
│ OnlineTransactionController                                      │
│                                                                  │
│ 공통 온라인 거래 Controller                                     │
│                                                                  │
│ · 모든 TCF 업무 요청의 단일 진입점                              │
│ · 표준 Header와 DTO Body 분리                                    │
│ · Service ID 추출                                                │
│ · TransactionContext 생성                                        │
│ · TcfFacade 호출                                                 │
│ · 업무 Handler를 직접 알지 않음                                  │
│ · 업무 로직을 수행하지 않음                                      │
└──────────────────────────────┬───────────────────────────────────┘
                               │
                               ▼
TcfFacade
   │
   ├─ STF 시스템 선처리
   │
   ▼
TransactionDispatcher
   │
   ├─ Service ID로 Handler 검색
   └─ Handler.handle() 호출
   │
   ▼
pdmg-service TransactionHandler
   │
   ▼
Business Facade
   │
   ├─ 트랜잭션 BEGIN
   ▼
Service → Rule → DAO → DB
   │
   ├─ 정상: COMMIT
   └─ 예외: ROLLBACK
   │
   ▼
ETF 시스템 후처리
   │
   ▼
HTTP 응답
```

## 3. TCF OFF 업무 Controller 구조

```text
사용자 / pdmg-ui
      │
      │ POST /mgcoa5530S0
      ▼
DefaultFilter
      │
      ▼
ServicePreventionInterceptor
      │
      ▼
┌──────────────────────────────────────────────────────────────────┐
│ mgcoa5530Controller                                              │
│                                                                  │
│ · 업무별 직접 HTTP Endpoint 제공                                │
│ · 입력 DTO 역직렬화                                             │
│ · Bean Validation 적용                                          │
│ · Business Facade 호출                                          │
│ · 출력 DTO 반환                                                 │
└──────────────────────────────┬───────────────────────────────────┘
                               │
                               ▼
mgcoa5530Facade
      │
      ├─ @Transactional
      ├─ DTO 변환
      └─ Service 호출
      │
      ▼
mgcoa5530Service
      │
      ▼
Rule → DAO → Mapper → DB
      │
      ▼
mgcoa5530S0DTOout
      │
      ▼
HTTP JSON 응답
```

권장 Controller 예시:

```java
@Slf4j
@RestController
@RequiredArgsConstructor
@ConditionalOnProperty(
    name = "nhnis.fw.tcf.enabled",
    havingValue = "false",
    matchIfMissing = true
)
public class mgcoa5530Controller {

    private final mgcoa5530Facade facade;

    @PostMapping("/mgcoa5530S0")
    public mgcoa5530S0DTOout mgcoa5530S0(
            @Valid @RequestBody mgcoa5530S0DTOin input
    ) throws Exception {
        return facade.mgcoa5530S0(input);
    }
}
```

## 4. Controller 계층 역할

```text
HTTP 요청
   │
   ▼
Controller
   │
   ├─ URL 매핑
   ├─ HTTP Method 매핑
   ├─ Request Body 수신
   ├─ 입력 DTO 변환
   ├─ 입력값 검증
   ├─ Facade 호출
   └─ 출력 DTO 반환
```

Controller가 담당하지 않아야 하는 일:

```text
Controller
   │
   ├─ X 업무 규칙 구현
   ├─ X DAO 직접 호출
   ├─ X SQL 실행
   ├─ X 여러 Service의 복잡한 조정
   ├─ X 수동 Commit / Rollback
   ├─ X 시스템 선후처리 복제
   └─ X 내부 예외를 클라이언트에 직접 노출
```

## 5. Controller와 Facade 관계

```text
Controller
   │
   │ HTTP 계약
   │
   ├─ URL
   ├─ Request
   └─ Response
   │
   ▼
Facade
   │
   │ 업무 유스케이스 경계
   │
   ├─ 트랜잭션
   ├─ DTO 변환
   ├─ Service 호출 조정
   └─ 예외 전파
```

역할 구분:

```text
┌────────────────┬──────────────────────────────────────────────┐
│ 계층           │ 주요 책임                                    │
├────────────────┼──────────────────────────────────────────────┤
│ Controller     │ HTTP 요청과 응답                              │
│ Handler        │ TCF Service ID 라우팅                         │
│ Facade         │ 업무 진입점과 트랜잭션 경계                   │
│ Service        │ 업무 처리 절차                                │
│ Rule           │ 업무 검증과 계산                              │
│ DAO / Mapper   │ 데이터베이스 접근                             │
└────────────────┴──────────────────────────────────────────────┘
```

## 6. Controller가 Service를 직접 호출하는 현재 호환 구조

일부 Controller는 현재 다음과 같은 구조를 사용합니다.

```text
Controller
   │
   ▼
Service
   │
   ▼
DAO → DB
```

예시:

```java
@PostMapping("/mgcoa5530S0")
public mgcoa5530S0DTOout mgcoa5530S0(
        @RequestBody mgcoa5530S0DTOin input
) throws Throwable {
    return mgcoa5530Service.mgcoa5530S0(input);
}
```

이 방식의 문제:

```text
Controller
   │
   ├─ Facade를 통과하지 않음
   ├─ Facade의 @Transactional 미적용
   ├─ 유스케이스 조정 경계 우회
   └─ TCF ON/OFF 실행 구조 불일치 가능
   │
   ▼
Service → DAO
```

권장 변경:

```text
변경 전

Controller → Service → DAO


변경 후

Controller → Facade(@Transactional) → Service → DAO
```

## 7. Controller에 `@Transactional`을 붙이는 경우

```text
Controller Proxy
   │
   ├────────────── TX BEGIN
   │
   ▼
Controller 메서드
   │
   ├─ 업무 선처리
   ├─ Service
   ├─ DAO / DB
   ├─ 업무 후처리
   └─ 응답 객체 생성
   │
   ├─ 정상: COMMIT
   └─ 예외: ROLLBACK
```

가능하지만 권장하지 않습니다.

```text
Controller 트랜잭션의 문제
├─ HTTP 계층과 DB 트랜잭션 결합
├─ 요청·응답 변환 시간까지 TX 점유
├─ 외부 호출까지 TX에 포함될 가능성
├─ TCF ON과 OFF의 TX 경계 불일치
├─ 업무 재사용 어려움
└─ Controller 테스트 복잡도 증가
```

권장 경계:

```text
Controller
   │
   ▼
Facade
   │
   ├────────── TX BEGIN
   ▼
Service → DAO
   │
   ├────────── COMMIT / ROLLBACK
   ▼
Controller
   │
   ▼
HTTP 응답
```

## 8. Controller 입력 DTO 처리

```text
HTTP JSON
   │
   ▼
Jackson ObjectMapper
   │
   ▼
@RequestBody
   │
   ▼
DTOin
   │
   ├─ 타입 변환
   ├─ 필수값 검증
   ├─ 길이 검증
   └─ 형식 검증
   │
   ▼
Controller
```

예시:

```text
POST /mgcoa5530S0
      │
      ▼
mgcoa5530S0DTOin
      │
      ├─ pageNo
      ├─ pageSize
      └─ 조회 조건
```

입력 오류:

```text
잘못된 JSON 또는 Validation 실패
        │
        ▼
Controller 호출 전 차단
        │
        ▼
GlobalExceptionHandler
        │
        ▼
HTTP 400 표준 오류 응답
```

## 10. 예외 처리 흐름

```text
Controller
   │
   ▼
Facade → Service → DAO
   │
   │ Exception 발생
   ▼
Facade TX ROLLBACK
   │
   ▼
Controller 밖으로 예외 전파
   │
   ▼
GlobalExceptionHandler
   │
   ├─ 예외 유형 판정
   ├─ exceptionCode.yml 조회
   ├─ 표준 오류 코드 설정
   ├─ 내부 오류 정보 숨김
   └─ HTTP Status 결정
   │
   ▼
표준 오류 응답
```

Controller에서 예외를 정상 결과로 바꾸면 안 됩니다.

```java
// 잘못된 예
try {
    return facade.execute(input);
} catch (Exception e) {
    return new OutputDTO();
}
```

이렇게 처리하면 트랜잭션이 정상 종료된 것으로 판단될 수 있습니다.

## 12. 최종 권장 Controller 아키텍처

```text
                    HTTP 요청
                        │
                        ▼
                  DefaultFilter
                        │
                        ▼
             ServicePreventionInterceptor
                        │
          ┌─────────────┴─────────────┐
          │                           │
          ▼                           ▼
      TCF ON                      TCF OFF
          │                           │
          ▼                           ▼
OnlineTransactionController    업무 Controller
          │                           │
          ▼                           │
TransactionDispatcher                 │
          │                           │
          ▼                           │
       Handler                        │
          │                           │
          └─────────────┬─────────────┘
                        ▼
              Business Facade
                        │
                 @Transactional
                        │
                        ▼
              Business Service
                        │
                        ▼
              Rule → DAO → DB
                        │
                        ▼
                 DTOout 반환
                        │
                        ▼
                표준 HTTP 응답
```

핵심 원칙은 다음과 같습니다.

```text
TCF ON
  → 공통 OnlineTransactionController 사용
  → 업무별 Handler에서 Facade 호출

TCF OFF
  → 업무별 Controller 사용
  → Controller에서 Facade 호출

공통
  → 트랜잭션은 Controller가 아닌 Facade에서 관리
```
