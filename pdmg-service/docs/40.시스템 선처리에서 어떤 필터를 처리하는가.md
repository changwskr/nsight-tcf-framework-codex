**로그의 `[시스템 선처리]`는 Servlet Filter가 아니라 `ServicePreventionInterceptor.preHandle`입니다.**
그 앞에서 `DefaultFilter`가 한 번 더 돕니다.

### 순서

```text
DefaultFilter          ← Servlet Filter (요청 준비)
  → ServicePreventionInterceptor.preHandle  ← 로그상 “시스템 선처리”
    → Controller / TCF …
```

### 1. Filter: `DefaultFilter`

설정: `nhnis.fw.commons.filter.enabled=true`

| 처리             | 내용                                       |
| ---------------- | ------------------------------------------ |
| Body 캐시        | `CachedBodyHttpServletRequest`             |
| JWT              | non-local에서 Bearer 검증                  |
| `hdr_nhnis`      | 파싱 / local이면 합성                      |
| `ServiceContext` | ThreadLocal 생성                           |
| MDC              | guid, userId, serviceId 등                 |
| 제외             | OPTIONS, GET, `/actuator`, `/.well-known/` |

### 2. 시스템 선처리: `ServicePreventionInterceptor`

설정: `nhnis.fw.commons.legacy-web.enabled=true`

| 처리           | 내용                   |
| -------------- | ---------------------- |
| GUID 보장      | 없으면 생성            |
| 헤더 보정      | serviceId, scid, IP 등 |
| 요청 전문 로그 | `[요청전문]`           |
| ImageLog PRE   | INSERT                 |

### 정리

- **Filter로 도는 것** → `DefaultFilter` 하나(PDMG commons 기준)
- **“시스템 선처리” 배너** → Interceptor (`ServicePreventionInterceptor`)
- 업무 선처리(`BizPrePostAspect`)는 그 다음입니다.

관련: [41.시스템 컨텍스트 정보는 어디서 생성되는가.md](./41.시스템%20컨텍스트%20정보는%20어디서%20생성되는가.md)

`ServiceContext`는 **`DefaultFilter`에서 생성**되어 `ServiceContextHolder`(ThreadLocal)에 넣습니다. 요청 종료 시 Filter `finally`에서 제거합니다.
