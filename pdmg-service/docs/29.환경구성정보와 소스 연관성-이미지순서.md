# PDMG 환경 구성정보와 소스 연관성

기준일: 2026-08-09  
대상: `pdmg-service`, `pdmg-fw`  
설명 순서: 사용자가 제공한 문서 목록 이미지의 `00 → 26` 순서

## 이 문서 읽는 방법

각 장은 다음 순서로 설명한다.

```text
설정 위치와 YAML 키
→ 설정을 읽는 Java 소스
→ 설정으로 생성되거나 활성화되는 Bean
→ 요청 처리 중 실행되는 위치
→ 값을 수정했을 때 달라지는 점
```

현재 대표 실행 설정은 다음과 같다.

```yaml
spring:
  profiles:
    active: local
  application:
    name: pdmg

nhnis:
  fw:
    tcf:
      enabled: true
    timeout:
      enabled: true
      milliseconds: 5000
      pool-size: 20
      queue-capacity: 100
    commons:
      legacy-web:
        enabled: true
      filter:
        enabled: true
```

> 주의: 현재 `pdmg-service`에는 기존 `nhnis.mg.*`와 신규 `nhnis.mg.co.a.*` 업무 Bean이 함께 존재한다. `PdmgApplication`이 `nhnis` 전체를 스캔하므로 동일 이름 Bean 충돌이 발생한다. 아래 업무 예시는 목표 구조로 보이는 `nhnis.mg.co.a.*`를 기준으로 설명한다.

## 00. BigPicture TX 흐름

### 설정

| YAML | 현재 값 | 의미 |
|---|---:|---|
| `nhnis.fw.tcf.enabled` | `true` | TCF 공통 Controller와 Dispatcher 사용 |
| `nhnis.fw.timeout.enabled` | `true` | Worker Thread와 외부 트랜잭션 사용 |
| `nhnis.fw.commons.filter.enabled` | `true` | 요청 Context와 JWT 처리 |
| `nhnis.fw.commons.legacy-web.enabled` | `true` | 시스템·업무 선후처리와 흐름 로그 활성 |

### 현재 실행 흐름

```text
DefaultFilter
→ ServicePreventionInterceptor.preHandle
→ OnlineTransactionController
→ TcfFacade
→ OnlineTimeoutExecutor
   → TransactionTemplate(rdwTransactionManager) TX 시작
   → TransactionDispatcher
   → Business Handler
   → Business Facade
   → BizPrePostAspect 업무 선처리
   → Service
   → DAO / Mapper
   → BizPrePostAspect 업무 후처리
   → Commit 또는 Rollback
→ ResponseBodyArgumentResolver
→ ServicePreventionInterceptor.afterCompletion
→ DefaultFilter 종료
```

핵심 소스:

- `pdmg-fw/.../commons/filter/DefaultFilter.java`
- `pdmg-fw/.../tcf/core/facade/TcfFacade.java`
- `pdmg-fw/.../tcf/timeout/DefaultOnlineTimeoutExecutor.java`
- `pdmg-service/.../co/a/config/RdwDataSourceConfig.java`

## 01. 트랜잭션 처리 변경

기존에는 업무 Facade의 `@Transactional`이 트랜잭션 경계였다. 타임아웃 기능이 활성화되면 `pdmg-fw`의 `TransactionTemplate`이 더 바깥에서 트랜잭션을 시작한다.

```text
timeout.enabled=false
Handler → Facade(@Transactional) → Service → DAO

timeout.enabled=true
OnlineTimeoutExecutor → TransactionTemplate TX
  → Handler → Facade(@Transactional REQUIRED, 기존 TX 참여)
  → Service → DAO
```

Facade 예시:

```java
@Transactional(
    transactionManager = "rdwTransactionManager",
    rollbackFor = Exception.class
)
public mgcoa9000C0DTOout mgcoa9000C0(Object dtoBody) throws Exception {
    return service.mgcoa9000C0(convert(dtoBody, mgcoa9000C0DTOin.class));
}
```

설정 변경 영향:

- `timeout.enabled=true`: 외부 공통 TX가 시작되고 Facade는 참여한다.
- `timeout.enabled=false`: `SyncOnlineTimeoutExecutor`를 사용하며 Facade TX만 남는다.

## 07. 도메인 정의 및 호출 방식

한 도메인의 Handler가 여러 거래를 등록한다.

```java
public Collection<String> serviceIds() {
    return List.of(
        "mgcoa9000S0",
        "mgcoa9000C0",
        "mgcoa9000U0",
        "mgcoa9000D0"
    );
}
```

`TransactionDispatcher`는 애플리케이션 시작 시 Handler 목록을 받아 `serviceId → Handler` Map을 구성한다. 동일 `serviceId`를 두 Handler가 등록하면 중복 오류 대상이다.

## 08. 대용량 페이징 처리 방식

페이징은 현재 YAML이 아니라 요청 DTO와 Service 코드로 관리한다.

```java
int pageNo = input.getPageNo() == null || input.getPageNo() <= 0
        ? 1 : input.getPageNo();
int pageSize = input.getPageSize() == null || input.getPageSize() <= 0
        ? 20 : input.getPageSize();
if (pageSize > 100) {
    pageSize = 100;
}
int offset = (pageNo - 1) * pageSize;
```

현재 기준:

| 항목 | 값 |
|---|---:|
| 기본 페이지 | 1 |
| 기본 크기 | 20 |
| 최대 크기 | 100 |

이 값을 환경화하려면 `pdmg.pagination.default-size`, `max-size` 같은 별도 Properties가 필요하지만 현재는 구현되어 있지 않다.

## 09. 서비스 ID

서비스 ID는 URL과 전문 Header에서 들어온다.

```text
POST /mgcoa9000S0
hdr_nhnis.sys_comm.rms_svc_c=mgcoa9000S0
```

`OnlineTransactionController.resolveServiceId()` 우선순위:

```text
ServiceContext Header
→ 요청 JSON Header
→ URL Path
```

URL과 Header가 모두 존재할 때 값이 다른 경우를 현재 코드가 거부하지 않으므로 일치 검증 보완이 필요하다.

주요 역할:

## 17. TCF - TcfFacade와 Dispatcher

`TcfFacade`는 타임아웃 실행기를 항상 호출한다.

```java
Object result = onlineTimeoutExecutor.execute(
    () -> dispatcher.dispatch(serviceId, dtoBody, context)
);
```

`timeout.enabled=true`이면 `DefaultOnlineTimeoutExecutor`, `false`이거나 누락되면 `SyncOnlineTimeoutExecutor` Bean이 주입된다. 따라서 `TcfFacade`는 설정 분기 코드를 직접 갖지 않는다.

## 20. 타임아웃

### YAML

```yaml
nhnis:
  fw:
    timeout:
      enabled: true
      milliseconds: 5000
      pool-size: 20
      queue-capacity: 100
```

### 설정값과 소스 연결

| YAML | Java 필드 | 실제 효과 |
|---|---|---|
| `enabled` | `OnlineTimeoutProperties.enabled` | Async/Sync Executor Bean 선택 |
| `milliseconds` | `milliseconds` | `Future.get()` 대기시간과 Deadline |
| `pool-size` | `poolSize` | Core/Max Worker 수 |
| `queue-capacity` | `queueCapacity` | 대기 큐 크기 |

### Bean 선택

```text
enabled=true
→ pdmgOnlineTimeoutTaskExecutor
→ DefaultOnlineTimeoutExecutor

enabled=false 또는 누락
→ SyncOnlineTimeoutExecutor
```

### 처리 원리

```text
요청 Thread: Future.get(5000ms)
Worker Thread: TransactionTemplate 시작
→ Dispatcher → Handler → Facade → Service → DAO
→ Deadline 재확인
→ 정상 Commit / 초과 Rollback
```

5초 초과 시 요청 Thread는 `future.cancel(true)`를 호출하고 `OnlineTimeoutException`을 발생시킨다. JDBC가 interrupt를 즉시 처리하지 않아도 Worker가 반환된 뒤 Deadline을 다시 검사하여 `rollbackOnly` 처리한다.

풀 20개와 큐 100개가 모두 차면 `OnlineOverloadException`으로 변환되어 HTTP 503을 반환한다.

설정 변경 예:

```yaml
# 10초로 변경
nhnis.fw.timeout.milliseconds: 10000

# 타임아웃 기능을 끄고 동기 실행
nhnis.fw.timeout.enabled: false
```

설정은 애플리케이션 시작 시 읽으므로 값을 바꾸면 재기동해야 한다.

## 21. 업무 선처리 - BizPrePostAspect

### 활성 조건

```yaml
nhnis.fw.commons.legacy-web.enabled: true
```

신규 구조의 Pointcut:

```java
@Pointcut(
    "execution(public * nhnis.mg.co.a.application.service..*(..))"
)
```

Facade의 외부 트랜잭션이 이미 시작된 뒤 Service 프록시에서 업무 선처리가 실행된다. 따라서 선처리에서 같은 `rdwDataSource` DAO를 호출하면 동일 트랜잭션에 참여한다.

## 22. Business Service

Service는 업무 흐름을 담당하며 환경 설정을 직접 읽지 않는 것이 원칙이다.

현재 예:

- 요청값 정규화
- 페이징 계산
- DAO 호출
- 결과 DTO 조립

타임아웃 설정은 Service에 복제하지 않고 `pdmg-fw`의 `OnlineTimeoutExecutor`가 공통 적용한다.

## 23. DAO

DAO는 MyBatis Mapper Interface다.

연결 설정:

## 24. DAO - Mapper

## 24. DAO - Namespace

Mapper XML의 namespace는 DAO 전체 클래스명과 같아야 한다.

```xml
<mapper namespace="nhnis.mg.co.a.persistence.dao.mgcoa9000DAO">
```

DAO 메서드와 Statement ID도 일치해야 한다.

```java
List<Map<String, Object>> mgcoa9000S0(Map<String, Object> param);
```

```xml
<select id="mgcoa9000S0" parameterType="map" resultType="map">
```

이 연결은 YAML이 아니라 MyBatis 규약으로 결정된다.

## 25. 업무 후처리 - BizPrePostAspect

`@AfterReturning`은 Service가 정상 반환한 경우에만 실행된다.

```text
Service 정상 반환
→ 업무 후처리
→ Facade 반환
→ TimeoutExecutor Deadline 검사
→ Commit
```

따라서 업무 후처리에서 같은 DataSource에 insert/update하고 예외를 밖으로 던지면 전체 업무가 Rollback된다.

주의사항:

- `@AfterReturning`은 Service 예외 시 실행되지 않는다.
- 예외까지 공통 처리하려면 `@AfterThrowing` 또는 `@Around`가 필요하다.
- Service를 여러 번 호출하면 선후처리도 여러 번 발생할 수 있다.

---

## 26. 시스템 후처리

주요 실행 소스:

- `ResponseBodyArgumentResolver.beforeBodyWrite()`
- `ServicePreventionInterceptor.postHandle()`
- `ServicePreventionInterceptor.afterCompletion()`
- `ImageLogHandler.postImagelog()`

실행 위치:

```text
업무 TX Commit/Rollback 완료
→ 응답 전문 조립
→ 시스템 후처리
→ 이미지 로그 응답 저장
→ Context 정리
```

시스템 후처리 DB 작업은 업무 트랜잭션에 포함되지 않는다. 감사 로그를 업무 성공·실패와 관계없이 남기는 목적에는 적합하다.

## 부록 C. 현재 점검 필요사항

1. 기존 `nhnis.mg.*`와 신규 `nhnis.mg.co.a.*` 중 공식 패키지를 하나로 확정해야 한다.
2. URL `serviceId`와 Header `rms_svc_c`가 다를 때 요청을 거부해야 한다.
3. `jwt.enabled`는 현재 `DefaultFilter`의 판단 기준이 아니며, Filter는 `local` 여부로 JWT 검증을 결정한다.
4. `pool-size=20`은 DB Connection Pool 최대 크기와 함께 조정해야 한다.
5. TimeoutExecutor의 트랜잭션은 Worker Thread에 있으므로 Context 전파 및 정리 테스트를 유지해야 한다.
