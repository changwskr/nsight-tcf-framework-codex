# 02. 애플리케이션 컴포넌트 구조 (PDMG)

기준일: 2026-08-09

관련: [MG-NAMING_CONVENTION.md](./MG-NAMING_CONVENTION.md) §4 · [네이밍원칙.md](./네이밍원칙.md) §4 · [01.트랜잭션처리 변경.md](./01.트랜잭션처리%20변경.md)

## 1. 목적

PDMG 업무 코드는 **컴포넌트 타입(역할)** 을 먼저 정하고, 그 역할을 **패키지**와 **클래스 이름**에 그대로 둔다.

| 질문 | 답 |
|------|----|
| 왜 컴포넌트를 나누는가? | 진입·TX·업무·영속을 분리해 의존·리뷰·트랜잭션 경계를 명확히 하기 위함 |
| 왜 Handler와 Facade를 나누는가? | TCF 라우팅(`entry`)과 DB TX 경계(`application`)를 분리하기 위함 |
| 왜 DTO를 `application` 밖인가? | 입출력 계약은 계층 공통 자산이기 때문 |

---

## 2. 컴포넌트 목록

| 컴포넌트 | 한 줄 정의 | 계층 | 패키지 (샘플 `co.a`) |
|----------|------------|------|----------------------|
| **Boot** | Spring Boot 진입 | 루트 | `nhnis.mg` |
| **Handler** | TCF ON `serviceId` 라우팅 | `entry` | `…entry.handler` |
| **Aspect** | 업무 선·후처리 / TX-FLOW | `entry` | `…entry.aspect` |
| **Controller** | TCF OFF HTTP 진입 | `application` | `…application.controller` |
| **Facade** | DTO 변환 + `@Transactional` + Service 호출 | `application` | `…application.facade` |
| **Service** | 업무 절차·검증·DAO 호출 | `application` | `…application.service` |
| **DTO** | 입출력 데이터 계약 | `dto` | `…dto` |
| **DAO** | MyBatis 영속 계약 | `persistence` | `…persistence.dao` |
| **Client** | 외부 WAS/API 호출 | `client` | `…client` |
| **Config** | DS·보안·Web 조립 | `config` | `…config` |
| **Support** | 업무 공통 유틸 | `support` | `…support` |
| **Mapper XML** | SQL 리소스 | (resources) | `rdw.mg.co.a/` |

FW 공통(컴포넌트는 아니지만 호출 경로에 포함):

| FW | 역할 |
|----|------|
| `OnlineTransactionController` | TCF ON 공통 HTTP (`POST /{serviceId}`) |
| `TcfFacade` / Dispatcher | Handler 탐색·호출 |
| `DefaultFilter` / `ServicePreventionInterceptor` | GUID·전문·ImageLog 시스템 선·후처리 |
| `GlobalExceptionHandler` | `NH_NIS_ERR_DTO` 실패 응답 |

## 3. 패키지 트리

```text
src/main/java/nhnis/mg
├── PdmgApplication.java              # Boot
├── ServletInitializer.java
└── co/a/                             # 업무=CO, 세부=A
    ├── entry/
    │   ├── handler/                  # Handler  ★ TCF ON 진입
    │   └── aspect/                   # Aspect   (BizPrePost, TX-FLOW)
    ├── application/
    │   ├── controller/               # Controller ★ TCF OFF 진입
    │   ├── facade/                   # Facade   ★ @Transactional
    │   └── service/                  # Service  ★ 업무 + Aspect 대상
    ├── dto/                          # DTOin / DTOout / Sub
    ├── persistence/
    │   └── dao/                      # DAO
    ├── client/
    ├── config/
    └── support/

src/main/resources/rdw.mg.co.a/
└── mgcoa[식별4]-ORA.xml              # Mapper XML
```

경로 규칙:

```text
nhnis.mg.[업무].[세부].[계층].[세부패키지]
```

다른 업무(예: IC+B)를 추가하면 `nhnis.mg.ic.b.*` / `rdw.mg.ic.b/` 아래에 동일 컴포넌트 트리를 둔다.

## 4. 컴포넌트별 책임

### 4.1 Handler (`entry.handler`)

- `TransactionHandler` 구현. `serviceIds()`로 담당 `serviceId` 등록.
- `handle`에서 Facade 메서드만 호출한다.
- **하지 않음**: `@Transactional`, SQL, 업무 검증, DTO 필드 조립.

```text
mgcoa8888Handler
  → facade.mgcoa8888S0 / mgcoa8888D0
```

### 4.2 Aspect (`entry.aspect`)

- Pointcut: `nhnis.mg.co.a.application.service..*`
- Facade TX **안**에서 Service 전후 실행 (`BizPrePostAspect`).
- **하지 않음**: 업무 분기, commit/rollback 결정.

### 4.3 Facade (`application.facade`)

- Object/`dto` → `*DTOin` 변환.
- **`@Transactional(rdwTransactionManager, …)`** — 업무 TX 참여(REQUIRED). 공통 timeout ON이면 Executor가 외부 BEGIN.
- Service 호출 후 `*DTOout` 반환.
- **하지 않음**: SQL 직접 실행, MyBatis 호출.

| 유형 | 선언 예 |
|------|---------|
| 조회 | `readOnly = true` |
| 쓰기 | `rollbackFor = Exception.class` |
| 공통 SLA | `OnlineTimeoutExecutor` (`nhnis.fw.timeout`) — Facade `timeout`은 보조·보통 미사용 |

→ [20.타임아웃.md](./20.타임아웃.md)

### 4.4 Service (`application.service`)

- 검증, 페이징, 업무 규칙, DAO 호출.
- Aspect 대상. **기본으로 TX 미보유** (Facade TX 안에서 실행).
- **하지 않음**: HTTP 매핑, Handler 라우팅.

### 4.5 Controller (`application.controller`)

- TCF OFF(`nhnis.fw.tcf.enabled=false`) 호환 HTTP 진입.
- `@PostMapping("/서비스ID")` → Service(또는 Facade) 호출.
- TCF ON에서는 비활성(또는 미사용). 신규 온라인 거래는 Handler+Facade를 우선한다.

### 4.6 DTO (`dto`)

- `*DTOin` / `*DTOout` / `*DTOSub0` — 필드만. 서비스 ID(구분자 포함)를 이름에 넣는다.
- **하지 않음**: Bean 주입, SQL, 트랜잭션.

### 4.7 DAO (`persistence.dao`) + Mapper XML

- DAO 메서드명 = MyBatis statement id = SQL ID (`mgcoa8888S0_S0` 등).
- `namespace` = DAO FQCN.
- **하지 않음**: 업무 판단, HTTP 응답 조립.

### 4.8 Config / Client / Support

| 컴포넌트 | 책임 |
|----------|------|
| Config | `RdwDataSourceConfig`, `SecurityConfig`, `MybatisLogInterceptor` 등 |
| Client | 외부 연동 (현재 package-info 수준) |
| Support | 순수 유틸 (현재 package-info 수준) |

## 5. 호출 흐름

### 5.1 TCF ON (기본)

```text
Filter / ServicePreventionInterceptor (pdmg-fw)
  → OnlineTransactionController
    → TcfFacade → Handler (entry.handler)
      → Facade (application.facade, @Transactional)
        → [BizPrePostAspect] Service (application.service)
          → DAO → Mapper XML (rdw.mg.co.a)
```

### 5.2 TCF OFF (호환)

```text
ServicePreventionInterceptor
  → Controller (application.controller)
    → Service → DAO → Mapper XML
```

(일관된 TX·선후처리를 원하면 Controller → Facade → Service 가 더 맞다.)

---

## 6. 의존 방향

```text
entry.handler ──────────────► application.facade
application.controller ─────► application.service   (TCF OFF)
application.facade ─────────► application.service
application.service ────────► persistence.dao , dto
persistence.dao ────────────► (MyBatis XML)
entry.aspect ───────────────► (pointcut) application.service
```

**금지**

| 금지 | 이유 |
|------|------|
| Handler → Service / DAO 직호출 | TX·선후처리 우회 |
| Service → Handler / Controller | 계층 역전 |
| DTO → Service / DAO 주입 | 계약 계층 오염 |
| DAO → 업무 판단·HTTP 조립 | 영속 책임 위반 |
| Facade 없이 Service에만 TX (기본) | Aspect와 TX 경계가 어긋날 수 있음 |

## 7. 프로그램 단위 파일 세트

식별번호가 같으면 Handler/Facade/Controller/Service/DAO 접두는 같고, **구분자(S/C/U/D)는 DTO·URL·SQL에만** 붙인다.

예: `mgcoa8888`

| 컴포넌트 | 파일 |
|----------|------|
| Handler | `entry/handler/mgcoa8888Handler.java` |
| Facade | `application/facade/mgcoa8888Facade.java` |
| Service | `application/service/mgcoa8888Service.java` |
| Controller | `application/controller/mgcoa8888Controller.java` (TCF OFF) |
| DAO | `persistence/dao/mgcoa8888DAO.java` |
| DTO | `dto/mgcoa8888S0DTOin.java` … |
| Mapper | `rdw.mg.co.a/mgcoa8888-ORA.xml` |

```text
서비스 ID: mgcoa8888S0, mgcoa8888D0
  → 클래스 접두: mgcoa8888*
  → URL / DTO / SQL ID: 서비스 ID 전체 사용
```

---

## 8. 신규 거래 추가 체크리스트

1. 서비스 ID·식별번호·구분자 확정 (`MG-NAMING` §3)
2. DTO (`dto`) → DAO + Mapper XML → Service → Facade → Handler
3. Facade에 `@Transactional(rdwTransactionManager, …)` 선언
4. (필요 시) TCF OFF용 Controller
5. Handler가 `serviceIds()`에 ID 등록했는지 확인
6. Pointcut·`@MapperScan` 패키지가 `nhnis.mg.co.a` 축과 일치하는지 확인
