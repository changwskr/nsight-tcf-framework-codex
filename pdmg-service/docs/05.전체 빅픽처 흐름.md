## 1. 목적

한 온라인 거래가 **브라우저에서 DB까지** 어떻게 흘러가는지 전체를 한 장에 둔다.  
세부 책임·패키지·TX 규칙은 01~04를 보고, 본 문서는 **순서와 경계**만 잡는다.

| 구분 | 포트(로컬 예) | 역할 |
|------|---------------|------|
| `pdmg-ui` | :8090 | 화면 · 브라우저 직접 호출용 대상 URL/샘플 제공 |
| `pdmg-service` + `pdmg-fw` | :8080 | 온라인 거래 처리 · DB |

전문 봉투: `{ hdr_nhnis, dto }`  
식별: `serviceId` (예: `mgcoa8888S0`) = URL path = Handler 라우팅 키

## 2. 빅픽처 (TCF ON — 기본)

```text
[브라우저]
    │  화면 호출
    ▼
[pdmg-ui :8090 브라우저]
    │  POST http://localhost:8080/{serviceId}
    │  body: { hdr_nhnis, dto } · CORS
    ▼
╔══════════════════════════════════════════════════════════════╗
║ pdmg-service (:8080) + pdmg-fw                               ║
║                                                              ║
║  ┌─ 시스템 구간 (업무 TX 밖) ─────────────────────────────┐  ║
║  │ ① DefaultFilter                                        │  ║
║  │    Body 캐시 · ServiceContext · GUID                   │  ║
║  │ ② ServicePreventionInterceptor                         │  ║
║  │    요청전문 로그 · ImageLog INSERT                     │  ║
║  │ ③ OnlineTransactionController  POST /{serviceId}       │  ║
║  │ ④ TcfFacade → OnlineTimeoutExecutor → Dispatcher       │  ║
║  │    (공통 timeout: nhnis.fw.timeout, 기본 5000ms)       │  ║
║  └────────────────────────────────────────────────────────┘  ║
║                         │ Worker Thread                      ║
║  ┌─ Entry (Executor TX 안) ───────────────────────────────┐  ║
║  │ ⑤ Handler (nhnis.mg.co.a.entry.handler)                │  ║
║  │    serviceId → Facade 메서드 라우팅만                  │  ║
║  └────────────────────────┬───────────────────────────────┘  ║
║                           ▼                                  ║
║  ┌─ Application ★ DB TX (Executor BEGIN) ─────────────────┐  ║
║  │ ⑥ Facade (@Transactional REQUIRED / rdw)               │  ║
║  │        ⑦ [BizPrePostAspect] 업무 선처리 (Service 전)   │  ║
║  │        ⑧ Service — 검증·절차                           │  ║
║  │        ⑨ DAO → MyBatis (rdw.mg.co.a) → DB              │  ║
║  │        ⑩ [BizPrePostAspect] 업무 후처리                │  ║
║  │      Deadline 재검사 → COMMIT / ROLLBACK               │  ║
║  └────────────────────────────────────────────────────────┘  ║
║  (timeout → 요청 Thread 504 FW_TIMEOUT)                      ║
║                         │                                    ║
║  ┌─ 시스템 구간 (업무 TX 밖) ─────────────────────────────┐  ║
║  │ ⑪ ResponseBodyAdvice — 성공 dto / 실패 result 응답     │  ║
║  │ ⑫ afterCompletion — ImageLog UPDATE                    │  ║
║  └────────────────────────────────────────────────────────┘  ║
╚══════════════════════════════════════════════════════════════╝
    │
    ▼
[브라우저]  성공 dto / 실패 result(NH_NIS_ERR_DTO)
```

한 줄 요약:

```text
UI 브라우저 직접 POST
 → CORS → Filter → 시스템선처리 → OnlineController → TcfFacade
 → OnlineTimeoutExecutor(Worker+TX) → Handler → Facade(REQUIRED)
 → [업무선] Service → DAO → [업무후]
 → 시스템후처리 → ImageLog
```

공통 타임아웃: [20.타임아웃.md](./20.타임아웃.md)

## 3. 구간별 경계

| 구간 | 담당 | DB TX | 비고 |
|------|------|-------|------|
| UI 중계 | pdmg-ui | — | 업무·SQL 없음 |
| Filter / Interceptor | pdmg-fw | 밖 | GUID, ImageLog 선처리 |
| OnlineController / TcfFacade | pdmg-fw | 밖(요청 Thread) | serviceId · TimeoutExecutor 위임 |
| OnlineTimeoutExecutor | pdmg-fw | **Worker에서 BEGIN** | 공통 SLA · [20.타임아웃](./20.타임아웃.md) |
| Handler | entry | 안 | 라우팅만 |
| **Facade** | application | **안 (REQUIRED)** | 같은 TX 참여 |
| Aspect 선·후 | entry.aspect | TX 안 | Service Pointcut |
| Service / DAO | application / persistence | TX 안 | 업무·SQL |
| 응답 Advice / ImageLog 후 | pdmg-fw | 밖 | 봉투·감사 |

**핵심:** ImageLog·시스템 선후처리는 업무 commit/rollback과 분리된다.

## 4. 성공 시퀀스 (개념)

```text
1. UI가 serviceId·전문 전달
2. FW가 GUID·Context·ImageLog(요청) 기록
3. Handler가 Facade.mgcoaXXXX**(dtoBody) 호출
4. Facade: Object → DTOin 변환 후 TX 시작
5. Service 진입 직전 업무 선처리 로그
6. Service → DAO → SQL 실행
7. Service 반환 후 업무 후처리
8. Facade 반환 → TX commit
9. FW가 응답 봉투 조립·ImageLog(응답) 갱신
10. UI가 화면 반영
```

## 5. 실패 시퀀스 (개념)

```text
Service/Facade에서 BizException 또는 시스템 예외
    │
    ├─ 쓰기 Facade면 → Spring TX ROLLBACK
    │
    ▼
GlobalExceptionHandler (pdmg-fw)
    │  NH_NIS_ERR_DTO (stdErrCode, stdErrMsgCntn, errType)
    ▼
시스템 후처리·ImageLog (가능 범위에서 실패 기록)
    ▼
UI 에러 표시
```

Handler 미매칭 → `ServiceHandlerNotFound` → 동일 핸들러 경로.  
상세: [에러처리.md](./에러처리.md)

## 6. TCF OFF (호환 경로)

`nhnis.fw.tcf.enabled=false` 일 때:

```text
Filter / Interceptor
  → application.controller.*Controller   ← 거래별 HTTP 진입
    → Service (또는 Facade)
      → DAO → DB
  → 시스템 후처리
```

- Handler / OnlineTransactionController 경로를 쓰지 않는다.
- 현재 샘플 Controller는 Service 직호출인 경우가 많다.
- TX·업무 선후처리를 TCF ON과 맞추려면 **Controller → Facade → Service** 가 더 일관적이다.

## 8. 예시: `POST /mgcoa8888S0`

| 단계 | 클래스·위치 |
|------|-------------|
| UI 직접 호출(현행) | `http://localhost:8080/mgcoa8888S0` |
| UI relay(호환) | `/api/relay/mgcoa8888S0` |
| HTTP | `POST /mgcoa8888S0` |
| Handler | `entry.handler.mgcoa8888Handler` |
| Facade | `application.facade.mgcoa8888Facade.mgcoa8888S0` (`readOnly`) |
| Aspect | `BizPrePostAspect` → `mgcoa8888Service.mgcoa8888S0` |
| Service | `application.service.mgcoa8888Service` |
| DAO/SQL | `persistence.dao.mgcoa8888DAO` / `mgcoa8888S0_S0` |
| DTO | `dto.mgcoa8888S0DTOin` → `…DTOout` |

쓰기 예(`mgcoa8888D0`): 같은 Handler·Facade·Service 체인, Facade에 `rollbackFor = Exception.class`.

## 9. 두 가지 “트랜잭션” (혼동 금지)

| 말 | 의미 | 어디 |
|----|------|------|
| **온라인 거래(요청) 흐름** | Filter~ImageLog까지 한 요청의 라이프사이클 | pdmg-fw + Handler |
| **DB 트랜잭션** | commit / rollback | **Facade `@Transactional`** |

과거 `@TcfTransaction` / STF·ETF 와 섞어 읽지 않는다. → [tcf.md](./tcf.md)

## 11. 기억할 세 줄

1. **진입:** UI → FW → Handler (TCF ON)  
2. **업무+TX:** Facade 안에서 Service → DAO  
3. **시스템 감사:** ImageLog·Filter는 업무 TX 밖
