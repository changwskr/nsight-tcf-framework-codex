```text

    ├─ rdwSqlSessionFactory
    └─ rdwTransactionManager

동일 DataSource
└─ 같은 트랜잭션 참여
```

## 3. `@Transactional` 처리

```text
TransactionHandler 또는 Controller
          │
          ▼
Business Facade Spring Proxy
          │
          ├─ @Transactional 발견
          │
          ├─ transactionManager 이름 확인
          │      └─ rdwTransactionManager
          │
          ▼
TransactionInterceptor
          │
          ▼
rdwTransactionManager
          │
          ├─ DataSource에서 Connection 획득
          ├─ autoCommit=false 설정
          ├─ TransactionSynchronizationManager 등록
          └─ 현재 Thread에 Connection 바인딩
          │
          ▼
실제 Business Facade 메서드 실행
```

선언 예:

```java
@Transactional(
    transactionManager = "rdwTransactionManager",
    rollbackFor = Exception.class
)
public OutputDTO execute(Object dtoBody) throws Exception {
    return service.execute(dtoBody);
}
```

## 4. 정상 Commit

```text
Facade Proxy
   │
   ▼
rdwTransactionManager
   │
   ├─ Connection 획득
   ├─ autoCommit=false
   └─ TX BEGIN
   │
   ▼
Business Facade
   │
   ▼
Service
   │
   ├─ DAO INSERT
   ├─ DAO UPDATE
   └─ DAO DELETE
   │
   ▼
Facade 정상 반환
   │
   ▼
TransactionInterceptor
   │
   ▼
rdwTransactionManager
   │
   ├─ Connection.commit()
   ├─ Thread 바인딩 해제
   ├─ Connection 상태 복구
   └─ Connection Pool 반환
```

## 5. Rollback

```text
Facade TX BEGIN
   │
   ▼
Service
   │
   ├─ DAO INSERT 성공
   ├─ DAO UPDATE 성공
   └─ 다음 DAO에서 Exception 발생
          │
          ▼
      Exception 외부 전파
          │
          ▼
TransactionInterceptor
          │
          ├─ rollbackFor 정책 확인
          └─ Rollback 대상 판정
          │
          ▼
rdwTransactionManager
          │
          ├─ Connection.rollback()
          ├─ INSERT 취소
          ├─ UPDATE 취소
          ├─ Thread 바인딩 해제
          └─ Connection Pool 반환
```

`rollbackFor = Exception.class`이면 Checked Exception도 롤백 대상입니다.

## 6. Thread와 Connection 관계

```text
HTTP 요청 Thread-1
│
├─ Facade TX BEGIN
├─ RDW Connection-A 바인딩
│
├─ Service
│   ├─ DAO-1 → Connection-A
│   ├─ DAO-2 → Connection-A
│   └─ DAO-3 → Connection-A
│
└─ COMMIT / ROLLBACK
    └─ Connection-A 반환
```

동시에 다른 요청이 들어오면:

```text
HTTP Thread-1
└─ Transaction-1
   └─ Connection-A

HTTP Thread-2
└─ Transaction-2
   └─ Connection-B
```

각 Thread가 독립적인 트랜잭션과 Connection을 사용합니다.

## 7. MyBatis와 Transaction Manager 관계

```text
Business Service
      │
      ▼
mgcoa8888DAO
      │
      ▼
MyBatis Mapper Proxy
      │
      ▼
SqlSessionTemplate
      │
      ▼
현재 Thread에 TX Connection이 있는가?
      │
      ├─ 있음
      │    └─ 기존 Connection 사용
      │
      └─ 없음
           └─ 새로운 SqlSession/Connection 사용
      │
      ▼
Mapper XML
      │
      ▼
SQL 실행
```

Facade 트랜잭션 내부:

```text
Facade TX
   ├─ DAO SELECT ─┐
   ├─ DAO INSERT ─┼─ 동일 Connection
   └─ DAO UPDATE ─┘
```

Facade 트랜잭션 외부:

```text
Controller → Service → DAO
                      │
                      └─ 명시적인 상위 TX가 없을 수 있음
```

## 10. 업무 선후처리 관계

```text
Business Facade Proxy
   │
   ├════════════ TX BEGIN ════════════╗
   ║                                 ║
   ║ BizPrePostAspect                ║
   ║   ├─ 업무 선처리                ║
   ║   │                             ║
   ║   ├─ Service                    ║
   ║   │    └─ DAO / DB              ║
   ║   │                             ║
   ║   └─ 업무 후처리                ║
   ║                                 ║
   ║ COMMIT 또는 ROLLBACK            ║
   ╚═════════════════════════════════╝
```

Service 포인트컷에서 선후처리가 실행되면 Facade가 시작한 트랜잭션에 참여합니다.

## 11. 전파 속성

### REQUIRED

```text
호출 시 기존 트랜잭션 있음
└─ 기존 트랜잭션에 참여

호출 시 기존 트랜잭션 없음
└─ 새로운 트랜잭션 시작
```

```text
Facade TX
   └─ Service REQUIRED
       └─ 동일 TX 참여
```

### REQUIRES_NEW

```text
기존 업무 TX
   │
   ├─ 일시 중지
   ▼
신규 TX 시작
   │
   ├─ 별도 COMMIT
   └─ 별도 ROLLBACK
   │
   ▼
기존 업무 TX 재개
```

오류 이력을 독립적으로 저장할 때 사용할 수 있습니다.

```text
본 업무 TX      → ROLLBACK
오류 이력 TX    → COMMIT
```

### MANDATORY

```text
상위 트랜잭션 있음
└─ 상위 TX 참여

상위 트랜잭션 없음
└─ 예외 발생
```

## 12. 여러 Transaction Manager

```text
애플리케이션
│
├─ rdwTransactionManager
│   └─ RDW DataSource
│
├─ logTransactionManager
│   └─ 로그 DataSource
│
└─ otherTransactionManager
    └─ 기타 DataSource
```

명시적 선택:

```java
@Transactional(
    transactionManager = "rdwTransactionManager"
)
```

다른 Transaction Manager가 관리하는 DAO는 자동으로 같은 트랜잭션에 포함되지 않습니다.

```text
Facade
└─ rdwTransactionManager
   ├─ RDW DAO       : 동일 TX
   └─ Log DB DAO    : 동일 TX 아님
```

## 13. 다중 DataSource

```text
Facade
   │
   ├─ RDW DAO
   │    └─ RDW DB UPDATE
   │
   └─ LOG DAO
        └─ LOG DB INSERT
```

각각 별도 Transaction Manager라면:

```text
RDW DB COMMIT 성공
LOG DB COMMIT 실패
        │
        ▼
두 DB의 상태가 서로 달라질 수 있음
```

원자성이 필요하면 다음 중 하나가 필요합니다.

```text
· XA/JTA 분산 트랜잭션
· Outbox Pattern
· Saga 또는 보상 트랜잭션
· 하나의 DB 트랜잭션으로 저장구조 통합
```

## 14. 이미지로그와 Transaction Manager

```text
Interceptor.preHandle
   │
   └─ ImageLog INSERT
       └─ 별도 TX 또는 Auto-commit
   │
   ▼
Business Facade
   │
   └─ rdwTransactionManager 업무 TX
   │
   ▼
Interceptor.afterCompletion
   │
   └─ ImageLog UPDATE
       └─ 별도 TX 또는 Auto-commit
```

즉 GUID는 같아도 트랜잭션은 다를 수 있습니다.

```text
GUID-A
├─ ImageLog INSERT : TX-1
├─ 업무 처리       : TX-2
└─ ImageLog UPDATE : TX-3
```

## 15. Transaction Manager와 타임아웃

### Spring 트랜잭션 타임아웃

```java
@Transactional(
    transactionManager = "rdwTransactionManager",
    timeout = 10,
    rollbackFor = Exception.class
)
```

```text
TX BEGIN
   │
   ├─ 제한시간 10초
   ▼
DAO / SQL
   │
   ├─ 제한시간 이내
   │    └─ COMMIT
   │
   └─ 제한시간 초과
        ├─ TransactionTimedOutException
        └─ ROLLBACK
```

### TimeoutExecutor와 연계

```text
Facade TX BEGIN
   │
   ▼
TimeoutExecutor
   │
   ▼
Service / DAO
   │
   ├─ 제한시간 초과
   ├─ 작업 취소 요청
   └─ OnlineTimeoutException
   │
   ▼
TransactionInterceptor
   │
   └─ ROLLBACK
```

별도 Thread에서 트랜잭션을 시작한다면 트랜잭션 경계도 그 작업 Thread 안에 있어야 합니다.

```text
잘못된 구조

요청 Thread : TX BEGIN
작업 Thread : Service / DAO
             └─ 요청 Thread의 TX에 참여하지 않음
```

```text
필요한 구조

작업 Thread
├─ TX BEGIN
├─ Service / DAO
└─ COMMIT / ROLLBACK
```

## 16. 자기 호출 문제

```text
외부 호출
   │
   ▼
Spring Proxy
   │
   └─ @Transactional 적용
```

하지만:

```text
같은 Bean
methodA()
   │
   └─ this.methodB()
       └─ Proxy를 통하지 않음
          └─ methodB의 별도 TX 속성 미적용
```

별도 트랜잭션이 필요하면 다른 Spring Bean으로 분리해야 합니다.

## 17. Transaction Manager가 담당하지 않는 것

```text
rdwTransactionManager
│
├─ 담당
│   ├─ Connection 획득
│   ├─ Thread 바인딩
│   ├─ Commit
│   ├─ Rollback
│   ├─ 트랜잭션 상태
│   └─ 트랜잭션 자원 정리
│
└─ 담당하지 않음
    ├─ Service ID 라우팅
    ├─ 업무 선후처리 내용
    ├─ 업무 규칙 판단
    ├─ SQL 생성
    ├─ HTTP 오류 응답
    └─ JWT 검증
```

## 18. 최종 구조

```text
RdwDataSourceConfig
   │
   ├─ RDW DataSource
   │      ├─ SqlSessionFactory
   │      └─ SqlSessionTemplate
   │
   └─ rdwTransactionManager
          │
          ▼
Business Facade Spring Proxy
          │
          ├─ @Transactional 확인
          ├─ Connection 획득
          ├─ TX BEGIN
          │
          ▼
Business Facade
          │
          ▼
BizPre → Service → Rule → DAO → Mapper → DB → BizPost
          │
          ├─ 정상 반환
          │      └─ COMMIT
          │
          └─ 예외 전파
                 └─ ROLLBACK
          │
          ▼
Connection 해제 및 Pool 반환
```

한 줄로 표현하면 다음과 같습니다.

```text
@Transactional
 → TransactionInterceptor
 → rdwTransactionManager
 → RDW Connection을 현재 Thread에 바인딩
 → Service·DAO가 같은 Connection 사용
 → 정상 COMMIT / 예외 ROLLBACK
 → Connection 반환
```
