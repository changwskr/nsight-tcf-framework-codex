# 시스템 컨텍스트(ServiceContext) 정보는 어디서 생성되는가

**생성 위치:** `pdmg-fw`의 `DefaultFilter`  
**보관:** `ServiceContextHolder` (ThreadLocal)

---

## 1. 생성 시점

```text
HTTP 요청
  → DefaultFilter.doFilterInternal
       → new ServiceContext(...)
       → ServiceContextHolder.setInstance(serviceContext)
  → ServicePreventionInterceptor (시스템 선처리, Context 사용/보정)
  → Controller / TCF …
  → DefaultFilter finally
       → ServiceContextHolder.removeInstance()
```

활성 조건:

```yaml
nhnis:
  fw:
    commons:
      filter:
        enabled: true
```

소스:

- `nhnis.fw.commons.filter.DefaultFilter`
- `nhnis.fw.commons.context.ServiceContext`
- `nhnis.fw.commons.context.ServiceContextHolder`

---

## 2. 생성 시 담는 정보

`new ServiceContext(applicationName, guid, active, requestHeaders, request, response, header)`

| 필드 | 내용 |
|------|------|
| `applicationName` | `spring.application.name` |
| `guid` | `hdr_nhnis.sys_comm.std_gbl_id` (없으면 이후 Interceptor에서 채번 가능) |
| `active` | `spring.profiles.active` |
| `requestHeaders` | HTTP 헤더 |
| `httpServletRequest` / `Response` | 요청·응답 객체 |
| `header` | 파싱(또는 local 합성)한 `hdr_nhnis` |
| `requestBody` | (이후) 캐시한 요청 전문 원문 |

JSON Body 경로에서는 Body 파싱 후 `hdr_nhnis`를 만들고 Context를 set 한다.  
multipart는 GUID 헤더 중심으로 단순 Context를 만든다.

---

## 3. 생성되지 않는 경우

`DefaultFilter.shouldNotFilter` 에 해당하면 Filter(및 Context 생성)를 **건너뛴다**.

- `OPTIONS` (CORS preflight)
- `GET` (JWKS 등)
- `/actuator/**`
- `/.well-known/**`

이 경우 Interceptor에서 `Service Context is null...!! (continue)` WARN이 날 수 있다.

---

## 4. 이후 단계와의 관계

| 단계 | Context 역할 |
|------|----------------|
| `DefaultFilter` | **생성** + ThreadLocal 보관 |
| `ServicePreventionInterceptor` | GUID/헤더 **보정**, 요청전문·ImageLog에 사용 |
| `ResponseBodyArgumentResolver` | 응답 조립 시 header/responseBody 사용 |
| `DefaultFilter` finally | **제거** (`removeInstance`) |

타임아웃 ON 시 Worker로 넘길 때 `OnlineTimeoutWorkerContext`가 요청 스레드의 `ServiceContext`를 캡처·복원한다.

---

## 5. 조회 방법

```java
ServiceContext ctx = ServiceContextHolder.getInstance();
```
