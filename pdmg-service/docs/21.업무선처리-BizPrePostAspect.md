# 21. 업무 선·후처리 — BizPrePostAspect (PDMG)

기준일: 2026-08-09  
대상: `nhnis.mg.co.a.entry.aspect.BizPrePostAspect`  
관련: [20.Tranaactional-rdwTransactionManager-Begin.md](./20.Tranaactional-rdwTransactionManager-Begin.md) · [22.Business-Service.md](./22.Business-Service.md) · [25.업무후처리-BizPrePostAspect.md](./25.업무후처리-BizPrePostAspect.md) · [14.시스템 선후처리.md](./14.시스템%20선후처리.md) · [01.트랜잭션처리 변경.md](./01.트랜잭션처리%20변경.md)

> 파일명은 「선처리」만 있으나, Aspect는 **선처리 + 후처리**를 함께 수행한다.  
> 후처리 구간만: [25.업무후처리-BizPrePostAspect.md](./25.업무후처리-BizPrePostAspect.md).

---

## 1. 역할

업무 **Service public 메서드** 전후에 공통 로그·추적을 남기는 AOP다.  
DB BEGIN은 Facade([20](./20.Tranaactional-rdwTransactionManager-Begin.md))가 열고, 이 Aspect는 그 **TX 안**에서 Service 경계를 감싼다.

```text
Facade (@Transactional 이미 BEGIN)
  → [BizPrePost @Before]  업무 선처리     ★
  → Service 본문 → DAO/SQL
  → [BizPrePost @AfterReturning] 업무 후처리  ★
→ Facade return → COMMIT
```

| 한다 | 하지 않는다 |
|------|-------------|
| 선/후 구간 로그 (`PdmgTxLog`) | `@Transactional` / SQL |
| GUID·서비스ID·호출 메서드·BRC 진행 로그 | 시스템 ImageLog INSERT/UPDATE |
| 정상 반환 시 응답 DTO 업무 메시지 로그 | serviceId 라우팅 |
| TCF ON/OFF 모두 Service 경계 통일 | 예외 시 후처리(아래 §5) |

---

## 2. 시스템 선후 vs 업무 선후

| | **시스템** | **업무 (이 문서)** |
|--|-----------|-------------------|
| 주체 | Filter · `ServicePreventionInterceptor` · Advice | `BizPrePostAspect` |
| 시점 | Controller 전 / 응답 조립 후 | **Service** 전후 |
| DB TX | 업무 Facade TX **밖** | 업무 Facade TX **안** |
| 예 | 요청전문, ImageLog | `[업무 선처리]`, 업무 DTO 로그 |

이름이 비슷해도 **계층이 다르다** ([14](./14.시스템%20선후처리.md)).

## 3. 위치 · 활성 조건

| 항목 | 값 |
|------|-----|
| 패키지 | `nhnis.mg.co.a.entry.aspect` |
| 클래스 | `BizPrePostAspect` |
| `@Order` | `100` |
| 활성 | `nhnis.fw.commons.legacy-web.enabled=true` (기본 `matchIfMissing = true`) |

같은 패키지 `PdmgBizTxFlowAspect`(`@Order(50)`)는 Handler~DAO **시작·종료 TX-FLOW** 로그용이다.  
Service에서는 Order 50이 바깥, BizPrePost(100)가 안쪽에 가깝게 감싼다.

## 4. Pointcut — 왜 Service인가

```java
@Pointcut("execution(public * nhnis.mg.co.a.application.service..*(..))")
public void mgBizBoundary() { }
```

| Pointcut을 Facade에 두면 | Service에 두면 (현재) |
|--------------------------|----------------------|
| DTO 변환 실패도 “선처리”에 섞임 | 변환 후 **실제 업무 메서드**만 |
| TX와 선후 경계가 한 메서드에 뭉침 | TX=Facade, 선후=Service로 분리 |
| TCF OFF(Controller→Service)와 불일치 | ON/OFF 모두 Service에서 동일 |

원칙: **`@Transactional` = Facade**, **업무 선후 = Service** ([01](./01.트랜잭션처리%20변경.md)).

---

## 5. `@Before` / `@AfterReturning`

### 5.1 선처리 (`before`)

```text
PdmgTxLog.bizPreStart()
  GUID / 서비스(rms_svc_c) / 호출(Service.method) / BRC
PdmgTxLog.bizPreEnd()
PdmgTxLog.bizProcessStart()   ← 이어서 Service 본문
```

- `ServiceContextHolder`에서 GUID·헤더 서비스 코드
- 인자 DTO에서 `getTrtBrc` / `getBrc` / `getBRC` / `getL5104` 반사 조회 (있으면)

### 5.2 후처리 (`after` — **정상 반환만**)

```text
PdmgTxLog.bizProcessEnd()
PdmgTxLog.bizPostStart()
  업무 응답 메시지 + PdmgMessagePrinter.businessDto(result)
PdmgTxLog.bizPostEnd()
```

`@AfterReturning` 이므로 **예외가 나면 업무 후처리 블록은 실행되지 않는다**.  
예외는 Facade TX rollback + `GlobalExceptionHandler` 경로 ([11](./11.예외처리.md)).

Facade에서 `convert`만 실패하고 Service에 도달하지 않으면 **선처리도 없다**.

## 6. 로그에서 보이는 위치

운영에서 `%C.%M`이 Aspect로 찍히도록 `log.info`는 **이 클래스에서 직접** 호출한다.

확인 예:

```text
[업무 선처리] … 호출: mgcoa5530Service.mgcoa5530S0
[업무처리] …
[업무 후처리] … (응답 DTO)
```

(정확한 문자열은 `PdmgTxLog` 구현.)

---

## 7. 호출 스택에서의 자리

```text
Handler
  → Facade 프록시          ★ BEGIN
       convert(dto → DTOin)
       → Service 프록시
            → BizPrePost @Before      ★ 업무 선처리
            → (TxFlow around 등)
            → Service 본문 → DAO
            → BizPrePost @AfterReturning ★ 업무 후처리
  → return                 ★ COMMIT
```

TCF OFF: `application.controller` → Service 직호출이어도 **같은 Pointcut**으로 선후처리된다.  
(TX는 Controller가 Facade를 안 타면 빠질 수 있음 → Facade 경유 권장.)

---

## 8. 하지 말 것

1. Pointcut을 `facade`/`handler`/`dao`로 바꿔 TX·라우팅과 섞기  
2. Aspect 안에서 SQL·commit·ImageLog  
3. 패키지를 `nhnis.mg.co.a.application.service` 밖으로 옮긴 채 Pointcut 미수정  
4. 시스템 선후와 업무 선후를 한 Aspect로 합치기  
5. 예외 시에도 후처리가 돈다고 가정하기 (`AfterReturning` 한계)

## 10. 요약

```text
BizPrePostAspect
  pointcut = application.service public *
  @Before  = 업무 선처리 로그 (GUID/서비스/메서드/BRC)
  @AfterReturning = 업무 후처리 + 응답 DTO 로그
  위치 = Facade @Transactional 안
  ≠ 시스템 선후 (Interceptor/Advice)
  ≠ PdmgBizTxFlowAspect (TX-FLOW 시작·종료)

다음: 22. Business Service
```
