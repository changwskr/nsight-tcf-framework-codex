> **현행 1차 정책:** 공통 온라인 타임아웃은 Facade `timeout`이 아니라  
> `TcfFacade` → `OnlineTimeoutExecutor` (`nhnis.fw.timeout`, 기본 5000ms, HTTP 504).  
> → [20.타임아웃.md](./20.타임아웃.md)

본 문서는 **보조(2차)** 수단인 Facade `@Transactional(timeout = 초)` 설명이다.  
공통 Executor가 켜진 환경에서는 보통 Facade timeout을 추가로 두지 않는다.

네. **특정 유스케이스만** Spring TX timeout이 필요하면 Business Facade 메서드에 `@Transactional(timeout = 초)`를 지정한다.

PDMG에서 DB 트랜잭션 경계는 Service가 아니라 `nhnis.mg.co.a.application.facade.*` 가 참여한다  
(공통 Executor가 외부 TX를 연 경우 Facade는 `REQUIRED`로 같은 TX에 합류).  
관련: [트랜잭션처리.md](./트랜잭션처리.md) · [01.트랜잭션처리 변경.md](./01.트랜잭션처리%20변경.md) · [20.타임아웃.md](./20.타임아웃.md)

예를 들어 4초 제한이면:

```java
@Transactional(
        transactionManager = "rdwTransactionManager",
        timeout = 4,
        rollbackFor = Exception.class)
public mgcoa8888D0DTOout mgcoa8888D0(Object dtoBody) throws Exception {
    return service.mgcoa8888D0(input);
}
```

현재 조회 Facade는 읽기 전용입니다.

```java
@Transactional(
        transactionManager = "rdwTransactionManager",
        readOnly = true)
public class /* 메서드 단위 예 */ mgcoa9999Facade {
    // mgcoa9999S0 ...
}
```

특정 메서드만 4초로 제한하려면 메서드에 덮어씁니다.

```java
@Transactional(
        transactionManager = "rdwTransactionManager",
        readOnly = true,
        timeout = 4)
public mgcoa9999S0DTOout mgcoa9999S0(Object dtoBody) throws Exception {
    // 조회 처리
}
```

주의할 점은 timeout이 일반 Java 코드 전체를 정확히 4초에 강제로 멈추는 타이머는 아니라는 것입니다.

```text
Facade @Transactional 시작
  ↓
[BizPrePost] → Service → DAO 쿼리
  ↓
4초 초과
  ↓
다음 DB 작업 또는 트랜잭션 완료 시점
  ↓
TransactionTimedOutException
  ↓
rollback
```

조회(`readOnly = true`)만 있으면 롤백할 데이터 변경은 없습니다.  
등록·수정·삭제 Facade에서 timeout이 발생하면 해당 트랜잭션의 변경사항이 롤백됩니다.

권장 형태는 업무마다 제한시간이 다르면 **Facade 메서드별**로 지정하는 것입니다.

```java
@Transactional(
        transactionManager = "rdwTransactionManager",
        timeout = 4,
        rollbackFor = Exception.class)
public ResultDto register(...) { ... }

@Transactional(
        transactionManager = "rdwTransactionManager",
        readOnly = true,
        timeout = 10)
public ResultDto search(...) { ... }
```

Service에 TX를 중복 선언하지 않는 것이 기본입니다. (`BizPrePostAspect`는 Service에 걸리고, TX는 Facade에 둡니다.)

느린 거래 경고(로그)와 timeout은 별개입니다.

```text
느린 거래 WARN: PdmgTx / ImageLog·흐름 로그로 추적 (강제 중단 아님)
공통 OnlineTimeoutExecutor: 기본 5000ms → 504 FW_TIMEOUT + Worker ROLLBACK  (1차)
Facade @Transactional(timeout): Spring TX timeout + rollback  (보조·2차)
```
