## 1. 네이밍의 한 축: 서비스 ID

모든 업무 이름은 **서비스 ID**에서 갈라진다.

```text
[대구분2][업무2][세부1][식별4][구분자1][순번1]
     mg    co     a     8888     S       0
─────────────────────────────
        프로그램 접두 = mgcoa8888
───────────────────────────────────────
              서비스 ID 전체 = mgcoa8888S0
```

| 세그먼트 | 길이 | 대소문자 | 예 | 쓰이는 곳 |
|----------|-----:|----------|----|-----------|
| 대구분 | 2 | 소문자 | `mg` | 서비스 ID, 패키지 `nhnis.mg`, Mapper `rdw.mg` |
| 업무구분 | 2 | 소문자 | `co` | 서비스 ID, 패키지 `.co.` |
| 세부업무 | 1 | 소문자 | `a` | 서비스 ID, 패키지 `.a.` |
| 식별번호 | 4 | 숫자 | `8888` | 클래스 접두 `mgcoa8888*` |
| 구분자 | 1 | 대문자 | `S`/`C`/`U`/`D`/`A`/`R` | URL, DTO, Facade/Service 메서드, SQL ID |
| 순번 | 1 | 숫자·A–Z | `0` | 동일 기능 내 순번 |

### 1.1 구분자

| 코드 | 의미 | 서비스 ID 예 |
|------|------|----------------|
| S | 조회 | `mgcoa8888S0` |
| C | 등록 | `mgcoa9000C0` |
| U | 수정 | `mgcoa9000U0` |
| D | 삭제 | `mgcoa8888D0` |
| A | 혼합 | `mgcoa0000A0` |
| R | 리포트 | `mgcoa0000R0` |

### 1.2 프로그램 접두 vs 서비스 ID

| 개념 | 형식 | 예 | 붙는 것 |
|------|------|----|---------|
| **프로그램 접두** | `mg`+업무+세부+식별4 | `mgcoa8888` | Handler, Facade, Service, Controller, DAO, Mapper 파일 |
| **서비스 ID** | 접두+구분자+순번 | `mgcoa8888S0` | URL, DTO 타입, Facade/Service **메서드**, SQL ID 앞부분 |

```text
좋음:  mgcoa8888Handler + mgcoa8888S0 / mgcoa8888D0
나쁨:  mgcoa8888S0Handler   ← 클래스에 구분자 넣지 않음
나쁨:  MgCoa8888Service     ← PascalCase 프로그램명 금지(업무 타입은 소문자 선두)
나쁨:  MG.SalesTip.list     ← 점 구분 서비스 ID 금지
```

업무 타입(`mgcoa8888Handler` 등)은 **소문자로 시작하는** 프로젝트 호환 규칙이다.  
FW·Config 등 일반 Java는 PascalCase(`RdwDataSourceConfig`, `BizPrePostAspect`).

## 2. 케이스·문자 규칙

| 대상 | 형식 | 예 |
|------|------|----|
| 패키지 | 소문자 + `.` | `nhnis.mg.co.a.application.facade` |
| 업무 타입(Handler/Facade/…) | 소문자 선두 + 식별 | `mgcoa8888Facade` |
| FW/Config/Aspect | PascalCase | `GlobalExceptionHandler`, `SecurityConfig` |
| 메서드·필드·JSON | camelCase | `pageNo`, `totalCount`, `serviceId` |
| 상수 | UPPER_SNAKE | `DEFAULT_PAGE_SIZE` |
| DB 컬럼·테이블 | UPPER_SNAKE | `TRT_BRC`, `TB_MG_TX_PARAM` |
| SQL ID / DAO 메서드 | 서비스ID_DML순번 | `mgcoa8888S0_S0` |
| 오류 코드 | `FW`+4자리 등 | `FW0001`, `FW9999` |

금지 예: `DtoIn`, `Dao`(→ `DTOin`, `DAO`), `selectList`만으로 서비스 식별, `/api/mg/co/a/8888/list`.

## 3. 패키지 네이밍 형식

```text
nhnis.mg.[업무소문자].[세부소문자].[계층].[세부패키지]
```

| 계층 | 세부패키지 | FQCN 골격 |
|------|------------|-----------|
| `entry` | `handler` | `nhnis.mg.co.a.entry.handler.mgcoa8888Handler` |
| `entry` | `aspect` | `nhnis.mg.co.a.entry.aspect.BizPrePostAspect` |
| `application` | `facade` | `…application.facade.mgcoa8888Facade` |
| `application` | `service` | `…application.service.mgcoa8888Service` |
| `application` | `controller` | `…application.controller.mgcoa8888Controller` |
| `dto` | (없음) | `nhnis.mg.co.a.dto.mgcoa8888S0DTOin` |
| `persistence` | `dao` | `…persistence.dao.mgcoa8888DAO` |
| `config` | (없음) | `nhnis.mg.co.a.config.RdwDataSourceConfig` |
| `client` / `support` | (없음) | `*Client`, 유틸 |

Mapper 리소스:

```text
rdw.mg.[업무].[세부]/mgcoa[식별4]-ORA.xml
→ rdw.mg.co.a/mgcoa8888-ORA.xml
```

```text
나쁨: nhnis.mg.entry.handler          (업무·세부 축 없음)
나쁨: nhnis.mg.co.a.application.dto   (dto는 application 밖)
나쁨: nhnis.mg.co.a.entry.facade      (Facade는 application)
나쁨: rdw.mg.co.a 와 Java ic.b 혼용
```

## 4. 컴포넌트별 타입·파일 형식

### 4.1 한눈에 (마스터)

| 컴포넌트 | 파일/타입 형식 | 메서드·기타 |
|----------|----------------|-------------|
| Handler | `mgcoa[식별4]Handler` | `serviceIds()`, `handle` |
| Facade | `mgcoa[식별4]Facade` | 메서드 = **서비스 ID** |
| Service | `mgcoa[식별4]Service` | 메서드 = **서비스 ID** |
| Controller | `mgcoa[식별4]Controller` | `@PostMapping("/서비스ID")` |
| DAO | `mgcoa[식별4]DAO` | 메서드 = **SQL ID** |
| DTO | `mgcoa[식별4][구분][순번]DTO…` | 필드 camelCase |
| Mapper XML | `mgcoa[식별4]-ORA.xml` | `namespace` = DAO FQCN |
| Aspect | 역할 PascalCase | Pointcut = 대상 패키지 |
| Config | `*Config` / `*Properties` | Bean camelCase |
| Boot | `PdmgApplication` | `nhnis.mg`만 |

### 4.2 Handler

```text
형식:  mgcoa[식별4]Handler.java
패키지: nhnis.mg.co.a.entry.handler
```

- 동일 식별번호의 S0/D0/… → **Handler 1개**
- 구현: `TransactionHandler`
- 상수로 서비스 ID를 두고 `switch`로 Facade 호출

```java
// 좋음
case "mgcoa8888S0" -> facade.mgcoa8888S0(dtoBody);
case "mgcoa8888D0" -> facade.mgcoa8888D0(dtoBody);

// 나쁨: facade 없이 service.mgcoa8888S0(...)
// 나쁨: class mgcoa8888S0Handler
```

### 4.3 Facade

```text
형식:  mgcoa[식별4]Facade.java
패키지: nhnis.mg.co.a.application.facade
메서드: public [서비스ID]DTOout [서비스ID](Object dtoBody)
```

```java
@Transactional(transactionManager = "rdwTransactionManager", readOnly = true)
public mgcoa8888S0DTOout mgcoa8888S0(Object dtoBody) { … }

@Transactional(transactionManager = "rdwTransactionManager", rollbackFor = Exception.class)
public mgcoa8888D0DTOout mgcoa8888D0(Object dtoBody) { … }
```

```text
좋음: 메서드명 mgcoa8888S0
나쁨: selectImageLogList / executeS0 / process
```

### 4.4 Service

```text
형식:  mgcoa[식별4]Service.java
패키지: nhnis.mg.co.a.application.service
메서드: public [서비스ID]DTOout [서비스ID]([서비스ID]DTOin in)
```

- 메서드명 = 서비스 ID (Facade와 **동일 문자열**)
- 기본 `@Transactional` 없음 (Facade TX 안)

### 4.5 Controller (TCF OFF)

```text
형식:  mgcoa[식별4]Controller.java
패키지: nhnis.mg.co.a.application.controller
매핑:  @PostMapping("/mgcoa8888S0")
```

```text
좋음: POST /mgcoa8888S0
나쁨: POST /api/mg/co/a/8888/list
나쁨: GET + @GetMapping
```

### 4.6 DAO

```text
형식:  mgcoa[식별4]DAO.java
패키지: nhnis.mg.co.a.persistence.dao
애노테이션: @RDWMapper
```

### 4.7 DTO

```text
입력:   [서비스ID]DTOin.java      → mgcoa8888S0DTOin
출력:   [서비스ID]DTOout.java     → mgcoa8888S0DTOout
목록행: [서비스ID]DTOSub[n].java  → mgcoa8888S0DTOSub0
부가:   [서비스ID]DTO*MsgJson.java (필요 시)
```

- 패키지: `nhnis.mg.co.a.dto`
- 보통 `DataObject` 상속
- **서비스 ID 전체**(구분자 포함)가 타입명에 들어간다

```text
좋음: mgcoa8888S0DTOin / mgcoa8888D0DTOin  (거래별 DTO)
나쁨: mgcoa8888DtoIn / mgcoa8888ListResponseDto
나쁨: ImageLogRequest (서비스 ID 없음)
```

필드:

```text
DB TRT_BRC     → Java/JSON trtBrc
DB PAGE_NO     → pageNo
개수           → totalCount / count
오프셋         → offset
```

### 4.8 Aspect / Config / Client / Support

| 종류 | 형식 | 예 |
|------|------|----|
| Aspect | `{역할}Aspect` | `BizPrePostAspect`, `PdmgBizTxFlowAspect` |
| Config | `{대상}Config` | `RdwDataSourceConfig`, `SecurityConfig` |
| Properties | `{대상}Properties` | `CorsProperties` |
| Client | `{대상}Client` | `XxxClient` |
| Support | 동사/명사 유틸 | `XxxUtils` (모호한 `Util` 단독 패키지 금지) |

## 5. SQL ID / MyBatis 네이밍 형식

### 5.1 SQL ID

```text
[서비스ID]_[DML구분][순번]
[서비스ID]_[DML구분][순번]_count     ← 목록 건수
```

| 부분 | 예 | 설명 |
|------|----|------|
| 서비스 ID | `mgcoa8888S0` | 어느 거래의 SQL인지 |
| `_` | | 고정 구분 |
| DML | `S`/`C`/`U`/`D`/`A` | 조회/등록/수정/삭제/혼합 |
| 순번 | `0` | 같은 거래 내 SQL 순번 |
| `_count` | | count 전용 접미 |

예:

```text
mgcoa8888S0_S0
mgcoa8888S0_S0_count
mgcoa8888D0_D0
mgcoa9000C0_C0
mgcoa9000U0_U0
```

```text
나쁨: selectList / selectSalesTip
나쁨: mgcoa8888S0S0          (_ 없음)
나쁨: MGCOA8888S0_S0         (대문자화)
```

### 5.2 DAO 메서드 = SQL ID

```java
List<Map<String, Object>> mgcoa8888S0_S0(Map<String, Object> param);
int mgcoa8888S0_S0_count(Map<String, Object> param);
int mgcoa8888D0_D0(Map<String, Object> param);
```

XML:

```xml
<mapper namespace="nhnis.mg.co.a.persistence.dao.mgcoa8888DAO">
  <select id="mgcoa8888S0_S0" …>
    /* mgcoa8888S0_S0 */
    …
  </select>
</mapper>
```

| 항목 | 형식 |
|------|------|
| 파일 | `mgcoa[식별4]-ORA.xml` |
| namespace | DAO FQCN과 **완전 일치** |
| statement `id` | DAO 메서드명과 **완전 일치** |
| 주석 | `/* SQL ID */` 본문 포함 권장 |

## 6. URL · API · 전문 필드

### 6.1 HTTP

```text
TCF ON:  POST /{serviceId}           → POST /mgcoa8888S0
UI 현행: 브라우저 POST {targetBaseUrl}/{serviceId}
UI 호환: POST /api/relay/{serviceId}
```

- 메서드는 **POST** 고정(온라인 전문 스타일)
- path = 서비스 ID 문자열 그대로

### 6.2 요청/응답 봉투

```text
요청/성공응답: { "hdr_nhnis": { … }, "dto": { … } }
실패응답:      NH_NIS_ERR_DTO  (stdErrCode, stdErrMsgCntn, errType)
```

```text
쓰지 않음: StandardRequestDto / StandardResponseDto / result.resultCode
쓰지 않음: @TcfTransaction(serviceId = "MG.Xxx.list")
```

### 6.3 헤더·로그 키 (관용)

| 이름 | 용도 |
|------|------|
| `guid` / `traceId` | 추적 |
| `serviceId` | 거래 식별 |
| `rms_svc_c` 등 | 헤더 내 서비스 코드(FW 계약) |

같은 값을 `requestId`와 `guid`로 이중 정의하지 않는다.

## 7. 이름 유도 워크북 (복사해서 채우기)

서비스 ID를 하나 정하면 나머지를 채운다.

```text
서비스 ID ........ : mgcoa9000C0
업무/세부 ........ : co / a
프로그램 접두 .... : mgcoa9000

Java 루트 ........ : nhnis.mg.co.a
Mapper 폴더 ...... : rdw.mg.co.a/

Handler .......... : entry.handler.mgcoa9000Handler
Facade ........... : application.facade.mgcoa9000Facade
  메서드 ......... : mgcoa9000C0
Service .......... : application.service.mgcoa9000Service
  메서드 ......... : mgcoa9000C0
Controller ....... : application.controller.mgcoa9000Controller
  매핑 ........... : POST /mgcoa9000C0
DTOin/out ........ : dto.mgcoa9000C0DTOin / mgcoa9000C0DTOout
DAO .............. : persistence.dao.mgcoa9000DAO
SQL ID ........... : mgcoa9000C0_C0
Mapper 파일 ...... : rdw.mg.co.a/mgcoa9000-ORA.xml
namespace ........ : nhnis.mg.co.a.persistence.dao.mgcoa9000DAO
```

동일 식별에 조회가 있으면 Handler/Facade/Service/DAO는 **파일을 추가하지 않고** 메서드·DTO·SQL만 추가한다.

```text
mgcoa9000S0, C0, U0, D0
  → 클래스: mgcoa9000Handler|Facade|Service|DAO|Controller (각 1)
  → DTO/SQL/URL: 서비스 ID별로 분리
```

## 10. 금지 목록 (네이밍)

1. REST 리소스형 path·동사만 있는 메서드명으로 서비스 대체  
2. `DtoIn` / `DtoOut` / `Dao` / `ListResponseDto` (구 스타일)  
3. 클래스명에 구분자(`S0`) 포함 (Handler/Facade/Service/DAO/Controller)  
4. 업무 코드를 `nhnis.mg` 바로 아래 또는 축 없는 `entry`에 배치  
5. Java 업무축과 `rdw.mg.*` Mapper 축 불일치  
6. DAO 메서드명 ≠ XML `id` ≠ namespace 불일치  
7. `@TcfTransaction` / `StandardRequestDto` 기반 신규 명명  
8. `common` / `misc` / `util` 패키지  
9. 의미 없는 이름: `data`, `obj`, `temp`, `proc`, `doIt`, `process1`

## 11. 체크리스트

- [ ] 서비스 ID 10자 구조(대2+업2+세1+식4+구1+순1)가 맞는가?

- [ ] DTO·URL·SQL ID에 구분자(S/C/U/D…)가 포함되는가?

- [ ] 패키지가 `nhnis.mg.[업무].[세부].[계층]…` 인가?
