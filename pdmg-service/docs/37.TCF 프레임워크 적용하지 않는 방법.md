# TCF 프레임워크 적용하지 않는 방법

TCF(단일 `/online` · Handler · TcfFacade · OnlineTimeoutExecutor)를 끄려면 설정만 바꾸면 된다.

---

## 1. 설정

`application.yml` (또는 기동 옵션):

```yaml
nhnis:
  fw:
    tcf:
      enabled: false
```

기동 시:

```text
--nhnis.fw.tcf.enabled=false
```

**재기동** 필요.

---

## 2. ON / OFF 차이

| 항목 | `tcf.enabled=true` (현재 기본) | `tcf.enabled=false` |
|------|-------------------------------|---------------------|
| HTTP 진입 | `OnlineTransactionController` (`/online`, `/{serviceId}`) | 업무 `application.controller.*` (`POST /mgcoa5530S0` 등) |
| 분기 | Handler → Facade → Service | Controller → Service (Facade 경유 여부는 구현에 따름) |
| Bean | Handler / TcfFacade / Dispatcher **활성** | Controller **활성**, Handler·TcfFacade **비활성** |
| 공통 타임아웃 | `TcfFacade` → `OnlineTimeoutExecutor` | TCF 경로 없음 → **이 Executor로 감싸지 않음** |
| 예외 | `GlobalExceptionHandler` (TCF ON 조건) | Controller 경로용 Advice 필요 여부 확인 |

조건부 등록:

- Handler / TcfFacade / OnlineTransactionController: `havingValue = "true"`
- Controller: `havingValue = "false", matchIfMissing = true`

---

## 3. 꺼지지 않는 것 (commons)

TCF를 꺼도 아래는 **별도 설정**이 없으면 그대로다.

```yaml
nhnis:
  fw:
    commons:
      legacy-web:
        enabled: true    # Interceptor, ResponseBodyAdvice 등
      filter:
        enabled: true    # DefaultFilter, ServiceContext
```

시스템 선후처리·Filter까지 끄려면 위 플래그를 `false`로 둔다 (영향 범위 큼).

---

## 4. 타임아웃과의 관계

```yaml
nhnis.fw.timeout.enabled: true
```

은 **TCF ON일 때** `TcfFacade`가 Worker+TX로 감싸는 스위치다.  
TCF OFF면 이 경로를 타지 않으므로, 제한이 필요하면 Service/Facade `@Transactional(timeout=…)` 또는 다른 수단을 써야 한다.

---

## 5. Controller 연계 활성화 (TCF 미적용 시)

별도 Bean 등록 작업은 없다. **TCF를 끄면 Controller가 자동 활성**된다.

### 조건 어노테이션 (이미 소스에 있음)

```java
// 업무 Controller — TCF OFF 일 때 등록
@RestController
@ConditionalOnProperty(name = "nhnis.fw.tcf.enabled", havingValue = "false", matchIfMissing = true)
public class mgcoa5530Controller {
    @PostMapping("/mgcoa5530S0")
    public mgcoa5530S0DTOout mgcoa5530S0(...) { ... }
}

// Handler — TCF ON 일 때만 등록 (OFF면 비활성)
@Component
@ConditionalOnProperty(name = "nhnis.fw.tcf.enabled", havingValue = "true")
public class mgcoa5530Handler implements TransactionHandler { ... }
```

### 활성화 절차

1. `nhnis.fw.tcf.enabled=false` 설정
2. 앱 재기동
3. 호출: `POST http://localhost:8080/mgcoa5530S0`  
   Body: `{ "hdr_nhnis": …, "dto": … }` (local이면 `dto`만도 가능)
4. 로그에 `mgcoa5530 Controller Start!` 가 보이면 Controller 경로 활성

### 신규 프로그램 추가 시

| TCF OFF용 | TCF ON용 |
|-----------|----------|
| `application.controller.*Controller` + `@PostMapping("/서비스ID")` + 위 `ConditionalOnProperty(false)` | `entry.handler.*Handler` + `ConditionalOnProperty(true)` |

둘 다 두고 설정으로 전환하는 것이 PDMG 샘플 패턴이다.

### 주의

- `GlobalExceptionHandler`는 TCF ON 전용 → OFF 시 `BizException` 표준 `result` 조립 Advice가 없을 수 있음
- 공통 OnlineTimeoutExecutor는 TCF Facade 경로 전용 → OFF 시 Controller→Service 직접 호출에는 미적용

---

## 6. 체크리스트

- [ ] `nhnis.fw.tcf.enabled=false` 후 재기동
- [ ] `POST /{serviceId}` 가 업무 Controller로 들어가는지 확인 (`Controller Start` 로그)
- [ ] Handler 전용 로직이 더 이상 안 나오는지 확인
- [ ] 예외·타임아웃 정책이 Controller 경로에 맞는지 확인
