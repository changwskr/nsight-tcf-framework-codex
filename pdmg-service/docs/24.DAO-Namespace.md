# 24. DAO Namespace (PDMG)

기준일: 2026-08-09  
대상: MyBatis `<mapper namespace="…">` ↔ DAO FQCN  
관련: [23.DAO.md](./23.DAO.md) · [24.DAO-Mapper.md](./24.DAO-Mapper.md) · [06.네이밍 형식.md](./06.네이밍%20형식.md)

> 같은 번호 `24`에 [DAO-Mapper](./24.DAO-Mapper.md)(SQL 본문)와 본 문서(네임스페이스 계약)가 나뉜다.

---

## 1. 한 줄 정의

**namespace = DAO 인터페이스의 Fully Qualified Class Name(FQCN).**  
MyBatis가 statement를 찾을 때 쓰는 루트 키이며, XML과 Java를 묶는 **유일한 계약**이다.

```text
DAO  FQCN     : nhnis.mg.co.a.persistence.dao.mgcoa8888DAO
XML  namespace : nhnis.mg.co.a.persistence.dao.mgcoa8888DAO   ← 문자 단위 일치
statement id  : mgcoa8888S0_S0                              ← DAO 메서드명
전체 SQL ID   : nhnis.mg.co.a.persistence.dao.mgcoa8888DAO.mgcoa8888S0_S0
```

---

## 2. 왜 FQCN인가

| 이유 | 설명 |
|------|------|
| Mapper 스캔 | `@MapperScan` / `@RDWMapper`가 인터페이스를 등록할 때 타입명으로 매핑 |
| 충돌 방지 | 프로그램마다 DAO가 다르므로 namespace도 분리 |
| 로그·MDC | `MybatisLogInterceptor`의 `sqlId` = `namespace.id` |
| 운영 규칙 | 패키지 리팩터 시 XML namespace를 **같이** 고쳐야 함 |

짧은 별칭(`mgcoa8888`)만 namespace로 쓰면 Java 타입과 어긋나 바인딩이 실패하거나, 관례가 깨진다. **현재 샘플은 전부 DAO FQCN.**

---

## 3. 세 축 정렬

네임스페이스만 맞아도 부족하다. 아래가 **동시에** 맞아야 한다.

```text
① Java 패키지     nhnis.mg.co.a.persistence.dao.mgcoa8888DAO
② Mapper 폴더     resources/rdw.mg.co.a/mgcoa8888-ORA.xml
③ XML namespace   nhnis.mg.co.a.persistence.dao.mgcoa8888DAO
```

| 축 | 규칙 |
|----|------|
| 업무·세부 | Java `co.a` ↔ 리소스 `rdw.mg.co.a` |
| 파일 | `{접두}-ORA.xml` ↔ `{접두}DAO` |
| namespace | **=** DAO FQCN (대소문자·패키지 경로 포함) |

```text
나쁨: namespace="mgcoa8888DAO"           (패키지 생략)
나쁨: namespace="…dao.Mgcoa8888DAO"      (클래스명 대소문자)
나쁨: Java는 co.a 인데 XML은 rdw.mg.ic.b
나쁨: namespace는 옛 패키지 nhnis.mg.persistence.dao.…
```

패키지 리팩터(`nhnis.mg.*` → `nhnis.mg.co.a.*`) 후 XML namespace 미수정이 전형적인 장애 원인이다.

---

## 4. 현재 샘플

| DAO FQCN | XML 파일 | namespace |
|----------|----------|----------|
| `…dao.mgcoa5530DAO` | `mgcoa5530-ORA.xml` | 동일 FQCN |
| `…dao.mgcoa8888DAO` | `mgcoa8888-ORA.xml` | 동일 FQCN |
| `…dao.mgcoa9000DAO` | `mgcoa9000-ORA.xml` | 동일 FQCN |
| `…dao.mgcoa9999DAO` | `mgcoa9999-ORA.xml` | 동일 FQCN |

공통 prefix: `nhnis.mg.co.a.persistence.dao.`

---

## 5. statement 전체 ID

호출·로그에 찍히는 식별자:

```text
{namespace}.{statement id}
= {DAO FQCN}.{DAO 메서드명}
```

예:

```text
nhnis.mg.co.a.persistence.dao.mgcoa9000DAO.mgcoa9000S0_S0
nhnis.mg.co.a.persistence.dao.mgcoa9000DAO.mgcoa9000C0_C0
```

- `id`만 같고 namespace가 다르면 **다른 statement**.
- 같은 namespace 안에 `id` 중복은 MyBatis 로드 시 충돌.

SQL 본문·페이징·Where 패턴은 [24.DAO-Mapper.md](./24.DAO-Mapper.md).

---

## 6. 로드 경로와의 관계

```text
RdwDataSourceConfig
  mapperLocations = classpath*:rdw.*/*.xml
  MapperScan basePackages = nhnis.mg.co.a.persistence.dao
```

1. 클래스패스의 `rdw.*/*.xml`을 읽음  
2. 각 파일의 `namespace`로 Mapper 등록  
3. 스캔된 DAO 인터페이스와 namespace가 일치해야 메서드 호출이 statement에 연결  

**폴더에 XML이 있어도 namespace가 틀린 DAO를 가리키면** 해당 인터페이스 호출은 실패(또는 빈/잘못된 매핑)한다.

---

## 7. 변경 시 체크리스트

DAO를 옮기거나 이름을 바꿀 때:

- [ ] Java 파일 패키지/클래스명  
- [ ] XML `<mapper namespace="…">` **전체 문자열**  
- [ ] (필요 시) `rdw.mg.[업무].[세부]` 폴더  
- [ ] 로그의 `sqlId`가 새 FQCN으로 찍히는지  
- [ ] statement `id`는 메서드명과 여전히 일치하는지  

신규 프로그램:

1. `…persistence.dao.mgcoaNNNNDAO` 생성  
2. `rdw.mg.co.a/mgcoaNNNN-ORA.xml` 생성  
3. namespace를 **복사-붙여넣기 수준으로 FQCN과 동일**하게  

---

## 8. 하지 말 것

1. namespace에 서비스 ID·SQL id만 넣기  
2. 여러 DAO가 하나의 namespace를 공유  
3. XML만 고치고 Java 패키지 리팩터를 안 맞추기 (또는 그 반대)  
4. `resultType`/테이블명과 namespace를 혼동하기 — namespace는 **타입 경로**  

---

## 9. 요약

```text
namespace = DAO FQCN (문자 단위 일치)
전체 SQL ID = namespace + "." + statement id
축: Java co.a ↔ rdw.mg.co.a ↔ XML namespace

SQL 작성 상세 → 24.DAO-Mapper.md
DAO 인터페이스 → 23.DAO.md
```
