# GUID 아키텍처 텍스트 다이어그램

## 1. 전체 GUID 흐름

```text
┌────────────────────────────┐
│ pdmg-ui / 외부 호출 시스템│
└──────────────┬─────────────┘
               │
               │ std_gbl_id 전달 또는 미전달
               ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ pdmg-fw DefaultFilter                                                       │
│                                                                              │
│ 요청 Header 확인                                                            │
│      │                                                                       │
│      ├─ std_gbl_id 존재                                                    │
│      │      └─ 전달받은 GUID 사용                                          │
│      │                                                                       │
│      └─ std_gbl_id 없음                                                    │
│             └─ 신규 GUID 생성                                               │
│      │                                                                       │
│      ▼                                                                       │
│ GUID를 공통 Context에 저장                                                   │
│      │                                                                       │
│      ├─ hdr_nhnis.sys_comm.std_gbl_id                                      │
│      ├─ ServiceContext.guid                                                 │
│      ├─ MDC / ThreadContext                                                 │
│      ├─ TransactionContext                                                  │
│      └─ HttpServletRequest 속성                                             │
└──────────────┬───────────────────────────────────────────────────────────────┘
               │
               ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ 거래 전체 구간                                                             │
│                                                                              │
│ Interceptor → Controller → TCF → Handler → Facade → Service → DAO           │
│                                                                              │
│ 모든 계층에서 동일한 GUID 사용                                              │
└──────────────┬───────────────────────────────────────────────────────────────┘
               │
               ├───────────────────────────────┐
               │                               │
               ▼                               ▼
       ImageLog / 업무 로그              외부 시스템 호출
       GUID로 거래 기록                  GUID를 추적 ID로 전달
               │                               │
               └───────────────┬───────────────┘
                               ▼
                        표준 응답 Header
                               │
                               └─ 동일한 std_gbl_id 반환
                               │
                               ▼
                        사용자 / pdmg-ui
```

## 2. GUID의 위치

표준 전문에서 GUID는 다음 위치에 있습니다.

```text
hdr_nhnis
└─ sys_comm
   └─ std_gbl_id
      └─ c3d65cb1a54a43838688b76afe82521e
```

요청 예:

```json
{
  "hdr_nhnis": {
    "sys_comm": {
      "std_gbl_id": "c3d65cb1a54a43838688b76afe82521e",
      "rms_svc_c": "mgcoa5530S0",
      "scid": "mgcoa5530"
    }
  },
  "dto": {
    "pageNo": 1,
    "pageSize": 20
  }
}
```

## 3. GUID 생성

```text
HTTP 요청
   │
   ▼
DefaultFilter
   │
   ▼
std_gbl_id 확인
   │
   ├─ 값 있음
   │    ├─ 형식 검증
   │    └─ 기존 GUID 유지
   │
   └─ 값 없음
        └─ UUID 신규 생성
             │
             ├─ 하이픈 제거
             └─ 32자리 문자열 생성
```

개념적인 생성 방식:

```java
String guid = UUID.randomUUID()
        .toString()
        .replace("-", "");
```

결과:

```text
UUID 원본
c3d65cb1-a54a-4383-8688-b76afe82521e

하이픈 제거
c3d65cb1a54a43838688b76afe82521e
```

## 4. UI에서 GUID 생성

```text
pdmg-ui 업무 화면
      │
      ├─ 신규 거래 실행
      ├─ GUID 재채번 버튼
      └─ 기존 GUID가 없는 요청
      │
      ▼
online-single.js
      │
      ▼
hdr_nhnis.sys_comm.std_gbl_id 설정
      │
      ▼
pdmg-service 호출
```

같은 업무를 새로 실행할 때는 새로운 GUID를 사용합니다.

```text
첫 번째 거래
└─ GUID-A

두 번째 신규 거래
└─ GUID-B
```

재조회·재시도 정책은 구분해야 합니다.

```text
새로운 독립 거래
└─ 신규 GUID

동일 거래의 기술적 재시도
├─ 원본 GUID 유지
└─ 별도의 retryCount 또는 child ID 추가 권장
```

## 5. ServiceContext 저장

```text
DefaultFilter
      │
      ▼
ServiceContext 생성
      │
      ├─ applicationName
      ├─ guid
      ├─ activeProfile
      ├─ requestHeaders
      ├─ request
      ├─ response
      └─ hdr_nhnis
      │
      ▼
ServiceContextHolder.setInstance()
      │
      ▼
현재 요청 Thread의 ThreadLocal
```

업무 계층에서 조회:

```text
Business Service
      │
      ▼
ServiceContextHolder.getInstance()
      │
      ▼
context.getGuid()
```

## 6. MDC 로그 연계

```text
DefaultFilter
      │
      ├─ GUID 생성·조회
      └─ ThreadContext.put("GUID", guid)
      │
      ▼
Controller 로그
      │
      ▼
Handler 로그
      │
      ▼
Facade 로그
      │
      ▼
Service 로그
      │
      ▼
DAO 로그
```

모든 로그에 동일한 GUID가 출력됩니다.

```text
[GUID=c3d65cb1...] DefaultFilter 요청 시작
[GUID=c3d65cb1...] TransactionDispatcher 서비스 라우팅
[GUID=c3d65cb1...] mgcoa5530Facade TX BEGIN
[GUID=c3d65cb1...] mgcoa5530Service 조회 시작
[GUID=c3d65cb1...] mgcoa5530DAO SQL 실행
[GUID=c3d65cb1...] mgcoa5530Facade TX COMMIT
[GUID=c3d65cb1...] ETF 거래 종료
```

이 GUID 하나로 거래 전체 로그를 검색할 수 있습니다.

## 7. TransactionContext 연계

```text
ServiceContext
      │
      └─ guid
      │
      ▼
TransactionContext.fromCurrent(serviceId)
      │
      ├─ serviceId
      ├─ serviceContext
      ├─ guid
      └─ startedAtNanos
```

TCF 처리:

```text
TransactionContext
      │
      ├─ STF 시작 로그
      ├─ Dispatcher 로그
      ├─ Handler 로그
      ├─ ETF 종료 로그
      └─ 타임아웃 오류 정보
```

## 8. GUID와 이미지로그

```text
HTTP 요청
   │
   ▼
DefaultFilter
   │
   └─ GUID 확보
   │
   ▼
Interceptor.preHandle
   │
   ▼
TB_FW_IMAGE_LOG INSERT
   │
   ├─ GUID = Primary Key
   ├─ Service ID
   ├─ 요청 전문
   ├─ 요청 시각
   └─ 사용자·영업점
   │
   ▼
업무 처리
   │
   ▼
Interceptor.afterCompletion
   │
   ▼
동일 GUID로 UPDATE
   │
   ├─ 응답 전문
   ├─ 결과 코드
   ├─ 오류 정보
   ├─ 종료 시각
   └─ 경과시간
```

관계:

```text
요청 INSERT
WHERE GUID = c3d65cb1...

응답 UPDATE
WHERE GUID = c3d65cb1...
```

GUID가 없거나 중간에 바뀌면 요청 로그와 응답 로그가 연결되지 않습니다.

## 9. GUID와 트랜잭션

```text
GUID
│
├─ 거래 추적 식별자
└─ DB 트랜잭션 식별자 자체는 아님
```

```text
동일 GUID
   │
   ├─ ImageLog INSERT 트랜잭션
   ├─ 업무 Facade 트랜잭션
   └─ ImageLog UPDATE 트랜잭션
```

하나의 GUID를 사용하지만 DB 트랜잭션은 서로 다를 수 있습니다.

```text
GUID-A
│
├─ ImageLog INSERT       TX-1
├─ 업무 데이터 처리      TX-2
└─ ImageLog UPDATE       TX-3
```

## 10. 정상 거래 추적

```text
GUID 생성
   │
   ▼
요청 ImageLog INSERT
   │
   ▼
STF 시스템 선처리
   │
   ▼
Facade TX BEGIN
   │
   ▼
Service → DAO → DB
   │
   ▼
Facade TX COMMIT
   │
   ▼
ETF 시스템 후처리
   │
   ▼
응답 ImageLog UPDATE
   │
   ▼
같은 GUID를 응답 Header에 반환
```

## 11. 예외 거래 추적

```text
GUID 생성
   │
   ▼
요청 ImageLog INSERT
   │
   ▼
Facade TX BEGIN
   │
   ▼
Service / DAO 예외
   │
   ▼
Facade TX ROLLBACK
   │
   ▼
GlobalExceptionHandler
   │
   ├─ 오류 코드
   ├─ 오류 메시지
   ├─ Service ID
   └─ GUID
   │
   ▼
ImageLog 오류정보 UPDATE
   │
   ▼
오류 응답에 동일 GUID 반환
```

사용자는 응답의 GUID를 운영자에게 전달하고, 운영자는 해당 GUID로 전체 로그를 조회할 수 있습니다.

## 12. 외부 시스템 연계

```text
PDMG 업무 Service
      │
      ├─ 현재 GUID 조회
      └─ 외부 요청 Header에 전달
      │
      ▼
외부 시스템
      │
      ├─ 동일 GUID로 로그 기록
      └─ 하위 시스템 처리
      │
      ▼
응답
```

권장 Header 예:

```http
X-Global-Transaction-Id: c3d65cb1a54a43838688b76afe82521e
```

또는 표준 전문 방식:

```text
외부 요청 hdr_nhnis
└─ sys_comm.std_gbl_id
   └─ 원본 GUID 유지
```

전체 추적:

```text
pdmg-ui
   │ GUID-A
   ▼
pdmg-service
   │ GUID-A
   ▼
외부 서비스 A
   │ GUID-A
   ▼
외부 서비스 B
   │ GUID-A
   ▼
업무 DB·로그
```

## 13. 비동기 처리

ThreadLocal의 GUID는 별도 Thread에 자동 전달되지 않습니다.

```text
HTTP 요청 Thread
   │
   ├─ ServiceContext GUID-A
   └─ MDC GUID-A
   │
   ▼
Executor 별도 Thread
   │
   ├─ ServiceContext 없음
   └─ MDC 없음
```

비동기 작업에는 GUID를 명시적으로 전달해야 합니다.

```text
업무 Thread
   │
   └─ AsyncCommand(guid=GUID-A)
           │
           ▼
비동기 Thread
   │
   ├─ MDC에 GUID-A 설정
   ├─ 작업 실행
   └─ finally에서 MDC 제거
```

## 14. GUID 보안과 검증

외부에서 받은 GUID를 그대로 로그에 넣기 전에 형식을 검증해야 합니다.

```text
외부 std_gbl_id
      │
      ├─ null 또는 공백
      │    └─ 신규 생성
      │
      ├─ 허용 형식
      │    └─ 기존 값 사용
      │
      └─ 비정상 형식
           ├─ 신규 값으로 대체하거나
           └─ 입력 오류 처리
```

권장 조건:

```text
길이     : 32자
문자     : 영문·숫자 또는 16진수
제어문자 : 허용하지 않음
개행문자 : 허용하지 않음
```

GUID에는 다음 값을 넣으면 안 됩니다.

```text
X 사용자 ID
X 주민번호
X 계좌번호
X Access Token
X 세션 ID
X 업무 데이터
```

## 15. 요청 종료 정리

```text
HTTP 응답 완료 또는 예외
      │
      ▼
DefaultFilter.finally
      │
      ├─ ServiceContextHolder.remove()
      ├─ ThreadContext.remove("GUID")
      └─ MDC 정리
```

정리가 필요한 이유:

```text
Tomcat Thread 재사용
   │
   ├─ 이전 요청 GUID가 남아 있음
   │
   ▼
다음 사용자 요청 로그에
이전 GUID가 출력될 위험
```

따라서 성공·실패·타임아웃 등 모든 종료 경로에서 `finally`로 정리해야 합니다.

## 16. 최종 GUID 구조

```text
사용자 요청
   │
   ▼
std_gbl_id 확인
   │
   ├─ 있음 → 기존 GUID 사용
   └─ 없음 → 신규 GUID 생성
   │
   ▼
DefaultFilter
   │
   ├─ Header
   ├─ ServiceContext
   ├─ MDC
   └─ Request
   │
   ▼
Interceptor
   │
   └─ ImageLog INSERT
   │
   ▼
TCF
   │
   ├─ TransactionContext
   ├─ STF
   └─ Dispatcher
   │
   ▼
Handler → Facade → Service → DAO
   │
   ├─ 동일 GUID 로그
   └─ 외부 호출에도 GUID 전파
   │
   ▼
ETF / ExceptionHandler
   │
   ▼
ImageLog UPDATE
   │
   ▼
응답 Header에 동일 GUID 반환
   │
   ▼
Context / MDC 제거
```

GUID는 다음 구성요소를 하나로 연결하는 거래 추적 키입니다.

```text
HTTP 요청
 + 표준 전문
 + ServiceContext
 + TransactionContext
 + 애플리케이션 로그
 + 이미지로그
 + 외부 시스템 호출
 + 오류 응답
 = 하나의 GUID로 통합 추적
```
