## 0. 한눈에

| 항목 | 현행 |
|------|------|
| 왜 필요한가 | `pdmg-ui(:8090)` 브라우저 JS가 `pdmg-service(:8080)` 를 **직접** `fetch` |
| Origin 예 | `http://localhost:8090` ≠ `http://localhost:8080` |
| 설정 위치 | `pdmg-service` `application.yml` → `spring.mvc.cors.*` |
| 코드 | `CorsProperties` · `WebMvcConfig` · Security `.cors(...)` |
| Filter | `DefaultFilter`는 **OPTIONS 스킵** (preflight 방해 금지) |
| 매핑 | `/**` (온라인은 `/api/**`가 아니라 `POST /{serviceId}`) |

```text
브라우저 (origin :8090)
  │  ① OPTIONS /mgcoa8888S0     ← preflight (CORS)
  │  ② POST    /mgcoa8888S0     ← 실제 전문
  ▼
pdmg-service :8080
  CorsFilter / WebMvc CORS 헤더
  → (POST만) DefaultFilter → … → TcfFacade
```

카탈로그·`/api/config` 는 여전히 UI same-origin. **거래 전문만** 서비스로 직접 간다.

---

## 1. CORS가 뭔가 (PDMG 맥락)

브라우저는 **다른 origin**으로 XHR/`fetch` 할 때 Same-Origin Policy를 적용한다.  
서버가 `Access-Control-Allow-Origin` 등으로 “이 UI origin을 허용”하지 않으면, 응답이 와도 JS가 읽지 못한다.

| 호출 방식 | CORS |
|-----------|------|
| **현행:** 브라우저 → `8080/{serviceId}` | **필요** |
| (구) UI 서버 RestClient 중계 | 불필요 (서버↔서버) |
| Postman / curl | 해당 없음 (브라우저 정책 아님) |

---

## 2. 설정 (`application.yml`)

```yaml
spring:
  mvc:
    cors:
      allowed-origins:
        - http://localhost:8090
        - http://127.0.0.1:8090
      allowed-methods:
        - GET
        - POST
        - OPTIONS
      allowed-headers:
        - "*"
```

| 키 | 의미 |
|----|------|
| `allowed-origins` | 허용 UI origin. **비어 있으면 CORS 미등록** |
| `allowed-methods` | preflight·실제 메서드. 온라인은 POST + OPTIONS |
| `allowed-headers` | 요청 헤더 허용. `Content-Type` 등 |

운영에서 UI 도메인이 바뀌면 origin 목록을 그에 맞게 추가한다.  
`*` origin + credentials 조합은 쓰지 않는 것이 안전하다(현행 credentials 미사용).

## 3. 코드 연결

### 3.1 `CorsProperties`

FQCN: `nhnis.mg.co.a.config.CorsProperties`  
접두: `spring.mvc.cors`

### 3.2 `WebMvcConfig`

FQCN: `nhnis.mg.co.a.config.WebMvcConfig`

| 역할 | 내용 |
|------|------|
| `addCorsMappings` | MVC 경로 `/**` 에 CORS |
| `@Bean CorsConfigurationSource` | Security `Customizer.withDefaults()` 가 참조 |

온라인 URL이 `/mgcoa8888S0` 형태이므로 과거 `/api/**` 만 열면 **거래 CORS가 안 된다.** 반드시 `/**`.

### 3.3 `SecurityConfig`

앱 `nhnis.mg.co.a.config.SecurityConfig`:

```java
http.cors(Customizer.withDefaults())
    .authorizeHttpRequests(auth -> auth.anyRequest().permitAll());
```

Security 필터 체인의 CorsFilter가 preflight·응답 헤더를 붙인다.

### 3.4 `DefaultFilter` (필수 주의)

`DefaultFilter`는 Body 필수·JSON 파싱을 한다.  
**OPTIONS에는 Body가 없으므로** 그대로 두면 preflight가 400으로 죽는다.

```java
@Override
protected boolean shouldNotFilter(HttpServletRequest request) {
    return "OPTIONS".equalsIgnoreCase(request.getMethod());
}
```

FQCN: `nhnis.fw.commons.filter.DefaultFilter`

## 4. 브라우저 측 (`pdmg-ui`)

| 파일 | 역할 |
|------|------|
| `_shared/service-client.js` | `fetch(targetUrl)` 직접 POST |
| `online-single.js` / `imagelog.js` / `txparam.js` | service-client 사용 |
| `/api/config` | `targetBaseUrl`, `timeoutMs` 초기값만 UI에서 조회 |

```text
PdmgServiceClient.post(
  'http://localhost:8080/mgcoa8888S0',
  { hdr_nhnis, dto },
  timeoutMs
)
```

UI `pdmg.ui.timeout-ms`(Abort)와 서버 `nhnis.fw.timeout`(5000ms)은 **별개**.

중계 API(`POST /api/relay/{id}`)는 하위 호환으로 남아 있으나 **화면은 사용하지 않는다.**

## 5. 요청 시퀀스

```text
1. 브라우저: Origin: http://localhost:8090
2. (필요 시) OPTIONS /mgcoa8888S0
     → CorsFilter 응답
       Access-Control-Allow-Origin: http://localhost:8090
       Access-Control-Allow-Methods: GET, POST, OPTIONS
       Access-Control-Allow-Headers: ...
3. POST /mgcoa8888S0  + JSON 전문
     → DefaultFilter → Interceptor → OnlineController → …
4. 응답에도 Allow-Origin 헤더 → JS가 body 읽기 가능
```

> **오류 경로 주의:** `DefaultFilter`는 `Ordered.HIGHEST_PRECEDENCE + 20`으로 등록된다. JWT 없음, Body 없음, JSON 오류 등으로 Filter가 `sendError(401/400)` 후 종료하면 뒤의 Security CORS 처리까지 도달하지 않아 `Access-Control-Allow-Origin`이 빠질 수 있다. 이 경우 브라우저에는 실제 400/401 대신 CORS 또는 네트워크 오류처럼 보일 수 있다. 오류 POST에도 CORS 헤더가 붙는지 반드시 통합 테스트한다.

## 6. 확인 방법

### 6.1 브라우저 DevTools

- Network: OPTIONS 204/200 후 POST  
- Response Headers에 `Access-Control-Allow-Origin: http://localhost:8090`  
- Console에 CORS 에러 없음

### 6.2 curl (preflight 흉내)

```bash
curl -i -X OPTIONS "http://localhost:8080/mgcoa8888S0" ^
  -H "Origin: http://localhost:8090" ^
  -H "Access-Control-Request-Method: POST" ^
  -H "Access-Control-Request-Headers: content-type"
```

`Access-Control-Allow-Origin`이 보이면 서버 CORS는 살아 있다.

### 6.3 흔한 실패

| 증상 | 원인 |
|------|------|
| CORS blocked / No ACAO | `allowed-origins` 비었거나 origin 불일치 (`127.0.0.1` vs `localhost`) |
| OPTIONS 400 Body empty | `DefaultFilter`가 OPTIONS를 스킵하지 않음 |
| POST만 되고 preflight 실패 | Security CORS Bean 미연결 · 매핑이 `/api/**`만 |
| 로컬은 되고 배포만 실패 | 실제 UI origin이 yml에 없음 |
