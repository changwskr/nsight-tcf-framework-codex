## 업무 거래 직접 호출 흐름

현재 일반 업무 화면은 브라우저에서 `pdmg-service`를 직접 호출합니다.

```text
사용자
  │
  ▼
업무 화면
  │
  ├─ /api/config 조회
  │      ├─ targetBaseUrl = http://localhost:8080
  │      └─ timeoutMs = 10000
  │
  ├─ /api/transactions 조회
  │      └─ Service ID·API 경로 확인
  │
  ▼
online-single.js
  │
  ├─ 입력 JSON 확인
  ├─ hdr_nhnis 생성·보완
  ├─ GUID 생성
  └─ Service ID 설정
  │
  ▼
service-client.js
  │
  ├─ 대상 URL 생성
  │      예: http://localhost:8080/mgcoa5530S0
  │
  ├─ AbortController 타이머 시작
  └─ Fetch POST 요청
  │
  ▼
pdmg-service
  │
  ├─ pdmg-fw DefaultFilter
  ├─ TCF 또는 업무 Controller
  ├─ Handler → Facade → Service
  └─ DAO → DB
  │
  ▼
JSON 응답
  │
  ▼
service-client.js
  │
  ├─ HTTP 상태
  ├─ 처리시간
  └─ 응답 Body
  │
  ▼
화면 결과 또는 오류 팝업
```

## 서버 중계 구조

이전 화면과 호환하기 위한 서버 측 중계 기능도 남아 있습니다.

```text
사용자 브라우저
      │
      │ POST /api/relay/{serviceId}
      ▼
PdmgUiApiController
      │
      ▼
TransactionCatalog
      │
      └─ Service ID에 해당하는 경로 조회
      │
      ▼
TransactionRelayService
      │
      ├─ targetBaseUrl 결합
      ├─ Spring RestClient 사용
      └─ pdmg-service POST 호출
      │
      ▼
pdmg-service
      │
      ▼
RelayResult
      │
      ├─ transactionId
      ├─ targetUrl
      ├─ httpStatus
      ├─ elapsedMs
      └─ responseBody
      │
      ▼
사용자 브라우저
```

현행 업무 화면은 직접 호출 방식이고, Relay API는 호환용으로 유지됩니다.

## UI 타임아웃 구조

```text
application.yml
│
├─ target-base-url: http://localhost:8080
└─ timeout-ms: 10000
          │
          ▼
     service-client.js
          │
          ├─ AbortController 생성
          ├─ 10초 타이머 시작
          └─ pdmg-service 호출
          │
          ├─ 10초 이내 응답
          │      └─ 정상 결과 처리
          │
          └─ 10초 초과
                 ├─ fetch 요청 취소
                 ├─ HTTP 504 형식 변환
                 └─ UI_TIMEOUT 표시
```

UI 타임아웃은 `pdmg-fw` 서버 타임아웃과 별개입니다.

```text
pdmg-ui 타임아웃       : 브라우저 대기 제한 10초
pdmg-fw 타임아웃       : 서버 업무 실행 제한
DB 트랜잭션 타임아웃   : 데이터베이스 작업 제한
```

## pdmg-ui의 핵심 책임

```text
pdmg-ui
 ├─ 업무 화면 제공
 ├─ 거래 카탈로그 표시
 ├─ 표준 요청 전문 작성
 ├─ Service ID와 GUID 설정
 ├─ pdmg-service 직접 호출
 ├─ UI 요청 타임아웃 처리
 ├─ HTTP 응답과 처리시간 표시
 ├─ 표준 오류 팝업 제공
 ├─ 거래 통제·파라미터 관리
 ├─ 실시간 거래 진단
 ├─ JWT 로그인·토큰 관리
 ├─ JWT 세션을 sessionStorage에 보관
 └─ JWKS Public Key 조회
```

현재 일반 업무 요청을 만드는 `service-client.js`에는 `Authorization` 헤더 설정이 없습니다. 따라서 `pdmg-service`에서 JWT 검증을 활성화하면 일반 업무 화면도 `sessionStorage`의 Access Token을 읽어 `Authorization: Bearer ...` 헤더를 전달하도록 통합해야 합니다.
