# pdmg-ui 로그인 JWT → pdmg-service 선처리 검증 확인

## 확인 결과 (요약)

| 기대 | 실제 |
|------|------|
| UI 로그인 토큰을 service로 올린다 | **현재 UI 전문 호출은 올리지 않음** |
| **시스템 선처리**(`ServicePreventionInterceptor`)에서 검증 | **검증하지 않음** |
| 토큰 검증이 일어나는 곳 | **`DefaultFilter` → `JwtProvider`** (non-local만) |
| 로그인(RS256) 토큰을 Filter에 넣으면 통과? | **비정합 → 통과 불가(401 가능)** |

즉, “올려주면 선처리에서 검증한다”는 **현재 코드 기준으로 성립하지 않는다.**

---

## 1. UI가 토큰을 올리는가

| 경로 | Authorization |
|------|----------------|
| JWT 로그인 (`jwt-admin.js` → pdmg-jwt `:8110`) | 발급만, sessionStorage 저장 |
| 전문 테스트 (`service-client.js` / `online-single.js` → `:8080`) | **헤더에 Bearer 없음** |

`service-client.js` fetch headers:

```text
Content-Type: application/json;charset=UTF-8
Accept: application/json
```

로그인으로 받은 `accessToken`은 **자동으로 pdmg-service에 전달되지 않는다.**

---

## 2. “선처리”에서 검증하는가

문서 [40](./40.시스템%20선처리에서%20어떤%20필터를%20처리하는가.md) 기준 **시스템 선처리** = `ServicePreventionInterceptor`.

- GUID / `ServiceContext` / ImageLog 등
- **JWT·Authorization 검사 코드 없음**

검증은 Interceptor **앞단** Filter에서만 한다.

```text
HTTP
  → DefaultFilter          ★ JWT (non-local)
       → ServicePreventionInterceptor   ← 시스템 선처리 (JWT 없음)
            → Controller / TCF
```

---

## 3. Filter 검증 조건 (올려줬을 때)

`DefaultFilter` (POST, Filter 대상 URI):

1. `spring.profiles.active` **≠ local** 일 때만 JWT 블록 실행  
2. `Authorization: Bearer …` 필수  
3. `JwtProvider.validate` (HS256 + `jwt.secret`)  
4. `JwtProvider.isAccessToken` → claim **`type == "ACCESS"`**  
5. subject → `request.setAttribute("ssoId", …)`

**local**이면 토큰을 올려도 **검증하지 않고** 통과한다 (올려준 사실과 무관).

---

## 4. 로그인 토큰과의 정합

| | pdmg-jwt 발급 (`JwtTokenIssuer`) | pdmg-service (`JwtProvider`) |
|--|----------------------------------|------------------------------|
| 알고리즘 | **RS256** | **HS256** (`jwt.secret`) |
| `type` claim | **없음** (DB/store의 tokenType과는 별개) | **`ACCESS` 필수** |

→ non-local에서 UI 로그인 Access Token을 Bearer로 넣어도  
`validate` 실패 또는 `isAccessToken` 실패로 **401**이 나는 구조다.

---

## 5. “확인”을 통과시키려면 (현재 갭)

1. UI 전문 호출에 `Authorization: Bearer {session.accessToken}` 추가  
2. service를 **non-local**로 기동해 Filter JWT 경로를 타게 함  
3. 발급·검증 정합 (예: service가 JWKS/RS256 검증 + `type` claim 정책 통일)

위가 되기 전에는 “올려주면 선처리에서 검증”을 **실측 확인할 수 없다.**
