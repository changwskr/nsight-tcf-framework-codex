## 9. 트랜잭션 롤백

```text
Facade
@Transactional(
    transactionManager = "rdwTransactionManager",
    rollbackFor = Exception.class
)
   │
   ├────────────── TX BEGIN
   │
   ├─ DAO INSERT
   ├─ DAO UPDATE
   ├─ 업무 후처리 INSERT
   │
   └─ Exception 발생
          │
          ▼
       ROLLBACK
          │
          ├─ INSERT 취소
          ├─ UPDATE 취소
          └─ 업무 후처리 INSERT 취소
```

예외는 트랜잭션 프록시 밖으로 전달되어야 합니다.

```text
Service 예외
   → Aspect 예외 재전파
   → Facade 밖으로 예외 전파
   → Spring TransactionInterceptor 감지
   → ROLLBACK
```

## 10. 예외를 삼킨 경우

```text
Service
   │
   ▼
try {
    dao.update();
} catch (Exception e) {
    log.error(...);
    return 정상 응답;
}
   │
   ▼
Facade 정상 종료
   │
   ▼
COMMIT
```

이 방식은 부분 데이터가 커밋될 위험이 있습니다.

권장:

```text
catch (Exception e)
   │
   ├─ 오류 로그
   └─ throw e
          │
          ▼
       ROLLBACK
```

또는 명시적으로:

```java
TransactionAspectSupport
    .currentTransactionStatus()
    .setRollbackOnly();
```

그러나 기본 원칙은 예외 재전파입니다.

## 11. 업무 후처리 예외

```text
Facade TX BEGIN
   │
   ▼
BizPre
   │
   ▼
Service
   │
   ├─ 업무 DB UPDATE 성공
   │
   ▼
BizPost
   │
   └─ 업무 이력 INSERT 실패
          │
          ▼
       예외 재전파
          │
          ▼
Facade ROLLBACK
   │
   ├─ 업무 UPDATE 취소
   └─ 이력 INSERT 취소
```

오류 이력을 반드시 남겨야 한다면 별도 트랜잭션을 사용합니다.

```text
오류 발생
   │
   ▼
ErrorHistoryService
   │
   │ propagation = REQUIRES_NEW
   ▼
오류 이력 별도 COMMIT
   │
   ▼
원래 예외 재전파
   │
   ▼
본 업무 ROLLBACK
```

## 12. 타임아웃 예외

```text
업무 실행
   │
   ▼
제한시간 초과
   │
   ▼
OnlineTimeoutException
   │
   ▼
Facade 트랜잭션 내부에서 발생했는가?
   │
   ├─ 예
   │    ├─ 작업 취소
   │    └─ ROLLBACK
   │
   └─ 아니오
        └─ 이미 COMMIT된 데이터는 롤백 불가
   │
   ▼
GlobalExceptionHandler
   │
   └─ HTTP 504 Gateway Timeout
```

권장 순서:

```text
Facade TX BEGIN
   → TimeoutExecutor
   → Service / DAO
   → 제한시간 초과
   → OnlineTimeoutException
   → Facade 밖으로 전파
   → ROLLBACK
```

## 17. Context 정리

예외가 발생해도 Context는 반드시 제거해야 합니다.

```text
정상 또는 예외
   │
   ▼
Interceptor.afterCompletion
   │
   ▼
DefaultFilter.finally
   │
   ├─ ServiceContextHolder.remove()
   ├─ MDC.remove()
   └─ ThreadContext.clear()
```

정리하지 않으면 Thread Pool 재사용 시 이전 사용자의 정보가 다음 요청에 남을 수 있습니다.
