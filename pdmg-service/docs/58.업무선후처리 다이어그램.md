# 업무 선·후처리 아키텍처 텍스트 다이어그램

## 1. 전체 구조

현재 기준으로 `BizPrePostAspect`의 포인트컷은 Business Service 메서드입니다.

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ pdmg-fw                                                                     │
│                                                                              │
│ OnlineTransactionController                                                 │
│      │                                                                       │
│      ▼                                                                       │
│ TcfFacade                                                                    │
│      │                                                                       │
│      ▼                                                                       │
│ TransactionDispatcher                                                       │
└──────┼───────────────────────────────────────────────────────────────────────┘
       │
       ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ pdmg-service                                                                │
│                                                                              │
│ TransactionHandler                                                          │
│      │                                                                       │
│      ▼                                                                       │
│ Business Facade                                                             │
│      │                                                                       │
│      ├──────────────────── 트랜잭션 BEGIN                                   │
│      │                                                                       │
│      ▼                                                                       │
│ BizPrePostAspect                                                             │
│      │                                                                       │
│      ├─ ① 업무 선처리                                                      │
│      │                                                                       │
│      ▼                                                                       │
│ Business Service                                                            │
│      │                                                                       │
│      ├─ ② 본 업무 처리                                                    │
│      │                                                                       │
│      ▼                                                                       │
│ Rule → DAO → Mapper → DB                                                    │
│      │                                                                       │
│      ▼                                                                       │
│ BizPrePostAspect                                                             │
│      │                                                                       │
│      ├─ ③ 업무 후처리                                                      │
│      │                                                                       │
│      ▼                                                                       │
│ Business Facade                                                             │
│      │                                                                       │
│      ├─ 정상: COMMIT                                                        │
│      └─ 예외: ROLLBACK                                                      │
└──────┼───────────────────────────────────────────────────────────────────────┘
       │
       ▼
pdmg-fw ETF 시스템 후처리
```

핵심 실행 순서는 다음과 같습니다.

```text
Facade @Transactional BEGIN
    → BizPrePostAspect 업무 선처리
    → Business Service
    → DAO / SQL
    → BizPrePostAspect 업무 후처리
    → Facade @Transactional COMMIT
```

## 2. 포인트컷 구조

```text
Handler
   │
   ▼
Business Facade
   │
   │ @Transactional
   ▼
Business Service Proxy
   │
   ├─ BizPrePostAspect 적용
   │
   ▼
실제 Service 메서드
```

포인트컷의 개념적인 대상은 다음과 같습니다.

```text
nhnis.mg.*.*.application.service.*Service.*
                         │
                         └─ 업무 Service 메서드
```

예:

```text
mgcoa5530Facade.mgcoa5530S0()
        │
        ▼
mgcoa5530Service.mgcoa5530S0()
        ▲
        │
BizPrePostAspect 포인트컷 적용
```

포인트컷이 Service에 있으므로 Facade가 시작한 트랜잭션 안에서 업무 선처리와 후처리가 실행됩니다.

## 3. `@Around` 처리 구조

```text
Business Facade
      │
      ▼
BizPrePostAspect.around()
      │
      ├─ Service ID 확인
      ├─ ServiceContext 확인
      ├─ 업무 선처리 실행
      │
      ▼
ProceedingJoinPoint.proceed()
      │
      ▼
Business Service
      │
      ▼
Rule → DAO → Mapper → DB
      │
      ▼
Service 결과 반환
      │
      ▼
업무 후처리 실행
      │
      ▼
Aspect 결과 반환
      │
      ▼
Business Facade
```

개념적인 구현:

```java
@Around("businessServicePointcut()")
public Object process(ProceedingJoinPoint joinPoint) throws Throwable {
    Object result = null;

    try {
        // 업무 선처리
        bizPreProcess(joinPoint);

        // 실제 Business Service 실행
        result = joinPoint.proceed();

        // 정상 업무 후처리
        bizPostProcess(joinPoint, result);

        return result;

    } catch (Throwable throwable) {
        // 오류 업무 후처리
        bizErrorProcess(joinPoint, throwable);

        // 트랜잭션 롤백을 위해 반드시 예외 재전파
        throw throwable;
    }
}
```

## 4. 업무 선처리 상세

```text
BizPrePostAspect
      │
      ▼
업무 선처리
      │
      ├─ ServiceContext 조회
      ├─ GUID 조회
      ├─ Service ID 조회
      ├─ 사용자 ID 조회
      ├─ 영업점 ID 조회
      ├─ 채널 ID 조회
      ├─ 업무 입력값 확인
      ├─ 업무 실행 로그
      ├─ 업무 공통 검증
      └─ 필요 시 사전 이력 저장
      │
      ├─ 정상
      │    └─ Business Service 실행
      │
      └─ 오류
           ├─ Business Service 실행 차단
           └─ 예외를 Facade 밖으로 전파
```

선처리에서 예외가 발생하면:

```text
업무 선처리
   │
   │ 예외 발생
   ▼
Business Service 호출 안 됨
   │
   ▼
Aspect가 예외 재전파
   │
   ▼
Facade 트랜잭션 ROLLBACK
```

## 5. 정상 업무 후처리

```text
Business Service 정상 종료
      │
      ▼
BizPrePostAspect
      │
      ├─ Service 결과 확인
      ├─ 업무 성공 상태 설정
      ├─ 처리 건수 확인
      ├─ 업무 성공 로그
      ├─ 업무 이력 등록·수정
      └─ 후속 업무 공통 처리
      │
      ▼
Facade로 결과 반환
      │
      ▼
트랜잭션 COMMIT
```

현재 후처리는 Service 실행 직후이면서 Facade 트랜잭션이 종료되기 전에 수행됩니다.

```text
┌──────────────────── Facade 트랜잭션 ────────────────────┐
│                                                         │
│ BizPre → Service → DAO → BizPost → COMMIT               │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

따라서 후처리에서 같은 DataSource로 실행한 `INSERT`, `UPDATE`, `DELETE`는 본 업무와 같은 트랜잭션에 참여할 수 있습니다.

## 6. 후처리에서 UPDATE를 수행하는 경우

```text
Facade TX BEGIN
   │
   ▼
BizPre
   │
   ▼
Business Service
   │
   ├─ 업무 데이터 UPDATE
   │
   ▼
BizPost
   │
   ├─ 업무 이력 한 건 UPDATE
   │
   ▼
Facade 정상 종료
   │
   ▼
COMMIT
```

같은 트랜잭션으로 묶이기 위한 조건:

```text
1. Facade에 @Transactional 적용
2. Aspect 포인트컷이 Service 메서드
3. BizPost가 joinPoint.proceed() 직후 실행
4. 같은 rdwTransactionManager 사용
5. 같은 RDW DataSource 사용
6. 별도 Thread를 사용하지 않음
7. REQUIRES_NEW를 사용하지 않음
8. 후처리 예외를 삼키지 않고 다시 전파
```

전체 결과:

```text
본 업무 UPDATE 성공
후처리 UPDATE 성공
        │
        ▼
둘 다 COMMIT
```

```text
본 업무 UPDATE 성공
후처리 UPDATE 실패
        │
        ▼
전체 ROLLBACK
```

## 7. 오류 업무 후처리

```text
Business Service
      │
      │ Exception 발생
      ▼
BizPrePostAspect catch
      │
      ├─ 오류 정보 수집
      ├─ Service ID 확인
      ├─ GUID 확인
      ├─ 업무 실패 로그
      ├─ 오류 이력 처리
      └─ 예외 재전파
      │
      ▼
Business Facade
      │
      ▼
트랜잭션 ROLLBACK
```

중요한 원칙:

```text
catch (Throwable e)
    │
    ├─ 업무 오류 후처리
    └─ throw e
```

예외를 정상 결과로 바꾸면 안 됩니다.

```text
잘못된 처리

catch (Exception e)
    │
    └─ return 빈 응답
             │
             ▼
Spring은 정상 종료로 판단
             │
             ▼
COMMIT 가능
```

## 8. 오류 이력을 반드시 남겨야 하는 경우

오류 후처리 이력을 본 업무와 같은 트랜잭션으로 저장하면 본 업무 롤백 시 오류 이력도 함께 롤백됩니다.

```text
본 업무 트랜잭션
   │
   ├─ 업무 DB 변경
   ├─ 예외 발생
   ├─ 오류 이력 INSERT
   └─ 전체 ROLLBACK
          │
          └─ 오류 이력도 사라짐
```

오류 이력을 반드시 남기려면 별도 Bean과 `REQUIRES_NEW`를 사용합니다.

```text
Business Service 오류
      │
      ▼
BizPrePostAspect
      │
      ▼
ErrorHistoryService
      │
      │ @Transactional(
      │     transactionManager = "rdwTransactionManager",
      │     propagation = REQUIRES_NEW
      │ )
      ▼
오류 이력 INSERT
      │
      └─ 별도 COMMIT
      │
      ▼
원래 예외 재전파
      │
      ▼
본 업무 트랜잭션 ROLLBACK
```

결과:

```text
본 업무 데이터     : ROLLBACK
오류 이력 데이터   : COMMIT
```

## 11. 자기 호출 문제

같은 Service 내부에서 자기 메서드를 호출하면 Spring AOP 프록시를 다시 통과하지 않습니다.

```text
외부 호출
   │
   ▼
Service Proxy
   │
   ├─ BizPre
   ▼
service.methodA()
   │
   └─ this.methodB()
          │
          └─ Aspect 다시 실행되지 않음
   │
   ▼
BizPost
```

즉 다음 호출에는 선후처리가 한 번만 적용됩니다.

```java
public void methodA() {
    this.methodB();
}
```

두 거래를 각각 독립적으로 선후처리해야 한다면 다른 Spring Bean으로 분리해야 합니다.

## 12. 비동기·별도 Thread 사용 시

```text
Facade 트랜잭션 Thread
      │
      ├─ BizPre
      ├─ Service
      └─ 비동기 작업 제출
              │
              ▼
        별도 Thread
              │
              ├─ 기존 Transaction 전달 안 됨
              ├─ ServiceContext ThreadLocal 전달 안 됨
              └─ MDC 자동 전달 안 됨
```

따라서 같은 트랜잭션으로 처리해야 하는 업무 후처리는 `@Async`, `CompletableFuture`, 별도 Executor에서 실행하면 안 됩니다.

## 13. 업무와 시스템 선후처리 관계

```text
DefaultFilter
   │
   └─ HTTP 공통 선처리
   │
   ▼
Interceptor.preHandle
   │
   └─ 거래 통제
   │
   ▼
STF
   │
   └─ 시스템 선처리
   │
   ▼
Facade TX BEGIN
   │
   ├─ BizPre
   │    └─ 업무 선처리
   │
   ├─ Business Service
   │
   ├─ BizPost
   │    └─ 업무 후처리
   │
   └─ COMMIT / ROLLBACK
   │
   ▼
ETF
   │
   └─ 시스템 후처리
```

구분:

```text
┌─────────────────────┬───────────────────────────┬──────────────────────┐
│ 구분                │ 실행 위치                 │ 업무 TX 포함 여부    │
├─────────────────────┼───────────────────────────┼──────────────────────┤
│ HTTP 선처리         │ DefaultFilter             │ 미포함               │
│ 거래 통제           │ Interceptor.preHandle     │ 미포함               │
│ 시스템 선처리       │ STF                       │ 미포함               │
│ 업무 선처리         │ BizPrePostAspect.before   │ 포함                  │
│ 본 업무             │ Business Service          │ 포함                  │
│ 업무 후처리         │ BizPrePostAspect.after    │ 포함                  │
│ 시스템 후처리       │ ETF                       │ 일반적으로 미포함     │
└─────────────────────┴───────────────────────────┴──────────────────────┘
```

## 14. 최종 요약

```text
Handler
   │
   ▼
Facade
   │
   ├════════════════ 트랜잭션 BEGIN ════════════════╗
   ║                                                ║
   ║ BizPrePostAspect                               ║
   ║   ├─ 업무 선처리                               ║
   ║   │                                            ║
   ║   ├─ Service 실행                              ║
   ║   │    └─ Rule → DAO → DB                     ║
   ║   │                                            ║
   ║   ├─ 정상: 업무 후처리                         ║
   ║   │                                            ║
   ║   └─ 오류: 오류 후처리 + 예외 재전파           ║
   ║                                                ║
   ├════════ 정상 COMMIT / 예외 ROLLBACK ═══════════╝
   │
   ▼
ETF 시스템 후처리
```

업무 선후처리에서 실행되는 DB 변경을 본 업무와 같이 묶으려면 `Facade 트랜잭션 안에서 Service 포인트컷으로 실행`하는 현재 구조를 유지해야 합니다.
