# pdmg-service에서 JWT 토큰을 받으면 누가 검증하는가

**검증 주체:** `pdmg-fw`의 `DefaultFilter` → `JwtProvider`

업무 Controller/Handler/Service는 토큰을 직접 검증하지 않는다.

---

## 1. 호출 위치

```text
HTTP 요청 (Authorization: Bearer …)
  → DefaultFilter.doFilterInternal
       ├─ (local 프로파일) JWT 검증 생략 → 통과
       └─ (그 외) JwtProvider.validate / isAccessToken
  → ServicePreventionInterceptor
  → Controller / TCF …
```

소스:

| 클래스 | 역할 |
|--------|------|
| `nhnis.fw.commons.filter.DefaultFilter` | 헤더 추출·검증 분기·실패 시 401 |
| `nhnis.fw.commons.jwt.JwtProvider` | 서명 검증·claim 조회 |

활성: `nhnis.fw.commons.filter.enabled=true`

---

## 2. DefaultFilter 검증 조건

`spring.profiles.active` 가 **`local`이 아닐 때**만 수행한다.

1. `Authorization` 헤더 존재
2. 값이 `Bearer ` 로 시작
3. `jwtProvider.validate(token)` → 서명·만료 등
4. `jwtProvider.isAccessToken(token)` → claim `type` == `"ACCESS"`
5. 성공 시 `request.setAttribute("ssoId", subject)`

실패 시:

- Access Token 없음 → 401
- 유효하지 않은 Token → 401
- Access Token이 아님 → 401

`local`이면 위 블록 전체를 건너뛴다.

---

## 3. JwtProvider 검증 방식 (현행)

```java
// jwt.secret 기반 HMAC (HS256)
Jwts.parser().verifyWith(key).build().parseSignedClaims(token);
```

설정: `application.yml` 의 `jwt.secret`  
Access 여부: payload claim `type` == `ACCESS`

---

## 4. 검증하지 않는 계층

| 계층 | JWT 검증 |
|------|----------|
| OnlineTransactionController / Handler / Facade / Service | 안 함 |
| ServicePreventionInterceptor | 안 함 (Context·ImageLog) |
| GlobalExceptionHandler | 안 함 |

Filter를 통과한 뒤의 업무 코드는 이미 인증된 요청으로 본다 (non-local).

---

## 5. Filter를 건너뛰는 요청

`shouldNotFilter` 대상은 JWT 검사도 없다.

- OPTIONS, GET
- `/actuator/**`, `/.well-known/**`
