# PDMG Naming 텍스트 다이어그램

기준 문서는 [MG-NAMING_CONVENTION.md](</C:/Programming(23-08-15)/nsight-tcf-framework-codex/pdmg-service/docs/MG-NAMING_CONVENTION.md>)입니다.

## 1. Service ID 전체 구조

```text
┌──────────┬──────────┬──────────┬──────────────┬──────────┬──────────┐
│ 대구분   │ 업무구분 │ 세부업무 │ 식별번호     │ 거래구분 │ 순번     │
│ 2자리    │ 2자리    │ 1자리    │ 4자리        │ 1자리    │ 1자리    │
└────┬─────┴────┬─────┴────┬─────┴──────┬───────┴────┬─────┴────┬─────┘
     │          │          │            │            │          │
     ▼          ▼          ▼            ▼            ▼          ▼
    mg         co          a           5530          S          0
     │          │          │            │            │          │
     │          │          │            │            │          └─ 동일 기능 순번
     │          │          │            │            └──────────── 거래 유형
     │          │          │            └───────────────────────── 프로그램 식별번호
     │          │          └────────────────────────────────────── 세부업무
     │          └───────────────────────────────────────────────── 업무구분
     └──────────────────────────────────────────────────────────── 시스템 대구분
```

조합 결과:

```text
mg + co + a + 5530 + S + 0
                 │
                 ▼
          mgcoa5530S0
```

## 2. 구성요소 의미

```text
mgcoa5530S0
│ │ │  │  ││
│ │ │  │  │└─ 순번: 0
│ │ │  │  └── 거래구분: S
│ │ │  └───── 식별번호: 5530
│ │ └──────── 세부업무: a
│ └────────── 업무구분: co
└──────────── 시스템 대구분: mg
```

```text
mg
└─ Marketing 또는 PDMG 시스템 대구분

co
└─ 업무구분 코드

a
└─ 세부업무 코드

5530
└─ 프로그램 식별번호

S
└─ 조회 거래

0
└─ 동일 기능 내 순번
```

## 3. 거래구분 코드

```text
┌──────────┬──────────────┬───────────────────────┐
│ 코드     │ 의미         │ 사용 예               │
├──────────┼──────────────┼───────────────────────┤
│ S        │ Select       │ 목록·상세 조회        │
│ C        │ Create       │ 신규 등록             │
│ U        │ Update       │ 데이터 수정           │
│ D        │ Delete       │ 데이터 삭제·폐기      │
│ A        │ Action       │ 일반 업무 실행        │
│ R        │ Report       │ 보고서·출력 처리      │
└──────────┴──────────────┴───────────────────────┘
```

예시:

```text
mgcoa8888S0  이미지 로그 목록 조회
mgcoa8888D0  이미지 로그 삭제

mgcoa9000S0  거래 파라미터 조회
mgcoa9000C0  거래 파라미터 등록
mgcoa9000U0  거래 파라미터 수정
mgcoa9000D0  거래 파라미터 삭제
```

## 4. 프로그램 ID와 Service ID 관계

```text
프로그램 ID
mgcoa8888
    │
    ├─ 조회 ───────────────▶ mgcoa8888S0
    │
    ├─ 등록 ───────────────▶ mgcoa8888C0
    │
    ├─ 수정 ───────────────▶ mgcoa8888U0
    │
    └─ 삭제 ───────────────▶ mgcoa8888D0
```

하나의 프로그램 ID 아래에 여러 Service ID가 존재할 수 있습니다.

```text
                    mgcoa8888
                         │
        ┌────────────────┼────────────────┐
        │                │                │
        ▼                ▼                ▼
   mgcoa8888S0       mgcoa8888D0      mgcoa8888D1
   목록 조회          단건 삭제         일괄 삭제
```

## 5. Java 클래스 네이밍

```text
Service ID: mgcoa8888S0
                  │
                  ├─ 프로그램 접두: mgcoa8888
                  └─ 거래 접미: S0
```

프로그램 단위 클래스:

```text
mgcoa8888
   │
   ├─ mgcoa8888Handler
   ├─ mgcoa8888Facade
   ├─ mgcoa8888Controller
   ├─ mgcoa8888Service
   └─ mgcoa8888DAO
```

거래 단위 클래스:

```text
mgcoa8888S0
   │
   ├─ mgcoa8888S0DTOin
   ├─ mgcoa8888S0DTOout
   ├─ mgcoa8888S0DTOSub0
   └─ mgcoa8888S0DTO*MsgJson
```

핵심 기준은 다음과 같습니다.

```text
Handler / Facade / Controller / Service / DAO
    └─ 프로그램 ID까지만 사용
       예: mgcoa8888Service

DTO / URL / 메서드 / SQL ID
    └─ 전체 Service ID 사용
       예: mgcoa8888S0DTOin
```

## 6. 컴포넌트 네이밍 구조

```text
                         mgcoa8888
                              │
       ┌──────────────┬───────┼────────┬──────────────┐
       │              │       │        │              │
       ▼              ▼       ▼        ▼              ▼
    Handler         Facade Controller Service         DAO
       │              │       │        │              │
       ▼              ▼       ▼        ▼              ▼
mgcoa8888Handler       │       │        │       mgcoa8888DAO
                mgcoa8888Facade│   mgcoa8888Service
                        mgcoa8888Controller
```

거래 메서드는 전체 Service ID를 사용합니다.

```text
mgcoa8888Handler
   │
   ├─ serviceIds()
   │    ├─ mgcoa8888S0
   │    └─ mgcoa8888D0
   │
   └─ handle()
        ├─ S0 → facade.mgcoa8888S0(...)
        └─ D0 → facade.mgcoa8888D0(...)
```

## 10. SQL Statement ID

권장 구조:

```text
[Service ID]_[SQL 구분][순번]
```

예시:

```text
mgcoa8888S0_S0
│           ││
│           │└─ SQL 순번
│           └── SELECT
└────────────── Service ID
```

```text
mgcoa9000S0_S0  첫 번째 조회 SQL
mgcoa9000C0_I0  첫 번째 등록 SQL
mgcoa9000U0_U0  첫 번째 수정 SQL
mgcoa9000D0_D0  첫 번째 삭제 SQL
```

SQL 구분:

```text
S : SELECT
I : INSERT
U : UPDATE
D : DELETE
```

전체 호출 관계:

```text
Service 메서드
mgcoa8888S0()
      │
      ▼
DAO 메서드
mgcoa8888S0_S0(...)
      │
      ▼
Mapper Statement ID
mgcoa8888S0_S0
```

## 11. DTO 네이밍

```text
[Service ID] + DTO + [역할]
```

입력 DTO:

```text
mgcoa8888S0 + DTOin
        │
        ▼
mgcoa8888S0DTOin
```

출력 DTO:

```text
mgcoa8888S0 + DTOout
        │
        ▼
mgcoa8888S0DTOout
```

목록 행 DTO:

```text
mgcoa8888S0 + DTOSub + 0
        │
        ▼
mgcoa8888S0DTOSub0
```

관계:

```text
mgcoa8888S0DTOin
        │
        ▼
    업무 조회
        │
        ▼
mgcoa8888S0DTOout
        │
        └─ List<mgcoa8888S0DTOSub0>
```

## 12. URL 네이밍

```text

POST /mgcoa8888D0
```

```text

      │
      ▼
hdr_nhnis.sys_comm.rms_svc_c
      │
      └─ mgcoa8888S0
```

## 15. 최종 네이밍 공식

```text
프로그램 ID
= 대구분 + 업무구분 + 세부업무 + 식별번호

Service ID
= 프로그램 ID + 거래구분 + 순번

컴포넌트 클래스
= 프로그램 ID + 컴포넌트 접미사

DTO
= Service ID + DTO 역할

Java 패키지
= nhnis.대구분.업무구분.세부업무.계층

Mapper 경로
= rdw.대구분.업무구분.세부업무

Mapper 파일
= 프로그램 ID-DB구분.xml

URL
= /Service ID
```
