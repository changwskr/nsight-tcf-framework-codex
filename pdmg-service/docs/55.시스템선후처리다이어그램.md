## 2. 시스템 선처리 상세 흐름

```text
HTTP 요청
   │
   ▼
DefaultFilter
   │
   ├─ Content-Type 확인
   ├─ 요청 Body 캐싱
   ├─ Authorization 헤더 확인
   ├─ Access Token 검증
   ├─ 사용자 ID 추출
   ├─ GUID 생성
   ├─ MDC에 GUID 저장
   ├─ 표준 Header 생성·보완
   └─ ServiceContextHolder 설정
   │
   ▼
ServicePreventionInterceptor.preHandle
   │
   ├─ ServiceContext 조회
   ├─ 요청 Header·Body 확인
   ├─ Service ID 추출
   ├─ 요청 데이터 유효성 확인
   └─ 거래 통제 수행
          │
          ├─ 서비스별 통제
          ├─ 사용자별 통제
          ├─ IP별 통제
          ├─ 영업점별 통제
          ├─ 채널별 통제
          └─ 시간대별 통제
   │
   ├─ 통과
   │    └─ Controller로 진행
   │
   └─ 거부
        └─ Controller 호출 없이 오류 응답
```

## 3. STF 시스템 선처리

```text
OnlineTransactionController
        │
        ▼
TcfFacade
        │
        ▼
STF
        │
        ├─ 거래 시작 로그
        ├─ TransactionContext 확인
        ├─ Service ID 확인
        ├─ GUID 확인
        ├─ ServiceContext 확인
        ├─ 시스템 필수값 검증
        ├─ 거래 시작 시간 기록
        └─ 업무 실행 가능 상태 확인
        │
        ├─ 정상
        │    └─ TransactionDispatcher 실행
        │
        └─ 오류
             ├─ 업무 Handler 호출 차단
             └─ 시스템 오류 처리
```

STF는 업무 로직이 실행되기 직전의 TCF 시스템 선처리입니다.

```text
HTTP 공통 선처리             TCF 거래 선처리
─────────────────────       ─────────────────────
DefaultFilter                STF
Interceptor.preHandle        TransactionContext 기준
요청·인증·거래 통제          거래 실행 직전 검증
```

## 4. 업무 실행 구간

```text
STF 완료
   │
   ▼
TransactionDispatcher
   │
   ├─ Service ID에 대응하는 Handler 검색
   └─ Handler 호출
   │
   ▼
pdmg-service TransactionHandler
   │
   ▼
Business Facade
   │
   ├───────────── 트랜잭션 BEGIN
   │
   ▼
BizPrePostAspect.before
   │
   └─ 업무 선처리
   │
   ▼
Business Service
   │
   ▼
Rule → DAO → Mapper → DB
   │
   ▼
BizPrePostAspect.after
   │
   └─ 업무 후처리
   │
   ▼
Business Facade
   │
   ├─ 정상: COMMIT
   └─ 예외: ROLLBACK
   │
   ▼
업무 결과 반환
```

## 5. ETF 시스템 후처리

```text
업무 Handler 처리 완료
        │
        ▼
TcfFacade
        │
        ▼
ETF
        │
        ├─ 업무 처리 결과 확인
        ├─ 시스템 후처리 실행
        ├─ 거래 종료 상태 기록
        ├─ 처리 경과 시간 계산
        ├─ 타임아웃 기준 확인
        ├─ 거래 종료 로그
        └─ 표준 응답에 필요한 정보 보완
        │
        ├─ 정상
        │    └─ 처리 결과 반환
        │
        └─ 타임아웃 초과
             └─ OnlineTimeoutException 발생
```

## 8. 시스템 선처리 오류 흐름

```text
DefaultFilter
   │
   ├─ 토큰 없음·오류
   │     └─ HTTP 401
   │
   └─ 토큰 정상
          │
          ▼
Interceptor.preHandle
   │
   ├─ 거래 통제 위반
   │     └─ 업무 Controller 호출 차단
   │
   └─ 통제 통과
          │
          ▼
STF
   │
   ├─ 필수 정보 오류
   ├─ 등록되지 않은 Service ID
   └─ 시스템 실행 불가
          │
          ▼
업무 Handler 호출 차단
          │
          ▼
GlobalExceptionHandler
          │
          ▼
표준 오류 응답
```

## 9. 타임아웃 발생 흐름

```text
거래 시작
   │
   ├─ TransactionContext 시작 시각 저장
   │
   ▼
STF
   │
   ▼
업무 처리
   │
   ▼
ETF
   │
   ├─ 현재 시각 확인
   ├─ 전체 경과 시간 계산
   └─ 설정된 timeout과 비교
          │
          ├─ 경과시간 ≤ timeout
          │      └─ 정상 응답
          │
          └─ 경과시간 > timeout
                 └─ OnlineTimeoutException
                        │
                        ▼
                 GlobalExceptionHandler
                        │
                        ▼
                 타임아웃 오류 응답
```

ETF에서 업무 트랜잭션이 이미 커밋된 후 타임아웃을 발견하면 DB 작업을 되돌릴 수 없습니다.

```text
잘못된 경계

업무 처리
  → COMMIT
  → ETF 타임아웃 발견
  → 오류 응답
  → 이미 커밋된 DB는 롤백 불가
```

작업 취소와 롤백이 목표라면 타임아웃이 트랜잭션 안쪽에서 발생해야 합니다.

```text
권장 경계

Facade TX BEGIN
  → TimeoutExecutor로 업무 실행
  → 제한시간 초과
  → 예외가 Facade 밖으로 전파
  → TX ROLLBACK
  → ETF 오류 후처리
```

## 10. 시스템 선후처리와 트랜잭션 관계

현재 기본 구조:

```text
시스템 선처리
  │
  ├─ DefaultFilter
  ├─ Interceptor.preHandle
  └─ STF
       │
       ▼
업무 Facade
  │
  ├─ TX BEGIN
  ├─ BizPre
  ├─ Service / DAO
  ├─ BizPost
  └─ COMMIT 또는 ROLLBACK
       │
       ▼
시스템 후처리
  │
  ├─ ETF
  ├─ Interceptor.afterCompletion
  └─ Filter Context 정리
```

따라서 기본적으로 다음과 같습니다.

```text
┌──────────────────────────────┬──────────────────────────────┐
│ 처리 영역                    │ 업무 트랜잭션 포함 여부      │
├──────────────────────────────┼──────────────────────────────┤
│ DefaultFilter                │ 포함되지 않음                │
│ Interceptor.preHandle        │ 포함되지 않음                │
│ STF                          │ 포함되지 않음                │
│ Facade 내부 BizPre           │ 포함됨                       │
│ Business Service             │ 포함됨                       │
│ DAO / Mapper                 │ 포함됨                       │
│ Facade 내부 BizPost          │ 포함됨                       │
│ ETF                          │ 일반적으로 포함되지 않음      │
│ Interceptor.afterCompletion  │ 포함되지 않음                │
└──────────────────────────────┴──────────────────────────────┘
```

## 11. 시스템 선후처리에서 DB를 변경하는 경우

시스템 로그를 업무 결과와 무관하게 남기려면:

```text
STF 또는 ETF
   │
   ▼
별도 로그 Service
   │
   │ @Transactional(
   │     propagation = REQUIRES_NEW
   │ )
   ▼
시스템 로그 DB
```

결과:

```text
업무 트랜잭션 ROLLBACK
          │
          └─ 시스템 로그는 별도 COMMIT
```

시스템 DB 변경도 업무와 같이 롤백해야 한다면:

```text
Facade TX BEGIN
   │
   ├─ 시스템 선처리 DB 작업
   ├─ 업무 Service / DAO
   ├─ 시스템 후처리 DB 작업
   └─ 전체 COMMIT 또는 ROLLBACK
```

이 경우 시스템 선후처리 호출 위치를 Facade 트랜잭션 내부로 옮겨야 합니다.

## 12. 구성요소별 역할 요약

```text
DefaultFilter
 └─ HTTP 요청·인증·Context 생성

ServicePreventionInterceptor
 └─ Controller 진입 전 거래 통제

STF
 └─ TCF 거래 실행 직전 시스템 선처리

TransactionDispatcher
 └─ Service ID에 해당하는 업무 Handler 실행

ETF
 └─ 업무 완료 후 시스템 후처리와 타임아웃 확인

GlobalExceptionHandler
 └─ 예외를 표준 오류 응답으로 변환

afterCompletion / Filter finally
 └─ ServiceContext와 MDC 정리
```
