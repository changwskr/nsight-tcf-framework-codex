## 25. 업무 후처리 `BizPrePostAspect` 분석 결과

현재 업무 후처리는 Service 메서드가 정상 반환했을 때 결과 DTO를 로그로 출력하는 AOP입니다. 포인트컷이 Service 계층으로 변경되어 Facade 트랜잭션 안에서 실행됩니다.

- [BizPrePostAspect.java](<C:/Programming(23-08-15)/nsight-tcf-framework-codex/pdmg-service/src/main/java/nhnis/mg/co/a/entry/aspect/BizPrePostAspect.java:57>)

### 1. 현재 처리 흐름

```text
Handler
  → Facade
      → @Transactional BEGIN
          → 업무 선처리 @Before
          → Service
              → DAO / SQL
              → 결과 DTO 반환
          → 업무 후처리 @AfterReturning
              → 결과 DTO 로그
      → Facade 반환
  → COMMIT
```

타임아웃 기능이 활성화된 현재 설정에서는 외곽에 `TransactionTemplate`이 하나 더 존재합니다.

```text
DefaultOnlineTimeoutExecutor
  → TransactionTemplate BEGIN
      → Handler
          → Facade @Transactional(REQUIRED)
              → 업무 선처리
              → Service / DAO
              → 업무 후처리
      → Deadline 재검사
  → COMMIT 또는 ROLLBACK
```

Facade의 `@Transactional`은 기본 전파 속성 `REQUIRED`이므로 Executor가 시작한 트랜잭션에 참여합니다.

---

### 2. 적용되는 Pointcut

현재 Pointcut은 다음과 같습니다.

```java
@Pointcut(
    "execution(public * " +
    "nhnis.mg.co.a.application.service..*(..))"
)
public void mgBizBoundary() {
}
```

대상은 다음 패키지 아래의 모든 `public` 메서드입니다.

```text
nhnis.mg.co.a.application.service
```

현재 다음 Service들이 적용 대상입니다.

```text
mgcoa5530Service
mgcoa8888Service
mgcoa9000Service
mgcoa9999Service
```

따라서 Controller, Handler, Facade, DAO는 이 업무 선후처리 Pointcut 대상이 아닙니다.

---

### 3. 업무 후처리 실제 코드

```java
@AfterReturning(
    pointcut = "mgBizBoundary()",
    returning = "result"
)
public void after(JoinPoint joinPoint, Object result) {
    log.info(PdmgTxLog.bizProcessEnd());
    log.info(PdmgTxLog.bizPostStart());

    if (log.isInfoEnabled()) {
        log.info(PdmgTxLog.bizResponseMessage());
        log.info(PdmgMessagePrinter.businessDto(result));
    }

    log.info(PdmgTxLog.bizPostEnd());
}
```

출력되는 로그 순서는 다음과 같습니다.

```text
[업무처리] 종료 ===============================================
[업무 후처리] 시작 ===============================================
[업무 후처리] 결과 DTO
{"PROC_CNT":1,"RSLT_CD":"0000","RSLT_MSG":"OK"}
[업무 후처리] 종료 ===============================================
```

`result`는 Service가 반환한 객체입니다.

```java
mgcoa9000C0DTOout output =
        service.mgcoa9000C0(input);
```

응답 전체 `{hdr_nhnis, dto}`가 아니라 Service의 `DTOout`만 기록합니다.

---

### 4. 결과 DTO 로그 가공

[PdmgMessagePrinter.java](<C:/Programming(23-08-15)/nsight-tcf-framework-codex/pdmg-fw/src/main/java/nhnis/fw/commons/log/PdmgMessagePrinter.java:65>)의 `businessDto()`가 결과 객체를 JSON으로 변환합니다.

```java
public static String businessDto(Object value) {
    if (value == null) {
        return "null";
    }

    try {
        JsonNode node = WIRE_MAPPER.valueToTree(value);
        sanitize(node);
        return WIRE_MAPPER.writeValueAsString(node);
    } catch (Exception e) {
        return String.valueOf(value);
    }
}
```

제거되는 메타 필드는 다음과 같습니다.

```text
dtoLogicalName
fieldPropertyMap
이름이 List로 끝나는 필드
이름이 Array로 끝나는 필드
```

여기서 주의할 점이 있습니다. `*List`, `*Array` 필드를 일괄 제거하므로 실제 업무 응답 필드가 이런 이름을 사용하면 정상 업무 데이터도 로그에서 빠질 수 있습니다.

예:

```text
txIdList
customerList
resultArray
```

클라이언트 응답에서는 없어지는 것이 아니며, 업무 후처리 로그에서만 제거됩니다.

---

### 5. 실행 조건

| 상황                                 |      업무 후처리 실행 |
| ------------------------------------ | --------------------: |
| Service가 DTO를 정상 반환            |                  실행 |
| Service가 `null` 정상 반환           |     실행, `null` 기록 |
| 결과 코드가 실패이지만 DTO 정상 반환 |                  실행 |
| Service에서 예외 발생                |                미실행 |
| DAO에서 예외 발생                    |                미실행 |
| Facade DTO 변환 중 예외              | 선·후처리 모두 미실행 |
| Handler에서 Service ID 분기 실패     |                미실행 |
| Facade 반환 후 오류                  | 이미 실행됐을 수 있음 |
| 타임아웃 Deadline 사후 검사 실패     | 이미 실행됐을 수 있음 |

`@AfterReturning`은 “업무 성공”이 아니라 “Java 메서드가 예외 없이 반환됨”을 의미합니다.

예를 들어 Service가 다음 결과를 정상 반환하면:

```java
output.setRSLT_CD("0002");
output.setRSLT_MSG("DUPLICATE_TX_ID");
return output;
```

업무적으로는 중복 오류지만 예외가 없으므로 업무 후처리가 실행되고 트랜잭션도 정상 커밋될 수 있습니다.

---

### 6. 예외가 발생하면

```text
Service / DAO 예외
  → @AfterReturning 실행 안 됨
  → Facade 밖으로 예외 전달
  → 트랜잭션 ROLLBACK
  → GlobalExceptionHandler
  → 시스템 오류 응답
  → Interceptor.afterCompletion
```

현재 `BizPrePostAspect`에는 다음 Advice가 없습니다.

```java
@AfterThrowing
@After
@Around
```

따라서 예외 거래에서는 다음 로그가 남지 않습니다.

```text
[업무처리] 종료
[업무 후처리] 시작
[업무 후처리] 종료
```

이 때문에 로그만 보면 업무처리가 시작된 뒤 갑자기 끊어진 것처럼 보일 수 있습니다. 실패 기록은 전역 예외 처리와 시스템 후처리에서 확인해야 합니다.

---

### 7. 트랜잭션과의 관계

현재 Facade 메서드에 트랜잭션이 선언되어 있습니다.

```java
@Transactional(
    transactionManager = "rdwTransactionManager",
    rollbackFor = Exception.class
)
public mgcoa9000C0DTOout mgcoa9000C0(Object dtoBody)
        throws Exception {

    return service.mgcoa9000C0(convert(
        dtoBody,
        mgcoa9000C0DTOin.class
    ));
}
```

따라서 업무 후처리 시점에는 트랜잭션이 아직 열려 있습니다.

```text
BEGIN
  → Facade
      → Service
          → DAO INSERT/UPDATE
          → Service return
      → BizPrePostAspect.after()
  → Facade return
COMMIT
```

현재 후처리는 로그만 기록하므로 DB 트랜잭션에는 직접적인 변경을 만들지 않습니다.

하지만 후처리에 DAO 작업을 추가하면 다음과 같이 동일 트랜잭션에 참여합니다.

```java
@AfterReturning(
    pointcut = "mgBizBoundary()",
    returning = "result"
)
public void after(JoinPoint joinPoint, Object result) {
    businessHistoryDAO.insertHistory(result);
}
```

이 경우:

```text
업무 DAO 작업
+
후처리 insert
=
같은 트랜잭션
```

후처리 INSERT가 실패하면 Advice가 예외를 던지고 Facade 트랜잭션 전체가 롤백될 수 있습니다.

다만 시스템 로그나 ImageLog처럼 업무 성공 여부와 관계없이 보존해야 하는 정보는 이 Aspect에 넣지 않는 것이 맞습니다.

### 8. 타임아웃에서 주의할 점

현재 설정은 다음과 같습니다.

```yaml
nhnis:
  fw:
    timeout:
      enabled: true
      milliseconds: 5000
```

Executor는 Service와 후처리가 끝난 다음 Deadline을 다시 검사합니다.

```java
T result = action.call();

if (isDeadlineExceeded(deadlineNanos)
        || Thread.currentThread().isInterrupted()) {

    status.setRollbackOnly();
    throw new OnlineTimeoutException(...);
}
```

따라서 다음 상황이 가능합니다.

```text
Service 정상 반환
→ 업무 후처리 성공 DTO 로그 출력
→ Executor Deadline 초과 확인
→ rollbackOnly
→ 실제 DB ROLLBACK
→ 클라이언트에는 Timeout 오류
```

즉, 업무 후처리 결과 로그가 있다고 해서 최종 커밋까지 성공했다는 뜻은 아닙니다.

현재 문서의 다음 표현은 보완이 필요합니다.

```text
업무 후처리 로그 존재 = Service 정상 반환
업무 후처리 로그 존재 ≠ 최종 COMMIT 성공
```

커밋 성공 여부는 Executor 완료 로그나 시스템 후처리 결과까지 확인해야 합니다.

### 9. Aspect 활성화 조건

Aspect는 다음 조건부 Bean입니다.

```java
@ConditionalOnProperty(
    name = "nhnis.fw.commons.legacy-web.enabled",
    havingValue = "true",
    matchIfMissing = true
)
```

현재 설정은 활성화 상태입니다.

```yaml
nhnis:
  fw:
    commons:
      legacy-web:
        enabled: true
```

| 설정값    | BizPrePostAspect |
| --------- | ---------------: |
| `true`    |             등록 |
| 설정 없음 |             등록 |
| `false`   |       등록 안 됨 |

`nhnis.fw.tcf.enabled`와 직접 연결된 조건은 아닙니다. 따라서 TCF가 꺼져 있어도 `legacy-web.enabled=true`이고 Service가 Spring Proxy를 통해 호출되면 Aspect는 실행됩니다.

### 10. `@Order(100)`의 의미

```java
@Order(100)
```

별도의 흐름 로그 Aspect는 `@Order(50)`입니다.

```text
PdmgBizTxFlowAspect @Order(50)
  → BizPrePostAspect @Order(100)
      → Service
```

따라서 Service 정상 호출의 개념적인 순서는 다음과 같습니다.

```text
TX-FLOW Service 진입
→ 업무 선처리
→ Service 실행
→ 업무 후처리
→ TX-FLOW Service 종료
```

`@Order`는 같은 Join Point에 적용되는 Aspect 간 순서를 조정합니다. Facade의 트랜잭션 경계를 Service 후처리 바깥으로 만드는 근본 이유는 `@Order`가 아니라 Facade가 Service를 호출하는 구조입니다.

---

### 11. 현재 문서에서 수정할 부분

25번 문서는 전반적으로 현행 소스와 일치합니다. 다음 세 가지는 표현을 보완하는 것이 정확합니다.

1. `INFO가 꺼져 있어도 시작/종료 로그가 남는다`

실제로는 `log.info()` 메서드가 호출될 뿐 INFO 레벨이 비활성화되어 있으면 로그 파일에는 기록되지 않습니다.

2. `업무 후처리 후 COMMIT`

일반적인 정상 흐름은 맞지만 타임아웃 Deadline 사후 검사에서 롤백될 수 있습니다.

3. `정상 반환 경로`

업무적인 성공이 아니라 예외 없는 Java 정상 반환입니다. 실패 결과 코드 DTO도 후처리 대상입니다.

### 12. 점검 결과

| 점검 항목                 | 결과                        |
| ------------------------- | --------------------------- |
| Pointcut 위치             | Service로 정상 변경         |
| Facade 트랜잭션 내부 실행 | 정상                        |
| 정상 반환 DTO 로깅        | 구현됨                      |
| 예외 경로 후처리          | 없음                        |
| 최종 커밋 성공 보장       | 후처리 로그만으로 판단 불가 |
| 타임아웃 롤백 가능성      | 후처리 실행 후에도 존재     |
| DB 후처리                 | 현재 없음                   |
| Aspect 활성 설정          | 현재 `true`                 |
| 결과 DTO 마스킹           | 개인정보 마스킹은 없음      |
| Aspect 전용 자동 테스트   | 발견되지 않음               |

가장 중요한 결론은 다음과 같습니다.

```text
BizPrePostAspect 업무 후처리
= Service가 예외 없이 반환했다는 로그

최종 거래 성공
= 후처리 완료
  + 타임아웃 검사 통과
  + 트랜잭션 COMMIT
  + 시스템 후처리 완료
```

이번 점검은 소스와 문서에 대한 정적 분석이며, 파일 수정이나 테스트 실행은 하지 않았습니다.
