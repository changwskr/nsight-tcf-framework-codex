## 1. 정의

**시스템 선·후처리**는 개별 업무(Service)와 무관하게,  
모든 온라인 거래에 공통으로 적용하는 **전문·추적·ImageLog·응답 봉투** 처리다.

| 구분 | 무엇 | 담당 | 업무 TX |
|------|------|------|---------|
| **시스템 선처리** | Context 준비, 요청전문 로그, ImageLog INSERT | Filter + Interceptor.`preHandle` | **밖** |
| **업무** | Handler → Facade → Service → DAO | `nhnis.mg.co.a.*` | Facade **안** |
| **시스템 후처리** | 응답 봉투, 응답전문 로그, ImageLog UPDATE | ResponseBodyAdvice + Interceptor.`afterCompletion` | **밖** |

**업무 선·후처리**(`BizPrePostAspect`)와 이름이 비슷하지만 **다르다**.  
업무 선후는 Service Pointcut · Facade TX **안**, 시스템은 그 **바깥**이다.

```text
[시스템 선처리]     ← Filter 준비 + Interceptor.pre
    ↓
[업무 선처리] → 업무처리 → [업무 후처리]   ← Facade @Transactional 안
    ↓
[시스템 후처리]     ← Advice + Interceptor.after
```

운영 로그 배너(`PdmgTxLog`)도 위 구간 이름을 그대로 쓴다.

## 2. 전체 순서

```text
① DefaultFilter                         [13]
     Body 캐시 · JWT(비-local) · hdr_nhnis · ServiceContext · MDC
     (준비 — 狭义 선처리 로그/ImageLog 는 아직)

② ServicePreventionInterceptor.preHandle  ★ 시스템 선처리 [15]
     GUID 보장 · 요청전문 로그 · ImageLog preImagelog(INSERT)

③ Spring MVC → OnlineTransactionController [14 Spring MVC] [16]
     → TcfFacade → Handler → Facade(TX)
          [BizPrePost] Service → DAO              ← 업무 (시스템 아님)

④ ResponseBodyArgumentResolver.beforeBodyWrite  ★ 시스템 후처리(응답) [26]
     { hdr_nhnis, dto } 조립 · 응답전문 로그
     ServiceContext.setResponseBody(…)

⑤ ServicePreventionInterceptor.afterCompletion  ★ 시스템 후처리(감사)
     정상: postImagelog(UPDATE )
     예외: exceptionImagelog
```

설정:

```yaml
nhnis.fw.commons.filter.enabled: true
nhnis.fw.commons.legacy-web.enabled: true
nhnis.fw.tcf.enabled: true
```

## 3. 시스템 선처리

### 3.1 목적

- 거래 추적 키(GUID · serviceId · 조작자) 확정  
- 요청 온라인 전문을 로그·ImageLog에 남김  
- 이후 업무가 `ServiceContext`를 신뢰하고 진행  

### 3.2 구성

| 단계 | 컴포넌트 | 내용 |
|------|----------|------|
| 준비 | `DefaultFilter` | Body·헤더·JWT·Context · `PDMG_REQUEST_BODY` |
| 선처리 본문 | `ServicePreventionInterceptor.preHandle` | 요청전문 로그 · `preImagelog` |

로그 패턴:

```text
[시스템 선처리] 시작 ===============================================
[시스템 선처리] GUID: …
[온라인전문][요청][원문] ===============================================
[요청전문] { … }
[시스템 선처리] 종료 ===============================================
```

### 3.3 규칙

- 업무 검증·SQL·`BizException` 메시지를 여기서 만들지 않는다.  
- ImageLog INSERT는 **업무 Facade TX와 커밋을 공유하지 않는다**.  
- multipart는 선처리 본문을 스킵할 수 있다.

## 4. 시스템 후처리

### 4.1 목적

- 업무가 반환한 `*DTOout`(또는 에러 DTO)을 **표준 응답 전문**으로 감싼다  
- 응답 원문을 로그·ImageLog에 남긴다  

### 4.2 응답 봉투 (`ResponseBodyArgumentResolver`)

`ResponseBodyAdvice` — `legacy-web.enabled=true`

```text
beforeBodyWrite:
  1. [시스템 후처리] 시작
  2. hdr_nhnis ← ServiceContext.header
  3. dto ← 업무 body (또는 NH_NIS_ERR_DTO)
  4. 메타 필드 정리
  5. 응답 전문 원문 로그
  6. [시스템 후처리] 종료
  7. ctx.setResponseBody(…) → afterCompletion postImagelog 입력
  8. return { hdr_nhnis, dto }
```

`postHandle`에서는 응답 전문을 찍지 않는다 (`@ResponseBody` 순서).  
상세는 [26.시스템후처리.md](./26.시스템후처리.md) 에 이어 적는다.

### 4.3 ImageLog (`afterCompletion`)

| 결과 | API |
|------|-----|
| 정상 | `postImagelog(header, responseBody)` |
| 예외 | `exceptionImagelog(header, null, ex)` |

Filter `sendError` 경로는 Advice/정상 후처리를 타지 않을 수 있다. → [11.예외처리.md](./11.예외처리.md)

## 5. 시스템 vs 업무 선후처리

| | 시스템 | 업무 (`BizPrePostAspect`) |
|--|--------|---------------------------|
| Point | Filter / Interceptor / Advice | `application.service..*` |
| TX | 밖 | Facade TX **안** |
| 로그 배너 | `[시스템 선/후처리]` | `[업무 선/후처리]` |
| ImageLog | O | X |
| 전문 봉투 | O (후처리) | X (DTO만) |
| 목적 | 감사·추적·공통 계약 | 업무 횡단(로그 등) |

---

## 6. 왜 업무 TX 밖인가

1. ImageLog·요청 감사가 업무 롤백에 같이 지워지면 장애 추적이 어렵다.  
2. 시스템 오류(`sendError`)와 업무 `BizException`(`NH_NIS_ERR_DTO`) 경로를 분리한다.  
3. 공통 OnlineController 한곳에서 선후처리를 고정해 거래별 누락을 막는다.

```text
업무 ROLLBACK  ≠  ImageLog 자동 삭제
업무 COMMIT    ≠  ImageLog 성공 보장 (시스템 구간 별도)
```

## 8. 하지 말 것

1. 시스템 선후를 거래별 Controller에 복사  
2. Facade `@Transactional` 안에서 ImageLog 필수 처리  
3. 시스템 후처리를 `postHandle`에만 의존  
4. 업무·시스템 로그 배너 혼용  
5. STF/ETF를 시스템 선후로 재도입

## 10. 요약

```text
시스템 선처리 = Filter(준비) + Interceptor.pre (요청전문·ImageLog INSERT)
시스템 후처리 = Advice (응답 봉투·로그) + Interceptor.after (ImageLog UPDATE)

업무 TX와 분리된 “공통 거래 껍질”이다.
```
