## 24. DAO Namespace 분석 결과

현재 `pdmg-service`의 DAO Namespace 구성은 정상입니다. 4개 DAO 인터페이스의 전체 클래스명과 Mapper XML의 `namespace`가 정확하게 일치합니다.

분석 대상: [24.DAO-Namespace.md](<C:/Programming(23-08-15)/nsight-tcf-framework-codex/pdmg-service/docs/24.DAO-Namespace.md>)

### 1. Namespace의 역할

MyBatis Namespace는 다음 두 대상을 연결하는 식별자입니다.

```text
Java DAO 인터페이스
        ↕ namespace 일치
Mapper XML
        ↕ 메서드명과 statement id 일치
SQL
```

예를 들어 다음 DAO가 있으면:

```java
package nhnis.mg.co.a.persistence.dao;

public interface mgcoa9000DAO {

    int mgcoa9000C0_C0(mgcoa9000C0DTOin input);
}
```

Mapper XML은 다음처럼 구성되어야 합니다.

```xml
<mapper namespace="nhnis.mg.co.a.persistence.dao.mgcoa9000DAO">

    <insert id="mgcoa9000C0_C0"
            parameterType="nhnis.mg.co.a.dto.mgcoa9000C0DTOin">
        ...
    </insert>

</mapper>
```

MyBatis가 내부적으로 사용하는 전체 SQL 식별자는 다음과 같습니다.

```text
nhnis.mg.co.a.persistence.dao.mgcoa9000DAO.mgcoa9000C0_C0
└────────────── namespace ───────────────┘ └── statement id ──┘
```

Mapper XML 파일명인 `mgcoa9000-ORA.xml`은 이 식별자에 포함되지 않습니다.

---

### 2. 현재 Namespace 점검 결과

| DAO 인터페이스 | Mapper XML          | Namespace 결과 |
| -------------- | ------------------- | -------------- |
| `mgcoa5530DAO` | `mgcoa5530-ORA.xml` | 일치           |
| `mgcoa8888DAO` | `mgcoa8888-ORA.xml` | 일치           |
| `mgcoa9000DAO` | `mgcoa9000-ORA.xml` | 일치           |
| `mgcoa9999DAO` | `mgcoa9999-ORA.xml` | 일치           |

현재 적용된 Namespace 형식은 다음과 같습니다.

```text
nhnis.mg.co.a.persistence.dao.{DAO 클래스명}
```

예:

```xml
<mapper namespace="nhnis.mg.co.a.persistence.dao.mgcoa5530DAO">
<mapper namespace="nhnis.mg.co.a.persistence.dao.mgcoa8888DAO">
<mapper namespace="nhnis.mg.co.a.persistence.dao.mgcoa9000DAO">
<mapper namespace="nhnis.mg.co.a.persistence.dao.mgcoa9999DAO">
```

따라서 현재 Namespace 불일치는 발견되지 않았습니다.

---

### 3. DAO가 등록되는 전체 과정

DAO가 동작하려면 세 가지 단계가 모두 정상이어야 합니다.

| 단계                | 설정              | 역할                                  |
| ------------------- | ----------------- | ------------------------------------- |
| DAO 인터페이스 검색 | `@MapperScan`     | DAO 인터페이스를 Spring Bean으로 등록 |
| Mapper XML 검색     | `mapperLocations` | XML 파일을 MyBatis 설정에 로딩        |
| DAO와 XML 연결      | `namespace`       | DAO 메서드와 XML statement를 연결     |

#### 3.1 DAO 인터페이스 검색

[RdwDataSourceConfig.java](<C:/Programming(23-08-15)/nsight-tcf-framework-codex/pdmg-service/src/main/java/nhnis/mg/config/RdwDataSourceConfig.java>)에서 다음 패키지를 검색합니다.

```java
@MapperScan(
    basePackages = "nhnis.mg.co.a.persistence.dao",
    sqlSessionTemplateRef = "rdwSqlSessionTemplate"
)
```

이 설정에 의해 DAO 인터페이스가 `rdwSqlSessionTemplate`을 사용하는 MyBatis Mapper Bean으로 등록됩니다.

#### 3.2 Mapper XML 검색

```java
private static final String MAPPER_LOCATION_PATTERN =
        "classpath*:rdw.*/*.xml";
```

현재 Mapper XML은 다음 리소스 경로에 있습니다.

```text
src/main/resources/
└─ rdw.mg.co.a/
   ├─ mgcoa5530-ORA.xml
   ├─ mgcoa8888-ORA.xml
   ├─ mgcoa9000-ORA.xml
   └─ mgcoa9999-ORA.xml
```

`rdw.mg.co.a`는 `rdw.*` 패턴과 일치하므로 XML이 로딩됩니다.

#### 3.3 Namespace 연결

DAO Proxy가 다음 메서드를 호출하면:

```java
mgcoa9000DAO.mgcoa9000C0_C0(input);
```

MyBatis는 다음 전체 ID를 찾습니다.

```text
nhnis.mg.co.a.persistence.dao.mgcoa9000DAO.mgcoa9000C0_C0
```

해당 Namespace와 ID가 등록되어 있으면 SQL이 실행됩니다.

---

### 4. 혼동하기 쉬운 부분

#### XML 폴더와 Namespace는 직접 연결되지 않는다

다음 구조는 프로젝트 규칙상 서로 비슷하게 맞춰 놓은 것입니다.

```text
Java 패키지
nhnis.mg.co.a.persistence.dao

Mapper 폴더
rdw.mg.co.a

XML namespace
nhnis.mg.co.a.persistence.dao.mgcoa9000DAO
```

하지만 MyBatis가 `rdw.mg.co.a` 폴더명을 보고 Namespace를 자동 생성하는 것은 아닙니다.

각 요소의 실제 역할은 다음과 같습니다.

- Java 패키지: `@MapperScan`이 DAO를 검색하는 대상
- 리소스 폴더: `mapperLocations`가 XML을 검색하는 대상
- XML Namespace: DAO 인터페이스와 XML을 연결하는 키
- XML 파일명: 개발자가 파일을 찾기 쉽게 하는 관리 규칙

따라서 XML이 로딩 패턴에 포함되기만 한다면 기술적으로 다른 폴더에도 둘 수 있습니다. 다만 현재 프로젝트 규칙을 유지하는 것이 좋습니다.

#### 데이터소스는 Namespace가 결정하지 않는다

Namespace에 `rdw`가 들어 있지 않아도 RDW 데이터소스가 사용됩니다.

실제 데이터소스를 결정하는 것은 다음 설정입니다.

```java
sqlSessionTemplateRef = "rdwSqlSessionTemplate"
```

즉:

```text
DAO 패키지
    → @MapperScan
        → rdwSqlSessionTemplate
            → rdwSqlSessionFactory
                → rdwDataSource
```

Namespace는 DAO와 SQL을 연결할 뿐 다음 항목은 결정하지 않습니다.

- 데이터소스
- 트랜잭션 매니저
- DB Schema
- 테이블
- SQL Dialect
- 커밋과 롤백

### 5. Namespace 오류가 발생하는 경우

#### Namespace가 DAO 전체 클래스명과 다른 경우

```xml
<!-- 잘못된 예 -->
<mapper namespace="nhnis.mg.co.a.dao.mgcoa9000DAO">
```

DAO 호출 시 일반적으로 다음 계열의 오류가 발생합니다.

```text
org.apache.ibatis.binding.BindingException:
Invalid bound statement (not found):
nhnis.mg.co.a.persistence.dao.mgcoa9000DAO.mgcoa9000C0_C0
```

#### statement id가 DAO 메서드명과 다른 경우

```java
int mgcoa9000C0_C0(...);
```

```xml
<!-- 잘못된 예 -->
<insert id="mgcoa9000C0_insert">
```

이 경우에도 DAO 메서드 호출 시 `Invalid bound statement`가 발생합니다.

#### XML 위치가 로딩 패턴을 벗어나는 경우

예를 들어 XML을 다음처럼 옮기면:

```text
src/main/resources/mapper/mgcoa9000-ORA.xml
```

현재 패턴과 일치하지 않습니다.

```text
classpath*:rdw.*/*.xml
```

DAO Bean은 만들어질 수 있지만 XML statement가 등록되지 않아 실제 호출 시 `Invalid bound statement`가 발생합니다.

#### 동일 Namespace와 ID가 중복되는 경우

서로 다른 XML에 다음 정의가 중복되면:

```xml
<mapper namespace="nhnis.mg.co.a.persistence.dao.mgcoa9000DAO">
    <insert id="mgcoa9000C0_C0">
```

애플리케이션 시작 중 다음 계열의 오류가 발생할 수 있습니다.

```text
Mapped Statements collection already contains value
```

현재 `classpath*:`로 여러 JAR의 리소스까지 검색할 수 있으므로, 의존 모듈에 동일 Namespace와 statement가 들어오지 않도록 주의해야 합니다.

### 6. DAO 이름이나 패키지를 변경할 때

예를 들어 다음 DAO를:

```text
nhnis.mg.co.a.persistence.dao.mgcoa9000DAO
```

다음 위치로 변경한다면:

```text
nhnis.mg.co.customer.persistence.dao.Mgcoa9000DAO
```

함께 변경해야 할 항목은 다음과 같습니다.

1. DAO의 `package`와 클래스명
2. Service의 import와 주입 타입
3. Mapper XML의 `namespace`
4. `@MapperScan` 범위
5. XML을 이동했다면 `mapperLocations` 패턴
6. DAO 메서드명을 바꿨다면 XML statement `id`
7. 이전 전체 SQL ID를 사용하는 로그·모니터링 검색 조건
8. 관련 테스트와 문서

Namespace는 대소문자까지 정확하게 일치해야 합니다.

변경 후에는 오래된 클래스와 Mapper XML이 빌드 디렉터리에 남지 않도록 clean build가 필요합니다.

```powershell
.\gradlew.bat clean :pdmg-service:test
```

### 7. 문서 현행화 관점의 보완 사항

현재 문서의 핵심 설명은 맞습니다. 다만 다음처럼 구분해서 표현하면 더 정확합니다.

```text
DAO 패키지와 @MapperScan
→ DAO 인터페이스 검색 및 Proxy 생성

Mapper XML 폴더와 mapperLocations
→ SQL XML 검색 및 로딩

DAO FQCN과 XML namespace
→ DAO 인터페이스와 XML의 논리적 연결

DAO 메서드명과 statement id
→ 실행할 SQL의 최종 연결
```

즉, 문서에서 말하는 “Java 패키지·리소스 폴더·Namespace의 3축”은 운영 규칙으로는 유효하지만, MyBatis의 직접적인 Mapper 바인딩 조건은 다음 두 가지입니다.

```text
DAO 인터페이스 FQCN = XML namespace
DAO 메서드명 = XML statement id
```

---

### 최종 평가

현재 Namespace 구성은 정상입니다.

- DAO FQCN과 XML Namespace: 모두 일치
- DAO 메서드명과 statement ID: 일치
- `@MapperScan` 범위: 정상
- Mapper XML 로딩 경로: 정상
- RDW SqlSessionTemplate 연결: 정상
- Namespace 자동 검증 테스트: 없음

따라서 현재 DAO 관련 장애가 있다면 Namespace보다는 SQL 컬럼, DTO 매핑, DB 스키마 또는 트랜잭션 설정을 다음 점검 대상으로 보는 것이 적절합니다. 이번 분석은 소스와 문서에 대한 정적 점검이며 빌드와 테스트는 실행하지 않았습니다.
