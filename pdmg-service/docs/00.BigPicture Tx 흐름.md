TCF ON 기준으로, **요청(온라인 거래) 흐름**과 **DB 트랜잭션**을 겹쳐 보면 아래와 같습니다.

## 1. 한눈에 보는 컴포넌트 흐름

```text
[브라우저]
    │
    ▼
[pdmg-ui :8090 브라우저]  POST http://localhost:8080/{serviceId}
                          { hdr_nhnis, dto }  (직접 fetch + CORS)
    │
    ▼
[pdmg-service + pdmg-fw]
────────────────────────────────────────────────────────────
 │ 업무 DB TX 밖 (시스템 구간)
 │
 │  ① DefaultFilter
 │       Body 캐시 · JWT(비-local) · hdr_nhnis · ServiceContext · MDC
 │  ② ServicePreventionInterceptor.preHandle
 │       요청전문 로그 · ImageLog INSERT
 │  ③ OnlineTransactionController
 │  ④ TcfFacade
 │       OnlineTimeoutExecutor (공통 5000ms, Worker+TX)
 │       → Dispatcher
 │
 │──────────────── Worker / DB TX 안 ────────────────
 │  ⑤ Handler (entry.handler)
 │       serviceId → Facade 메서드만
 │
 │╔════════════ DB TX 경계 ══════════════════════════════╗
 │║  TransactionTemplate(rdw) BEGIN (Executor Worker)     ║
 │║  ⑥ Facade @Transactional(REQUIRED) — 같은 TX 참여     ║
 │║  ⑦ BizPrePostAspect  [업무 선처리]                    ║
 │║  ⑧ Service (application.service)                      ║
 │║  ⑨ DAO → Mapper(rdw.mg.co.a) → DB                     ║
 │║  ⑩ BizPrePostAspect  [업무 후처리]                    ║
 │║  Deadline 재검사 → COMMIT / ROLLBACK                  ║
 │╚═══════════════════════════════════════════════════════╝
 │  (타임아웃 시 요청 Thread: 504 FW_TIMEOUT)
 │
 │  ⑪ ResponseBodyAdvice
 │       성공 { hdr_nhnis, dto } / 실패 { hdr_nhnis, result }
 │       응답전문 로그
 │  ⑫ Interceptor.afterCompletion
 │       ImageLog UPDATE / exceptionImagelog
────────────────────────────────────────────────────────────
    │
    ▼
[브라우저]  성공 dto / 실패 result(NH_NIS_ERR_DTO)
```

## 2. 계층 · 컴포넌트 · TX

| #     | 컴포넌트                                    | 패키지/모듈                       | DB TX                   |
| ----- | ------------------------------------------- | --------------------------------- | ----------------------- |
| 1     | `DefaultFilter`                             | `pdmg-fw` commons                 | 밖                      |
| 2     | `ServicePreventionInterceptor`              | `pdmg-fw`                         | 밖                      |
| 3     | `OnlineTransactionController`               | `pdmg-fw` tcf                     | 밖                      |
| 4     | `TcfFacade` + `OnlineTimeoutExecutor`       | `pdmg-fw` tcf.timeout             | **Worker에서 TX 시작**  |
| 5     | `*Handler`                                  | `entry.handler`                   | 안 (Executor TX)        |
| **6** | `*Facade`                                   | `application.facade`              | **REQUIRED 참여**       |
| 7·10  | `BizPrePostAspect`                          | `entry.aspect`                    | **안** (Facade TX 참여) |
| 8     | `*Service`                                  | `application.service`             | 안                      |
| 9     | `*DAO` + XML                                | `persistence.dao` / `rdw.mg.co.a` | 안                      |
| 11    | `ResponseBodyAdvice`                        | `pdmg-fw`                         | 밖                      |
| 12    | Interceptor `afterCompletion`               | `pdmg-fw`                         | 밖                      |

## 3. DB 트랜잭션만 확대

```text
Handler
  └─ Facade 프록시 (REQUIRED — Executor TX 안이거나, Sync 시 BEGIN)
        ├─ [업무 선처리]  Service 진입 직전
        ├─ Service
        │     └─ DAO / SQL
        ├─ [업무 후처리]  Service 반환 직후
        │  ★ COMMIT/ROLLBACK은 Executor(또는 Facade) 경계
        └─ 반환 → Handler → 시스템 후처리
```

핵심: **외부 TX는 OnlineTimeoutExecutor(Worker)** 가 열고, Facade는 `REQUIRED`로 참여한다.  
공통 제한시간·504/롤백: [20.타임아웃.md](./20.타임아웃.md).  
업무 선후처리는 **Service Pointcut**이라 그 TX **안**에서 돈다.

## 4. 의존 방향 (구조)

```text
UI ──► FW(Filter/Interceptor/OnlineController/TcfFacade)
         ──► Handler
              ──► Facade ★TX
                   ──► Service
                        ──► DAO ──► DB
         ◄── ResponseBodyAdvice / ImageLog (TX 밖)
```

금지에 가까운 우회: `Handler → Service/DAO` 직호출 (TX·선후처리 깨짐).

## 5. 두 가지 “트랜잭션” 구분

| 말               | 의미                    | 컴포넌트                      |
| ---------------- | ----------------------- | ----------------------------- |
| 온라인 거래 흐름 | 요청 1건의 라이프사이클 | Filter → … → ImageLog         |
| DB 트랜잭션      | commit/rollback         | **Executor TX + Facade REQUIRED** |
