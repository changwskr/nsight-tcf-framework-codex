# 09. 서비스 ID (PDMG)

기준일: 2026-08-09  
대상: `pdmg-service` / `pdmg-ui` / `pdmg-fw`  
관련: [06.네이밍 형식.md](./06.네이밍%20형식.md) · [07.도메인 정의 및 호출방식.md](./07.도메인%20정의%20및%20호출방식.md) · [MG-NAMING_CONVENTION.md](./MG-NAMING_CONVENTION.md) §3

---

## 1. 정의

**서비스 ID**는 PDMG 온라인 거래의 **유일 식별자**다.

- HTTP path: `POST /{serviceId}`
- TCF Handler 라우팅 키 (`serviceIds()` / `TransactionContext.getServiceId()`)
- Facade·Service **메서드명**
- DTO 타입명의 접두 (`{serviceId}DTOin`)
- SQL ID의 앞부분 (`{serviceId}_S0`)
- UI catalog / relay id
- ImageLog·MDC 등 추적 필드

```text
한 서비스 ID = 한 거래 = Facade 메서드 1개 ≈ DB TX 1건(쓰기)
```

REST 스타일(`/api/.../list`)이나 `MG.Domain.action` 점 구분 ID는 **쓰지 않는다**.

---

## 2. 형식

```text
[대구분2][업무2][세부1][식별4][구분자1][순번1]
   mg      co     a    8888     S       0
─────────────────────────────────────────
전체 길이: 11자 (대소문자 혼합: 앞은 소문자, 구분자는 대문자)
```

| 위치 | 길이 | 문자 | 예 | 설명 |
|------|-----:|------|----|------|
| 1–2 | 2 | 소문자 | `mg` | 애플리케이션 `MG` |
| 3–4 | 2 | 소문자 | `co` | 업무 CO/IC/MS/SA |
| 5 | 1 | 소문자 | `a` | 세부 A/B |
| 6–9 | 4 | 숫자 | `8888` | 화면·프로그램 식별번호 |
| 10 | 1 | **대문자** | `S` | 거래 종류(구분자) |
| 11 | 1 | 숫자 또는 A–Z | `0` | 동일 종류 내 순번 |

예: `mgcoa8888S0`, `mgcoa9000C0`, `mgcoa8888D0`

### 2.1 구분자

| 코드 | 의미 | 예 |
|------|------|----|
| **S** | 조회 (Select) | `mgcoa8888S0` |
| **C** | 등록 (Create) | `mgcoa9000C0` |
| **U** | 수정 (Update) | `mgcoa9000U0` |
| **D** | 삭제 (Delete) | `mgcoa8888D0` |
| **A** | 혼합 (여러 DML) | `mgcoa0000A0` |
| **R** | 리포트/추출 | `mgcoa0000R0` |

### 2.2 순번

- 같은 프로그램·같은 구분자에서 거래가 늘어나면 `0` → `1` → … → `9` → `A` …
- 목록/상세를 나누면 예: `S0`(목록), `S1`(상세)
- CRUD는 보통 `S0`/`C0`/`U0`/`D0` 각각 순번 `0`

### 2.3 프로그램 접두 (서비스 ID에서 유도)

```text
서비스 ID   mgcoa8888S0
프로그램 접두 mgcoa8888     ← 구분자·순번 제거 (앞 9자: mg+co+a+8888)
```

Handler/Facade/Service/DAO/Controller/Mapper 파일명은 **프로그램 접두**만 쓴다.  
구분자·순번은 서비스 ID가 필요한 곳에만 붙인다.

## 3. 서비스 ID가 쓰이는 곳 (일치 필수)

| 위치 | 사용 형태 | 예 |
|------|-----------|----|
| URL | `POST /{serviceId}` | `/mgcoa8888S0` |
| Handler | `serviceIds()` 문자열, `switch` 분기 | `"mgcoa8888S0"` |
| Facade | 메서드명 | `mgcoa8888S0(Object)` |
| Service | 메서드명 | `mgcoa8888S0(DTOin)` |
| Controller | `@PostMapping("/{serviceId}")` | `"/mgcoa8888S0"` |
| DTO | `{serviceId}DTOin/out/Sub` | `mgcoa8888S0DTOin` |
| SQL ID | `{serviceId}_{DML}{n}` | `mgcoa8888S0_S0` |
| UI Catalog | id / path | `mgcoa8888S0`, `/mgcoa8888S0` |
| UI 직접 호출 | catalog path → 서비스 URL | `http://localhost:8080/mgcoa8888S0` |
| 전문 헤더 | 서비스 코드 필드(FW 계약) | path와 동일 권장 |
| ImageLog | `SERVICE_ID` | 요청 거래 ID |

**불일치 시:** Handler 미매칭, 404/매핑 실패, UI 중계 실패, SQL namespace 오류.

---

## 4. 라우팅 흐름에서의 역할

```text
POST /mgcoa8888S0
        │
        ▼
OnlineTransactionController   path = serviceId
        │
        ▼
TcfFacade / Dispatcher
        │  Handler.serviceIds() 에 "mgcoa8888S0" 있는 빈 탐색
        ▼
mgcoa8888Handler.handle(…)
        │  context.getServiceId() == "mgcoa8888S0"
        ▼
facade.mgcoa8888S0(dtoBody)
```

```java
// Handler 등록 예
private static final String S0 = "mgcoa8888S0";
private static final String D0 = "mgcoa8888D0";

public Collection<String> serviceIds() {
    return List.of(S0, D0);
}
```

미등록 ID → `ServiceHandlerNotFound` → `NH_NIS_ERR_DTO`.

## 5. 패키지·Mapper와의 관계

서비스 ID 앞부분으로 패키지 축이 결정된다.

```text
mg | co | a | 8888 | S | 0
 │    │   │
 │    │   └─ nhnis.mg.co.a.* , rdw.mg.co.a/
 │    └───── 업무
 └────────── nhnis.mg , rdw.mg
```

| 서비스 ID 접두 | Java | Mapper |
|----------------|------|--------|
| `mgcoa…` | `nhnis.mg.co.a` | `rdw.mg.co.a/` |
| `mgicb…` (예) | `nhnis.mg.ic.b` | `rdw.mg.ic.b/` |

---

## 6. SQL ID와의 관계

```text
서비스 ID     mgcoa8888S0
SQL (목록)    mgcoa8888S0_S0
SQL (건수)    mgcoa8888S0_S0_count
SQL (삭제)    mgcoa8888D0_D0
```

형식: `[서비스ID]_[DML구분][순번]`.  
DAO 메서드명 = XML `id` = 이 문자열.

서비스 ID의 구분자(S/C/U/D)와 SQL의 DML 구분자는 **의미상 맞추는 것**이 원칙이다  
(조회 거래 `…S0` → SQL `…_S0`, 삭제 거래 `…D0` → `…_D0`).

## 8. 신규 서비스 ID 발급 절차

1. **업무·세부·식별번호** 확정 → 프로그램 접두 (`mgcoa9010`)  
2. **구분자·순번** 확정 → 서비스 ID (`mgcoa9010S0`)  
3. **충돌 검사** — Handler `serviceIds()`, catalog, URL 중복 없음  
4. **구현** — DTO·DAO·SQL·Service·Facade 메서드명을 ID와 동일하게  
5. **Handler** — `serviceIds()`에 추가, `switch` 분기  
6. **UI** — catalog + relay  
7. **호출 검증** — `POST /mgcoa9010S0`, `/api/relay/mgcoa9010S0`

식별번호가 같은 기존 프로그램에 거래만 추가할 때는 **클래스 파일을 늘리지 않고** 메서드·DTO·SQL·Handler 분기만 추가한다.

## 9. 금지·주의

| 금지 | 이유 |
|------|------|
| `MG.SalesTip.list` | 점 구분·대문자 체계 미사용 |
| `/api/mg/co/a/8888/list` | path ≠ 서비스 ID |
| `mgcoa8888S0Handler` | 클래스에 구분자 포함 금지 |
| Facade 메서드 `selectList` | 메서드명 ≠ 서비스 ID |
| Handler 미등록 채 UI만 추가 | 중계 후 Handler not found |
| 대소문자 변형 (`MgCoa8888S0`) | 라우팅·SQL 불일치 |
| 구분자 소문자 (`mgcoa8888s0`) | 규약 위반 |

헤더의 서비스 코드와 path가 다르면 현재 FW는 `ServiceContext`/전문 헤더의 `rms_svc_c`를 우선한다. 서버와 UI 모두 불일치를 아직 강제 차단하지 않으므로, **업무 표준은 path = rms_svc_c = Handler 키**로 맞추고 쓰기 거래에서는 호출 전에 검증해야 한다.

## 10. 체크리스트

- [ ] 형식: `mg` + 업무2 + 세부1 + 식별4 + 구분자1 + 순번1  
- [ ] 구분자가 S/C/U/D/A/R 중 하나인가?  
- [ ] URL·Handler·Facade·Service·DTO·SQL·UI id가 **동일 문자열**인가?  
- [ ] 프로그램 접두로 Handler/Facade/DAO 파일명이 맞는가?  
- [ ] 신규 ID가 기존 `serviceIds()`와 겹치지 않는가?  
- [ ] ImageLog/추적에 남길 ID가 호출 ID와 같은가?
