# 트랜잭션 이미지로그 아키텍처 텍스트 다이어그램

이미지로그는 화면 이미지 파일을 저장하는 기능이라기보다, 온라인 거래의 요청·응답 전문과 처리 결과를 `TB_FW_IMAGE_LOG`에 기록하고 관리하는 기능입니다.

하나의 거래는 동일한 GUID로 두 단계에 걸쳐 기록됩니다.

```text

   │
   ▼

   │
   └─ c3d65cb1a54a43838688b76afe82521e
   │
   ▼

   │
   ├─ GUID
   ├─ Service ID
   ├─ 요청 Header
   ├─ 요청 Body
   ├─ 사용자
   ├─ 영업점
   ├─ IP

   │
```

## 5. 이미지로그와 업무 트랜잭션 관계

```text
ImageLog INSERT
   │
   │ 업무 TX 밖
   ▼
Facade TX BEGIN
   │
   ├─ 업무 데이터 INSERT
   ├─ 업무 데이터 UPDATE
   └─ 업무 후처리
   │
   ├─ 정상: COMMIT
   └─ 오류: ROLLBACK
   │
   ▼
ImageLog UPDATE
   │
   │ 업무 TX 밖
   ▼
응답
```

```text
┌──────────────────────────┬────────────────────────────┐
│ 처리                     │ 업무 트랜잭션 포함 여부    │
├──────────────────────────┼────────────────────────────┤
│ ImageLog 요청 INSERT     │ 포함되지 않음              │
│ BizPre                   │ 포함됨                     │
│ Business Service         │ 포함됨                     │
│ DAO / Mapper             │ 포함됨                     │
│ BizPost                  │ 포함됨                     │
│ ImageLog 응답 UPDATE     │ 포함되지 않음              │
└──────────────────────────┴────────────────────────────┘
```

## 6. 이미지로그 DB 오류

### 요청 로그 INSERT 실패

```text
HTTP 요청
   │
   ▼
ImageLog INSERT
   │
   │ DB 오류
   ▼
정책 결정
   │
   ├─ Fail-open
   │    ├─ 로그 오류만 기록
   │    └─ 업무 거래는 계속 실행
   │
   └─ Fail-closed
        ├─ 업무 거래 차단
        └─ 시스템 오류 응답
```

감사 필수 거래라면 `Fail-closed`, 단순 모니터링 로그라면 `Fail-open`을 고려할 수 있습니다.

### 응답 로그 UPDATE 실패

```text
업무 TX COMMIT
   │
   ▼
ImageLog UPDATE
   │
   │ 실패
   ▼
업무 COMMIT 데이터
   └─ 이미 확정되어 롤백할 수 없음
```

즉 이미지로그 UPDATE 실패가 업무 데이터까지 자동으로 되돌리지는 않습니다.

## 10. 자기 자신의 이미지로그 생성 문제

`mgcoa8888S0` 조회 거래도 일반 온라인 거래이므로 조회 자체의 이미지로그가 새로 기록될 수 있습니다.

```text
이미지로그 조회 요청
mgcoa8888S0
      │
      ▼
ImageLog INSERT
      │
      ▼
TB_FW_IMAGE_LOG 조회
      │
      ▼
ImageLog UPDATE
```

따라서 조회할 때마다 이미지로그가 증가할 수 있습니다.

해결 정책:

```text
방법 1
└─ mgcoa8888S0/D0도 로그 생성
   └─ 완전한 감사 추적 가능

방법 2
└─ 이미지로그 관리 Service ID는 로그 대상에서 제외
   └─ 불필요한 자기 로그 방지

방법 3
└─ 관리 거래는 별도 관리 로그에 기록
   └─ 업무 이미지로그와 분리
```

감사 요구사항이 있다면 삭제 거래인 `mgcoa8888D0`은 반드시 별도의 관리자 감사 로그를 남기는 것이 안전합니다.
