# TCF ON 이면 트랜잭션 시작은 어디인가

`nhnis.fw.tcf.enabled=true` 일 때 진입은  
`OnlineTransactionController` → `TcfFacade` → `OnlineTimeoutExecutor` → Handler → Facade → Service 이다.

트랜잭션 **실제 BEGIN 위치**는 `timeout.enabled` 에 따라 다르다.

---

## 1. TCF ON + timeout ON (현행 기본)

```yaml
nhnis.fw.tcf.enabled: true
nhnis.fw.timeout.enabled: true
```

**TX 시작:** Worker 스레드의 `DefaultOnlineTimeoutExecutor` → `TransactionTemplate.execute(...)`  
(`rdwTransactionManager`)

```text
요청 스레드: TcfFacade → submit(Worker) → Future.get(timeout)
Worker:      TransactionTemplate BEGIN
               → Handler → Facade(@Transactional join) → Service(@Transactional join) → DAO
             COMMIT / ROLLBACK
```

- 바깥(최외곽) TX = OnlineTimeoutExecutor
- Facade / Service 의 `@Transactional` 은 같은 TX에 **참여(join)**
- 타임아웃·예외 시 Worker 쪽 rollback (늦은 commit 방지)

---

## 2. TCF ON + timeout OFF

```yaml
nhnis.fw.tcf.enabled: true
nhnis.fw.timeout.enabled: false # SyncOnlineTimeoutExecutor (동기, TX 없음)
```

**TX 시작:** 업무 **Facade** 의 `@Transactional`  
(Handler → Facade 진입 시 Spring AOP가 BEGIN)

```text
요청 스레드: TcfFacade → SyncExecutor(그대로 호출)
             → Handler → Facade(@Transactional BEGIN) → Service(join) → DAO
             → COMMIT / ROLLBACK
```

---

## 3. 요약

| 설정                     | TX BEGIN 위치                                                    |
| ------------------------ | ---------------------------------------------------------------- |
| TCF ON + **timeout ON**  | `DefaultOnlineTimeoutExecutor` 의 `TransactionTemplate` (Worker) |
| TCF ON + **timeout OFF** | 업무 `Facade` `@Transactional`                                   |
| TCF OFF                  | 업무 `Service` `@Transactional` (Controller 직행)                |
