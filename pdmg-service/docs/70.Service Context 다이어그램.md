```text
┌────────────────────────────┐
```

## 2. ServiceContext 내부 정보

```text
ServiceContext
│
├─ applicationName
│   └─ 현재 실행 애플리케이션
│      예: pdmg-service
│
├─ guid
│   └─ 거래 추적 ID
│
├─ activeProfile
│   └─ local / dev / prod
│
├─ requestHeaders
│   └─ HTTP 요청 Header 정보
│
├─ request
│   └─ HttpServletRequest
│
├─ response
│   └─ HttpServletResponse
│
└─ header
    └─ hdr_nhnis
       └─ sys_comm
          ├─ std_gbl_id
          ├─ rms_svc_c
          ├─ scid
          ├─ tr_trm_ipadr
          ├─ tr_brc
          ├─ optr_eno
          └─ ttl_ug_ync
```

사용자 인증정보를 포함하면 다음과 같은 구조가 됩니다.

```text
ServiceContext
│
├─ 거래정보
│   ├─ guid
│   ├─ serviceId
│   └─ programId
│
├─ 사용자정보
│   ├─ ssoId
│   ├─ userId
│   ├─ authGroupId
│   └─ branchId
│
├─ 채널정보
│   ├─ channelId
│   ├─ clientIp
│   └─ userAgent
│
└─ HTTP정보
    ├─ requestHeaders
    ├─ request
    └─ response
```

## 3. 생성 흐름

```text
HTTP 요청
   │
   ▼
DefaultFilter.doFilter()
   │
   ├─ applicationName 조회
   ├─ activeProfile 조회
   ├─ 요청 Header 수집
   ├─ 요청 Body 파싱
   ├─ hdr_nhnis 추출
   ├─ GUID 생성·보완
   ├─ JWT에서 ssoId 추출
   └─ 표준 Header 보완
   │
   ▼
new ServiceContext(
    applicationName,
    guid,
    activeProfile,
    requestHeaders,
    request,
    response,
    header
)
   │
   ▼
ServiceContextHolder.setInstance(context)
```

## 4. ServiceContextHolder 구조

```text
ServiceContextHolder
       │
       └─ ThreadLocal<ServiceContext>
                │
                ├─ HTTP Thread-1 → ServiceContext-A
                ├─ HTTP Thread-2 → ServiceContext-B
                └─ HTTP Thread-3 → ServiceContext-C
```

동시에 여러 요청이 들어와도 각 요청은 자기 Context만 사용합니다.

```text
사용자 A 요청
Thread-1
└─ GUID-A / USER-A / SERVICE-A

사용자 B 요청
Thread-2
└─ GUID-B / USER-B / SERVICE-B
```

정상적인 경우 서로의 Context는 섞이지 않습니다.

## 5. Context 저장·조회·삭제

```text
요청 시작
   │
   ▼
ServiceContextHolder.setInstance(context)
   │
   ▼
거래 처리
   │
   ├─ ServiceContextHolder.getInstance()
   ├─ ServiceContextHolder.getInstance()
   └─ ServiceContextHolder.getInstance()
   │
   ▼
요청 종료
   │
   ▼
ServiceContextHolder.remove()
```

개념적인 구조:

```java
public final class ServiceContextHolder {

    private static final ThreadLocal<ServiceContext> HOLDER =
            new ThreadLocal<>();

    public static void setInstance(ServiceContext context) {
        HOLDER.set(context);
    }

    public static ServiceContext getInstance() {
        return HOLDER.get();
    }

    public static void remove() {
        HOLDER.remove();
    }
}
```

## 6. 계층별 활용

```text
DefaultFilter
└─ ServiceContext 생성·저장

Interceptor
├─ 사용자·IP·영업점 확인
└─ 거래 통제

OnlineTransactionController
├─ GUID 확인
└─ 표준 Header 확인

TransactionContext
└─ 현재 ServiceContext 연결

STF
├─ 거래 시작 정보 확인
└─ 시스템 검증

Handler
├─ Service ID 확인
└─ 업무 분기

Facade
├─ 사용자·거래정보 확인
└─ 트랜잭션 로그

Service
├─ 등록자·수정자 설정
├─ 영업점·채널 확인
└─ 외부 연계 추적정보 생성

DAO
└─ 필요한 사용자·감사정보를 파라미터로 전달

ETF
├─ GUID·Service ID 확인
└─ 거래 종료 로그

ExceptionHandler
├─ 오류 응답 GUID
└─ Service ID 설정
```

## 7. Business Service 사용 흐름

```text
Business Service
      │
      ▼
ServiceContextHolder.getInstance()
      │
      ▼
ServiceContext
      │
      ├─ getGuid()
      ├─ getHeader()
      ├─ getRequestHeaders()
      └─ 사용자 정보
      │
      ▼
업무 데이터 구성
      │
      ├─ registrationUserId
      ├─ updateUserId
      ├─ transactionBranchId
      ├─ channelId
      └─ transactionGuid
      │
      ▼
DAO 호출
```

개념적인 사용:

```java
ServiceContext context =
        ServiceContextHolder.getInstance();

String guid = context.getGuid();
hdr_nhnis header = context.getHeader();

String serviceId =
        header.getSys_comm().getRms_svc_c();

String branchId =
        header.getSys_comm().getTr_brc();

String userId =
        header.getSys_comm().getOptr_eno();
```

## 9. JWT와 ServiceContext

```text
HTTP 요청
   │
   │ Authorization: Bearer {Access Token}
   ▼
DefaultFilter
   │
   ▼
JWT 검증
   │
   ├─ sub / userId
   ├─ branchId
   ├─ channelId
   └─ authGroupId
   │
   ▼
ServiceContext
   │
   ├─ ssoId
   ├─ userId
   ├─ branchId
   ├─ channelId
   └─ authGroupId
   │
   ▼
거래 통제 및 업무 처리
```

신뢰 기준:

```text
JWT 검증 전 사용자정보
└─ 신뢰하면 안 됨

JWT 검증 후 Claim
└─ ServiceContext에 저장 가능

요청 Body의 userId
└─ 인증 사용자 ID로 사용하면 안 됨
```

## 13. 예외 발생 시 정리

```text
ServiceContext 생성
      │
      ▼
Service 또는 DAO에서 예외
      │
      ▼
GlobalExceptionHandler
      │
      ├─ GUID 조회
      ├─ Service ID 조회
      └─ 표준 오류 응답 생성
      │
      ▼
Interceptor.afterCompletion
      │
      ▼
DefaultFilter.finally
      │
      └─ ServiceContextHolder.remove()
```

`finally`를 사용해야 모든 종료 경로에서 정리됩니다.

```java
try {
    ServiceContextHolder.setInstance(context);
    filterChain.doFilter(request, response);
} finally {
    ServiceContextHolder.remove();
    ThreadContext.clearAll();
}
```

## 14. ThreadLocal 정리가 필요한 이유

```text
Tomcat Thread-1
   │
   ├─ 사용자 A 요청
   │    └─ ServiceContext-A
   │
   ├─ 요청 종료 후 Context 미삭제
   │
   └─ 사용자 B 요청에서 Thread-1 재사용
        │
        └─ 사용자 A 정보가 남을 위험
```

발생 가능한 문제:

```text
· 이전 사용자 ID 노출
· 잘못된 영업점 적용
· 이전 GUID로 로그 기록
· 거래 권한 오판
· 개인정보 유출
```

따라서 `remove()`는 필수입니다.

## 15. 비동기 처리

```text
HTTP Thread
│
├─ ServiceContext-A
├─ Spring Transaction
└─ MDC GUID-A
      │
      ▼
Executor Thread
│
├─ ServiceContext 없음
├─ 기존 트랜잭션 없음
└─ MDC 없음
```

ThreadLocal은 별도 Thread로 자동 전달되지 않습니다.

권장 구조:

```text
HTTP Thread
   │
   ├─ 필요한 값 추출
   │    ├─ GUID
   │    ├─ userId
   │    ├─ branchId
   │    └─ serviceId
   │
   ▼
AsyncCommand DTO
   │
   ▼
Executor Thread
   │
   ├─ 필요한 Context 재설정
   ├─ 작업 실행
   └─ finally에서 Context 제거
```

전체 `HttpServletRequest`를 비동기 Thread로 전달하는 것은 피해야 합니다.

## 18. 최종 ServiceContext 흐름

```text
HTTP 요청
   │
   ▼
DefaultFilter
   │
   ├─ JWT 검증
   ├─ GUID 생성
   ├─ Header 추출
   └─ 사용자 정보 추출
   │
   ▼
ServiceContext 생성
   │
   ▼
ServiceContextHolder
   │
   └─ ThreadLocal 저장
   │
   ├─────────────┬─────────────┬─────────────┐
   │             │             │             │
   ▼             ▼             ▼             ▼
Interceptor    TCF/Handler    Service       ExceptionHandler
   │             │             │             │
거래 통제      라우팅·추적    업무 공통값    오류 GUID
   │             │             │             │
   └─────────────┴─────────────┴─────────────┘
                         │
                         ▼
                  HTTP 요청 종료
                         │
                         ▼
                  Filter finally
                         │
                         ├─ ThreadLocal 제거
                         └─ MDC 제거
```

ServiceContext는 한 건의 HTTP 요청 동안 GUID, 사용자, 영업점, 채널 및 표준 Header를 모든 처리 계층에 전달하는 요청 단위 공통 Context입니다.
