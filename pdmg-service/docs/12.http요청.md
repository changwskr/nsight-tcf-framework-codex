# 12. HTTP 요청 (PDMG)

기준일: 2026-08-09  
대상: `pdmg-ui` → `pdmg-service` + `pdmg-fw`  
관련: [10.전문.md](./10.전문.md) · [09.서비스ID.md](./09.서비스ID.md) · [07.도메인 정의 및 호출방식.md](./07.도메인%20정의%20및%20호출방식.md) · [13.Filter-DefaultFilter.md](./13.Filter-DefaultFilter.md)

---

## 1. 정의

PDMG 온라인 거래의 HTTP 계약은 다음과 같다.

| 항목 | 값 |
|------|-----|
| Method | **POST** only |
| Content-Type | `application/json;charset=UTF-8` |
| Accept | `application/json;charset=UTF-8` |
| Body | 전문 `{ "hdr_nhnis": { "sys_comm": … }, "dto": … }` |
| 식별 | **서비스 ID** (path 및/또는 `sys_comm.rms_svc_c`) |

REST 리소스 URL(`GET /api/.../list`)·쿼리 페이징 전용 API는 쓰지 않는다.

---

## 2. URL 스타일 (TCF ON)

공통 진입: `OnlineTransactionController` (`nhnis.fw.tcf.enabled=true`)

| 스타일 | Method + Path | serviceId 출처 |
|--------|---------------|----------------|
| **PDMG 기본** | `POST /{serviceId}` | path (예: `/mgcoa8888S0`) |
| tcf-web 호환 | `POST /online` | Header `rms_svc_c` (및 Body) |
| tcf-web 호환 | `POST /{businessCode}/online` | Header 우선, path는 업무코드 |

**권장(화면·연동):**

```http
POST /mgcoa8888S0 HTTP/1.1
Host: localhost:8080
Content-Type: application/json;charset=UTF-8

{ "hdr_nhnis": { "sys_comm": { "rms_svc_c": "mgcoa8888S0", … } }, "dto": { … } }
```

serviceId 해석 우선순위(컨트롤러): **Header `rms_svc_c` → 요청 JSON → path**.  
표준은 **path = `rms_svc_c` = 동일 서비스 ID**.

로컬 포트 예: `pdmg-service` **:8080**, `pdmg-ui` **:8090**.

---

## 3. 요청 헤더

| 헤더 | 필수 | 설명 |
|------|------|------|
| `Content-Type` | O | `application/json` |
| `Accept` | 권장 | `application/json` |
| `Authorization` | 비-local | `Bearer {accessToken}` — `DefaultFilter`가 검증 |
| `X-GUID` | multipart 등 | GUID 전달 시 |
| `X-Forwarded-For` | 선택 | 클라이언트 IP 보강 |

`local` 프로파일에서는 JWT 검증을 생략한다. → Filter 문서.

---

## 4. 요청 Body (전문)

```json
{
  "hdr_nhnis": {
    "sys_comm": {
      "rms_svc_c": "mgcoa8888S0",
      "scid": "mgcoa8888",
      "tr_sysid": "PDMG",
      "optr_eno": "E0000001",
      "tr_trm_ipadr": "127.0.0.1",
      "tr_dtm": "20260807000000"
    }
  },
  "dto": {
    "pageNo": 1,
    "pageSize": 20
  }
}
```

| 키 | 역할 |
|----|------|
| `hdr_nhnis.sys_comm` | 거래·단말·조작자 (FW 헤더) |
| `dto` | 업무 입력 → `*DTOin` |

상세 필드·실패 응답: [10.전문.md](./10.전문.md)

local에서는 `{"dto":…}` 만 보내도 Filter가 헤더를 합성할 수 있다. 운영은 완전 전문을 표준으로 한다.

---

## 5. 호출 경로

### 5.1 UI 브라우저 직접 호출 (현행 화면)

```text
브라우저(`pdmg-ui :8090`)
  → POST http://localhost:8080/{serviceId}
       Body = 전문 전체
       CORS 적용
```

- 화면은 `_shared/service-client.js`의 `fetch()`로 서비스를 직접 호출한다.
- `/api/relay/{id}`와 `TransactionRelayService`는 하위 호환으로 남아 있지만 일반 화면은 사용하지 않는다.
- catalog의 id·path와 전문 `rms_svc_c`는 같아야 하지만 현재 UI와 서버가 불일치를 강제 차단하지 않는다.

### 5.2 직접 호출 (도구·연동)

```text
POST http://localhost:8080/mgcoa9000S0
```

Postman·배치성 HTTP 클라이언트. 인증은 프로파일·Security·Filter 정책 준수.

### 5.3 서버 내부 처리 (요청 수신 후)

```text
HTTP POST
  → DefaultFilter
  → ServicePreventionInterceptor
  → OnlineTransactionController
  → TcfFacade → Handler → Facade(TX) → Service → DAO
  → ResponseBodyAdvice → afterCompletion
```

---

## 6. TCF OFF 시 HTTP

`nhnis.fw.tcf.enabled=false` 이면 거래별 `application.controller.*Controller` 가 받는다.

```text
POST /mgcoa8888S0  →  mgcoa8888Controller.@PostMapping("/mgcoa8888S0")
```

URL·전문 형태는 동일하게 맞추는 것이 원칙이다. Handler/`/online` 단일 컨트롤러는 쓰지 않는다.

---

## 7. 응답과의 대응

| 결과 | HTTP (현행) | Body |
|------|-------------|------|
| 성공 | 보통 200 | `{ "hdr_nhnis": …, "dto": … }` |
| 업무/라우팅 예외 | Advice 경로 시 500 등 | `NH_NIS_ERR_DTO` (또는 Advice가 감싼 형태) |
| Filter JWT/Body 오류 | `sendError` 401/400 | 서블릿 에러 (전문 봉투와 다를 수 있음) |

호출자는 HTTP 상태만 보지 말고 **본문 스키마**(성공 봉투 vs 에러 DTO)를 구분한다.

---

## 8. 현재 서비스 URL 예

| Path | 의미 |
|------|------|
| `/mgcoa5530S0` | 마케팅희망고객 목록 |
| `/mgcoa8888S0` · `/mgcoa8888D0` | 이미지로그 조회·삭제 |
| `/mgcoa9999S0` | 영업팁 실적 목록 |
| `/mgcoa9000S0`·`C0`·`U0`·`D0` | 거래 파라미터 CRUD |

---

## 9. 금지·주의

1. `GET`/`PUT`/`DELETE` 로 온라인 거래 대체  
2. path ≠ `rms_svc_c` 불일치 방치  
3. `dto` 없이 헤더만, 또는 임의 키(`body`, `request`)  
4. URL path와 전문 `rms_svc_c`가 다른 상태로 호출  
5. 대용량 전체를 한 POST에 실어 페이징 계약 무시

- [ ] 비-local이면 `Authorization: Bearer …` 인가?

## 11. 요약

```text
HTTP 요청 = POST /{serviceId} + JSON 전문
  UI:  브라우저가 서비스 URL을 직접 호출(CORS)
  수신: Filter → Interceptor → OnlineController → Handler → …

서비스 ID가 URL이고, 전문이 Body다.
```
