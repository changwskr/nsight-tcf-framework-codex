관련: [21.업무선처리-BizPrePostAspect.md](./21.업무선처리-BizPrePostAspect.md) · [19.Business-Facade.md](./19.Business-Facade.md) · [23.DAO.md](./23.DAO.md) · [08.대용량 페이징 처리방식.md](./08.대용량%20페이징%20처리방식.md) · [09.서비스ID.md](./09.서비스ID.md)

## 1. 역할

Facade가 넘긴 `*DTOin`으로 **업무 절차**를 수행하고 `*DTOout`을 만드는 계층이다.

```text
Facade (TX 안, DTOin 확정)
  → [BizPrePost 선처리]
  → *Service.mgcoaXXXXYn(*DTOin)   ★
       · 검증·기본값·param Map 조립
       · DAO 호출 (count / select / CUD)
       · row → Sub DTO · out 조립
  → [BizPrePost 후처리]
```

| 한다 | 하지 않는다 |
|------|-------------|
| 업무 검증·분기·기본값 | `@Transactional` (Facade) |
| DAO param 조립 · 결과 매핑 | MyBatis XML / SQL 문자열 |
| 페이징 offset·totalPages 계산 | serviceId 라우팅 (Handler) |
| `BizException` 등 업무 예외 | `dto` Map → DTOin 변환 (Facade) |
| 메서드명 = 서비스 ID | 응답 `{ hdr_nhnis, dto }` 봉투 |

한 줄: **일(절차). TX·바인딩은 Facade, SQL은 DAO.**

---

## 2. 위치 · 네이밍

| 항목 | 규칙 |
|------|------|
| 패키지 | `nhnis.mg.co.a.application.service` |
| 클래스 | `{프로그램접두}Service` — `mgcoa8888Service` |
| 스테레오타입 | `@Service` |
| 메서드 | **서비스 ID와 동일** — `mgcoa8888S0(mgcoa8888S0DTOin)` |
| 인자 / 반환 | `*DTOin` / `*DTOout` (Object 아님) |
| DAO | 같은 접두 `*DAO` 주입 |

Pointcut: `execution(public * nhnis.mg.co.a.application.service..*(..))`  
→ public 메서드여야 업무 선후처리가 걸린다 ([21](./21.업무선처리-BizPrePostAspect.md)).

샘플: `mgcoa5530` / `8888` / `9000` / `9999` Service.

---

## 3. Facade · Aspect · DAO 경계

| 계층 | Service와의 관계 |
|------|------------------|
| **Facade** | `convert` 후 `service.xxx(input)` 1회. TX 소유 |
| **BizPrePostAspect** | Service 진입 전·정상 반환 후 로그 |
| **DAO** | Service만 호출. SQL ID는 `서비스ID_구분자순번` 관례 |

```text
Handler → Facade@TX → Service ← BizPrePost
                         ↓
                        DAO → Mapper XML
```

TCF OFF에서 Controller가 Service를 직호출하면 선후처리는 되지만 **TX가 빠질 수 있다** → Facade 경유 권장.

---

## 4. 표준 절차 (조회 S)

`mgcoa5530S0` / `mgcoa8888S0` / `mgcoa9000S0` 공통 골격:

```text
1. DTOin → Map param (빈 문자열 제외 putIfHasText 등)
2. pageNo / pageSize 기본값·상한 (예: pageSize ≤ 100)
3. offset = (pageNo - 1) * pageSize
4. DAO count + DAO select
5. 각 row → *DTOSub0 → out 리스트
6. size, pageNo, pageSize, totalCount, totalPages 세팅
7. return out
```

상세 페이징: [08.대용량 페이징 처리방식.md](./08.대용량%20페이징%20처리방식.md).

---

## 5. 표준 절차 (쓰기 C/U/D)

`mgcoa9000` · `mgcoa8888D0` 관례:

```text
1. 필수값·목록 검증 → 실패 시 out에 RSLT_CD/MSG (또는 BizException)
2. 중복/존재 확인 등 업무 규칙 (필요 시 DAO exists)
3. param 조립 (등록·변경 일시, 사용자 기본값 등)
4. DAO insert/update/delete
5. PROC_CNT · RSLT_CD("0000") · RSLT_MSG("OK")
```

| 예 (9000) | 코드 | 의미 |
|-----------|------|------|
| 필수 누락 | `0001` | REQUIRED / NO_DATA |
| 중복 | `0002` | DUPLICATE_TX_ID |
| 없음 | `0003` | NOT_FOUND |
| 성공 | `0000` | OK |

업무 오류를 HTTP 예외로 올릴지는 [11.예외처리.md](./11.예외처리.md)와 맞춘다.  
샘플 일부는 **out 결과코드**로 반환하고, 심각한 경우 `BizException`을 쓴다.

## 6. DAO 호출 네이밍

| Service 메서드 | DAO 메서드 예 |
|----------------|---------------|
| `mgcoa8888S0` | `mgcoa8888S0_S0`, `mgcoa8888S0_S0_count` |
| `mgcoa8888D0` | `mgcoa8888D0_D0` |
| `mgcoa9000C0` | `mgcoa9000C0_C0` |

Service는 SQL을 쓰지 않고 **메서드·param 키**만 DAO/XML과 맞춘다 ([23](./23.DAO.md)).

---

## 7. 신규 거래 체크리스트

1. `mgcoaXXXXYn(*DTOin)` public 메서드 추가 (클래스 = 프로그램 접두)  
2. Facade에서 동일 메서드명으로 호출 + TX  
3. Handler `switch` 연결  
4. DAO/XML/DTO 준비  
5. 기동 후 로그: `[업무 선처리] 호출: …Service.mgcoaXXXXYn`

---

## 8. 하지 말 것

1. Service에 `@Transactional`을 기본으로 올리기 (중첩·경계 혼란)  
2. Mapper/`SqlSession` 직접 사용 (DAO 우회)  
3. `Object dtoBody`를 Service 시그니처로 받기  
4. Handler/Controller에서 DAO만 호출하고 Service 생략  
5. 패키지를 `application.service` 밖으로 옮겨 Pointcut 깨기  
6. private 메서드만 두고 public 거래 진입점을 없애기 (선후처리 미적용)

---

  TX = Facade 안 / 선후 = BizPrePost on Service
