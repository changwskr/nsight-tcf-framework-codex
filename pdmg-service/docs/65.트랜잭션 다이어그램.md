# 트랜잭션 아키텍처 텍스트 다이어그램

## 1. 전체 트랜잭션 구조

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 트랜잭션 외부 영역                                                         │
│                                                                              │
│ HTTP 요청                                                                   │
│   → DefaultFilter                                                           │
│   → ServicePreventionInterceptor                                            │
│   → OnlineTransactionController                                             │
│   → TcfFacade                                                               │
│   → STF 시스템 선처리                                                       │
│   → TransactionDispatcher                                                   │
│   → TransactionHandler                                                      │
└─────────────────────────────────────┬────────────────────────────────────────┘
                                      │ Facade 호출
                                      ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ Business Facade 트랜잭션 영역                                              │
│                                                                              │
│ @Transactional(                                                             │
│     transactionManager = "rdwTransactionManager",                          │
│     rollbackFor = Exception.class                                           │
│ )                                                                            │
│                                                                              │
│   TX BEGIN                                                                   │
│      │                                                                       │
│      ├─ BizPrePostAspect 업무 선처리                                        │
│      │                                                                       │
│      ├─ Business Service                                                    │
│      │      │                                                                │
│      │      ├─ Business Rule                                                │
│      │      ├─ DAO SELECT                                                   │
│      │      ├─ DAO INSERT                                                   │
│      │      ├─ DAO UPDATE                                                   │
│      │      └─ DAO DELETE                                                   │
│      │                                                                       │
│      ├─ BizPrePostAspect 업무 후처리                                        │
│      │                                                                       │
│      ├─ 정상 반환 ───────────────────────────────▶ COMMIT                   │
│      └─ 예외 전파 ───────────────────────────────▶ ROLLBACK                 │
└─────────────────────────────────────┬────────────────────────────────────────┘
                                      │
                                      ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ 트랜잭션 외부 영역                                                         │
│                                                                              │
│ ETF 시스템 후처리                                                          │
│   → 표준 응답 변환                                                         │
│   → GlobalExceptionHandler                                                  │
│   → ServiceContext / MDC 정리                                               │
│   → HTTP 응답                                                               │
└──────────────────────────────────────────────────────────────────────────────┘
```

핵심 경계:

```text
STF
 │
 │ 트랜잭션 밖
 ▼
Handler
 │
 ▼
Facade @Transactional
 ├══════════════════ TX BEGIN ══════════════════╗
 ║ BizPre                                      ║
 ║   → Service                                 ║
 ║     → Rule                                  ║
 ║       → DAO                                 ║
 ║         → Mapper                            ║
 ║           → DB                             ║
 ║   → BizPost                                 ║
 ╚══════════ COMMIT 또는 ROLLBACK ═════════════╝
 │
 │ 트랜잭션 밖
 ▼
ETF
```

## 2. 트랜잭션 구성요소

```text
application.yml
      │
      ├─ RDW DB URL
      ├─ 사용자
      ├─ 비밀번호
      └─ Connection Pool 설정
      │
      ▼
RdwDataSourceConfig
      │
      ├─ RDW DataSource
      ├─ SqlSessionFactory
      ├─ SqlSessionTemplate
      └─ rdwTransactionManager
      │
      ▼
Spring TransactionInterceptor
      │
      ▼
Business Facade의 @Transactional
      │
      ▼
동일 RDW Connection
      │
      ▼
DAO / Mapper / DB
```

## 3. `@Transactional` 실행 구조

```text
Handler 또는 Controller
        │
        ▼
Spring Facade Proxy
        │
        ├─ @Transactional 확인
        ├─ rdwTransactionManager 선택
        ├─ Connection 획득
        └─ 트랜잭션 BEGIN
        │
        ▼
실제 Business Facade
        │
        ▼
Business Service
        │
        ▼
DAO / Mapper
        │
        ▼
업무 DB
        │
        ├─ 정상 반환
        │      └─ Proxy가 COMMIT
        │
        └─ Exception 전파
               └─ Proxy가 ROLLBACK
```

선언 예:

```java
@Transactional(
    transactionManager = "rdwTransactionManager",
    rollbackFor = Exception.class
)
public OutputDTO execute(InputDTO input) throws Exception {
    return service.execute(input);
}
```

## 4. 정상 처리

```text
Facade Proxy
   │
   ├─ TX BEGIN
   ▼
Facade
   │
   ▼
BizPre
   │
   └─ 업무 이력 INSERT
   │
   ▼
Service
   │
   ├─ DAO INSERT
   └─ DAO UPDATE
   │
   ▼
BizPost
   │
   └─ 처리 결과 UPDATE
   │
   ▼
Facade 정상 반환
   │
   ▼
TransactionInterceptor
   │
   └─ COMMIT
```

결과:

```text
업무 선처리 INSERT   ─┐
본 업무 INSERT       ├─ 모두 COMMIT
본 업무 UPDATE       │
업무 후처리 UPDATE   ─┘
```

## 5. 예외와 롤백

```text
Facade TX BEGIN
   │
   ├─ DAO INSERT 성공
   ├─ DAO UPDATE 성공
   ├─ BizPost INSERT 실행
   └─ BizPost에서 Exception 발생
          │
          ▼
      Aspect가 예외 재전파
          │
          ▼
      Facade 밖으로 예외 전파
          │
          ▼
      TransactionInterceptor
          │
          ▼
        ROLLBACK
```

결과:

```text
DAO INSERT          취소
DAO UPDATE          취소
BizPost INSERT      취소
```

`rollbackFor = Exception.class`이 있으므로 Checked Exception도 롤백 대상입니다.

## 6. 예외를 처리하고 반환하면 발생하는 문제

```text
Service
   │
   ▼
try {
    dao.update();
} catch (Exception e) {
    log.error(...);
    return 정상 DTO;
}
   │
   ▼
Facade 정상 반환
   │
   ▼
TransactionInterceptor
   │
   └─ COMMIT
```

따라서 예외를 반드시 다시 던져야 합니다.

```java
catch (Exception e) {
    log.error("업무 처리 실패", e);
    throw e;
}
```

```text
예외 재전파
   → TransactionInterceptor 감지
   → ROLLBACK
```

## 7. 업무 선후처리와 트랜잭션

현재 Service 포인트컷 구조:

```text
Facade TX BEGIN
   │
   ▼
Service Proxy
   │
   ├─ BizPre
   │
   ▼
실제 Service
   │
   ├─ Rule
   └─ DAO / DB
   │
   ▼
Service Proxy
   │
   ├─ BizPost
   │
   ▼
Facade
   │
   └─ COMMIT
```

따라서 다음 작업은 같은 트랜잭션에 포함됩니다.

```text
┌─────────────────────────────┬───────────────────┐
│ 처리 영역                   │ 동일 TX 포함      │
├─────────────────────────────┼───────────────────┤
│ BizPre DB 처리              │ 포함              │
│ Service DB 처리             │ 포함              │
│ Rule에서 호출한 DB 처리     │ 포함              │
│ DAO / Mapper 처리           │ 포함              │
│ BizPost DB 처리             │ 포함              │
└─────────────────────────────┴───────────────────┘
```

조건:

```text
· 같은 Thread
· 같은 rdwTransactionManager
· 같은 RDW DataSource
· REQUIRES_NEW 미사용
· 예외를 삼키지 않음
```

## 8. 시스템 선후처리와 트랜잭션

```text
DefaultFilter                 TX 밖
Interceptor.preHandle         TX 밖
STF                           TX 밖

Facade
├─ BizPre                     TX 안
├─ Service                    TX 안
├─ DAO                        TX 안
└─ BizPost                    TX 안

ETF                           TX 밖
Interceptor.afterCompletion   TX 밖
Filter.finally                TX 밖
```

```text
시스템 선처리
   │
   │ TX 없음
   ▼
업무 Facade
   │
   │ TX BEGIN
   ├─ 업무 선처리
   ├─ 본 업무
   └─ 업무 후처리
   │
   │ COMMIT / ROLLBACK
   ▼
시스템 후처리
   │
   │ 기존 TX 종료
   ▼
응답
```

ETF에서 DB 오류가 발생해도 이미 완료된 업무 트랜잭션은 롤백할 수 없습니다.

## 9. TCF ON 트랜잭션

```text
POST /online
   │
   ▼
OnlineTransactionController
   │
   ▼
TcfFacade
   │
   ├─ STF
   ▼
TransactionDispatcher
   │
   ▼
TransactionHandler
   │
   ▼
Business Facade
   │
   ├─ TX BEGIN
   ▼
BizPre → Service → DAO → BizPost
   │
   ├─ 정상: COMMIT
   └─ 예외: ROLLBACK
   │
   ▼
ETF
```

TCF 자체가 트랜잭션을 시작하는 것이 아니라 업무 Facade가 시작합니다.

## 10. TCF OFF 트랜잭션

권장:

```text
POST /mgcoa5530S0
   │
   ▼
업무 Controller
   │
   ▼
Business Facade
   │
   ├─ TX BEGIN
   ▼
BizPre → Service → DAO → BizPost
   │
   ├─ COMMIT
   └─ ROLLBACK
```

주의:

```text
Controller → Service 직접 호출
                    │
                    ▼
        Facade @Transactional 우회
                    │
                    ▼
       명시적인 업무 TX가 없을 수 있음
```

## 11. 전파 속성

### `REQUIRED` — 기본값

```text
기존 트랜잭션 있음
   └─ 기존 TX 참여

기존 트랜잭션 없음
   └─ 신규 TX 시작
```

```java
@Transactional(
    transactionManager = "rdwTransactionManager",
    propagation = Propagation.REQUIRED
)
```

### `REQUIRES_NEW`

```text
기존 업무 TX
   │
   ├─ 일시 중지
   ▼
신규 독립 TX
   │
   ├─ COMMIT / ROLLBACK
   ▼
기존 업무 TX 재개
```

오류 이력을 반드시 남길 때 사용합니다.

```text
본 업무 TX          ROLLBACK
오류 이력 신규 TX   COMMIT
```

### `MANDATORY`

```text
기존 TX 있음
   └─ 참여

기존 TX 없음
   └─ 예외 발생
```

반드시 상위 트랜잭션 안에서만 호출되어야 하는 처리에 사용할 수 있습니다.

## 12. 여러 DAO의 트랜잭션

```text
Facade TX BEGIN
   │
   ▼
Service
   │
   ├─ customerDAO.update()
   ├─ historyDAO.insert()
   └─ controlDAO.update()
   │
   ▼
동일 RDW DataSource
   │
   ├─ 전체 성공
   │      └─ 전체 COMMIT
   │
   └─ 하나라도 실패
          └─ 전체 ROLLBACK
```

다른 DataSource:

```text
rdwTransactionManager
   └─ RDW DataSource만 관리

다른 DataSource DAO
   └─ 자동으로 같은 트랜잭션에 포함되지 않음
```

여러 DB를 원자적으로 처리하려면 분산 트랜잭션이나 보상 트랜잭션 설계가 필요합니다.

## 13. 자기 호출 문제

```text
외부 Bean
   │
   ▼
Facade Spring Proxy
   │
   └─ @Transactional 적용
```

하지만 같은 객체 내부 호출은 프록시를 거치지 않습니다.

```text
Facade.methodA()
   │
   └─ this.methodB()
           │
           └─ methodB의 별도 @Transactional 적용 안 됨
```

별도 트랜잭션 정책이 필요하면 다른 Spring Bean으로 분리해야 합니다.

## 14. 비동기 처리

```text
업무 TX Thread
   │
   ├─ ServiceContext
   ├─ JDBC Connection
   └─ Spring Transaction
   │
   ▼
별도 Executor Thread
   │
   ├─ 기존 TX 전달 안 됨
   ├─ Connection 공유 안 됨
   └─ ThreadLocal 자동 전달 안 됨
```

따라서 같은 트랜잭션이어야 하는 처리는 `@Async`, `CompletableFuture` 또는 별도 Executor로 실행하면 안 됩니다.

## 15. 타임아웃과 롤백

작업 취소와 롤백을 달성하려면 타임아웃 예외가 Facade 트랜잭션 내부에서 발생해야 합니다.

```text
Facade TX BEGIN
   │
   ▼
TimeoutExecutor
   │
   ▼
Service → DAO
   │
   ├─ 제한시간 이내
   │      └─ 정상 반환 → COMMIT
   │
   └─ 제한시간 초과
          ├─ 작업 취소 요청
          ├─ OnlineTimeoutException
          └─ Facade 밖으로 예외 전파
                    │
                    ▼
                 ROLLBACK
```

잘못된 위치:

```text
Facade TX COMMIT
   │
   ▼
ETF에서 타임아웃 발견
   │
   ▼
오류 응답
   │
   └─ 이미 COMMIT된 데이터는 롤백 불가
```

## 16. 트랜잭션 로그

```text
Facade 진입
   │
   ├─ TX BEGIN 로그
   ├─ GUID
   ├─ Service ID
   └─ TransactionManager
   │
   ▼
Service / DAO 실행
   │
   ▼
Facade 종료
   │
   ├─ COMMIT
   └─ ROLLBACK + 예외 정보
```

권장 로그:

```text
[TX-BEGIN]
guid=...
serviceId=mgcoa8888U0
transactionManager=rdwTransactionManager

[TX-COMMIT]
guid=...
serviceId=mgcoa8888U0
elapsedMs=...

[TX-ROLLBACK]
guid=...
serviceId=mgcoa8888U0
exceptionCode=...
```

비밀번호, Token, 개인정보, SQL 파라미터 원문은 남기지 않아야 합니다.

## 17. 최종 트랜잭션 흐름

```text
HTTP 요청
   │
   ▼
시스템 선처리
   │
   │ TX 밖
   ▼
Handler 또는 Controller
   │
   ▼
Facade Proxy
   │
   ├════════════ rdwTransactionManager BEGIN ════════════╗
   ║                                                     ║
   ║ BizPre                                              ║
   ║    │                                                ║
   ║ Service                                             ║
   ║    │                                                ║
   ║ Rule → DAO → Mapper → RDW DB                        ║
   ║    │                                                ║
   ║ BizPost                                             ║
   ║                                                     ║
   ║ 정상 반환    → COMMIT                               ║
   ║ Exception    → ROLLBACK                             ║
   ╚═════════════════════════════════════════════════════╝
   │
   ▼
시스템 후처리
   │
   │ TX 밖
   ▼
HTTP 응답
```

핵심은 `Facade가 트랜잭션 경계`, `Service가 업무 흐름`, `DAO가 데이터 처리`를 담당하는 구조입니다.
