# PDMG 패키지 아키텍처 텍스트 다이어그램

## 1. 전체 모듈 구조

```text
nsight-tcf-framework-codex
│
├─ pdmg-ui
│   └─ 화면·브라우저 클라이언트
│
├─ pdmg-service
│   └─ 업무 애플리케이션
│
├─ pdmg-fw
│   └─ 공통 Web·TCF·트랜잭션 프레임워크
│
└─ pdmg-jwt
    └─ 인증·JWT 발급·토큰 관리
```

모듈 호출 방향:

```text
pdmg-ui
   │
   ├──────────────▶ pdmg-jwt
   │                 로그인·토큰 발급·갱신
   │
   └──────────────▶ pdmg-service
                     │
                     └──────────────▶ pdmg-fw
                                       공통 Web·TCF 기능
```

# 2. `pdmg-service` 업무 패키지

기본 업무 패키지 형식:

```text
nhnis.mg.[업무구분].[세부업무구분]
```

현재 `CO/A` 업무 패키지:

```text
nhnis.mg.co.a
│     │  │  │
│     │  │  └─ 세부업무: A
│     │  └──── 업무구분: CO
│     └─────── 시스템 대구분: MG
└───────────── 회사·프로젝트 루트
```

## 5. 패키지 의존 방향

```text
entry.handler
      │
      ▼
application.facade
      │
      ▼
application.service
      │
      ├──────────────▶ application.rule
      │
      ├──────────────▶ persistence.dao
      │
      └──────────────▶ client
                           │
                           ▼
                       외부 시스템
```

상세 구조:

```text
Handler
   │
   │ Service ID 분기
   ▼
Facade
   │
   │ 트랜잭션·유스케이스 조정
   ▼
Service
   │
   ├─ Rule
   │    └─ 검증·계산
   │
   ├─ DAO
   │    └─ Mapper → DB
   │
   └─ Client
        └─ 외부 시스템
```

피해야 하는 역방향 의존:

```text
X DAO → Service
X DAO → Controller
X Rule → Controller
X Service → Handler
X Facade → Controller
X pdmg-fw → pdmg-service 업무 클래스
```

# 11. 패키지별 트랜잭션 경계

```text
entry.handler
      │
      │ TX 밖
      ▼
application.facade
      │
      ├════════ @Transactional BEGIN ════════╗
      ║                                     ║
      ║ application.service                 ║
      ║      │                              ║
      ║      ├─ application.rule            ║
      ║      ├─ persistence.dao             ║
      ║      └─ client                      ║
      ║                                     ║
      ╚════════ COMMIT / ROLLBACK ══════════╝
```

```text
entry.aspect
└─ application.service 포인트컷
   └─ Facade가 시작한 트랜잭션 안에서 실행
```

# 12. 최종 패키지 아키텍처

```text
pdmg-ui
└─ 화면·HTTP Client
       │
       ▼
pdmg-fw
├─ Filter
├─ Interceptor
├─ ServiceContext
├─ TCF
├─ Timeout
├─ JWT 검증
└─ Exception 처리
       │
       ▼
pdmg-service
└─ nhnis.mg.[업무].[세부]
   │
   ├─ entry
   │  ├─ handler
   │  └─ aspect
   │
   ├─ application
   │  ├─ controller
   │  ├─ facade
   │  ├─ service
   │  └─ rule
   │
   ├─ dto
   │
   ├─ persistence
   │  └─ dao
   │
   ├─ client
   ├─ config
   └─ support
       │
       ▼
Mapper XML
       │
       ▼
업무 DB
```

패키지 설계의 핵심 원칙은 다음과 같습니다.

```text
entry
└─ 외부 또는 TCF 거래 진입

application
└─ 업무 유스케이스와 처리 흐름

dto
└─ 거래 입출력 계약

persistence
└─ 데이터 접근

client
└─ 외부 시스템 연계

config
└─ Spring·DataSource 구성

support
└─ 업무 공통 보조 기능
```
