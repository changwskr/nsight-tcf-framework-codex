## 1. 위치

Spring MVC가 Controller 메서드를 실행하기 **직전**에 호출된다.

```text
DefaultFilter
  → DispatcherServlet · HandlerMapping
  → ServicePreventionInterceptor.preHandle   ★ 본 문서
  → OnlineTransactionController → Handler → Facade(TX) → …
```

| 항목 | 값 |
|------|-----|
| 클래스 | `nhnis.fw.commons.interceptor.ServicePreventionInterceptor` |
| 인터페이스 | `HandlerInterceptor` |
| 메서드 | `boolean preHandle(...)` → 내부 `preHandleInternal` |
| 역할 | **시스템 선처리** (요청전문 로그 + ImageLog INSERT) |
| 업무 TX | **밖** |
| 반환 | 항상 `true` (현행 — 요청을 막지 않음) |

등록: `WebConfiguration` — `/**`, `/error` 제외, `legacy-web.enabled=true`.

---

## 2. 하는 일 / 하지 않는 일

| 한다 | 하지 않는다 |
|------|-------------|
| `[시스템 선처리]` 로그 배너 | JWT 검증 (Filter) |
| GUID 보장·MDC 반영 | Body 최초 캐시 (Filter) |
| `sys_comm` 보강 (서비스·화면·IP·조작자) | 업무 검증·`BizException` |
| 요청 전문 원문 CORE 로그 | 응답 봉투 조립 (Advice) |
| `imageLogHandler.preImagelog` | `postImagelog` (afterCompletion) |
| | Service/DAO/`@Transactional` |

---

## 3. 처리 순서 (`preHandleInternal`)

```text
TX-FLOW enter (preHandle)
│
├─ 1. [시스템 선처리] 시작  (+ 거래 구분 라인피드)
│
├─ 2. Content-Type 이 multipart* ?
│      YES → [시스템 선처리] 종료 → return true
│
├─ 3. ServiceContextHolder.getInstance() == null ?
│      YES → WARN (Context null) → 선처리 종료 → return true
│
├─ 4. ensureHeader(ctx)
│      hdr_nhnis / sys_comm 없으면 생성
│
├─ 5. ensureGuid(ctx, header)
│      std_gbl_id 없으면 UUID 채번
│      ctx.guid · ThreadContext("guid") 반영
│
├─ 6. enrichHeaderFromRequest(request, header)
│      rms_svc_c ← path 마지막 세그먼트 (비어 있을 때)
│      scid ← 서비스 ID에서 [SD]\d+$ 제거
│      tr_trm_ipadr ← X-Forwarded-For / remoteAddr
│      optr_eno ← MDC userId 또는 "LOCAL"
│
├─ 7. 로그: [시스템 선처리] GUID: …
│
├─ 8. resolveRequestBodyRaw → logRequestMessage
│      [온라인전문][요청][원문]
│      [요청전문] {…}
│
├─ 9. imageLogHandler.preImagelog(header, requestRaw)
│      ImageLog INSERT (요청 시점)
│
├─10. [시스템 선처리] 종료
│
└─ return true
   TX-FLOW leave
```

---

## 4. 요청 전문 원문 (`resolveRequestBodyRaw`)

우선순위:

1. `ServiceContext.getRequestBody()` — Filter가 넣어 둔 원문  
2. request attribute `PDMG_REQUEST_BODY` (`DefaultFilter.REQUEST_BODY_ATTR`)  
3. 래퍼 체인에서 `CachedBodyHttpServletRequest.getCachedBody()`  
4. 없으면 `"(empty-request-body)"`  

출력 전 `PdmgMessagePrinter.asIs(raw)` 로 정리한다.

Filter가 없거나 Context가 비면 전문 로그·ImageLog 품질이 떨어진다. **Filter → preHandle** 순서가 전제다.

---

## 5. GUID · 헤더 보강

### 5.1 `ensureGuid`

| 상태 | 동작 |
|------|------|
| `std_gbl_id` 있음 | ctx·MDC에 그대로 반영 |
| 없음/공백 | UUID(하이픈 제거) 채번 후 헤더·ctx·MDC |

ImageLog·추적은 GUID가 키이므로, 선처리에서 비어 있으면 **강제 채번**한다.

### 5.2 `enrichHeaderFromRequest`

local 합성 헤더·부분 헤더를 ImageLog에 남길 수 있게 보완한다.  
이미 값이 있으면 덮어쓰지 않는다(공백만 채움).

---

## 6. ImageLog (`preImagelog`)

```text
시점: Controller/Handler 진입 전
입력: hdr_nhnis + 요청 전문 원문
효과: ImageLog 행 INSERT (요청시각·요청전문 등)
TX:   업무 Facade 트랜잭션과 분리
```

응답·예외 갱신은 **afterCompletion** (`postImagelog` / `exceptionImagelog`). → [26.시스템후처리.md](./26.시스템후처리.md)

---

## 7. 로그 패턴 (기대)

```text
[시스템 선처리] 시작 ===============================================
[시스템 선처리] GUID: …
[온라인전문][요청][원문] ===============================================
[요청전문] { "hdr_nhnis": …, "dto": … }
[시스템 선처리] 종료 ===============================================
```

`log.info`는 Interceptor 클래스에서 **직접** 호출한다 (`%C.%M` 위치가 `ServicePreventionInterceptor`로 남도록).

---

## 8. 특수·예외 케이스

| 케이스 | 동작 |
|--------|------|
| multipart | 선처리 본문 스킵, `true` |
| Context null | WARN 후 `true` (요청은 계속 — Filter 미동작 등) |
| 요청전문 로그 실패 | WARN, 가능하면 ImageLog는 계속 시도 |
| `return false` | **현행 코드에 없음** — 차단은 Filter `sendError` 쪽 |

업무 예외는 preHandle 이후 Handler/Facade에서 발생한다.

---

## 9. postHandle / afterCompletion (이 문서 범위 밖 요약)

| 콜백 | preHandle과의 관계 |
|------|-------------------|
| `postHandle` | 응답 전문은 Advice에 위임 (여기선 no-op에 가깝다) |
| `afterCompletion` | 시스템 후처리 ImageLog — pre의 INSERT를 UPDATE |

전체 시스템 선후: [14.시스템 선후처리.md](./14.시스템%20선후처리.md)

---

## 10. 하지 말 것

1. `preHandle`에서 업무 Service 호출·TX  
2. `return false`로 막으면서 Filter와 다른 에러 포맷 혼용  
3. ImageLog를 Facade `@Transactional` 안으로 옮기기  
4. Filter 없이 preHandle만으로 Body/GUID를 완전하다고 가정  
5. 응답 로그를 `preHandle`에 넣기

## 12. 요약

```text
preHandle = 시스템 선처리의 본체
  GUID 확정 → 요청전문 로그 → ImageLog INSERT → return true
  → 그다음 OnlineController / Handler / Facade(TX)

준비는 Filter, 선처리 실행은 preHandle, 후처리는 Advice + afterCompletion.
```
