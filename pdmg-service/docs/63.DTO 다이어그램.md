## 8. TCF ON DTO 변환

TCF ON에서는 업무 Body가 처음에 구체적인 DTO가 아닌 `Object` 또는 `Map` 형태로 전달될 수 있습니다.

```text
POST /online
      │
      ▼
표준 요청 JSON
      │
      ├─ hdr_nhnis
      └─ dto
           │
           ▼
OnlineTransactionController
           │
           ▼
TransactionDispatcher
           │
           ▼
TransactionHandler
           │
           │ Object dtoBody
           ▼
Business Facade
           │
           ▼
ObjectMapper.convertValue()
           │
           ▼
mgcoa8888S0DTOin
           │
           ▼
Business Service
```

개념 코드:

```java
public mgcoa8888S0DTOout mgcoa8888S0(
        Object dtoBody
) throws Exception {

    mgcoa8888S0DTOin input =
            objectMapper.convertValue(
                    dtoBody,
                    mgcoa8888S0DTOin.class
            );

    return service.mgcoa8888S0(input);
}
```

```text

   ▼
```

```text
   ├─ @Min / @Max

   │

   │    └─ Service 실행
   │

        └─ GlobalExceptionHandler

```

예:


```text
│
```

```text
│   │
│   └─ hdr_nhnis
│       └─ sys_comm
│           ├─ GUID

│           ├─ 영업점
│           └─ 채널
│
└─ 업무 DTO
    │

        ├─ 페이지 번호
        └─ 페이지 크기
```

업무 DTO에 시스템 공통값을 중복 정의하지 않는 것이 좋습니다.

```text
├─ serviceId
├─ userId
├─ branchId

```

권장 구조:

```text

├─ guid
├─ serviceId
├─ userId
└─ branchId

DTOin
└─ 업무 입력값만 보유
```

## 13. DTO 변환 경계

```text
외부 HTTP JSON
      │
      ▼
Controller / Facade
      │
      └─ 외부 계약 DTO
      │
      ▼
Service
      │
      ├─ 필요하면 내부 Command/Domain으로 변환
      └─ 업무 처리
      │
      ▼
DAO
      │
      └─ 조회·저장용 파라미터
      │
      ▼
DB
```

복잡한 업무에서는 DTO와 도메인 모델을 분리합니다.

```text
DTOin
  → Command
  → Domain Model
  → DAO Parameter

DB Result
  → Domain Model
  → DTOout
```

단순 CRUD에서는 DTO를 DAO 파라미터와 결과로 직접 사용하는 현재 방식도 가능합니다.

## 14. DTO와 트랜잭션

DTO 자체는 트랜잭션을 관리하지 않습니다.

```text
DTOin
   │
   ▼
Facade
   │
   ├─ TX BEGIN
   ▼
Service
   │
   ├─ DTOin 사용
   ├─ DAO 처리
   └─ DTOout 생성
   │
   ▼
Facade
   │
   ├─ 정상: COMMIT
   └─ 예외: ROLLBACK
   │
   ▼
DTOout
```

트랜잭션 롤백이 발생하면 생성 중이던 DTOout은 사용자에게 반환하지 않고 표준 오류 응답으로 변환합니다.

## 15. DTO 필드 네이밍

Java DTO 필드는 `camelCase`를 사용합니다.

```text
데이터베이스             Java DTO
────────────────────────────────────
SERVICE_ID              serviceId
SERVICE_NAME            serviceName
TOTAL_COUNT             totalCount
PAGE_NO                 pageNo
PAGE_SIZE               pageSize
BRANCH_ID               branchId
REGISTRATION_DATE       registrationDate
```

권장:

```java
private String serviceId;
private int totalCount;
private int pageNo;
```

피해야 할 이름:

```java
private String svc_id;
private String data1;
private String tempValue;
private Object obj;
```

## 18. 최종 DTO 관계 공식

```text
Service ID
  = mgcoa8888S0

입력 DTO
  = Service ID + DTOin
  = mgcoa8888S0DTOin

출력 DTO
  = Service ID + DTOout
  = mgcoa8888S0DTOout

목록 DTO
  = Service ID + DTOSub + 순번
  = mgcoa8888S0DTOSub0
```

한 줄로 표현하면:

```text
화면 입력
 → JSON
 → DTOin
 → Facade
 → Service
 → DAO / Mapper
 → DTOSub
 → DTOout
 → JSON
 → 화면 출력
```
