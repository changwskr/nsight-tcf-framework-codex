# PDMG Spring 환경 파일 중심 소스 연관성

기준일: 2026-08-09  
대상: `pdmg-service`, `pdmg-fw`

## 1. 환경 파일 적용 관계

실제 애플리케이션의 중심 환경 파일은 다음이다.

```text
pdmg-service/src/main/resources/application.yml
```

`pdmg-service`가 실행 애플리케이션이고 `pdmg-fw`는 라이브러리이므로, 최종 환경값은 실행 애플리케이션의 Spring `Environment`에서 결정된다.

```text
OS 환경변수 / JVM 옵션 / 실행 인자
             ↓ 우선순위가 높음
application-{profile}.yml 또는 profile 문서
             ↓
application.yml
             ↓
Java 코드의 @Value 기본값 또는 Properties 필드 기본값
```

`pdmg-fw/src/main/resources/application-fw-defaults.yml`은 파일명 자체로는 Spring Boot가 자동 로딩하지 않는다. 현재 `application.yml`에서 이 파일을 import하지도 않으므로 **참고용 샘플**이다.

현재 자동 import되는 별도 파일은 다음뿐이다.

```yaml
spring:
  config:
    import: classpath:exceptionCode.yml
```

## 2. 전체 환경 파일과 소스 연결 지도

```text
application.yml
├─ spring.profiles.active
│   └─ DefaultFilter.active
├─ spring.application.name
│   └─ DefaultFilter.applicationName → ServiceContext.applicationName
├─ spring.config.import
│   └─ exceptionCode.yml → ExceptionCodeProperties
├─ spring.mvc.cors
│   └─ CorsProperties → WebMvcConfig / SecurityConfig
├─ spring.datasource.rdw
│   └─ RdwDataSourceConfig → rdwDataSource
├─ spring.sql.init
│   └─ Spring Boot SQL Initialization → schema.sql / data.sql
├─ nhnis.fw.tcf.enabled
│   ├─ OnlineTransactionController
│   ├─ TcfFacade
│   ├─ TransactionDispatcher
│   ├─ GlobalExceptionHandler
│   ├─ Business Handler ON
│   └─ 거래별 Controller OFF
├─ nhnis.fw.timeout
│   ├─ OnlineTimeoutProperties
│   ├─ OnlineTimeoutConfiguration
│   ├─ DefaultOnlineTimeoutExecutor 또는 SyncOnlineTimeoutExecutor
│   └─ rdwTransactionManager
├─ nhnis.fw.commons.legacy-web.enabled
│   ├─ WebConfiguration
│   ├─ ServicePreventionInterceptor
│   ├─ ResponseBodyArgumentResolver
│   └─ 업무/시스템 흐름 Aspect
├─ nhnis.fw.commons.filter.enabled
│   ├─ DefaultFilter
│   └─ FilterConfiguration
└─ jwt
    ├─ secret → JwtProvider
    ├─ enabled → 현재 Filter 판단에 사용되지 않음
    └─ access-token-expiration → 현재 검증 경로에서 직접 사용되지 않음
```

## 3. `spring.profiles.active`

### YAML

```yaml
spring:
  profiles:
    active: local
```

### 연결 소스

```java
@Value("${spring.profiles.active:local}")
private String active;
```

위 코드는 `pdmg-fw`의 `DefaultFilter`에 있다.

### 실제 동작

```java
if (!"local".equalsIgnoreCase(active)) {
    // Bearer Token 검증
    // 공통 Header 필수 검증
}
```

| 값 | 동작 |
|---|---|
| `local` | JWT 검증 생략, Header가 없으면 합성 Header 생성 |
| `dev`, `prod` 등 | Bearer Token과 공통 Header 요구 |

### 변경할 때 확인할 것

- `dev`로 변경하면 `jwt.enabled=false`여도 현재 Filter는 JWT를 요구한다.
- 운영에서는 `PDMG_JWT_SECRET`이 설정되어 있어야 한다.
- `spring.profiles.active`를 YAML에 고정하기보다 실행 인자로 주는 방식이 배포 환경에는 더 적합하다.

```powershell
java -jar app.jar --spring.profiles.active=dev
```

## 4. `spring.application.name`

### YAML

```yaml
spring:
  application:
    name: pdmg
```

### 연결 소스

```java
@Value("${spring.application.name}")
private String applicationName;
```

`DefaultFilter`가 `ServiceContext`를 만들 때 사용한다.

```java
new ServiceContext(
    applicationName,
    guid,
    active,
    requestHeaders,
    request,
    response,
    header
);
```

### 영향

- Context에 저장되는 애플리케이션 식별자
- Local 합성 Header의 `tr_sysid`
- 로그와 시스템 간 호출 식별 정보

이름을 바꾸면 외부 시스템과 로그 수집기의 시스템 ID 계약도 함께 확인해야 한다.

## 5. `spring.config.import`

### YAML

```yaml
spring:
  config:
    import: classpath:exceptionCode.yml
```

### 연결 파일

```text
pdmg-service/src/main/resources/exceptionCode.yml
```

### 연결 소스

```java
@ConfigurationProperties("nhnis")
public class ExceptionCodeProperties { ... }
```

`exceptionCode.yml`의 `nhnis.exception.*` 항목이 `ExceptionCodeProperties`로 바인딩된다.

### 주의사항

`pdmg-fw`에도 동일한 classpath 이름의 `exceptionCode.yml`이 존재한다. 실행 WAR에 같은 경로 리소스가 둘 이상 들어가면 어떤 파일을 기준으로 삼을지 혼동될 수 있으므로 다음 중 하나가 안전하다.

- 서비스 파일을 유일한 `exceptionCode.yml`로 사용
- FW 파일명을 `pdmg-fw-exception-code.yml`처럼 구분
- import 경로를 명확하게 분리

## 6. `spring.mvc.cors`

### YAML

```yaml

  mvc:
    cors:
      allowed-origins:
      allowed-methods:
      allowed-headers:
```

### 연결 소스

```java
@ConfigurationProperties("spring.mvc.cors")
public class CorsProperties { ... }
```

```text
CorsProperties
→ WebMvcConfig
→ Spring MVC CORS Registry
```

`SecurityConfig`도 다음처럼 Spring Security CORS를 활성화한다.

```java
http.cors(Customizer.withDefaults());
```

### 변경 예시

```yaml
spring:
  mvc:

      allowed-methods:
        - GET
        - POST
      allowed-headers:
        - Content-Type
        - Authorization
```

운영에서 `*`를 사용하면 임의 Origin의 호출을 허용할 수 있으므로 구체적인 UI 주소를 지정한다.

## 7. `spring.datasource.rdw`

### 현재 Local YAML

```yaml
spring:
  datasource:
    rdw:
      jdbc-url: jdbc:log4jdbc:h2:mem:pdmg;MODE=Oracle;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE
      driver-class-name: net.sf.log4jdbc.sql.jdbcapi.DriverSpy
      username: sa
      password:
```

### 연결 소스

```java
@Bean
@Primary
@ConfigurationProperties("spring.datasource.rdw")
public DataSource rdwDataSource() {
    return DataSourceBuilder.create()
            .type(HikariDataSource.class)
            .build();
}
```

설정값과 Hikari 속성 연결:

| YAML | HikariDataSource |
|---|---|
| `jdbc-url` | `jdbcUrl` |
| `driver-class-name` | `driverClassName` |
| `username` | `username` |
| `password` | `password` |

### 파생 Bean

```text
spring.datasource.rdw
→ rdwDataSource
→ rdwSqlSessionFactory
→ rdwSqlSessionTemplate
→ MyBatis DAO

rdwDataSource
→ rdwTransactionManager
→ Facade @Transactional
→ DefaultOnlineTimeoutExecutor TransactionTemplate
```

### Oracle 전환

```yaml
spring:
  datasource:
    rdw:
      jdbc-url: jdbc:log4jdbc:oracle:thin:@HOST:1521:SID
      driver-class-name: net.sf.log4jdbc.sql.jdbcapi.DriverSpy
      username: MFCR
      password: ${PDMG_RDW_PASSWORD:}
```

Oracle로 전환할 때 함께 변경할 항목:

- H2 Runtime 의존성 비활성화
- Oracle JDBC 의존성 활성화
- `spring.sql.init.mode=never`
- 운영 Password 환경변수 설정
- Mapper SQL의 Oracle 호환성 확인

### 현재 구조상 주의사항

기존 `nhnis.mg.config.RdwDataSourceConfig`와 신규 `nhnis.mg.co.a.config.RdwDataSourceConfig`가 동시에 스캔되면 같은 이름의 DataSource, SqlSession과 TransactionManager Bean이 중복된다.

## 8. `spring.sql.init`

### YAML

```yaml
spring:
  sql:
    init:
      mode: always
      encoding: UTF-8
      schema-locations: classpath:db/h2/schema.sql
      data-locations: classpath:db/h2/data.sql
```

### 연결 방식

이 설정은 별도 업무 Java 코드가 읽는 것이 아니라 Spring Boot의 SQL Initialization Auto Configuration이 처리한다.

```text
DataSource 생성
→ schema.sql 실행
→ data.sql 실행
→ 애플리케이션 준비 완료
```

### 값별 의미

| 키 | 의미 |
|---|---|
| `mode=always` | Embedded 여부와 관계없이 초기화 수행 |
| `encoding=UTF-8` | SQL 파일 문자 인코딩 |
| `schema-locations` | 테이블 생성 SQL |
| `data-locations` | 샘플 데이터 입력 SQL |

운영 Oracle에서 `always`를 유지하면 운영 Schema에 초기화 SQL을 실행할 위험이 있으므로 `never`로 변경한다.

## 9. `nhnis.fw.tcf.enabled`

### YAML

```yaml
nhnis:
  fw:
    tcf:
      enabled: true
```

### `true`일 때 활성화되는 소스

| 소스 | 역할 |
|---|---|
| `OnlineTransactionController` | 단일 HTTP 거래 진입점 |
| `TcfFacade` | Context 생성 후 TimeoutExecutor 호출 |
| `TransactionDispatcher` | `serviceId → Handler` 라우팅 |
| `GlobalExceptionHandler` | TCF 오류 응답 변환 |
| `mgcoa*Handler` | 업무 거래 등록과 Facade 분기 |

각 클래스는 다음 조건을 사용한다.

```java
@ConditionalOnProperty(
    name = "nhnis.fw.tcf.enabled",
    havingValue = "true"
)
```

### `false`일 때

거래별 Controller가 다음 조건으로 활성화된다.

```java
@ConditionalOnProperty(
    name = "nhnis.fw.tcf.enabled",
    havingValue = "false",
    matchIfMissing = true
)
```

### 변경 영향

```text
true
→ /{serviceId} → 공통 Controller → Handler → Facade

false
→ /mgcoa9000S0 → 거래별 Controller
```

TCF On/Off 경로가 동일한 Facade와 트랜잭션 정책을 사용하도록 유지해야 동작 차이가 생기지 않는다.

## 10. `nhnis.fw.timeout`

### YAML

```yaml
nhnis:
  fw:
    timeout:
      enabled: true
      milliseconds: 5000
      pool-size: 20
      queue-capacity: 100
```

### 1단계: Properties 바인딩

```java
@ConfigurationProperties(prefix = "nhnis.fw.timeout")
public class OnlineTimeoutProperties {
    private boolean enabled = false;
    private long milliseconds = 5000L;
    private int poolSize = 20;
    private int queueCapacity = 100;
}
```

`@ConfigurationPropertiesScan("nhnis")` 또는 `@EnableConfigurationProperties`로 Bean이 등록된다.

### 2단계: 설정 검증

```java
@PostConstruct
void validate() {
    // milliseconds >= 1
    // poolSize >= 1
    // queueCapacity >= 0
}
```

잘못된 값을 넣으면 애플리케이션 시작을 실패시킨다.

### 3단계: Bean 선택

```text
enabled=true
→ ThreadPoolTaskExecutor
→ DefaultOnlineTimeoutExecutor

enabled=false 또는 키 누락
→ SyncOnlineTimeoutExecutor
```

관련 소스는 `OnlineTimeoutConfiguration`이다.

### 4단계: Thread Pool 구성

```java
executor.setCorePoolSize(properties.getPoolSize());
executor.setMaxPoolSize(properties.getPoolSize());
executor.setQueueCapacity(properties.getQueueCapacity());
executor.setRejectedExecutionHandler(
    new ThreadPoolExecutor.AbortPolicy()
);
```

현재 값은 다음 의미다.

```text
동시 실행 Worker: 최대 20개
대기 요청: 최대 100개
그 이상: OnlineOverloadException → HTTP 503
```

### 5단계: TcfFacade 연결

```java
Object result = onlineTimeoutExecutor.execute(
    () -> dispatcher.dispatch(serviceId, dtoBody, context)
);
```

### 6단계: 제한시간과 트랜잭션

```text
요청 Thread
→ Future.get(5000ms)

Worker Thread
→ TransactionTemplate(rdwTransactionManager)
→ Dispatcher → Handler → Facade → Service → DAO
→ Deadline 검사
→ Commit 또는 Rollback
```

제한시간을 초과하면:

```java
future.cancel(true);
throw new OnlineTimeoutException(...);
```

Worker가 JDBC 호출을 마치고 늦게 반환하더라도 Deadline을 재검사하고 `rollbackOnly`로 처리한다.

### 변경 예시

```yaml
# 3초
milliseconds: 3000

# Worker 40개, 큐 200개
pool-size: 40
queue-capacity: 200
```

Pool을 늘릴 때는 Hikari Connection Pool과 DB 허용 Session 수를 함께 확인해야 한다. Worker만 늘리면 DB Connection 대기가 증가할 수 있다.

## 11. `nhnis.fw.commons.legacy-web.enabled`

### YAML

```yaml
nhnis:
  fw:
    commons:
      legacy-web:
        enabled: true
```

### 연결되는 소스

| 소스 | 역할 |
|---|---|
| `WebConfiguration` | Interceptor 등록 |
| `ClientHttpConnectorConfiguration` | 레거시 외부 호출 Connector |
| `ResponseBodyArgumentResolver` | 응답 전문 및 시스템 후처리 |
| `PdmgFwTxFlowAspect` | FW 흐름 로그 |
| `BizPrePostAspect` | 업무 선후처리 |
| `PdmgBizTxFlowAspect` | Handler/Facade/Service/DAO 흐름 로그 |

대표 조건:

```java
@ConditionalOnProperty(
    name = "nhnis.fw.commons.legacy-web.enabled",
    havingValue = "true",
    matchIfMissing = true
)
```

### 변경 영향

`false`로 변경하면 단순 로그뿐 아니라 시스템 선후처리와 응답 가공까지 빠질 수 있다. 이름이 `legacy-web`이어도 현재 실행 파이프라인의 일부이므로 개별 기능별 스위치로 분리하기 전에는 끄지 않는 것이 안전하다.

## 12. `nhnis.fw.commons.filter.enabled`

### YAML

```yaml
nhnis:
  fw:
    commons:
      filter:
        enabled: true
```

### 연결 소스

```java
@Component
@ConditionalOnProperty(
    name = "nhnis.fw.commons.filter.enabled",
    havingValue = "true"
)
public class DefaultFilter implements Filter { ... }
```

`FilterConfiguration`도 같은 설정으로 Filter 등록 Bean을 만든다.

### Filter가 만드는 실행 정보

```text
요청 Header와 Body
→ hdr_nhnis / sys_comm
→ ServiceContext
→ ServiceContextHolder(ThreadLocal)
→ MDC(guid, userId, serviceId, ip)
```

TimeoutExecutor는 `OnlineTimeoutWorkerContext`를 이용하여 위 Context를 Worker Thread로 전달한다.

### 변경 영향

`false`로 끄면 다음 기능이 함께 사라진다.

- Header 파싱과 Local Header 합성
- JWT 검증
- GUID 및 사용자 정보 설정
- ServiceContext 생성
- MDC 기반 거래 로그

현재 TCF 구조에서는 사실상 필수 설정이다.

## 13. `jwt` 프로파일 설정

### Local

```yaml
spring:
  config:
    activate:
      on-profile: local

jwt:
  enabled: false
  secret: "${PDMG_JWT_SECRET:pdmg-local-dev-secret-key-change-me-32b}"
  access-token-expiration: 180000
```

### Dev

```yaml
spring:
  config:
    activate:
      on-profile: dev

jwt:
  enabled: false
  secret: "${PDMG_JWT_SECRET:pdmg-local-dev-secret-key-change-me-32b}"
  access-token-expiration: 240000
```

### 소스 연결 상태

| YAML | 소스 | 현재 사용 여부 |
|---|---|---|
| `jwt.secret` | `JwtProvider.@Value` | 사용 |
| `jwt.enabled` | 직접 바인딩 소스 없음 | Filter 판단에는 미사용 |
| `jwt.access-token-expiration` | 현재 토큰 검증 경로 직접 소비 확인 안 됨 | 사실상 미사용 |

`JwtProvider`는 다음 값만 직접 주입받는다.

```java
@Value("${jwt.secret}")
private String secret;
```

### 중요한 불일치

현재 JWT 검증 여부는 `jwt.enabled`가 아니라 다음 코드로 결정된다.

```java
if (!"local".equalsIgnoreCase(active)) {
    // JWT 검증
}
```

따라서 `dev + jwt.enabled=false`여도 JWT가 필요하다. 설정 키를 신뢰할 수 있게 하려면 `DefaultFilter`가 `jwt.enabled`를 사용하도록 개선해야 한다.

### Secret 우선순위

```text
PDMG_JWT_SECRET 환경변수 존재
→ 환경변수 사용

환경변수 없음
→ local 개발 기본값 사용
```

운영에서는 기본값으로 실행되지 않도록 환경변수를 필수화해야 한다.

## 14. `application-fw-defaults.yml`

### 파일 내용

```yaml
jwt:
  secret: pdmg-fw-dev-secret-key-change-me-32bytes

storage:
  fos:
    connect-timeout: -1
    response-timeout: -1
```

### 현재 적용 여부

다음 이유로 자동 적용되지 않는다.

- Spring Boot 기본 파일명 `application.yml` 또는 `application-{profile}.yml`이 아님
- `spring.config.import`에 등록되지 않음
- `@PropertySource`로 읽는 코드가 없음

따라서 이 파일은 현재 **설정 예시 문서** 역할이다.

실제로 적용하려면 서비스 `application.yml`에 값을 직접 정의하거나 다음처럼 import해야 한다.

```yaml
spring:
  config:
    import:
      - classpath:application-fw-defaults.yml
      - classpath:exceptionCode.yml
```

단, FW 기본값과 서비스 최종값의 우선순위가 혼동될 수 있으므로 현재처럼 서비스 `application.yml`을 단일 진실 원천으로 사용하는 방식이 더 단순하다.

## 15. FOS와 APIGW 타임아웃

온라인 거래 공통 타임아웃과 외부 연동 타임아웃은 서로 다른 설정이다.

### FOS

```java
@Value("${storage.fos.connect-timeout:-1}")
private int connectTimeout;

@Value("${storage.fos.response-timeout:-1}")
private int responseTimeout;
```

연결 소스:

```text
ObjectStorageHandler
```

### APIGW

```java
@Value("${apigw.connect-timeout:30}")
private int connectTimeout;

@Value("${apigw.response-timeout:30}")
private int responseTimeout;
```

연결 소스:

```text
ApiGatewayHandler
```

### 차이

```text
nhnis.fw.timeout.milliseconds
→ PDMG 온라인 거래 전체 제한시간

storage.fos.* / apigw.*
→ 개별 외부 HTTP 연결과 응답 제한시간
```

외부 호출의 응답 제한이 온라인 공통 타임아웃보다 길면 사용자 요청은 먼저 504가 되고 외부 호출 Worker가 더 오래 남을 수 있다. 외부 응답 타임아웃을 공통 온라인 제한보다 짧게 설정하는 것이 일반적으로 안전하다.

---

## 16. Java 설정 클래스와 환경값 생성 순서

애플리케이션 시작 시 개념적인 순서는 다음과 같다.

```text
1. application.yml과 활성 Profile 읽기
2. exceptionCode.yml import
3. PdmgApplication Component Scan
4. @ConfigurationProperties 바인딩
5. RdwDataSourceConfig
   → DataSource / MyBatis / TransactionManager
6. OnlineTimeoutConfiguration
   → Sync 또는 Async Executor
7. TCF 조건부 Bean 생성
8. Filter / Interceptor / Advice 생성
9. Handler 목록으로 TransactionDispatcher 구성
10. HTTP 요청 수신 가능 상태
```

`timeout.enabled=true`인데 `rdwTransactionManager`가 없으면 `DefaultOnlineTimeoutExecutor`를 만들 수 없어 애플리케이션 시작이 실패한다. 이는 타임아웃과 트랜잭션을 분리하지 않기 위한 의도된 의존성이다.

## 17. 환경값 변경별 영향도

| 변경 | 영향 소스 | 재기동 | 주요 위험 |
|---|---|---:|---|
| Profile | `DefaultFilter` | 필요 | JWT 동작 변경 |
| 앱 이름 | `DefaultFilter`, Context | 필요 | 시스템 ID 계약 변경 |
| DB URL/계정 | `RdwDataSourceConfig` | 필요 | 접속 실패, 초기화 위험 |
| TCF On/Off | Controller, Handler, Dispatcher | 필요 | 호출 경로 변경 |
| Timeout 시간 | `DefaultOnlineTimeoutExecutor` | 필요 | 504/롤백 시점 변경 |
| Pool/Queue | `OnlineTimeoutConfiguration` | 필요 | 처리량과 DB 부하 변경 |
| Legacy Web | Interceptor/Advice/Aspect | 필요 | 선후처리 누락 |
| Filter | Filter/Context/JWT | 필요 | TCF Context 누락 |
| JWT Secret | `JwtProvider` | 필요 | 기존 Token 검증 실패 |

현재 구성은 동적 갱신 기능을 사용하지 않으므로 YAML을 수정하면 애플리케이션을 재기동해야 한다.

## 18. 권장 환경 파일 분리안

현재 하나의 `application.yml` 안에 Local과 Dev Profile 문서가 들어 있다. 운영 확장 시 다음처럼 분리하면 관리가 쉽다.

```text
application.yml
├─ 공통 Bean 활성 스위치
├─ 공통 타임아웃 기본값
└─ 공통 MVC 설정

application-local.yml
├─ H2 DataSource
├─ SQL init always
└─ JWT 개발 설정

application-dev.yml
├─ 개발 Oracle DataSource
├─ SQL init never
└─ 환경변수 Secret

application-prod.yml
├─ 운영 Oracle DataSource
├─ SQL init never
├─ 운영 Pool 크기
└─ Secret Store 또는 환경변수
```

공통 파일 예:

```yaml
spring:
  application:
    name: pdmg
  config:
    import: classpath:exceptionCode.yml

nhnis:
  fw:
    tcf:
      enabled: true
    timeout:
      enabled: true
      milliseconds: 5000
      pool-size: 20
      queue-capacity: 100
    commons:
      legacy-web:
        enabled: true
      filter:
        enabled: true
```

## 19. 현재 반드시 정리할 환경·소스 불일치

### 19.1 `jwt.enabled`

YAML에는 있지만 Filter가 사용하지 않는다.

```text
설정 표현: jwt.enabled=false
실제 동작: profile != local이면 JWT 검증
```

### 19.2 FW 기본 파일

`application-fw-defaults.yml`은 자동 적용되는 것처럼 보이지만 실제로는 import되지 않는다.

### 19.3 중복 DataSource 설정 클래스

```text
nhnis.mg.config.RdwDataSourceConfig
nhnis.mg.co.a.config.RdwDataSourceConfig
```

두 클래스가 같은 환경 키와 같은 Bean 이름을 사용한다.

### 19.4 중복 CORS와 Security 설정

기존·신규 패키지 양쪽의 `CorsProperties`, `WebMvcConfig`, `SecurityConfig`가 모두 스캔 대상이다.

### 19.5 Timeout Pool과 DB Pool

온라인 Worker는 20개지만 `spring.datasource.rdw.hikari.maximum-pool-size`가 명시되어 있지 않다. Hikari 기본 Connection Pool과 Worker 수가 다르면 일부 Worker가 Connection을 기다리게 된다.

명시 예:

```yaml
spring:
  datasource:
    rdw:
      maximum-pool-size: 20
      minimum-idle: 5
      connection-timeout: 3000
```

실제 운영값은 DB Session 용량과 인스턴스 수를 기준으로 결정해야 한다.

## 20. 운영 적용 체크리스트

- [ ] `spring.profiles.active`를 실행 환경에서 지정하는가?
- [ ] 운영 DB에서 `spring.sql.init.mode=never`인가?
- [ ] `PDMG_RDW_PASSWORD`가 주입되는가?
- [ ] `PDMG_JWT_SECRET`이 개발 기본값을 대체하는가?
- [ ] `jwt.enabled`와 실제 Filter 정책이 일치하는가?
- [ ] `nhnis.fw.timeout.milliseconds`가 업무 SLA와 맞는가?
- [ ] Timeout Worker 수와 Hikari Pool, DB Session 수가 맞는가?
- [ ] 큐 포화 시 503 모니터링이 가능한가?
- [ ] URL `serviceId`와 Header `rms_svc_c`가 일치하는가?
- [ ] 기존·신규 패키지 중복 Bean이 제거됐는가?
- [ ] 운영 CORS가 허용된 UI Origin으로 제한됐는가?
- [ ] 로그에 Secret, Token, 개인정보가 기록되지 않는가?

## 21. 핵심 요약

```text
pdmg-service/application.yml이 최종 환경 설정의 중심이다.

spring.datasource.rdw
→ DataSource → MyBatis → rdwTransactionManager

nhnis.fw.tcf.enabled
→ 공통 Controller → Dispatcher → Handler

nhnis.fw.timeout
→ Worker Pool → TransactionTemplate → Timeout/Rollback

commons.filter.enabled
→ Header/JWT/ServiceContext/MDC

legacy-web.enabled
→ 시스템 및 업무 선후처리
```

환경 파일을 변경할 때는 YAML 값만 보는 것이 아니라 그 값을 소비하는 `@ConfigurationProperties`, `@Value`, `@ConditionalOnProperty`, `@Bean` 소스를 함께 확인해야 한다.
