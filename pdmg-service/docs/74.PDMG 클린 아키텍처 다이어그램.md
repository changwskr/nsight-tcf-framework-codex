# PDMG 클린 아키텍처 텍스트 다이어그램

현재 PDMG는 완전한 정통 Clean Architecture라기보다는 `TCF + Layered Architecture + Clean Architecture 원칙`을 결합한 구조입니다.

## 1. 전체 구조

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ Frameworks & Drivers · 외부 실행 환경                                       │
│                                                                              │
│  pdmg-ui       pdmg-fw        Spring Boot        MyBatis       업무 DB       │
│  Web Browser   TCF/Filter     Spring MVC         JDBC          외부 시스템   │
└───────────┬───────────┬───────────────┬──────────────┬───────────────────────┘
            │           │               │              │
            ▼           ▼               ▼              ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ Interface Adapters · 인터페이스 어댑터                                      │
│                                                                              │
│  Controller              TransactionHandler             DAO / Mapper         │
│                                                                              │
│  · HTTP 요청 변환        · Service ID 라우팅           · DB 요청 변환       │
│  · DTO 입력              · Facade 호출                 · SQL 실행            │
│  · DTO 응답              · TCF 업무 연결               · 결과 매핑           │

                                       │

┌──────────────────────────────────────────────────────────────────────────────┐
│ Application Business Rules · 애플리케이션 유스케이스                        │
│                                                                              │
│  Business Facade                        Business Service                     │
│                                                                              │
│  · 유스케이스 진입점                    · 업무 처리 순서                    │

│  · 여러 Service 조정                    · Port 호출                         │

└──────────────────────────────────────┬───────────────────────────────────────┘
```

```text

          │
          ▼
Application Use Case
          │
          ▼
Domain Rule
```

## 4. Inbound Adapter 구조

```text
외부 요청
   │
   ├───────────────────────────────┐
   │                               │
   ▼                               ▼
TCF ON                          TCF OFF
   │                               │
   ▼                               ▼
OnlineTransactionController     업무 Controller
   │                               │
   ▼                               │
TransactionDispatcher              │
   │                               │
   ▼                               │
TransactionHandler                 │
   │                               │
   └───────────────┬───────────────┘
                   ▼
             Business Facade
```

클린 아키텍처 관점:

```text
OnlineTransactionController
TransactionHandler
업무 Controller
       │
       └─ 외부 요청을 내부 Use Case 호출로 변환하는
          Inbound Adapter
```

이 계층은 업무 규칙을 직접 구현하지 않습니다.

## 5. 유스케이스 계층

```text
Business Facade
      │
      ├─ 입력 DTO 변환
      ├─ 유스케이스 시작
      ├─ 트랜잭션 경계
      ├─ 여러 Service 조정
      └─ 출력 반환
      │
      ▼
Business Service
      │
      ├─ 업무 처리 순서
      ├─ Domain Rule 실행
      ├─ Output Port 호출
      └─ 결과 조립
```

```text
Facade
└─ 한 건의 유스케이스 경계

Service
└─ 유스케이스의 실제 처리 절차
```

예:

```text
마케팅 희망 고객 조회
        │
        ▼
mgcoa5530Facade.mgcoa5530S0()
        │
        ├─ TX BEGIN
        ▼
mgcoa5530Service.mgcoa5530S0()
        │
        ├─ 조회 조건 검증
        ├─ 고객 목록 조회
        ├─ 전체 건수 조회
        └─ 결과 DTO 조립
```

## 6. 도메인 계층

현재 PDMG에서는 `application.rule`이 도메인 규칙 역할을 담당합니다.

```text
Business Service
      │
      ▼
Business Rule
      │
      ├─ 입력 유효성 판단
      ├─ 상태 변경 가능 여부
      ├─ 권한·한도 정책
      ├─ 업무 계산
      └─ 도메인 예외
```

클린 아키텍처를 강화하면 다음처럼 분리할 수 있습니다.

```text
nhnis.mg.co.a
│
├─ domain
│  ├─ model
│  ├─ rule
│  ├─ policy
│  └─ exception
│
├─ application
│  ├─ port
│  │  ├─ in
│  │  └─ out
│  └─ service
│
└─ adapter
   ├─ in
   │  ├─ web
   │  └─ tcf
   └─ out
      ├─ persistence
      └─ client
```

도메인 계층에는 다음 기술 의존성을 두지 않는 것이 좋습니다.

```text
X Spring MVC
X HttpServletRequest
X MyBatis
X JDBC
X Mapper XML
X JSON
X JWT
X TCF
```

## 8. 현재 구조와 엄격한 구조 비교

```text
현재 PDMG

Service
  → DAO(MyBatis Interface)
    → Mapper XML
      → DB
```

```text
엄격한 Clean Architecture

Application Service
  → Repository Port
    ← Persistence Adapter
       → MyBatis DAO
         → Mapper XML
           → DB
```

현재 구조에서는 Service가 MyBatis DAO에 직접 의존합니다. 따라서 DB 기술이 애플리케이션 계층에 노출됩니다.

개선 구조에서는 Service가 업무 관점의 Port만 참조합니다.

```java
public interface ImageLogQueryPort {
    List<ImageLog> find(ImageLogCondition condition);
    long count(ImageLogCondition condition);
}
```

```text
Service
   │
   └─ ImageLogQueryPort
             ▲
             │ implements
MyBatisImageLogAdapter
   │
   └─ mgcoa8888DAO
       └─ Mapper XML
```

## 9. 의존성 역전

잘못된 방향:

```text
Application Service
       │
       ▼
MyBatis 구현체
       │
       ▼
DB
```

권장 방향:

```text
Application Service
       │
       ▼
Repository Port
       ▲
       │ 구현
Persistence Adapter
       │
       ▼
MyBatis / DB
```

컴파일 의존 방향:

```text
adapter.in ───────▶ application
adapter.out ──────▶ application
application ──────▶ domain
framework ────────▶ adapter

domain
└─ 다른 외부 계층을 참조하지 않음
```

## 11. 트랜잭션 경계

```text
Inbound Adapter
Controller / Handler
      │
      │ TX 밖
      ▼
Business Facade
      │
      ├══════════ Use Case Transaction ══════════╗
      ║                                         ║
      ║ Business Service                        ║
      ║    │                                    ║
      ║    ├─ Domain Rule                       ║
      ║    ├─ Repository Port                   ║
      ║    └─ External Port                     ║
      ║                                         ║
      ║ 정상: COMMIT                            ║
      ║ 예외: ROLLBACK                          ║
      ╚═════════════════════════════════════════╝
```

트랜잭션은 개별 DAO가 아니라 하나의 유스케이스 단위로 관리합니다.

## 12. TCF와 클린 아키텍처

```text
pdmg-fw TCF
│
├─ DefaultFilter
├─ ServicePreventionInterceptor
├─ OnlineTransactionController
├─ STF
├─ TransactionDispatcher
└─ ETF
       │
       │ Inbound Framework
       ▼
pdmg-service
│
├─ TransactionHandler
│   └─ Inbound Adapter
│
├─ Business Facade
│   └─ Use Case Boundary
│
├─ Business Service
│   └─ Use Case
│
├─ Business Rule
│   └─ Domain
│
└─ DAO / Client
    └─ Outbound Adapter
```

TCF는 업무 도메인의 내부 구성요소가 아니라 업무 유스케이스를 호출하는 외부 프레임워크입니다.

따라서 다음 방향을 지켜야 합니다.

```text
TCF → 업무 Handler → Use Case
```

피해야 하는 방향:

```text
Domain Rule → TCF
Service → OnlineTransactionController
DAO → ServiceContext
```

## 17. 최종 의존 방향

```text
┌────────────────────────────────────────────────────────┐
│ Framework / Driver                                     │
│ pdmg-ui · pdmg-fw · Spring · MyBatis · DB · pdmg-jwt   │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│ Adapter                                                │
│ Controller · Handler · DAO Adapter · Client Adapter    │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│ Application                                            │
│ Facade · Service · Input/Output Port · Use Case        │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│ Domain                                                 │
│ Model · Rule · Policy · Domain Exception               │
└────────────────────────────────────────────────────────┘
```

핵심 원칙은 다음과 같습니다.

```text
Domain
└─ Spring·HTTP·MyBatis·TCF를 모른다.

Application
└─ 업무 유스케이스와 Port만 안다.

Adapter
└─ HTTP·TCF·DB·외부 시스템을 Application에 연결한다.

Framework
└─ 실행환경과 공통 기술을 제공한다.
```

현재 PDMG 구조를 한 줄로 표현하면 다음과 같습니다.

```text
pdmg-ui
 → pdmg-fw
 → Controller/Handler
 → Facade
 → Service
 → Rule
 → DAO/Mapper
 → DB
```

클린 아키텍처 관점의 목표 구조는 다음과 같습니다.

```text
외부 요청
 → Inbound Adapter
 → Use Case
 → Domain
 → Output Port
 ← Outbound Adapter
 → DB/외부 시스템
```
