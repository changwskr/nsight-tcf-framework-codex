## 1. 역할

Service가 넘긴 `Map` 파라미터로 **SQL을 실행하는 MyBatis Mapper 인터페이스**다.  
구현 클래스는 없고, XML statement와 1:1로 바인딩된다.

```text
Service (업무 절차)
  → *DAO.mgcoaXXXXYn_Yn(Map)     ★
       → MyBatis → rdw.mg.co.a/*-ORA.xml
  → List<Map> / int 반환
```

| 한다 | 하지 않는다 |
|------|-------------|
| SQL 진입점 (메서드 = statement id) | 업무 검증·페이징 totalPages 계산 |
| RDW DS / Facade TX에 참여 | `@Transactional` 선언 |
| count / select / CUD 시그니처 정의 | DTO ↔ row 조립 (Service) |
| `@RDWMapper`로 Mapper 표기 | Handler·Facade에서 직호출 (금지) |

한 줄: **SQL 문만. 일은 Service, TX는 Facade.**

## 2. 위치 · 등록

| 항목 | 규칙 |
|------|------|
| 패키지 | `nhnis.mg.co.a.persistence.dao` |
| 클래스 | `{프로그램접두}DAO` — `mgcoa8888DAO` (구분자 `S0` 없음) |
| 애노테이션 | `@RDWMapper` (`@Mapper` 포함) |
| 스캔 | `RdwDataSourceConfig` `@MapperScan(…persistence.dao, sqlSessionTemplateRef = "rdwSqlSessionTemplate")` |
| XML | `classpath*:rdw.*/*.xml` → 실무 `resources/rdw.mg.co.a/{접두}-ORA.xml` |
| namespace | DAO FQCN과 **완전 일치** |

```java
@RDWMapper
public interface mgcoa8888DAO {
    List<Map<String, Object>> mgcoa8888S0_S0(Map<String, Object> input) throws Exception;
    int mgcoa8888S0_S0_count(Map<String, Object> input) throws Exception;
    int mgcoa8888D0_D0(Map<String, Object> input) throws Exception;
}
```

## 3. 메서드명 = SQL ID

형식: **`{서비스ID}_{DML구분자}{순번}`** (+ 필요 시 `_count` / `_exists`)

| DAO 메서드 | 용도 |
|------------|------|
| `mgcoa8888S0_S0` | 목록 조회 |
| `mgcoa8888S0_S0_count` | 동일 조건 건수 |
| `mgcoa8888D0_D0` | 삭제 |
| `mgcoa9000C0_C0` / `U0_U0` / `D0_D0` | 등록·수정·삭제 |
| `mgcoa9000S0_S0_exists` | 존재 여부 |

XML:

```xml
<mapper namespace="nhnis.mg.co.a.persistence.dao.mgcoa8888DAO">
  <select id="mgcoa8888S0_S0" …>
  <select id="mgcoa8888S0_S0_count" …>
  <delete id="mgcoa8888D0_D0" …>
</mapper>
```

**DAO 메서드명 = XML `id` = (관례상) SQL 주석 `/* id */`.**  
불일치 시 MyBatis 바인딩 실패.

상세 XML·ROWNUM 페이징: [24.DAO-Mapper.md](./24.DAO-Mapper.md).

## 4. 파라미터 · 반환 타입

| 관례 | 타입 |
|------|------|
| 입력 | `Map<String, Object>` (Service가 조립) |
| 목록 | `List<Map<String, Object>>` |
| 건수·CUD·exists | `int` |

- Map 키는 XML `#{…}` / `<if test="…">`와 **동일** (`guid`, `offset`, `pageSize`, `guidList` …).
- 컬럼 별칭은 대문자(`GUID`) 등으로 두고, Service가 upper/camel 모두 읽는다.
- DTO를 DAO 인자로 직접 넘기지 않는 것이 현재 샘플 표준이다.

---

## 5. 트랜잭션 참여

DAO에 `@Transactional`을 두지 않는다.

```text
Facade @Transactional(rdwTransactionManager) BEGIN
  → Service
       → DAO 메서드들   ← 같은 rdwDataSource 커넥션에 참여
→ COMMIT / ROLLBACK
```

- SqlSessionTemplate은 `rdwSqlSessionFactory`(동일 DS).
- Facade 밖에서 DAO만 호출하면 자동커밋·TX 부재 위험 → **Service ← Facade** 경로만.

---

## 6. Service와의 계약

| From → To | 내용 |
|-----------|------|
| Service → DAO | 완성된 `Map` (페이징 offset 포함) |
| DAO → Service | raw `List<Map>` / `int` |
| Service | Sub DTO·out·totalPages·RSLT_* 조립 |

한 프로그램 = DAO 인터페이스 **1개**.  
거래 추가 시 메서드·XML statement만 추가 ([06](./06.네이밍%20형식.md)).

---

## 7. 신규 SQL 체크리스트

1. DAO에 메서드 추가 (`서비스ID_DML순번`)  
2. 같은 파일의 `*-ORA.xml`에 동일 `id` statement  
3. `namespace` = DAO FQCN 유지  
4. Service에서 해당 메서드 호출·param 키 맞춤  
5. 기동 후 Mapper 로드·SQL 로그(`MybatisLogInterceptor`) 확인  

---

## 8. 하지 말 것

1. Handler / Facade / Controller에서 DAO 직호출  
2. DAO에 업무 if·DTO 조립·`@Transactional`  
3. 메서드명을 `selectList`만 쓰고 서비스 ID 생략  
4. Java 패키지 `co.a`와 Mapper 폴더 `rdw.mg.*` 축 불일치  
5. namespace ≠ DAO FQCN, 메서드명 ≠ XML id  
6. `mgcoa8888S0DAO`처럼 클래스명에 구분자 포함
