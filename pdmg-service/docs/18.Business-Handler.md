# 18. Business Handler (PDMG)

기준일: 2026-08-09  
대상: `nhnis.mg.co.a.entry.handler.*` (`TransactionHandler` 구현)  
관련: [17.TCF-TcfFace-Dispatcher.md](./17.TCF-TcfFace-Dispatcher.md) · [19.Business-Facade.md](./19.Business-Facade.md) · [09.서비스ID.md](./09.서비스ID.md) · [02.어플리케이션 컴포넌트 구조.md](./02.어플리케이션%20컴포넌트%20구조.md)

---

## 1. 역할

Dispatcher가 고른 뒤, **프로그램(식별번호) 단위로 serviceId를 업무 Facade 메서드에 연결**하는 Entry 컴포넌트다.

```text
TransactionDispatcher
  → *Handler.handle(dtoBody, context)     ★
       switch context.getServiceId()
         → *Facade.mgcoaXXXXYn(dtoBody)   ★ @Transactional (Facade)
```

| 한다 | 하지 않는다 |
|------|-------------|
| `serviceIds()`로 TCF 등록 | SQL / MyBatis |
| `context.getServiceId()`로 거래 분기 | `@Transactional` |
| 해당 `*Facade` 메서드 1회 호출 | DTO 필드 검증·비즈니스 규칙 |
| 미지원 ID → `ServiceHandlerNotFound` | 응답 `{ hdr_nhnis, dto }` 조립 |

한 줄: **라우팅만. 일은 Facade 이하.**

---

## 2. 위치 · 네이밍

| 항목 | 규칙 |
|------|------|
| 패키지 | `nhnis.mg.co.a.entry.handler` |
| 클래스 | `{프로그램접두}Handler` — 예: `mgcoa8888Handler` |
| 구분자 | 파일명에 `S0`/`D0` **넣지 않음** (한 프로그램 = 한 Handler) |
| 빈 | `@Component` + `@ConditionalOnProperty(nhnis.fw.tcf.enabled=true)` |
| 계약 | `nhnis.fw.tcf.core.handler.TransactionHandler` |

현재 샘플:

| Handler | serviceIds |
|---------|------------|
| `mgcoa5530Handler` | `mgcoa5530S0` |
| `mgcoa8888Handler` | `mgcoa8888S0`, `mgcoa8888D0` |
| `mgcoa9000Handler` | `S0`, `C0`, `U0`, `D0` |
| `mgcoa9999Handler` | `mgcoa9999S0` |

---

## 3. 인터페이스 계약

```java
Collection<String> serviceIds();   // Dispatcher 등록 키
Object handle(Object dtoBody, TransactionContext context) throws Exception;
```

| 인자 | 내용 |
|------|------|
| `dtoBody` | 전문의 `dto` 노드 (보통 `Map`) — 헤더 없음 |
| `context` | `getServiceId()`로 분기. 필요 시 header/guid |

반환값은 Facade의 `*DTOout` (또는 동일 의미 Object).  
시스템 응답 봉투는 이후 `ResponseBodyAdvice`가 감싼다.

---

## 4. 표준 패턴 (도메인 묶음)

같은 프로그램에 거래가 여러 개면 **상수 + `serviceIds()` + `switch`**.

```java
@Component
@ConditionalOnProperty(name = "nhnis.fw.tcf.enabled", havingValue = "true")
public class mgcoa8888Handler implements TransactionHandler {

    private static final String S0 = "mgcoa8888S0";
    private static final String D0 = "mgcoa8888D0";

    private final mgcoa8888Facade facade;

    public mgcoa8888Handler(mgcoa8888Facade facade) {
        this.facade = facade;
    }

    @Override
    public Collection<String> serviceIds() {
        return List.of(S0, D0);
    }

    @Override
    public Object handle(Object dtoBody, TransactionContext context) throws Exception {
        return switch (context.getServiceId()) {
            case S0 -> facade.mgcoa8888S0(dtoBody);
            case D0 -> facade.mgcoa8888D0(dtoBody);
            default -> throw new ServiceHandlerNotFound(
                    "mgcoa8888Handler 미지원 serviceId: " + context.getServiceId());
        };
    }
}
```

거래 1개만 있어도 `serviceIds()` + equals/`switch`로 동일하게 둔다 (`mgcoa5530`, `mgcoa9999`).

## 5. 호출 직전·직후 경계

```text
[이전] Dispatcher: handlerMap.get(serviceId) → handle(…)
[여기] Handler: serviceId → Facade 메서드
[다음] Facade: @Transactional · Object→DTO · Service 호출
```

| 경계 | 주의 |
|------|------|
| Handler → Facade | `dtoBody`를 **그대로** 넘김 (변환은 Facade) |
| Handler ↔ Service | **직접 호출 금지** |
| Handler ↔ DAO | **금지** |
| TX | Facade에만. Handler에 `@Transactional` 금지 |

업무 선·후처리 Aspect는 **Service** 메서드에 걸린다. Handler는 그 바깥(Facade 안쪽 Service 호출 시 적용).

---

## 6. 등록 · 실패 모드

기동 시 Dispatcher가 모든 Handler 빈의 `serviceIds()`를 맵에 넣는다 ([17](./17.TCF-TcfFace-Dispatcher.md)).

| 상황 | 결과 |
|------|------|
| `serviceIds`에 없는 URL/헤더 ID | Dispatcher `ServiceHandlerNotFound` |
| 맵에는 있으나 `switch` default | Handler `ServiceHandlerNotFound` (등록·분기 불일치) |
| 동일 ID를 두 Handler가 선언 | **기동 실패** `IllegalStateException` |
| `tcf.enabled≠true` | Handler 빈 미생성 → 전체 TCF 경로 불가 |

등록 문자열과 Facade 메서드명·URL·UI id는 **완전 동일** ([09](./09.서비스ID.md)).

---

## 7. 신규 거래 체크리스트

식별번호가 같은 프로그램에 거래만 추가할 때:

1. 상수 + `serviceIds()`에 ID 추가  
2. `switch`에 `facade.mgcoaXXXXYn(dtoBody)` 분기 추가  
3. Facade/Service/DTO/SQL/UI는 각 문서 절차  
4. **새 Handler 클래스 만들지 않음** (같은 접두면 기존 파일 확장)

새 프로그램(식별번호)이면:

1. `mgcoaNNNNHandler` + 대응 Facade 신규  
2. 기동 로그 `Registered TCF handler. serviceId=…` 확인  

---

## 8. 하지 말 것

1. Handler에서 SQL·Mapper·DAO 호출  
2. Handler에 `@Transactional`  
3. `Object`→DTO 변환·페이징·업무 검증을 Handler에 넣기  
4. `mgcoa8888S0Handler`처럼 거래마다 클래스 분리  
5. `serviceIds()`와 `switch` case 문자열 불일치  
6. old 패키지 `nhnis.mg.entry.handler`에 신규 작성 (현행은 `nhnis.mg.co.a.entry.handler`)
