## 2. 프로파일

기본 프로파일은 `local`입니다.

```yaml
spring:
  profiles:
    active: local
```

명령행으로 변경할 수 있습니다.

```powershell
.\gradlew.bat bootRun `
  --args="--spring.profiles.active=dev"
```

또는 환경변수:

```powershell
$env:SPRING_PROFILES_ACTIVE = "dev"
```

Spring 설정 우선순위상 명령행이나 환경변수가 `application.yml` 값보다 우선합니다.

### 프로파일별 설정

| 항목            |                local |           dev |
| --------------- | -------------------: | ------------: |
| `jwt.enabled`   |              `false` |       `false` |
| JWT 만료 설정   |                180초 |         240초 |
| Filter JWT 검증 |                 생략 |          실행 |
| 헤더 생략 허용  | 허용, 합성 헤더 생성 | 허용하지 않음 |

여기에는 중요한 불일치가 있습니다.

`DefaultFilter`는 `jwt.enabled` 값을 사용하지 않고 다음 조건만 검사합니다.

```java
if (!"local".equalsIgnoreCase(active)) {
    // JWT 검증
}
```

따라서:

```text
dev + jwt.enabled=false
→ JWT 검증 생략 아님
→ Authorization: Bearer 토큰 필요
```

`jwt.enabled=false`는 현재 JWT 검증 여부를 제어하지 못하는 사실상 미사용 설정입니다.


Facade의 `@Transactional`은 그대로 적용됩니다.

## 5. 타임아웃 설정

```yaml
nhnis:
  fw:
    timeout:
      enabled: true
      milliseconds: 5000
      pool-size: 20
      queue-capacity: 100
```

바인딩 클래스:

[OnlineTimeoutProperties.java](<C:/Programming(23-08-15)/nsight-tcf-framework-codex/pdmg-fw/src/main/java/nhnis/fw/tcf/timeout/OnlineTimeoutProperties.java:17>)

```java
@ConfigurationProperties(
    prefix = "nhnis.fw.timeout"
)
public class OnlineTimeoutProperties {
    private boolean enabled = false;
    private long milliseconds = 5000L;
    private int poolSize = 20;
    private int queueCapacity = 100;
}
```

### 설정별 역할

| 키               | 역할                             |
| ---------------- | -------------------------------- |
| `enabled`        | 비동기 Worker 타임아웃 사용 여부 |
| `milliseconds`   | 온라인 업무 처리 제한시간        |
| `pool-size`      | 동시 Worker 수                   |
| `queue-capacity` | 대기 가능한 요청 수              |

현재 최대 구조:

```text
실행 중 최대 20건
+
대기 최대 100건
```

실행과 큐가 모두 차면 `FW_OVERLOADED`, HTTP 503으로 처리됩니다.

### 값 검증

애플리케이션 시작 시 다음을 검사합니다.

```text
milliseconds >= 1
pool-size >= 1
queue-capacity >= 0
```

잘못된 값이면 애플리케이션 기동이 실패합니다.

### `timeout.enabled=false`

```text
Worker Pool 사용 안 함
Future timeout 사용 안 함
외곽 TransactionTemplate 사용 안 함
현재 HTTP 스레드에서 동기 실행
Facade @Transactional이 업무 TX 시작
```

문서의 “제한 없음”은 엄밀히 다음 의미입니다.

```text
공통 OnlineTimeoutExecutor Deadline이 없음
```

DB Query Timeout, HTTP 컨테이너 Timeout 등 다른 제한까지 모두 없다는 뜻은 아닙니다.

## 7. 로컬 H2 초기화

```yaml
spring:
  sql:
    init:
      mode: always
      encoding: UTF-8
      schema-locations: classpath:db/h2/schema.sql
      data-locations: classpath:db/h2/data.sql
```

기동 순서:

```text
H2 DataSource 생성
→ schema.sql 실행
→ data.sql 실행
→ MyBatis DAO 사용 가능
```

현재 H2는 메모리 DB입니다.

```text
애플리케이션 시작 → DB 생성 및 샘플 데이터 입력
애플리케이션 종료 → DB 데이터 소멸
```

`DB_CLOSE_DELAY=-1`은 JVM이 살아 있는 동안 연결이 모두 닫혀도 DB를 유지한다는 의미입니다.

## 8. Oracle 전환

현재 Oracle 설정은 주석으로 남아 있습니다.

```yaml
spring:
  datasource:
    rdw:
      jdbc-url: jdbc:log4jdbc:oracle:thin:@서버:1521:SID
      driver-class-name: net.sf.log4jdbc.sql.jdbcapi.DriverSpy
      username: MFCR
      password: ${PDMG_RDW_PASSWORD:}
```

전환할 때 함께 처리해야 하는 항목:

1. H2 DataSource 블록 비활성화
2. Oracle 블록 활성화
3. `PDMG_RDW_PASSWORD` 환경변수 설정
4. H2 `spring.sql.init.mode=always` 비활성화
5. Oracle JDBC Driver 의존성 활성화
6. H2 Runtime 의존성 비활성화
7. Mapper SQL의 Oracle 호환성 확인
8. ImageLog 테이블과 컬럼 존재 확인

운영에서는 다음 설정이 안전합니다.

```yaml
spring:
  sql:
    init:
      mode: never
```

운영 DB에 H2용 `schema.sql`이 실행되지 않도록 해야 합니다.

## 12. Spring Security

현재 애플리케이션 보안 설정은 모든 요청을 허용합니다.

```java
.authorizeHttpRequests(
    auth -> auth.anyRequest().permitAll()
);
```

Security의 역할:

```text
CSRF 비활성
CORS 연결
Session STATELESS
HTTP Basic/Form Login 비활성
모든 요청 permitAll
```

따라서 인증 강제점은 Spring Security가 아니라 `DefaultFilter`입니다.

```text
Spring Security permitAll
→ DefaultFilter
→ 비-local이면 JWT 검증
```

`filter.enabled=false`로 설정하면 Spring Security가 `permitAll`이므로 인증 없이 모든 API가 노출됩니다. 비-local 환경에서 매우 위험한 조합입니다.

## 13. `legacy-web.enabled`

```yaml
nhnis:
  fw:
    commons:
      legacy-web:
        enabled: true
```

이 값을 `false`로 바꾸면 단순히 레거시 Controller만 사라지는 것이 아닙니다.

```yaml
nhnis:
  exception:
    FW0001: "{0} 오류가 발생하였습니다."
    MP0404: "요청한 영업팁 실적을 찾을 수 없습니다."

```

`pdmg-fw`에도 같은 이름의 `exceptionCode.yml`이 있습니다. 그러나 import는 다음과 같습니다.

```text
classpath:exceptionCode.yml
```

이는 `classpath*:` 병합 검색이 아닙니다. 동일 경로의 두 파일이 자동으로 안전하게 병합된다고 보장할 수 없습니다.

따라서 “FW 파일과 서비스 파일을 병합하고 서비스가 덮어쓴다”는 문서 설명은 부정확합니다.

현재는 서비스 `exceptionCode.yml`에 FW 공통 코드까지 모두 포함시키는 방식으로 보는 것이 안전합니다.

권장 구조는 파일명을 분리하는 것입니다.

```yaml
spring:
  config:
    import:
      - classpath:pdmg-fw-exception-code.yml
      - classpath:pdmg-service-exception-code.yml
```

## 16. 로그 설정

[log4j2.xml](<C:/Programming(23-08-15)/nsight-tcf-framework-codex/pdmg-service/src/main/resources/log4j2.xml>)의 로컬 경로:

```text

logs/service
```

상대 경로이므로 실제 위치는 현재 실행 디렉터리에 따라 달라집니다.

```text
pdmg-service에서 bootRun
→ pdmg-service/logs/...

저장소 루트에서 다른 방식으로 실행
→ 저장소 루트/logs/...
```

운영 WAS에서는 절대 경로를 외부 설정으로 주입하는 편이 안전합니다.

현재 주요 로그 레벨:

| Logger                | 레벨  |
| --------------------- | ----- |
| Root                  | INFO  |
| `org.springframework` | INFO  |
| `nhnis.fw`            | INFO  |
| `nhnis.mg`            | INFO  |
| MyBatis Interceptor   | DEBUG |
| `jdbc.sqltiming`      | DEBUG |
| `jdbc.sqlonly`        | OFF   |

SQL Timing이 DEBUG로 활성화되어 있어 운영에서는 SQL 파라미터나 개인정보 노출 여부를 확인해야 합니다.

## 17. 설정 우선순위

실제 설정값은 대략 다음 순서로 덮어써집니다.

```text
낮은 우선순위
application.yml 공통
→ application.yml 프로필 문서
→ 외부 application.yml
→ 환경변수
→ JVM -D 옵션
→ 명령행 --key=value
높은 우선순위
```

예:

```powershell
java -jar pdmg-service.war `
  --spring.profiles.active=dev `
  --nhnis.fw.timeout.milliseconds=10000
```

환경변수 예:

```powershell
$env:SPRING_PROFILES_ACTIVE = "dev"
$env:NHNIS_FW_TIMEOUT_MILLISECONDS = "10000"
$env:PDMG_JWT_SECRET = "운영-Secret"
$env:PDMG_RDW_PASSWORD = "운영-DB-비밀번호"
```

## 18. 문서 현행화가 필요한 부분

| 문서 설명                        | 현행 분석                                  |
| -------------------------------- | ------------------------------------------ |
| `jwt.enabled=false`              | Filter에서 사용하지 않음                   |
| dev JWT 비활성                   | 실제로 dev는 JWT를 요구                    |
| `access-token-expiration`        | 현재 검증 코드에서 직접 미사용             |
| FW 기본 설정을 앱이 덮어씀       | FW defaults 파일 자체가 자동 로딩되지 않음 |
| 두 exceptionCode 파일 병합       | 자동 병합 보장 없음                        |
| Timeout OFF는 제한 없음          | 공통 Online Deadline만 없어짐              |
| ImageLog 별도 DS                 | Primary RDW DataSource 사용                |
| `legacy-web`는 보조 로그 설정    | 응답 봉투와 Interceptor까지 제어           |
| `application.yml` 단일 진실 원천 | 기본 파일이지만 외부 설정이 우선 가능      |

## 최종 평가

| 영역                  | 상태                |
| --------------------- | ------------------- |
| 프로파일 분리         | local/dev만 존재    |
| H2 로컬 구성          | 정상                |
| Oracle 전환           | 수동 주석 전환 필요 |
| TCF ON/OFF 전환       | 구현됨              |
| Timeout ON/OFF 전환   | 구현됨              |
| Timeout 값 검증       | 구현됨              |
| CORS 바인딩           | 정상                |
| JWT Secret 환경변수   | 지원                |
| `jwt.enabled` 연동    | 불일치              |
| FW defaults 자동 로딩 | 안 됨               |
| 오류 코드 리소스 병합 | 불명확              |
| 운영 Secret 누락 방지 | 부족                |
| 설정 전용 자동 테스트 | 제한적              |

가장 우선해서 정리할 설정은 다음 세 가지입니다.

1. `DefaultFilter`가 `jwt.enabled`를 실제로 사용하도록 통일
2. 운영 프로필에서 JWT 기본 Secret을 제거하고 미설정 시 기동 실패
3. FW와 서비스의 `exceptionCode.yml` 파일명을 분리해 명시적으로 import

이번 분석은 정적 점검이며 파일 수정과 애플리케이션 기동 테스트는 수행하지 않았습니다.
