`exceptionCode.yml`은 **오류 코드와 사용자 표시 메시지를 분리해서 관리하는 메시지 사전**입니다.

다만 현재 구현에서는 YAML이 정상적으로 로딩되지만, 실제 `GlobalExceptionHandler`가 메시지 조회에 사용하지 않아 절반만 연결된 상태입니다.

## 1. 파일의 용도

파일: [exceptionCode.yml](../src/main/resources/exceptionCode.yml)

```yaml
nhnis:
  exception:
    FW0001: "{0} 오류가 발생하였습니다."
    FW0002: "TEST Exception"
    FW0003: "{0} Exception 은 {1}로 문의해주세요"
    FW0401: "인증에 실패하였습니다. 다시 로그인해주세요."
    FW0403: "요청한 거래에 대한 권한이 없습니다."
    MP0404: "요청한 영업팁 실적을 찾을 수 없습니다."
    MP0409: "동일한 기본키의 영업팁 실적이 이미 존재합니다."
    FW9999: "예기치 않은 시스템 오류가 발생하였습니다."
    FW_TIMEOUT: "온라인 거래 처리시간을 초과했습니다."
    FW_OVERLOADED: "온라인 거래 처리 요청이 일시적으로 많습니다."
```

목적은 코드에서 메시지를 직접 작성하지 않고 오류 코드만 사용하는 것입니다.

```java
// 권장
throw new BizException("MP0404");

// 비권장
throw new RuntimeException(
    "요청한 영업팁 실적을 찾을 수 없습니다."
);
```

메시지를 바꿀 때 Java 소스를 수정하지 않고 YAML만 변경할 수 있습니다.

## 2. 환경 파일에서 로딩하는 방법

[application.yml](../src/main/resources/application.yml)에 다음 설정이 있습니다.

```yaml
spring:
  config:
    import: classpath:exceptionCode.yml
```

애플리케이션 시작 시 흐름은 다음과 같습니다.

```text
application.yml
→ spring.config.import
→ exceptionCode.yml 읽기
→ Spring Environment에 nhnis.exception.* 등록
→ ExceptionCodeProperties로 바인딩
```

## 3. Java 객체로 바인딩

연결 소스: [ExceptionCodeProperties.java](../../pdmg-fw/src/main/java/nhnis/fw/exception/ExceptionCodeProperties.java)

```java
@ConfigurationProperties("nhnis")
public class ExceptionCodeProperties {

    public static final String DEFAULT_CODE = "FW9999";

    private Map<String, String> exception =
            new LinkedHashMap<>();

    public String message(String code, Object... args) {
        String template = exception.get(code);

        if (template == null) {
            template = exception.getOrDefault(
                DEFAULT_CODE,
                "시스템 오류가 발생하였습니다."
            );
        }

        if (args == null || args.length == 0) {
            return template;
        }

        return MessageFormat.format(template, args);
    }
}
```

YAML과 Java 필드의 대응 관계는 다음과 같습니다.

```text
nhnis
└─ exception
   ├─ MP0404 → Map의 key/value
   ├─ MP0409 → Map의 key/value
   └─ FW9999 → Map의 key/value
```

결과적으로 다음 Map이 만들어집니다.

```java
{
    "MP0404":
        "요청한 영업팁 실적을 찾을 수 없습니다.",
    "MP0409":
        "동일한 기본키의 영업팁 실적이 이미 존재합니다.",
    "FW9999":
        "예기치 않은 시스템 오류가 발생하였습니다."
}
```

## 4. 메시지 조회 방법

`ExceptionCodeProperties`를 필요한 Component에 주입합니다.

```java
@Service
@RequiredArgsConstructor
public class SampleService {

    private final ExceptionCodeProperties exceptionMessages;

    public void process() {
        String message =
                exceptionMessages.message("MP0404");

        log.info(message);
    }
}
```

결과:

```text
요청한 영업팁 실적을 찾을 수 없습니다.
```

하지만 업무 Service에서 직접 메시지를 조회하는 것보다, 업무에서는 오류 코드만 던지고 공통 예외 처리기가 메시지를 조회하는 구조가 더 좋습니다.

## 5. 업무 코드에서 권장 사용법

`BizException`은 코드와 메시지 인자를 보관합니다.

파일: [BizException.java](../../pdmg-fw/src/main/java/nhnis/fw/exception/BizException.java)

```java
public class BizException extends RuntimeException {

    private final String code;
    private final transient Object[] args;

    public BizException(String code, Object... args) {
        super(code);
        this.code = code;
        this.args = args;
    }
}
```

업무 Service나 Rule에서는 다음처럼 사용합니다.

```java
if (result == null) {
    throw new BizException("MP0404");
}
```

중복 데이터라면:

```java
if (dao.exists(input) > 0) {
    throw new BizException("MP0409");
}
```

파라미터가 있는 메시지는 다음처럼 사용합니다.

YAML:

```yaml
nhnis:
  exception:
    FW0001: "{0} 오류가 발생하였습니다."
    FW0003: "{0} Exception 은 {1}로 문의해주세요"
```

Java:

```java
throw new BizException(
    "FW0001",
    "고객정보 조회"
);
```

변환 결과:

```text
고객정보 조회 오류가 발생하였습니다.
```

인자가 두 개라면:

```java
throw new BizException(
    "FW0003",
    "DB",
    "시스템 관리자"
);
```

결과:

```text
DB Exception 은 시스템 관리자로 문의해주세요
```

## 6. 현재 코드의 실제 문제

현재 [GlobalExceptionHandler.java](../../pdmg-fw/src/main/java/nhnis/fw/exception/GlobalExceptionHandler.java)는 다음처럼 처리합니다.

```java
@ExceptionHandler(BizException.class)
public ResponseEntity<NH_NIS_ERR_DTO> handleBizException(
        BizException e) {

    return error(
        e.getCode(),
        e.getMessage(),
        TYPE.BIZ,
        HttpStatus.INTERNAL_SERVER_ERROR,
        null
    );
}
```

그런데 `BizException` 생성자는 다음과 같습니다.

```java
super(code);
```

따라서 다음 예외를 발생시키면:

```java
throw new BizException("MP0404");
```

현재 응답은 이렇게 나옵니다.

```json
{
  "stdErrCode": "MP0404",
  "stdErrMsgCntn": "MP0404"
}
```

원하는 응답은 다음입니다.

```json
{
  "stdErrCode": "MP0404",
  "stdErrMsgCntn": "요청한 영업팁 실적을 찾을 수 없습니다."
}
```

즉, 현재 `ExceptionCodeProperties`는 테스트에서만 메시지 조회에 사용되고 실제 `GlobalExceptionHandler`에는 연결되지 않았습니다.

현재 업무 소스에서도 `new BizException(...)`을 실제 사용하는 부분은 확인되지 않았습니다.

## 7. 공통 예외 처리기 연결 방법

`GlobalExceptionHandler`에 `ExceptionCodeProperties`를 주입합니다.

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    private final ExceptionCodeProperties exceptionMessages;

    public GlobalExceptionHandler(
            ExceptionCodeProperties exceptionMessages) {
        this.exceptionMessages = exceptionMessages;
    }

    @ExceptionHandler(BizException.class)
    public ResponseEntity<NH_NIS_ERR_DTO> handleBizException(
            BizException e) {

        String message = exceptionMessages.message(
            e.getCode(),
            e.getArgs()
        );

        return error(
            e.getCode(),
            message,
            TYPE.BIZ,
            HttpStatus.BAD_REQUEST,
            null
        );
    }
}
```

완성된 실행 흐름은 다음과 같습니다.

```text
Service 또는 Rule
→ throw new BizException("MP0404")
→ GlobalExceptionHandler
→ ExceptionCodeProperties.message("MP0404")
→ exceptionCode.yml 메시지 조회
→ NH_NIS_ERR_DTO 생성
→ HTTP 오류 응답
```

## 8. 등록되지 않은 코드 처리

다음처럼 YAML에 없는 코드를 조회하면:

```java
exceptionMessages.message("UNKNOWN_CODE");
```

[ExceptionCodeProperties.java](../../pdmg-fw/src/main/java/nhnis/fw/exception/ExceptionCodeProperties.java)는 `FW9999` 메시지를 사용합니다.

```text
UNKNOWN_CODE 없음
→ FW9999 조회
→ 예기치 않은 시스템 오류가 발생하였습니다.
```

코드는 원래 요청한 `UNKNOWN_CODE`로 응답할 수도 있지만, 운영에서는 알 수 없는 코드를 `FW9999`로 통일하는 편이 안전합니다.

```java
String responseCode =
        exceptionMessages.getException().containsKey(e.getCode())
        ? e.getCode()
        : ExceptionCodeProperties.DEFAULT_CODE;
```

## 9. 타임아웃 메시지의 현재 상태

YAML에는 다음 코드가 있습니다.

```yaml
FW_TIMEOUT: "온라인 거래 처리시간을 초과했습니다."
FW_OVERLOADED: "온라인 거래 처리 요청이 일시적으로 많습니다."
```

하지만 현재 타임아웃 예외는 예외 클래스가 자체 메시지를 가지고 있고, `GlobalExceptionHandler`도 `e.getMessage()`를 사용합니다.

```java
return error(
    "FW_TIMEOUT",
    e.getMessage(),
    TYPE.COMMON,
    HttpStatus.GATEWAY_TIMEOUT,
    detail
);
```

따라서 이 두 YAML 메시지도 현재 응답 생성에는 직접 사용되지 않습니다.

메시지 관리 체계를 통일하려면 다음처럼 처리하는 것이 좋습니다.

```java
String message =
        exceptionMessages.message("FW_TIMEOUT");
```

## 10. 동일 파일이 두 곳에 존재

현재 파일은 두 군데 있습니다.

- 서비스 파일: [pdmg-service exceptionCode.yml](../src/main/resources/exceptionCode.yml)
- FW 파일: 현재 `pdmg-fw/src/main/resources`에는 별도 `exceptionCode.yml`이 없으며 서비스가 위 파일을 `spring.config.import`로 읽는다.

현재 두 파일 내용은 같습니다. 하지만 같은 classpath 경로에 같은 이름의 리소스가 존재하면 유지보수 시 혼동이 생깁니다.

권장 구조는 다음입니다.

```text
pdmg-fw
└─ 공통 코드
   FW0001, FW0401, FW0403, FW9999,
   FW_TIMEOUT, FW_OVERLOADED

pdmg-service
└─ 업무 코드
   MP0404, MP0409
```

파일명을 분리하는 것도 좋습니다.

```yaml
spring:
  config:
    import:
      - classpath:pdmg-fw-exception-code.yml
      - classpath:pdmg-service-exception-code.yml
```

중복 코드가 있을 경우 서비스가 공통 메시지를 덮어쓸 수 있도록 우선순위도 명확하게 정의해야 합니다.

## 최종 정리

현재 상태:

```text
exceptionCode.yml
→ Spring Environment 로딩
→ ExceptionCodeProperties 바인딩
→ 테스트에서는 조회 성공
→ 실제 GlobalExceptionHandler에는 미연결
```

권장 완성 상태:

```text
업무 코드
→ new BizException("MP0404")
→ GlobalExceptionHandler
→ ExceptionCodeProperties.message("MP0404")
→ YAML 메시지 조회
→ 표준 오류 DTO 응답
```

따라서 `exceptionCode.yml`의 목적과 바인딩은 정상적으로 구현되어 있지만, **실제 업무 예외 응답에서 사용하려면 `GlobalExceptionHandler`가 `ExceptionCodeProperties`를 조회하도록 한 단계 더 연결해야 합니다.**
