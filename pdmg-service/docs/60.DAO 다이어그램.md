
```java
    int mgcoa8888S0_COUNT(mgcoa8888S0DTOin input);

    List<mgcoa8888S0DTOSub0> mgcoa8888S0_S0(
            mgcoa8888S0DTOin input
    );

    int mgcoa8888D0_D0(mgcoa8888D0DTOin input);
```

```xml
<mapper namespace=
    "nhnis.mg.co.a.persistence.dao.mgcoa8888DAO">
```

## 8. 삭제 DAO

물리 삭제:

```text
Service
   │
   ▼
DAO.delete(...)
   │
   ▼
DELETE FROM 업무테이블
 WHERE 식별키 = #{id}
```

논리 삭제:

```text
Service
   │
   ▼
DAO.updateDeleteFlag(...)
   │
   ▼
UPDATE 업무테이블
   SET 삭제여부   = 'Y',
       삭제자     = #{userId},
       삭제일시   = CURRENT_TIMESTAMP
 WHERE 식별키     = #{id}
```

감사·복구 요구가 있으면 논리 삭제 방식이 일반적으로 적합합니다.

## 9. 파라미터 바인딩

```text
DTO / Map
   │
   ├─ customerId = "C10001"
   ├─ branchId   = "10001"
   └─ status     = "ACTIVE"
   │
   ▼
MyBatis
   │
   ├─ #{customerId}
   ├─ #{branchId}
   └─ #{status}
   │
   ▼
PreparedStatement
   │
   ├─ 첫 번째 ? = C10001
   ├─ 두 번째 ? = 10001
   └─ 세 번째 ? = ACTIVE
```

권장:

```xml
WHERE CUSTOMER_ID = #{customerId}
```

피해야 하는 방식:

```xml
WHERE CUSTOMER_ID = '${customerId}'
```

차이:

```text
#{value}
└─ PreparedStatement 파라미터 바인딩
   └─ SQL Injection 방지

${value}
└─ 문자열을 SQL에 직접 결합
   └─ SQL Injection 위험
```

동적 컬럼명이나 정렬 기준에 `${}`가 불가피하다면 허용 목록으로 검증해야 합니다.

## 11. DAO와 트랜잭션

```text
Business Facade
   │
   ├──────────── TX BEGIN
   │
   ▼
Business Service
   │
   ├─ DAO.select()
   │
   ├─ DAO.insert()
   │
   ├─ DAO.update()
   │
   └─ DAO.delete()
   │
   ▼
같은 RDW Connection 사용
   │
   ├─ 정상 반환
   │      └─ COMMIT
   │
   └─ 예외 발생
          └─ ROLLBACK
```

같은 트랜잭션으로 묶이기 위한 조건:

```text
Facade
  @Transactional(
      transactionManager = "rdwTransactionManager",
      rollbackFor = Exception.class
  )

DAO
  └─ rdwTransactionManager와 같은 RDW DataSource 사용
```

다른 DataSource를 사용하는 DAO는 자동으로 같은 트랜잭션에 묶이지 않습니다.

## 13. DAO 예외 흐름

```text
Mapper SQL 실행
      │
      ├─ SQL 문법 오류
      ├─ 제약조건 위반
      ├─ 중복 키
      ├─ 데이터 타입 오류
      ├─ Lock Timeout
      └─ DB 연결 오류
      │
      ▼
MyBatis / JDBC Exception
      │
      ▼
Spring DataAccessException 변환
      │
      ▼
DAO → Service
      │
      ▼
BizPrePostAspect 오류 후처리
      │
      ▼
Facade ROLLBACK
      │
      ▼
GlobalExceptionHandler
      │
      └─ 표준 오류 응답
```

DAO에서 예외를 숨기면 안 됩니다.

```java
// 피해야 하는 방식
default int update(Input input) {
    try {
        return executeUpdate(input);
    } catch (Exception e) {
        return 0;
    }
}
```

예외가 외부로 전파돼야 트랜잭션이 롤백됩니다.

## 16. DAO가 담당하지 않는 영역

```text
DAO
   │
   ├─ X HTTP 요청 처리
   ├─ X Service ID 라우팅
   ├─ X 업무 흐름 조정
   ├─ X 업무 정책 판단
   ├─ X 트랜잭션 시작·종료
   ├─ X 예외를 정상 결과로 변환
   ├─ X 사용자 응답 DTO 조립
   └─ X 외부 시스템 호출
```

책임 위치:

```text
HTTP 처리          → Controller
Service ID 라우팅  → Handler
트랜잭션 경계      → Facade
업무 흐름          → Service
업무 정책          → Rule
데이터 접근        → DAO / Mapper
외부 호출          → Client
```
