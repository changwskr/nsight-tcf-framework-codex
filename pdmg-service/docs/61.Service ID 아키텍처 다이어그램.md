# Service ID 아키텍처 텍스트 다이어그램

## 1. Service ID 기본 구조

```text
┌──────────┬──────────┬──────────┬────────────┬──────────┬──────────┐
│ 대구분   │ 업무구분 │ 세부업무 │ 식별번호   │ 거래구분 │ 순번     │
│ 2자리    │ 2자리    │ 1자리    │ 4자리      │ 1자리    │ 1자리    │
└────┬─────┴────┬─────┴────┬─────┴─────┬──────┴────┬─────┴────┬─────┘
     │          │          │           │           │          │
     ▼          ▼          ▼           ▼           ▼          ▼
    mg         co          a          5530         S          0
```

조합 결과:

```text
mg + co + a + 5530 + S + 0
                 │
                 ▼
          mgcoa5530S0
```

Service ID 분석:

```text
mgcoa5530S0
│ │ │  │  ││
│ │ │  │  │└─ 순번: 0
│ │ │  │  └── 거래구분: S(조회)
│ │ │  └───── 프로그램 식별번호: 5530
│ │ └──────── 세부업무구분: A
│ └────────── 업무구분: CO
└──────────── 대구분: MG
```

## 2. 프로그램 ID와 Service ID 관계

```text
프로그램 ID
└─ mgcoa8888
        │
        ├─ 조회 거래
        │    └─ mgcoa8888S0
        │
        ├─ 등록 거래
        │    └─ mgcoa8888C0
        │
        ├─ 수정 거래
        │    └─ mgcoa8888U0
        │
        └─ 삭제 거래
             └─ mgcoa8888D0
```

```text
프로그램 ID = mgcoa8888
Service ID  = mgcoa8888 + 거래구분 + 순번
```

하나의 프로그램은 여러 Service ID를 가질 수 있습니다.

```text
                     mgcoa9000
                         │
       ┌─────────────────┼─────────────────┐
       │                 │                 │
       ▼                 ▼                 ▼
  mgcoa9000S0       mgcoa9000C0       mgcoa9000U0
  거래 조회          거래 등록          거래 수정
                         │
                         ▼
                    mgcoa9000D0
                    거래 삭제
```

## 3. 거래구분

```text
┌──────────┬──────────────┬──────────────────────────┐
│ 코드     │ 의미         │ 예                       │
├──────────┼──────────────┼──────────────────────────┤
│ S        │ Select       │ 목록·상세 조회           │
│ C        │ Create       │ 신규 등록                │
│ U        │ Update       │ 데이터 수정              │
│ D        │ Delete       │ 삭제·폐기                │
│ A        │ Action       │ 일반 업무 실행           │
│ R        │ Report       │ 보고서·출력              │
└──────────┴──────────────┴──────────────────────────┘
```

순번은 동일한 거래구분의 여러 기능을 구분합니다.

```text
mgcoa8888S0  목록 조회
mgcoa8888S1  상세 조회
mgcoa8888S2  통계 조회

mgcoa8888D0  단건 삭제
mgcoa8888D1  일괄 삭제
```

## 6. Handler Registry

애플리케이션 시작 시 Handler가 자신이 담당하는 Service ID를 등록합니다.

```text
Spring Boot 시작
      │
      ▼
TransactionHandler Bean 검색
      │
      ├─ mgcoa5530Handler
      ├─ mgcoa8888Handler
      ├─ mgcoa9000Handler
      └─ mgcoa9001Handler
      │
      ▼
각 Handler의 serviceIds() 호출
      │
      ▼
Service ID → Handler Registry 생성
```

Registry 예시:

```text
┌──────────────────┬──────────────────────┐
│ Service ID       │ Handler              │
├──────────────────┼──────────────────────┤
│ mgcoa5530S0      │ mgcoa5530Handler     │
│ mgcoa8888S0      │ mgcoa8888Handler     │
│ mgcoa8888D0      │ mgcoa8888Handler     │
│ mgcoa9000S0      │ mgcoa9000Handler     │
│ mgcoa9000C0      │ mgcoa9000Handler     │
│ mgcoa9000U0      │ mgcoa9000Handler     │
│ mgcoa9000D0      │ mgcoa9000Handler     │
└──────────────────┴──────────────────────┘
```

## 7. Handler 내부 Service ID 분기

```java
@Component
public class mgcoa8888Handler implements TransactionHandler {

    private final mgcoa8888Facade facade;

    @Override
    public Collection<String> serviceIds() {
        return List.of(
            "mgcoa8888S0",
            "mgcoa8888D0"
        );
    }

    @Override
    public Object handle(
            TransactionContext context,
            Object dtoBody
    ) throws Exception {
        return switch (context.getServiceId()) {
            case "mgcoa8888S0" ->
                facade.mgcoa8888S0(dtoBody);

            case "mgcoa8888D0" ->
                facade.mgcoa8888D0(dtoBody);

            default ->
                throw new ServiceHandlerNotFound(
                    context.getServiceId()
                );
        };
    }
}
```

다이어그램:

```text
mgcoa8888Handler
        │
        ▼
context.getServiceId()
        │
        ├─ mgcoa8888S0
        │      └─ facade.mgcoa8888S0(dtoBody)
        │
        ├─ mgcoa8888D0
        │      └─ facade.mgcoa8888D0(dtoBody)
        │
        └─ 기타
               └─ ServiceHandlerNotFound
```

## 11. Service ID와 트랜잭션

```text
Service ID
mgcoa8888U0
      │
      ▼
TransactionDispatcher
      │
      ▼
mgcoa8888Handler
      │
      ▼
mgcoa8888Facade.mgcoa8888U0()
      │
      ├──────────── TX BEGIN
      │
      ▼
mgcoa8888Service.mgcoa8888U0()
      │
      ▼
mgcoa8888DAO.mgcoa8888U0_U0()
      │
      ▼
업무 DB UPDATE
      │
      ├─ 정상: COMMIT
      └─ 예외: ROLLBACK
```

Service ID 자체가 트랜잭션을 시작하지는 않습니다. Service ID는 실행할 Handler와 업무 메서드를 선택하며, 실제 트랜잭션은 Facade의 `@Transactional`에서 시작합니다.

## 13. Service ID와 타임아웃

```text
Service ID
   │
   ▼
TransactionContext
   │
   ├─ serviceId
   └─ startedAtNanos
   │
   ▼
타임아웃 정책 조회
   │
   ├─ 서비스별 설정 존재
   │      └─ 해당 설정 사용
   │
   └─ 서비스별 설정 없음
          └─ 공통 timeout 사용
   │
   ▼
업무 실행
   │
   ▼
ETF
   │
   ├─ 경과시간 계산
   └─ 제한시간 비교
```

예시 설정 개념:

```yaml
nhnis:
  fw:
    timeout:
      milliseconds: 5000
      services:
        mgcoa9000U0: 10000
```

```text
mgcoa9000U0
└─ 제한시간 10초

그 외 Service ID
└─ 공통 제한시간 5초
```

단, 현재 `OnlineTimeoutProperties`에는 서비스별 설정을 해석하는 `resolveMilliseconds(serviceId)`가 구현되어 있지 않아 보완이 필요합니다.

## 14. Service ID 오류 처리

```text
Service ID 수신
      │
      ├─ 형식 오류
      │    └─ 잘못된 서비스 ID 오류
      │
      ├─ Handler 미등록
      │    └─ ServiceHandlerNotFound
      │
      ├─ 동일 ID 중복 등록
      │    └─ 애플리케이션 시작 실패 권장
      │
      ├─ 거래 통제 차단
      │    └─ 거래 불가 오류
      │
      └─ 정상 등록
           └─ Handler 실행
```

검증 형식:

```text
^[a-z]{2}[a-z]{2}[a-z][0-9]{4}[SCUDAR][0-9A-Z]$
```

예:

```text
mgcoa5530S0  정상
mgcoa9000U0  정상
mgicb7000C1  정상

MGCOA5530S0  대소문자 규칙 위반
mgco5530S0   세부업무 누락
mgcoa553S0   식별번호 자릿수 오류
mgcoa5530X0  정의되지 않은 거래구분
```

## 16. Service ID 최종 구조

```text
                         Service ID
                        mgcoa8888S0
                              │
          ┌───────────────────┼────────────────────┐
          │                   │                    │
          ▼                   ▼                    ▼
       라우팅 키           업무 식별자          통제·로그 키
          │                   │                    │
          ▼                   ▼                    ▼
TransactionDispatcher      Java 클래스         거래 통제
          │                DTO / Mapper         타임아웃
          ▼                   │                 모니터링
       Handler                ▼                 감사 로그
                          업무 실행 추적
```

핵심 원칙:

```text
Service ID
  ├─ HTTP 요청에서 거래를 식별
  ├─ Dispatcher가 Handler를 선택
  ├─ Handler가 Facade 메서드를 선택
  ├─ DTO와 SQL Statement를 식별
  ├─ 거래 통제와 타임아웃의 정책 키
  ├─ 로그와 모니터링의 추적 키
  └─ 화면·서비스·DB 실행을 하나로 연결하는 기준 식별자
```
