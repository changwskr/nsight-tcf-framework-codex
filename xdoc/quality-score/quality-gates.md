# 품질 Gate와 평가 기준

## 목적

변경의 완료 여부를 개인 판단이 아닌 반복 가능한 기준으로 평가한다. 점수는 위험을 숨기기 위한 수단이 아니며 필수 Gate 실패는 총점과 관계없이 배포를 막는다.

## 필수 Gate

다음 항목은 모두 통과해야 한다.

- [ ] 대상 모듈이 컴파일된다.
- [ ] 관련 자동화 테스트가 통과한다.
- [ ] `serviceId`, Bean과 설정 키의 중복이 없다.
- [ ] 비밀번호, 토큰, 개인키와 개인정보가 포함되지 않는다.
- [ ] 기존 사용자 변경을 덮어쓰지 않았다.
- [ ] API 또는 설정 호환성 변경이 문서화되었다.
- [ ] 오류 및 타임아웃 경로를 검토했다.

## 100점 평가표

| 영역 | 배점 | 평가 기준 |
|---|---:|---|
| 기능 정확성 | 25 | 요구사항, 정상·실패 경로와 경계조건 충족 |
| 아키텍처 적합성 | 20 | 모듈 방향, 계층 책임, Handler 규칙 준수 |
| 테스트 | 20 | 단위·통합 테스트 품질과 회귀 범위 |
| 보안 | 15 | 입력, 인증/권한, 비밀정보와 로그 안전성 |
| 운영성 | 10 | 로그, 메트릭, 타임아웃, 설정과 장애 대응 |
| 문서화 | 10 | API, 설정, 실행법과 설계 결정 최신화 |

## 판정 기준

| 점수 | 판정 |
|---:|---|
| 90–100 | 배포 후보. 필수 Gate와 운영 검증 확인 필요 |
| 80–89 | 병합 가능. 낮은 위험의 후속 개선사항 기록 |
| 70–79 | 보완 후 재검토 |
| 0–69 | 병합 또는 배포 불가 |

## 변경 유형별 최소 검증

| 변경 | 최소 검증 |
|---|---|
| `tcf-util` | 모듈 테스트와 의존 모듈 컴파일 |
| `tcf-core` | Core 테스트, Web 테스트와 대표 업무 모듈 빌드 |
| `tcf-web` | Web 테스트와 대표 업무 WAR 빌드 |
| 업무 거래 | Handler/Service/Rule 테스트, Mapper 검증과 해당 WAR 빌드 |
| 설정 | Profile별 바인딩과 애플리케이션 기동 확인 |
| Gateway/JWT | 인증 성공·실패·만료·우회 방지 검증 |
| 문서/도움말 | 링크, 색인 생성과 Help 검증 Task |
| WAR/배포 | 생성물 이름, Context와 `ztomcat` 배포 확인 |
