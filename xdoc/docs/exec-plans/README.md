# 실행 계획 작성법

여러 모듈, DB, API 또는 배포 절차에 영향을 주는 변경은 구현 전에 실행 계획을 작성한다. 계획은 작업 중 발견한 사실에 맞춰 갱신한다.

## 실행 계획이 필요한 경우

- `tcf-core` 또는 `tcf-web`의 공개 계약 변경
- 두 개 이상의 업무 또는 플랫폼 모듈 변경
- DB Schema, Service Catalog 또는 운영 데이터 마이그레이션
- 인증, Gateway, 세션과 권한 변경
- 배포 토폴로지, WAR 구성 또는 Profile 변경
- 대규모 리팩터링과 자동 생성 코드 반영

## 파일 이름

```text
YYYY-MM-DD-short-topic.md
```

예: `2026-07-26-service-timeout-policy.md`
