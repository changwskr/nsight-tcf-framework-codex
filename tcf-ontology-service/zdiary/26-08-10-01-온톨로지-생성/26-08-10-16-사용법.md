# Architecture Design Wizard 사용법

설계서: `26-08-10-16-Architecture_Design_Wizard_ServiceId_DataTable_설계서.md`

### 1. 서비스 기동

```bat
cd tcf-ontology-service
RUN.bat
```

또는

```bat
gradlew.bat bootRun --args="--spring.profiles.active=local"
```

기본: `http://localhost:8098`

### 2. Workbench 열기

`http://localhost:8098/workbench/index.html#/design`

### 3. 7-Step Wizard 흐름

1. **Requirement** — 요건 제목, Transaction Type, Paging/Timeout/PersonalData
2. **Classification** — NSIGHT 분류표 기준 System/Business/Function 확정 (`packageRoot`, Program 접두 표시)
3. **ServiceId Design**
   - 축별 Program Inventory 조회 (`GET /api/ontology/design/programs`)
   - Program No 제안(예: 7000대) 선택 후 중복 검증 (`POST /api/ontology/design/service-id/validate`)
   - **자동 확정 금지** — 상태는 항상 PROPOSED
4. **Data / Table Design**
   - Ontology Table만 검색·선택 (`GET /api/ontology/design/tables`, `/table/{name}`)
   - Access Type / Column / Join / Paging Key 설계
   - 없는 Table → `[+ 신규 Table 설계]` → `NEW_TABLE_PROPOSAL` (PROPOSED, DDL/Ontology VERIFIED 없음)
5. **Application Architecture** — Handler/Facade/Service/DAO/Mapper 명명 제안
6. **Runtime / Policy** — Message/TX/Timeout/Paging/Security (근거 없으면 UNRESOLVED)
7. **Gate / Export**
   - Run Design Gate → `PASS` 또는 `PASS_WITH_UNRESOLVED`
   - Export Markdown/JSON
   - **Done · 서버 저장** → session `COMPLETED` (`POST /api/ontology/design/session/{id}/complete`)
   - Dashboard Detail `Designs (PROPOSED)` / Programs / ServiceIds에서 재조회

### 4. Dashboard에서 설계 다시 보기

- Home → **Designs (PROPOSED)** 또는 `#/dashboard?view=designs`
- Programs / ServiceIds 상세에도 Wizard Done 분이 `PROPOSED`로 함께 표시
- Concepts는 Ontology 로드분(VERIFIED)만 — 설계 Proposal은 Designs 탭

### 5. 주요 API

| Method | Path | 용도 |
|--------|------|------|
| POST | `/api/ontology/design/session` | 설계 세션 |
| GET | `/api/ontology/design/sessions` | 세션 목록 |
| POST | `/api/ontology/design/session/{id}/complete` | Done 저장 (COMPLETED) |
| POST | `/api/ontology/design/service-id/validate` | Program/ServiceId 중복·형식 검증 |
| GET | `/api/ontology/design/programs` | 축별 Program 현황 + proposed Nos |
| GET | `/api/ontology/design/tables` | Ontology Table 검색 |
| POST | `/api/ontology/design/table-proposal` | NEW_TABLE_PROPOSAL 생성 |
| POST | `/api/ontology/design/validate` | Wizard Gate |
| POST/GET | `/api/ontology/design/export` | Markdown/JSON export |
| GET | `/api/ontology/dashboard/designs` | 완료 설계 상세 |

### 6. 골든 시나리오

**기존 Table (QUERY)**  
1. Requirement: `마케팅희망고객 조회` / QUERY / Paging YES  
2. Classification: MG / CO / A  
3. ServiceId: Program No `7000` → `mgcoa7000S0` AVAILABLE  
4. Data: `TB_MK_CO_A_5530` SELECT  
5. Gate → Done → Dashboard Designs

**신규 Table**  
1. Classification: MG / IC / B  
2. ServiceId: `mgicb7000S0`  
3. Data: 검색 없음 → 신규 Table `TB_MG_IC_7000` PROPOSED  
4. Gate `PASS_WITH_UNRESOLVED` → Done → Dashboard에서 `mgicb7000S0` / `TB_MG_IC_7000` 조회

### 7. 금지사항

- Program No / ServiceId 자동 확정
- Ontology에 없는 Table/Column 날조
- Export에 `undefined` / `[object Object]` 포함
- 신규 Table을 VERIFIED로 둔갑
- Gate FAIL 상태에서 Done 완료

### 8. 참고

- Done 저장은 **프로세스 메모리** (서버 재시작 시 소실). Ontology YAML로 승격하는 단계는 후속.
- local profile에서 mapping seed → validate → `POST /api/ontology/reload` → `GET /api/ontology/validate/service/{serviceId}`
