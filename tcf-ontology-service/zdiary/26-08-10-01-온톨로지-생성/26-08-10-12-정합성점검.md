현재 Architecture Design Assistant 신규 기능 구현을 중단하고 `src` 정합성 결함을 먼저 수정하라.

우선순위는 다음과 같다.

P0-01 ArchitectureRuleValidator 수정

`validateAll()`의 failCount 계산이 `severity`를 읽고 있으나 Finding은 `verdict` 필드를 사용한다.

반드시 `verdict=FAIL` 기준으로 집계하도록 수정하고 다음 통합 테스트를 추가하라.

- 깨진 Graph 생성
- validateAll() 실행
- status = FAIL
- failCount > 0

개별 rule 메서드 FAIL만 검사하는 테스트로 완료처리하지 마라.

P0-02 Architecture Design Route 정합성

현재 index.html은 `./js/design.js`를 로딩하지만 파일이 존재하지 않는다.

또한 `#/design` 메뉴는 존재하지만 app.js의 META와 Router에는 design 처리가 없다.

다음을 확인하고 수정하라.

- design.js 실제 존재
- static resource 200 테스트
- META.design
- #/design Router
- Architecture Design 화면 진입 테스트

아직 Design 기능을 전부 구현할 필요는 없다.
최소한 깨진 Route/Asset 상태부터 해소하라.

P0-03 Impact Path 의미 오류

`OntologyQueryService.synthesizeImpactPaths()`가 fallback에서 다음과 같은 의미적으로 잘못된 Edge를 만들 수 있다.

ServiceId -HANDLED_BY→ Table

HANDLED_BY의 대상은 반드시 Handler여야 한다.

실제 OntologyStore에 존재하지 않는 Relation을 path 증명용으로 생성하지 마라.

Fallback은 실제 Graph Relation만 사용하거나, 경로를 증명할 수 없으면 PARTIAL/UNRESOLVED로 반환하라.

추가로 다음 P1을 분석만 하고 목록화하라.

- RecommendService가 OntologyRegistry 휴리스틱에 의존
- Provenance.sourceCode가 추측 경로도 VERIFIED 처리
- classificationPath가 실제 Relation을 확인하지 않고 ServiceId 파싱으로 관계 생성
- summarizeStructure의 findFirst() 비결정성
- Gate가 입력 ServiceId가 아니라 전체 validateAll() 수행
- /reload가 Registry만 reload하고 OntologyStore는 갱신하지 않음
- Workbench detectType의 Program regex가 mgcoa8888 9자리 형식과 불일치
- 외부 Google Font 의존성

수정 후 다음 보고서를 작성하라.

`ONTOLOGY-SOURCE-CODE-REVIEW-FIX-REPORT.md`

보고서에는:

1. 수정 전 문제
2. 변경 파일
3. 수정 코드
4. 신규 테스트
5. 실제 테스트 결과
6. 회귀 결과
7. 아직 남은 P1/P2
8. Architecture Design Assistant 구현 재개 가능 여부

를 작성한다.
