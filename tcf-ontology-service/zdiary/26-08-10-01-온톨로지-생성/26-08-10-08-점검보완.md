새로운 기능은 추가하지 마라.

`ONTOLOGY-FINAL-ACCEPTANCE-REPORT.md`의 남은 3개 결함만 수정하고 Ontology Core 1.0을 마감하라.

## 1. Impact Table resolve 오류 수정

현재:

GET /api/ontology/impact/table/TB_FW_IMAGE_LOG

응답의 `table`이 다음처럼 잘못 반환된다.

type = COLUMN
name = GUID

원인은 Table 이름 alias가 Column의 `tableName` 속성과 충돌하는 것으로 보인다.

수정 원칙:

- `/impact/table/{tableName}`에서는 반드시 ConceptType.TABLE만 resolve한다.
- Column의 attribute 값이 Table alias로 등록되지 않도록 한다.
- 범용 alias 검색과 type-specific 검색을 분리한다.
- 기존 다른 조회 API는 깨지지 않아야 한다.

수정 후:

GET /api/ontology/impact/table/TB_FW_IMAGE_LOG

의 `table.type`은 반드시 `TABLE`이어야 한다.

## 2. Function / System 역추적 추가

현재 영향도는 다음까지 가능하다.

Table
← Mapper
← DAO
← Service
← Facade
← Handler
← ServiceId
← Program
← Business

이를 다음까지 확장하라.

Table
← Mapper
← DAO
← Service
← Facade
← Handler
← ServiceId
← Program
← Function
← Business
← System

현재 Design Graph에 이미 다음 관계가 존재한다.

System
-HAS_BUSINESS→ Business

Business
-HAS_FUNCTION→ Function

Function
-HAS_PROGRAM→ Program

따라서 새로운 지식을 만드는 것이 아니라 기존 관계를 역방향 탐색에 포함하라.

Impact Response에 최소 다음을 추가한다.

- affectedFunctions
- affectedSystems

그리고 paths에도 해당 단계가 포함되게 한다.

## 3. 재검증

수정 후 반드시 실제 실행한다.

gradlew.bat clean test
gradlew.bat war
gradlew.bat bootRun --args="--server.port=8099"

다음 API를 실제 호출한다.

GET /api/ontology/impact/table/TB_FW_IMAGE_LOG

다음을 증명한다.

table.type = TABLE

affectedMappers 비어있지 않음
affectedDaos 비어있지 않음
affectedServices 비어있지 않음
affectedFacades 비어있지 않음
affectedHandlers 비어있지 않음
affectedServiceIds 비어있지 않음
affectedPrograms 비어있지 않음
affectedFunctions 비어있지 않음
affectedBusinesses 비어있지 않음
affectedSystems 비어있지 않음

paths가 다음 End-to-End 관계를 포함해야 한다.

System
→ Business
→ Function
→ Program
→ ServiceId
→ Handler
→ Facade
→ Service
→ DAO
→ Mapper/SQL
→ Table

역방향으로도 동일 관계가 탐색되어야 한다.

## 4. Git Baseline

기능 검증이 모두 PASS한 뒤에만 Git Baseline 후보 상태를 확인한다.

git status
git diff --stat
git ls-files tcf-ontology-service

아직 commit은 임의로 수행하지 마라.

대신 다음을 보고하라.

- 최초 add 대상 파일 수
- 제외해야 할 build/, log/, temp 파일
- .gitignore 보완 필요 여부
- Ontology Core 1.0 최초 Commit 후보 메시지

예:

feat(ontology): establish NSIGHT ontology core 1.0 baseline

`ONTOLOGY-CORE-1.0-ACCEPTANCE.md`를 작성한다.

최종 판정은 아래 두 가지 중 하나만 사용한다.

A. Ontology Core 1.0 ACCEPTED
B. Ontology Core 1.0 NOT ACCEPTED

A 조건:

- clean test PASS
- war PASS
- boot PASS
- impact.table TABLE 정상
- Table→System 전체 역추적 PASS
- Provenance PASS
- 기존 API 회귀 PASS
