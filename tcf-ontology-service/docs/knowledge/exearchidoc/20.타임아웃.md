## 0. 정책 한눈에 (현행)

**TCF 온라인 거래의 Dispatcher~DAO 구간**에 공통 타임아웃이 **적용되어 있다.**

| 항목 | 값 |
|------|-----|
| 스위치 | `nhnis.fw.timeout.enabled=true` (`pdmg-service` `application.yml`) |
| 기본 제한시간 | **5000 ms** (`milliseconds`) |
| serviceId별 | `overrides.<serviceId>` (예: `mgcoa5530S0: 10000`). 미등록 → 기본값 |
| Pool | size **20**, queue **100**, thread 접두 `pdmg-online-` |
| 진입점 | `TcfFacade.process` → `OnlineTimeoutExecutor.execute` |
| 외부 TX | Worker의 `TransactionTemplate` + `rdwTransactionManager` |
| Facade | 기존 `@Transactional(REQUIRED)`로 **같은 TX에 참여** |
| 타임아웃 응답 | HTTP **504**, `stdErrCode=FW_TIMEOUT` |
| 과부하 응답 | HTTP **503**, `stdErrCode=FW_OVERLOADED` |
| 비활성 | `enabled=false` 또는 설정 누락 → `SyncOnlineTimeoutExecutor` (동기, 제한 없음) |

```text
요청 Thread (HTTP)
  Filter → Interceptor.pre → OnlineController → TcfFacade
      │
      ├─ OnlineTimeoutExecutor
      │     timeoutMs = resolveMilliseconds(serviceId)
      │     Future.get(timeoutMs)
      │     cancel(true) on timeout
      │
      └─ Worker (pdmg-online-*)
            TransactionTemplate BEGIN
              Dispatcher → Handler → Facade → BizPrePost → Service → DAO
              Deadline / interrupt 재검사
            COMMIT 또는 ROLLBACK
  → Advice → Interceptor.after → Response
```

**범위 밖:** DefaultFilter, 시스템 선·후처리, ImageLog, ResponseBodyAdvice.  
**보장하지 않음:** 실행 중 JDBC의 물리적 즉시 종료 (늦은 반환 후 롤백만 보장).  
**전제:** `nhnis.fw.tcf.enabled=true`. TCF OFF면 Executor 경로를 타지 않는다.

## 2. 설정

### 2.1 현행 (`pdmg-service` `application.yml`)

```yaml
nhnis:
  fw:
    timeout:
      enabled: true
      milliseconds: 5000          # 기본 (미등록 serviceId)
      overrides:
        mgcoa5530S0: 10000        # 이 거래만 10초
      pool-size: 20
      queue-capacity: 100
```

### 2.2 제한시간 결정

```text
OnlineTimeoutProperties.resolveMilliseconds(serviceId)

1. serviceId 가 overrides 에 있으면 → 해당 ms
2. 없으면 → milliseconds (기본)
```

`serviceId`는 Worker 제출 전 스냅샷의 `rms_svc_c`(또는 MDC `serviceId`)를 사용한다.  
`Future.get`·Deadline·`OnlineTimeoutException.timeoutMs`·로그의 `timeoutMs`에 **동일 값**이 반영된다.

### 2.3 규칙

| 키 | 제약 | 비고 |
|----|------|------|
| `enabled` | boolean | `false` / 미설정 → 동기 경로 (`matchIfMissing=true`로 Sync) |
| `milliseconds` | `>= 1` | 기본 제한시간. 위반 시 기동 실패 (`@PostConstruct`) |
| `overrides.<serviceId>` | `>= 1` | 키 공백·값 `<1` 이면 기동 실패 |
| `pool-size` | `>= 1` | core = max |
| `queue-capacity` | `>= 0` | 포화 시 `AbortPolicy` → `OnlineOverloadException` |

TM 주입: `@Qualifier("rdwTransactionManager")`.  
종료: pool `waitForTasksToCompleteOnShutdown` + await 30초.

## 3. 실행 정책

### 3.1 정상

```text
요청 Thread: resolveMilliseconds → submit + Future.get(timeoutMs)
Worker: TX BEGIN → 업무 완료 → Deadline OK → COMMIT
요청 Thread: 결과 반환 (기존 *DTOout 계약 유지)
```

### 3.2 제한시간 초과

```text
요청 Thread: Future.get timeout
요청 Thread: future.cancel(true)
요청 Thread: OnlineTimeoutException(timeoutMs=…) → 504 FW_TIMEOUT  (대표 WARN 로그)
Worker: interrupt 또는 업무 종료 후 Deadline 초과
Worker: setRollbackOnly → OnlineTimeoutException → ROLLBACK  (필요 시 DEBUG)
```

### 3.3 JDBC가 interrupt를 무시하고 늦게 끝난 경우

```text
요청 Thread: 이미 504 반환 가능
Worker: JDBC 반환 후 Deadline 재검사 → rollbackOnly → ROLLBACK
```

늦은 **커밋은 막는다.** SQL을 중간에 끊는 것은 후속(MyBatis/JDBC statement timeout) 과제.

### 3.4 Executor 포화

Pool·큐가 가득 차 `RejectedExecutionException` → `OnlineOverloadException` → **503** `FW_OVERLOADED`.  
무제한 대기는 하지 않는다.

### 3.5 컨텍스트 전파

제출 전 스냅샷 → Worker `install` → `finally`에서 정리:

- `ServiceContextHolder` (동일 `ServiceContext` 참조; Servlet 장기 보관 금지)
- Log4j2 `ThreadContext` (guid / serviceId / userId / ip 등)

Worker `finally`: `ServiceContextHolder.removeInstance()` + `ThreadContext.clearAll()`  
→ 다음 작업으로 ThreadLocal 누출 방지.

## 4. 오류 응답

`GlobalExceptionHandler` → `NH_NIS_ERR_DTO` → Advice가 **`result`** 로 감쌈 (`dto`는 업무 전용).

| 예외 | HTTP | `stdErrCode` | `stdErrMsgCntn` |
|------|------|--------------|-----------------|
| `OnlineTimeoutException` | **504** Gateway Timeout | `FW_TIMEOUT` | 온라인 거래 처리시간을 초과했습니다. |
| `OnlineOverloadException` | **503** Service Unavailable | `FW_OVERLOADED` | 온라인 거래 처리 요청이 일시적으로 많습니다. |

`addMsgContents` 예: `serviceId=mgcoa5530S0,guid=…,timeoutMs=10000,elapsedMs=…`  
(해당 거래의 **적용된** timeoutMs가 들어간다.)  
전문 원문·Token·개인정보는 예외/로그에 넣지 않는다.

로그:

```text
[ONLINE-TIMEOUT] guid=… serviceId=mgcoa5530S0 timeoutMs=10000 elapsedMs=10007 cancelRequested=true
[ONLINE-OVERLOAD] guid=… serviceId=… active=20 poolSize=20 queueSize=100
```

요청 Thread WARN과 Worker DEBUG 중복 ERROR는 피한다.

## 5. 트랜잭션과의 관계

| 층 | 역할 |
|----|------|
| **OnlineTimeoutExecutor** | Worker에서 `TransactionTemplate`으로 **외부 TX 1건** 시작 |
| **Facade `@Transactional`** | `REQUIRED` → 외부 TX **참여** (거래당 TX 하나) |
| **Service `@Transactional`** | Facade TX가 있으면 참여. TCF OFF 시 Service가 BEGIN 가능 |
| Facade `readOnly=true` | 이미 열린 read-write 외부 TX의 속성을 바꾸지 못함 (현행 단순 구현) |

Facade에 `@Transactional(timeout = 초)`를 **추가로** 두는 것은 선택(샘플 미사용).  
온라인 공통 제한의 **주 정책은 Executor의 `resolveMilliseconds(serviceId)`** 이다.

상세 BEGIN: [20.Tranaactional-…](./20.Tranaactional-rdwTransactionManager-Begin.md).

## 6. 다른 계층 (참고 · 미적용/보조)

| 계층 | 현행 |
|------|------|
| Filter~Advice 전체 wall-clock kill | **없음** |
| MyBatis `defaultStatementTimeout` / XML `timeout` | **없음** |
| Hikari `connection-timeout` | 미명시(풀 대기). SQL 실행 제한 아님 |
| UI `pdmg.ui.timeout-ms` | 브라우저 `AbortController` (`PdmgServiceClient`). **서버 Executor와 별개** |
| 성능 감시 로그 / ImageLog | 추적만. **자동 롤백 아님** |

UI Abort가 서버보다 짧으면 브라우저는 먼저 끊고, 서버 Worker는 계속 돌다 cancel/Deadline으로 롤백을 시도한다.  
**권장:** UI `timeout-ms` ≥ 서버 적용 최대 timeout(기본·overrides 중 큰 값).

## 7. 운영 방침

```text
1. 온라인 기본 SLA     → nhnis.fw.timeout.milliseconds
2. 특정 거래만 연장    → nhnis.fw.timeout.overrides.<serviceId>
3. Pool 여유           → pool-size / queue-capacity (503 모니터링)
4. 끄기                → enabled=false (동기 경로, 제한 없음)
5. SQL 강제 중단 필요  → 후속 MyBatis/JDBC timeout (현행 미구현)
6. UI Abort            → pdmg.ui.timeout-ms 를 서버 최대값보다 크게
```

## 8. 하지 말 것

1. Controller/Handler/Service에 타임아웃 복제  
2. Filter/Interceptor에 sleep 감시로 대체  
3. UI `timeout-ms`만 보고 서버 Executor와 동일하다고 가정  
4. JDBC가 무조건 즉시 끊긴다고 가정  
5. Worker에서 `ServiceContext`/`MDC` 정리 생략  
6. `enabled=true`인데 `rdwTransactionManager` 없이 기동  
7. override 키를 URL path와 다른 임의 문자열로 두기 (`rms_svc_c` / serviceId와 일치)
