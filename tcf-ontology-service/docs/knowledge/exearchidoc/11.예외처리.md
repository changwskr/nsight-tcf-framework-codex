## 1. 원칙

| 원칙 | 내용 |
|------|------|
| 업무 예상 오류 | `BizException(code, args…)` 로 명시적 throw |
| 실패 응답 포맷 | **`NH_NIS_ERR_DTO`** (성공 전문 `hdr_nhnis`+`dto`와 다름) |
| 메시지 사전 | `exceptionCode.yml` → `ExceptionCodeProperties` |
| DB 롤백 | 쓰기 Facade `@Transactional` 안에서 예외 시 Spring이 rollback |
| 시스템 감사 | Filter/Interceptor·ImageLog는 **업무 TX 밖** |
| 구 계약 금지 | STF/ETF, `result.resultCode`, Controller별 임의 JSON |

```text
업무 예외
  → (쓰기면) TX ROLLBACK
  → GlobalExceptionHandler
  → NH_NIS_ERR_DTO
  → (가능 시) ImageLog 예외 기록
```

## 2. 예외 종류

| 유형 | 타입 | 언제 | errType / HTTP 예 |
|------|------|------|-------------------|
| 업무 | `nhnis.fw.exception.BizException` | 검증 실패, 미존재, 중복 등 | `BIZ` / 보통 200+ERR DTO |
| 라우팅 | `ServiceHandlerNotFound` | serviceId에 Handler/분기 없음 | `SERVICE` |
| **온라인 타임아웃** | `OnlineTimeoutException` | Executor deadline 초과 | `FW_TIMEOUT` / **504** |
| **풀 포화** | `OnlineOverloadException` | 큐 거절 | `FW_OVERLOADED` / **503** |
| 시스템 | 그 외 `Exception` / Runtime | NPE, DB 접속 등 | (핸들러·후처리 경로) |
| 인증 | Security 필터 | 토큰 없음·만료 | Controller 도달 전 |

타임아웃 상세: [20.타임아웃.md](./20.타임아웃.md)

## 3. `BizException`

```java
package nhnis.fw.exception;

public class BizException extends RuntimeException {
    public BizException(String code, Object... args) { … }
    public String getCode() { … }
    public Object[] getArgs() { … }
}
```

### 3.1 사용 규칙

```java
// 좋음 — 코드 + 메시지 인자
throw new BizException("FW0001", "요청 Body");
throw new BizException("MP0404");
throw new BizException("FW0003", "BizException", "시스템관리자");

// 나쁨 — 메시지 문자열만, 코드 없음
throw new RuntimeException("없는 데이터입니다");
// 나쁨 — 예외를 catch 하고 성공 dto 반환
```

| 규칙 | 설명 |
|------|------|
| Service(또는 Facade)에서 throw | Handler에서 업무 판단하지 않음 |
| 코드는 yml에 등록 | 미등록 시 `FW9999` 메시지 폴백 가능 |
| checked Exception 남발 금지 | 업무는 unchecked `BizException` |
| 삼키지 말 것 | `catch (Exception e) { return ok; }` 금지 |

### 3.2 메시지 해석

`pdmg-service` / `pdmg-fw` 의 `exceptionCode.yml`:

```yaml
nhnis:
  exception:
    FW0001: "{0} 오류가 발생하였습니다."
    FW0003: "{0} Exception 은 {1}로 문의해주세요"
    FW0401: "인증에 실패하였습니다. 다시 로그인해주세요."
    FW0403: "요청한 거래에 대한 권한이 없습니다."
    FW9999: "예기치 않은 시스템 오류가 발생하였습니다. …"
    MP0404: "요청한 영업팁 실적을 찾을 수 없습니다."
    MP0409: "동일한 기본키의 영업팁 실적이 이미 존재합니다."
```

`ExceptionCodeProperties.message(code, args…)` 가 `MessageFormat`으로 치환한다.  
신규 업무 코드는 **MG/프로그램 규칙에 맞게 추가**하고, 샘플의 `MP*`는 호환·예시로 남을 수 있다.

> 구현 참고: `GlobalExceptionHandler`는 현재 `e.getCode()` / `e.getMessage()` 를 DTO에 넣는다.  
> `BizException` 생성 시 `super(code)` 이라 `getMessage()`가 코드 문자열일 수 있다.  
> 화면용 문구가 필요하면 Handler에서 `ExceptionCodeProperties.message(code, args)` 로 `stdErrMsgCntn`을 채우도록 보강하는 것이 바람직하다.

## 4. 중앙 처리: `GlobalExceptionHandler`

위치: `pdmg-fw` … `nhnis.fw.exception.GlobalExceptionHandler`  
조건: `nhnis.fw.tcf.enabled=true` (`@RestControllerAdvice`)

```java
@ExceptionHandler(ServiceHandlerNotFound.class)
→ stdErrCode = "E9999", errType = SERVICE

@ExceptionHandler(BizException.class)
→ stdErrCode = e.getCode(), errType = BIZ

// 공통
NH_NIS_ERR_DTO
  stdErrCode, stdErrMsgCntn, errType
ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
```

| 항목 | 현재 동작 |
|------|-----------|
| HTTP 상태 | 업무·라우팅 실패도 **500** 으로 반환하는 구현 |
| 클라이언트 판별 | HTTP보다 **`stdErrCode` / `errType`** 을 본다 |
| 성공 전문 | 사용하지 않음 (`hdr_nhnis`+`dto` 아님) |

TCF OFF에서는 이 Advice가 비활성일 수 있다. 거래별 Controller 예외 전략을 별도로 맞춘다.

## 5. 실패 응답 본문 (`NH_NIS_ERR_DTO`)

```text
stdErrCode      오류 코드
stdErrMsgCntn   오류 메시지
addMsgContents  부가 메시지 (선택)
errType         BIZ / SERVICE / …
errClassName …  발생 위치 메타 (선택)
```

성공 전문과 스키마가 다르므로 UI는 **실패 시 에러 DTO 전용 파서/팝업**을 쓴다.  
→ [10.전문.md](./10.전문.md) §4

## 6. 경로별 예외 흐름

### 6.1 업무 중 (Facade/Service)

```text
Service throw BizException
  → Facade 프록시: rollback (쓰기 TX, rollbackFor=Exception 등)
  → GlobalExceptionHandler
  → NH_NIS_ERR_DTO
  → Interceptor afterCompletion: exceptionImagelog (가능 시)
```

조회(`readOnly`)도 예외는 동일하게 응답으로 나가지만, 롤백할 변경은 없다.

### 6.2 Handler 미지원 serviceId

```text
Handler switch default
  → throw ServiceHandlerNotFound("…미지원 serviceId: …")
  → GlobalExceptionHandler → E9999 / SERVICE
```

Dispatcher가 Handler 자체를 못 찾는 경우도 동일 계열로 처리된다.

### 6.3 Controller·JSON 이전

잘못된 JSON, 역직렬화 실패 등은 Handler 진입 전이다.  
Spring MVC / Filter 경로로 처리되며, GUID는 Filter가 심은 Context·MDC로 추적한다.

### 6.4 인증

Security 필터에서 거절 → Controller/Advice 도달 전.  
`FW0401` 등 코드·EntryPoint 정책은 Security 설정을 따른다.

## 7. 트랜잭션과의 관계

| 선언 | 예외 시 |
|------|---------|
| Facade `@Transactional(..., rollbackFor = Exception.class)` | checked 포함 롤백 |
| Facade `readOnly = true` | 변경 없음 |
| Service에 TX 없음(기본) | Facade TX에 참여 |
| ImageLog INSERT/UPDATE | 업무 롤백과 **독립** |

업무 예외를 catch 한 뒤 정상 반환하면 **롤백되지 않고** 성공 전문이 나간다. 금지.

상세: [01.트랜잭션처리 변경.md](./01.트랜잭션처리%20변경.md)

## 8. 계층별 책임

| 계층 | 예외 |
|------|------|
| Handler | `ServiceHandlerNotFound` 만 (라우팅). 업무 BizException 생성 금지 권장 |
| Facade | 변환 실패 시 예외 전파. 가능하면 Service에 검증 위임 |
| Service | **`BizException` throw 주 장소** |
| DAO | SQLException 등 전파 (업무 코드로 감싸려면 Service에서) |
| FW Advice | `NH_NIS_ERR_DTO` 조립 |
| Interceptor | `exceptionImagelog` |

| 패턴 | 용도 | 예 |
|------|------|----|
| `FW0xxx` | 프레임워크·공통 | `FW0001` 입력, `FW0401` 인증, `FW9999` 미분류 |
| `FW0403` | 권한 | |
| `E9999` | Handler 미존재(현재 Advice 고정) | |
| 업무코드 | 프로그램·도메인별 | 예: `MP0404`/`MP0409` (샘플). 신규는 MG 규칙으로 정의 |

```text
추가 절차
1. exceptionCode.yml 에 코드·메시지 템플릿 추가
2. Service에서 throw new BizException("코드", args…)
3. UI/호출자가 stdErrCode 로 분기할지 합의
```

## 10. 로깅

| 위치 | 수준 | 내용 |
|------|------|------|
| `GlobalExceptionHandler` | WARN | code / handler not found |
| Service | (선택) INFO/WARN | 업무 맥락. 스택은 중복 가능 |
| ImageLog | DB | 예외 타입·코드·메시지 |
| `pk_service.log` / `pk_framework.log` | | GUID·serviceId로 추적 |

비밀번호·토큰·개인정보를 예외 메시지·로그에 넣지 않는다.

---

## 11. 금지·주의

1. Controller/Handler에서 업무용 try-catch 후 임의 JSON 반환  
2. ETF / `StandardResponseDto` 실패 전문 재도입  
3. 예외 삼키고 성공 `dto` 반환  
4. yml에 없는 코드를 남발하고 메시지를 하드코딩만 하기  
5. DAO에서 HTTP 상태·에러 DTO 조립  
6. 인증 실패를 업무 `BizException`과 혼동 (필터 단계)

## 13. 요약

```text
BizException(업무) / ServiceHandlerNotFound(라우팅)
  → GlobalExceptionHandler (TCF ON)
  → NH_NIS_ERR_DTO
  → (쓰기) Facade TX rollback
  → ImageLog 예외 기록(시스템 구간)

성공 전문과 실패 전문은 스키마가 다르다.
```
