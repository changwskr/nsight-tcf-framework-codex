## 1. 목적

패키지는 **업무 축 + 레이어 + 컴포넌트 타입**을 경로에 고정한다.  
클래스 위치만 봐도 “어느 업무의 어떤 역할인지” 알 수 있어야 한다.

| 문서 | 초점 |
|------|------|
| 02 | 컴포넌트 책임 |
| 03 | 레이어·의존 방향 |
| **04 (본 문서)** | **실제 패키지·리소스 경로·스캔 규칙** |

---

## 2. 루트 구분

| 루트 | 모듈 | 내용 |
|------|------|------|
| `nhnis.fw.*` | `pdmg-fw` | TCF·commons·예외·ImageLog 등 공통 FW |
| `nhnis.mg` | `pdmg-service` | Boot만 (`PdmgApplication`, `ServletInitializer`) |
| `nhnis.mg.[업무].[세부].*` | `pdmg-service` | 업무 코드 전부 |
| `nhnis.mg.ui.*` | `pdmg-ui` | UI (본 서비스 패키지 밖) |

Boot 스캔:

```java
@SpringBootApplication(scanBasePackages = "nhnis")
@ConfigurationPropertiesScan("nhnis")
```

→ `nhnis.fw` 와 `nhnis.mg.*` 를 함께 스캔한다.

## 3. 패키지 경로 규칙

```text
nhnis.mg.[업무구분].[세부업무구분].[계층].[세부패키지]
         └─ 소문자 ──┘ └─ 소문자 ──┘
```

| 세그먼트 | 필수 | 예시 | 설명 |
|----------|------|------|------|
| `nhnis.mg` | O | `nhnis.mg` | 앱 루트. Boot만 직접 둠 |
| 업무구분 | O | `co` | CO→`co`, IC→`ic`, … |
| 세부업무구분 | O | `a` | A→`a`, B→`b`, … |
| 계층 | O | `entry` | `entry` / `application` / `dto` / `persistence` / `client` / `config` / `support` |
| 세부패키지 | △ | `handler` | 계층 안 컴포넌트 타입 |

서비스 ID·패키지·Mapper 축을 맞춘다.

```text
서비스 ID 접두  mgcoa     ← mg + co + a
Java 업무 루트  nhnis.mg.co.a
Mapper 폴더     rdw.mg.co.a/
```

## 4. 현재 샘플 트리 (`co.a`)

```text
src/main/java/nhnis/mg/
├── PdmgApplication.java
├── ServletInitializer.java
└── co/a/
    ├── entry/
    │   ├── handler/          # *Handler
    │   └── aspect/           # BizPrePostAspect, PdmgBizTxFlowAspect
    ├── application/
    │   ├── controller/       # *Controller (TCF OFF)
    │   ├── facade/           # *Facade (@Transactional)
    │   └── service/          # *Service
    ├── dto/                  # *DTOin / *DTOout / *DTOSub*
    ├── persistence/
    │   ├── dao/              # *DAO
    │   └── file/             # (파일 영속 확장용, 현재 비움)
    ├── client/               # *Client (package-info)
    ├── config/               # *Config, *Properties, MyBatis interceptor
    └── support/              # 유틸 (package-info)

src/main/resources/
└── rdw.mg.co.a/
    ├── mgcoa5530-ORA.xml
    ├── mgcoa8888-ORA.xml
    ├── mgcoa9000-ORA.xml
    └── mgcoa9999-ORA.xml
```

FQCN 예시:

```text
nhnis.mg.co.a.entry.handler.mgcoa8888Handler
nhnis.mg.co.a.entry.aspect.BizPrePostAspect
nhnis.mg.co.a.application.facade.mgcoa8888Facade
nhnis.mg.co.a.application.service.mgcoa8888Service
nhnis.mg.co.a.application.controller.mgcoa8888Controller
nhnis.mg.co.a.dto.mgcoa8888S0DTOin
nhnis.mg.co.a.persistence.dao.mgcoa8888DAO
nhnis.mg.co.a.config.RdwDataSourceConfig
```

## 5. 계층 패키지 ↔ 넣는 것

| 패키지 | 넣는다 | 넣지 않는다 |
|--------|--------|-------------|
| `entry.handler` | TCF ON Handler | Facade, Service, DAO, DTO |
| `entry.aspect` | 업무/TX-FLOW Aspect | 업무 로직 클래스 |
| `application.facade` | Facade (`@Transactional`) | Controller, DAO |
| `application.service` | Service | Handler, `@Transactional`(기본) |
| `application.controller` | TCF OFF Controller | Handler |
| `dto` | DTOin/out/Sub | Service 주입, SQL |
| `persistence.dao` | DAO 인터페이스 | 업무 if 분기 |
| `persistence.file` | 파일 저장 등 비DB 영속(확장) | 일반 DAO |
| `config` | DS, Security, Web, MyBatis 조립 | 거래 Handler |
| `client` | 외부 API Client | 화면 Controller |
| `support` | 순수 유틸 | 도메인 Service |

## 6. Mapper·스캔·Pointcut (패키지와 동기화)

패키지를 바꾸면 **스캔·Pointcut·XML 폴더**를 같이 맞춘다.

| 설정 | 현재 값 |
|------|---------|
| `@MapperScan` | `nhnis.mg.co.a.persistence.dao` |
| Mapper XML | `classpath*:rdw.mg.co.a/**/*.xml` (설정과 동일 축) |
| `BizPrePostAspect` Pointcut | `execution(public * nhnis.mg.co.a.application.service..*(..))` |
| TX-FLOW Aspect (예) | `entry.handler` 등 진입 구간 (구현 클래스 참고) |
| MyBatis `namespace` | DAO FQCN (`nhnis.mg.co.a.persistence.dao.mgcoa8888DAO`) |

```java
// nhnis.mg.co.a.config.RdwDataSourceConfig
@MapperScan(
    basePackages = "nhnis.mg.co.a.persistence.dao",
    sqlSessionTemplateRef = "rdwSqlSessionTemplate")
```

## 7. 업무 축 추가 시

예: 업무 `IC` + 세부 `B`

```text
src/main/java/nhnis/mg/ic/b/
├── entry/handler|aspect
├── application/controller|facade|service
├── dto
├── persistence/dao
├── client | config | support   # 필요 시 업무별 또는 co.a config 공유 정책에 따름

src/main/resources/rdw.mg.ic.b/
└── mgicb****-ORA.xml
```

- 서비스 ID 접두: `mgicb`
- `@MapperScan` / Pointcut / XML 경로에 `ic.b` 축 추가
- Boot의 `scanBasePackages = "nhnis"` 는 그대로 두면 하위 패키지가 포함된다

Config를 업무마다 둘지, `co.a.config`에 공통으로 둘지는 팀 정책으로 정하되, **DAO 패키지와 Mapper 폴더 축은 반드시 1:1** 이다.

## 8. 금지 패키지 패턴

| 금지 | 이유 |
|------|------|
| `nhnis.mg.entry.*` (업무·세부 없음) | 업무 축 누락. `nhnis.mg.co.a.entry` 사용 |
| `nhnis.mg.application.*` (축 없음) | 동일 |
| `application.dto` | DTO는 `nhnis.mg.co.a.dto` |
| `entry.facade` / `entry.controller` | Facade·Controller는 `application.*` |
| `common` / `misc` / `util` | 책임 불명. 유틸은 `support` |
| Java `co.a` 와 Mapper `rdw.mg.xx` 불일치 | 스캔·namespace 파손 |

## 10. 한 프로그램이 차지하는 패키지

`mgcoa8888` 기준:

```text
entry.handler          → mgcoa8888Handler
application.facade     → mgcoa8888Facade
application.service    → mgcoa8888Service
application.controller → mgcoa8888Controller   (TCF OFF)
dto                    → mgcoa8888S0DTOin/out …
persistence.dao        → mgcoa8888DAO
rdw.mg.co.a/           → mgcoa8888-ORA.xml
```

식별번호(`8888`)는 클래스 접두에, 구분자(`S0`/`D0`)는 DTO·URL·SQL ID·Facade/Service 메서드명에 둔다.
