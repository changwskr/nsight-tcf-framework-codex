## 0. 한눈에

```text
Service (Map param)
  → DAO 인터페이스 메서드 (@RDWMapper)
  → MyBatis Proxy
  → MappedStatement = {namespace}.{id}
  → *-ORA.xml SQL
  → rdwSqlSessionTemplate
  → rdwDataSource (Facade @Transactional 커넥션)
  → DB (로컬 H2 MODE=Oracle / 운영 Oracle)
  → MybatisLogInterceptor (MDC sqlId, debug 경과)
```

| 계층 | 파일 | 책임 |
|------|------|------|
| DAO | `…persistence.dao.*DAO` | 메서드 시그니처 = SQL id |
| XML | `rdw.mg.co.a/{접두}-ORA.xml` | SQL 본문 |
| Config | `RdwDataSourceConfig` | DS · SqlSession · MapperScan · TM |
| Log | `MybatisLogInterceptor` + `log4j2` SQL | sqlId · param · ms |

## 1. 역할 / 비역할

| 한다 | 하지 않는다 |
|------|-------------|
| SELECT / INSERT / UPDATE / DELETE | 업무 검증 · DTOout 조립 |
| 동적 WHERE · `<foreach>` | `@Transactional` |
| ROWNUM 페이징 · `*_count` | serviceId 라우팅 |
| `#{bind}` · SQL 주석 id | Java에서 SQL 문자열 합치기 |
| 힌트 `/*+ INDEX… */` (선택) | Handler/Facade에서 직호출 |

## 2. 파일 · 로드 · 스캔

### 2.1 경로 · 이름

| 항목 | 규칙 | 예 |
|------|------|-----|
| 디렉터리 | `resources/rdw.mg.[업무].[세부]/` | `rdw.mg.co.a/` |
| 파일 | `{프로그램접두}-ORA.xml` | `mgcoa8888-ORA.xml` |
| 축 일치 | Java `nhnis.mg.co.a` ↔ `rdw.mg.co.a` | 혼용 금지 |
| 단위 | **프로그램 접두 1파일** | S/C/U/D를 한 XML에 |

### 2.2 Config (`RdwDataSourceConfig`)

```java
@MapperScan(
    basePackages = "nhnis.mg.co.a.persistence.dao",
    sqlSessionTemplateRef = "rdwSqlSessionTemplate")

mapperLocations = "classpath*:rdw.*/*.xml"

@Bean rdwDataSource()          // spring.datasource.rdw, Hikari, @Primary
@Bean rdwSqlSessionFactory()   // JdbcType.NULL, callSettersOnNulls, plugins=MybatisLogInterceptor
@Bean rdwSqlSessionTemplate()
@Bean rdwTransactionManager()  // DataSourceTransactionManager(@Primary)
```

### 2.3 namespace · id (필수 계약)

상세: [24.DAO-Namespace.md](./24.DAO-Namespace.md)

```text
namespace     = DAO FQCN
statement id  = DAO 메서드명
전체 SQL ID   = namespace + "." + id
```

불일치 → `BindingException` / Invalid bound statement.

## 3. XML 골격 (표준 헤더)

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "https://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="nhnis.mg.co.a.persistence.dao.mgcoa8888DAO">

    <sql id="mgcoa8888Where"> … </sql>

    <select id="…" resultType="java.util.HashMap"
            parameterType="java.util.HashMap"> … </select>
    <insert|update|delete id="…" parameterType="java.util.HashMap"> … </insert|…>

</mapper>
```

| 관례 | 값 |
|------|-----|
| `parameterType` | `java.util.HashMap` |
| 목록 `resultType` | `java.util.HashMap` |
| count / exists / CUD 영향행 | `int` |
| SQL 식별 주석 | `SELECT /* mgcoa8888S0_S0 */ …` |
| XML 특수문자 | `<` → `&lt;` , `>` → `&gt;` (`ROWNUM &lt;=`) |

`#{}` = PreparedStatement 바인드.  
`${}` 문자열 치환은 **기본 금지**(인젝션·플랜 오염). 동적 컬럼/정렬이 필요하면 화이트리스트 후 제한적으로만.

## 4. 공통 WHERE (`<sql>` + `<include>`)

목록과 count가 **동일 조건**을 쓰도록 분리한다.

```xml
<sql id="mgcoa9000Where">
    WHERE 1 = 1
    <if test="keyword != null and keyword != ''">
       AND ( … LIKE '%' || UPPER(#{keyword}) || '%' … )
    </if>
    <if test="txId != null and txId != ''">
       AND T1.TX_ID = #{txId}
    </if>
</sql>
```

| 규칙 | 내용 |
|------|------|
| Map 키 | Service `param.put` 이름 = `test` / `#{}` 이름 |
| 문자열 | `!= null and != ''` |
| Boolean | `exceptionOnly == true` 형태 (`mgcoa8888`) |
| 연결 | Oracle/H2-Oracle모드 `\|\|` |
| null 함수 | `NVL` 등 Oracle 방언 (로컬도 MODE=Oracle) |

`exists`처럼 조건이 고정이면 Where include 없이 단독 SQL도 허용 (`mgcoa9000S0_S0_exists`).

## 5. 목록 페이징 (Oracle ROWNUM)

업무·DTO·Service 보정: [08](./08.대용량%20페이징%20처리방식.md).

### 5.1 Service가 넣는 키

| 키 | 의미 |
|----|------|
| `pageNo` | 1-based (로그/응답용, SQL 필수 아님) |
| `pageSize` | 페이지 크기 (기본 20, **상한 100**) |
| `offset` | `(pageNo-1)*pageSize` — **클라이언트가 보내지 않음** |

### 5.2 SQL 패턴

```xml
<select id="mgcoa5530S0_S0" resultType="java.util.HashMap"
        parameterType="java.util.HashMap">
    SELECT * FROM (
      SELECT a.*, ROWNUM rnum
        FROM (
           SELECT /*+ INDEX(T1 TB_MK_CO_A_5530_PK) */ /* mgcoa5530S0_S0 */
                  T1.L5101 AS L5101
                , …
             FROM TB_MK_CO_A_5530 T1
           <include refid="mgcoa5530Where"/>
            ORDER BY T1.L5101
        ) a
       WHERE ROWNUM &lt;= #{offset} + #{pageSize}
    )
    WHERE rnum > #{offset}
</select>

<select id="mgcoa5530S0_S0_count" resultType="int"
        parameterType="java.util.HashMap">
    SELECT /* mgcoa5530S0_S0_count */ COUNT(*)
      FROM TB_MK_CO_A_5530 T1
    <include refid="mgcoa5530Where"/>
</select>
```

```text
pageNo=1, pageSize=20 → offset=0  → rnum 1..20
pageNo=2, pageSize=20 → offset=20 → rnum 21..40
```

### 5.3 필수 · 금지

| 필수 | 금지 |
|------|------|
| 안쪽 `ORDER BY` 고정 | Service `subList` 페이징 |
| list/count WHERE 동일 | 클라이언트 `offset` 직접 수신 |
| `#{offset}` / `#{pageSize}` bind | 상한 없이 거대 pageSize |

### 5.4 한계

깊은 페이지는 `offset+pageSize`까지 만든 뒤 자르므로 비용↑.  
일반 화면은 현재 방식으로 충분. 무한 스크롤·초심층 페이지는 keyset 검토([08](./08.대용량%20페이징%20처리방식.md)).  
대량 추출은 목록 S0가 아니라 전용 거래/배치.

### 5.5 예외: 비페이징 목록

`mgcoa9999S0_S0`는 ROWNUM/`_count` 없이 조건 조회만 한다.  
대량 가능 테이블이면 **표준 페이징으로 바꾸는 것을 권장**.

## 6. CUD · foreach · exists

| 태그 | id 예 | 반환 |
|------|-------|------|
| `<insert>` | `mgcoa9000C0_C0` | int (영향 행) |
| `<update>` | `mgcoa9000U0_U0` | int |
| `<delete>` | `mgcoa8888D0_D0`, `mgcoa9000D0_D0` | int |
| `<select>` exists | `mgcoa9000S0_S0_exists` | int (`COUNT(*)`) |

```xml
<delete id="mgcoa8888D0_D0" parameterType="java.util.HashMap">
    DELETE /* mgcoa8888D0_D0 */ FROM TB_FW_IMAGE_LOG
     WHERE GUID IN
    <foreach collection="guidList" item="guid" open="(" separator="," close=")">
        #{guid}
    </foreach>
</delete>
```

| foreach | 예 |
|---------|-----|
| `collection` | Service Map 키 (`guidList`, `txIdList`) |
| 빈 리스트 | Service에서 사전 차단 권장 (SQL `IN ()` 방지) |

INSERT/UPDATE 컬럼·`#{}` 키는 Service param과 1:1.

## 7. 결과 Map · 컬럼 별칭

| 관례 | 이유 |
|------|------|
| `AS GUID`, `AS TX_ID` 대문자 별칭 | 드라이버/환경별 키 대소문자 편차 완화 |
| Service `asString(row, "TX_ID", "txId")` | upper → camel → ignoreCase 순 조회 |
| CLOB | Service에서 `Clob` 분기 (`mgcoa8888` 요청/응답 전문) |

DAO/XML은 DTO를 모른다. **별칭만 안정적으로** 맞춘다.

## 8. 트랜잭션 · 커넥션

```text
Facade @Transactional(rdwTransactionManager) BEGIN
  → Service → DAO 여러 번 호출 = 같은 커넥션 참여
→ COMMIT / ROLLBACK
```

- `SqlSessionTemplate` + 스프링 TX 동기화.
- DAO/XML에 `@Transactional` 없음.
- Facade 밖 DAO 단독 호출 → 자동커밋/TX 부재 위험.

MyBatis 설정(`rdwSqlSessionFactory`):

- `JdbcTypeForNull = NULL`
- `callSettersOnNulls = true`
- plugin: `MybatisLogInterceptor`

## 9. DB 방언 (로컬 H2 vs 운영 Oracle)

| 환경 | JDBC |
|------|------|
| 로컬 기본 | `jdbc:log4jdbc:h2:mem:pdmg;MODE=Oracle;…` (`application.yml`) |
| 스키마 | `classpath:db/h2/schema.sql` · `data.sql` |
| 운영 | Oracle thin (주석 처리된 rdw URL 참고) |

`-ORA.xml` 이름은 Oracle 문법 전제.  
H2는 **Oracle 모드**로 ROWNUM·`||`·NVL 등을 맞춤.  
방언이 갈리면 Mapper 파일/프로파일을 분리한다(현재는 단일 `*-ORA.xml`).

## 10. SQL 로그

### 10.1 `MybatisLogInterceptor`

- `@Intercepts` `Executor.query` / `Executor.update`
- `MDC.put("sqlId", statement.getId())` → `log4j2` `SQL_HEADER`의 `%X{sqlId}`
- debug: `{sqlId} | param=… | {ms}ms`
- Logger: `nhnis.mg.co.a.config.MybatisLogInterceptor` → Appender `SQL`

### 10.2 로그에 찍히는 id

```text
nhnis.mg.co.a.persistence.dao.mgcoa8888DAO.mgcoa8888S0_S0
```

추가로 log4jdbc가 실제 JDBC SQL을 남길 수 있다 (`log4jdbc.*`).

## 13. 신규 statement 절차

1. DAO 인터페이스에 메서드 추가 ([23](./23.DAO.md))

## 14. 장애 · 체크리스트

| 증상 | 확인할 것 |
|------|-----------|
| Invalid bound statement | namespace ≠ FQCN, id ≠ 메서드, XML 미로드(`rdw.*`) |
| 결과가 비거나 키 null | 별칭·Service `asString`·`callSettersOnNulls` |
| totalPages 이상 | count/list Where 불일치 |
| 페이지 행이 흔들림 | `ORDER BY` 누락 |
| `IN ()` 오류 | 빈 리스트를 Service에서 막지 않음 |
| 롤백 안 됨 | Facade TX 밖 DAO 호출 |
| sqlId 빈 칸 | Interceptor/MDC·로거 레벨 |
| H2만 실패/성공 | 방언·MODE=Oracle·스키마 |

배포 전:

- [ ] namespace = DAO FQCN  
- [ ] id = 메서드명  
- [ ] 폴더 `rdw.mg.co.a` ↔ 패키지 `co.a`  
- [ ] 목록이면 count 쌍 · ORDER BY · pageSize 상한(Service)  
- [ ] `#{}`만 · XML `&lt;` 이스케이프  
- [ ] SQL 로그에 전체 id
