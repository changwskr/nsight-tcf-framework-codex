# 에러 처리 (PDMG)

기준: TCF ON (`nhnis.fw.tcf.enabled=true`), `pdmg-fw` + `pdmg-service`  
관련: [tcf.md](./tcf.md) · [트랜잭션처리.md](./트랜잭션처리.md)

PDMG는 구 Pdmk의 **STF/ETF 표준 전문**을 쓰지 않는다.  
실패 시 응답 포맷은 commons **`NH_NIS_ERR_DTO`** 이다.

---

## 1. 로그 파일

`log4j2.xml` 기준:

```text
logs/application/pk_framework.log
logs/service/pk_service.log
```

```text
fileName="${FRAMEWORK_LOG_PATH}/pk_framework.log"
fileName="${SERVICE_LOG_PATH}/pk_service.log"
```

운영 경로 접두어가 사내 수집 규칙으로 고정돼 있으면 배포 설정을 따른다.

---

## 2. 에러 처리 경로

### 2.1 업무·Handler 경로 (`GlobalExceptionHandler`)

`nhnis.fw.exception.GlobalExceptionHandler` (`@RestControllerAdvice`, TCF ON 전용).

```java
@ExceptionHandler(ServiceHandlerNotFound.class)
public ResponseEntity<NH_NIS_ERR_DTO> handleServiceHandlerNotFound(...);

@ExceptionHandler(BizException.class)
public ResponseEntity<NH_NIS_ERR_DTO> handleBizException(BizException e);
```

- `ServiceHandlerNotFound`: serviceId에 Handler 없음 → 코드 예 `E9999`
- `BizException`: 업무 예상 오류 → `e.getCode()` / 메시지
- `OnlineTimeoutException`: 공통 Executor deadline → HTTP **504**, `FW_TIMEOUT`
- `OnlineOverloadException`: 풀/큐 포화 → HTTP **503**, `FW_OVERLOADED`

상세: [20.타임아웃.md](./20.타임아웃.md) · [11.예외처리.md](./11.예외처리.md)

응답 바디 요지:

```text
NH_NIS_ERR_DTO
├─ stdErrCode
├─ stdErrMsgCntn
└─ errType   (BIZ / SERVICE / …)
```

업무·라우팅 예외의 HTTP 상태는 핸들러 구현상 `500` 계열일 수 있다. 호출자는 **에러 DTO 필드**를 본다.  
타임아웃·과부하는 **504 / 503** 으로 구분한다.

#### 업무 오류: BizException

```java
throw new BizException("FW0001", "요청 Body");
```

```text
Service / Facade에서 BizException
↓
쓰기 Facade면 DB 트랜잭션 rollback
↓
GlobalExceptionHandler
↓
NH_NIS_ERR_DTO
```

#### 시스템·기타 예외

Handler에 없는 일반 `Exception`은 FW/컨테이너 경로와 ImageLog 후처리로 이어질 수 있다.  
업무에서 예상 가능하면 `BizException`으로 올린다.

---

### 2.2 Controller 도착 전

잘못된 JSON·역직렬화 실패 등은 Handler/Facade에 들어가기 전이다.  
Filter/Spring MVC 예외 처리와 `GlobalExceptionHandler` 가능 범위를 구분한다.  
GUID는 Filter가 심은 MDC/Context로 추적한다.

---

### 2.3 인증 에러

Security 필터에서 거절되면 Controller/Handler에 도달하지 않는다.  
프로젝트 `SecurityConfig`·EntryPoint 설정을 따른다.

---

## 3. 에러 메시지 출처

`pdmg-fw` / `pdmg-service` 의 `exceptionCode.yml` 과 `ExceptionCodeProperties` 를 사용한다.

```yaml
nhnis:
  exception:
    FW0001: "{0} 오류가 발생하였습니다."
    FW9999: "예기치 않은 시스템 오류가 발생하였습니다."
    # 업무 코드는 MG 규칙에 맞게 추가
```

등록되지 않은 코드는 기본(미분류) 메시지로 대체될 수 있다.

---

## 4. DB 롤백과의 관계

쓰기 Facade `@Transactional(..., rollbackFor = Exception.class)` 안에서  
`BizException` 또는 런타임 예외가 나면 **실패 응답 조립 전에** Spring이 rollback한다.

Filter / Interceptor / ImageLog 는 업무 TX 밖이다.

---

## 5. 전체 흐름 (요약)

```text
에러 발생
├─ Handler 미존재 → ServiceHandlerNotFound → NH_NIS_ERR_DTO
├─ 업무 BizException → rollback(쓰기) → NH_NIS_ERR_DTO
├─ JSON·진입 이전 → MVC/Filter 경로
└─ 인증 실패 → Security
```

구 문서의 `ETF.businessFail` / `result.resultCode = E0001` 설명은 **Pdmk 설계**이며 PDMG 현행과 다르다.
