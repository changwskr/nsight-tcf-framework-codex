# 25. 업무 후처리 — BizPrePostAspect (PDMG)

기준일: 2026-08-09  
대상: `BizPrePostAspect.after` (`@AfterReturning`)  
관련: [21.업무선처리-BizPrePostAspect.md](./21.업무선처리-BizPrePostAspect.md) · [22.Business-Service.md](./22.Business-Service.md) · [26.시스템후처리.md](./26.시스템후처리.md) · [20.Tranaactional-rdwTransactionManager-Begin.md](./20.Tranaactional-rdwTransactionManager-Begin.md)

> 선·후처리 **Aspect 전체**는 [21](./21.업무선처리-BizPrePostAspect.md).  
> 본 문서는 흐름상 DAO/Service 종료 직후인 **업무 후처리 구간만** 본다.

---

## 1. 역할

Service 메서드가 **정상 반환**한 직후, Facade TX가 아직 열려 있는 동안  
업무 결과 DTO를 공통 로그로 남긴다.

```text
Service 본문 · DAO SQL 완료
  → [업무처리] 종료
  → [업무 후처리] 시작          ★
       결과 DTO (PdmgMessagePrinter.businessDto)
  → [업무 후처리] 종료
→ Facade return → COMMIT
→ (이후) 시스템 후처리 · ImageLog UPDATE
```

| 한다 | 하지 않는다 |
|------|-------------|
| 업무처리 종료 / 후처리 시작·종료 로그 | DB commit (Facade) |
| `*DTOout` JSON 형태 로그 | `{ hdr_nhnis, dto }` 응답 봉투 (Advice) |
| 메타 필드 sanitize 후 한 줄 JSON | ImageLog UPDATE |
| 정상 반환 경로만 | 예외 경로 후처리 |

---

## 2. 시스템 후처리와 구분

| | **업무 후처리 (여기)** | **시스템 후처리** |
|--|------------------------|-------------------|
| 시점 | Service `@AfterReturning` | Controller 반환 후 Advice 등 |
| TX | Facade TX **안** | 업무 TX **밖** (대개 COMMIT 이후) |
| 내용 | 업무 DTO 로그 | 응답 봉투·시스템 로그·ImageLog |
| Aspect | `BizPrePostAspect` | Filter/Interceptor/Advice |

번호 흐름: 25(업무 후) → [26.시스템후처리](./26.시스템후처리.md).

## 3. 코드

FQCN: `nhnis.mg.co.a.entry.aspect.BizPrePostAspect`

```java
@AfterReturning(pointcut = "mgBizBoundary()", returning = "result")
public void after(JoinPoint joinPoint, Object result) {
    log.info(PdmgTxLog.bizProcessEnd());      // [업무처리] 종료
    log.info(PdmgTxLog.bizPostStart());        // [업무 후처리] 시작
    if (log.isInfoEnabled()) {
        log.info(PdmgTxLog.bizResponseMessage()); // [업무 후처리] 결과 DTO
        log.info(PdmgMessagePrinter.businessDto(result));
    }
    log.info(PdmgTxLog.bizPostEnd());          // [업무 후처리] 종료
}
```

Pointcut은 선처리와 동일:

```text
execution(public * nhnis.mg.co.a.application.service..*(..))
```

`result` = Service가 반환한 `*DTOout` (Facade가 다시 Handler로 올림).

---

## 4. 로그에 보이는 순서

정상 거래 한 건에서 Service 구간 로그 골격:

```text
[업무 선처리] …          ← 21
[업무처리] 시작
  … Service / SQL …
[업무처리] 종료
[업무 후처리] 시작       ← 여기
[업무 후처리] 결과 DTO
{ … sanitized JSON … }
[업무 후처리] 종료
```

`PdmgMessagePrinter.businessDto`:

- DTO → JSON
- `fieldPropertyMap` / `*List` / `*Array` 등 메타 제거(sanitize)
- 한 줄 문자열로 출력 (로그 오염·절단 완화)

INFO가 꺼져 있으면 결과 DTO 본문만 스킵하고, 시작/종료 섹션 로그는 그대로 `log.info`로 남는다.

---

## 5. 실행 조건 · 스킵되는 경우

| 상황 | 업무 후처리 |
|------|-------------|
| Service 정상 return | **실행** |
| Service / DAO에서 예외 | **미실행** (`AfterReturning`) |
| Facade `convert` 실패 (Service 미호출) | 선·후 **둘 다 없음** |
| `@AfterThrowing` / `finally` 후처리 | **현재 없음** |

예외 시: Facade ROLLBACK → `GlobalExceptionHandler` → 시스템 측 오류 응답.  
업무 후처리 로그에 성공 DTO가 안 찍히는 것이 정상이다.

---

## 6. TX와의 관계

```text
BEGIN (Facade)
  선처리 → Service/DAO → ★ 후처리(로그) → return
COMMIT
```

후처리는 **커밋 전**이다.  
여기에 추가 DB 쓰기를 넣으면 같은 TX에 묶이므로, ImageLog·시스템성 쓰기는 넣지 않는다 (시스템 후처리 몫).

현재 구현은 **로그만** — 커밋 내용에 영향을 주지 않는다.

---

## 7. 선처리(21)와 한눈에

| | 선처리 `@Before` | 후처리 `@AfterReturning` |
|--|------------------|---------------------------|
| 시점 | Service 진입 직전 | Service 정상 반환 직후 |
| 입력 | JoinPoint 인자·Context | `result` (DTOout) |
| 로그 | GUID / 서비스 / 호출 / BRC | 결과 DTO JSON |
| 예외 시 | (진입 전이면 미실행) | 미실행 |

---

## 8. 하지 말 것

1. 후처리 Aspect에서 SQL·ImageLog·응답 헤더 조작  
2. 예외 시에도 후처리가 돈다고 가정  
3. 시스템 Advice와 업무 후처리 로그를 한곳으로 합치기  
4. Pointcut을 Facade로 옮겨 “변환 실패 결과”를 업무 후처리로 로깅
