## 1. 정의

**Spring MVC**는 Servlet Filter 이후, 요청을 **핸들러(Controller)에 매핑**하고 Interceptor·ArgumentResolver·`@ResponseBody`·Advice를 돌리는 웹 계층이다.

PDMG에서 MVC가 담당하는 것:

| 담당 | 구현 |
|------|------|
| Handler 매핑 | `OnlineTransactionController` (TCF ON) 또는 `*Controller` (TCF OFF) |
| 시스템 선처리 | `ServicePreventionInterceptor` |
| Body/`dto` 해석 | `RequestBodyArgumentResolver` 등 |
| 응답 봉투 | `ResponseBodyArgumentResolver` (`ResponseBodyAdvice`) |
| CORS (앱) | `nhnis.mg.co.a.config.WebMvcConfig` |

MVC가 **직접** 하지 않는 것: Body 최초 캐시·JWT·`ServiceContext` 생성 → **Filter**.  
DB TX → **Facade**. 업무 라우팅 세부는 **Handler**.

---

## 2. 요청이 MVC에 들어오기까지

```text
HTTP
  → DefaultFilter                         ← Servlet Filter (MVC 밖)
  → SecurityFilterChain
  → DispatcherServlet                     ← Spring MVC 시작
       → HandlerMapping (URL → Controller 메서드)
       → Interceptor.preHandle
       → ArgumentResolver / @RequestBody
       → Controller 메서드 실행
       → Return value → HttpMessageConverter
            (ResponseBodyAdvice.beforeBodyWrite 개입)
       → Interceptor.postHandle
       → Interceptor.afterCompletion
```

한 줄:

```text
Filter(준비) → MVC(매핑·Interceptor·Controller·Advice) → (내부) TCF/Handler/Facade…
```

## 3. PDMG MVC 구성 요소

### 3.1 DispatcherServlet

Spring Boot 기본 서블릿. `POST /mgcoa8888S0` 등을 `OnlineTransactionController`에 매핑한다.

### 3.2 Controller (핸들러 어댑터 대상)

| 모드 | 클래스 | 매핑 |
|------|--------|------|
| TCF ON | `OnlineTransactionController` | `POST /{serviceId}`, `/online`, … |
| TCF OFF | `application.controller.*Controller` | `POST /{serviceId}` |

TCF ON일 때 거래별 Controller는 진입하지 않는 것이 기본이다.  
→ [16.TCF-OnlineTransactionController.md](./16.TCF-OnlineTransactionController.md)

Controller 반환값(업무 DTO 또는 에러 DTO)은 곧 **ResponseBodyAdvice** 입력이다.

### 3.3 HandlerInterceptor

등록: `WebConfiguration` (`nhnis.fw.commons.legacy-web.enabled=true`)

```java
registry.addInterceptor(servicePreventionInterceptor)
        .addPathPatterns("/**")
        .excludePathPatterns("/error");
```

| 콜백 | PDMG 용도 |
|------|-----------|
| `preHandle` | 시스템 선처리 · 요청전문 · ImageLog INSERT |
| `postHandle` | 응답 로그는 Advice에 위임 (순서상) |
| `afterCompletion` | ImageLog UPDATE / exceptionImagelog |

→ [15.Interceptor-…](./15.Interceptor-ServicePrevention.preHandle.md)

### 3.4 ArgumentResolver

`RequestBodyArgumentResolver` — `@RequestBody` 파라미터에 대해 캐시된 Body/전문에서 값을 맞춘다.  
Filter의 `CachedBodyHttpServletRequest` / `PDMG_REQUEST_BODY` 와 짝을 이룬다.

`OnlineTransactionController`는 `@RequestBody Map<String,Object>` 로 전문 전체를 받고 `dto` 키만 `TcfFacade`에 넘긴다.

### 3.5 ResponseBodyAdvice

`ResponseBodyArgumentResolver` (`@ControllerAdvice`, `legacy-web.enabled=true`)

- 업무 반환 객체를 `{ hdr_nhnis, dto }` 로 감쌈  
- 응답 전문 로그 · `ServiceContext.setResponseBody`  
- 시스템 후처리의 MVC 측 핵심  

### 3.6 `@RestControllerAdvice` (예외)

`GlobalExceptionHandler` (TCF ON) — `BizException` 등 → `NH_NIS_ERR_DTO`.  
MVC 예외 처리 경로. Filter `sendError`와는 별개. → [11.예외처리.md](./11.예외처리.md)

### 3.7 CORS (`WebMvcConfig`)

앱: `nhnis.mg.co.a.config.WebMvcConfig` — `CorsProperties` 기반 `/api/**` (주로 UI 쪽 패턴).  
서비스 직접 브라우저 호출보다 **UI relay**가 기본. → [12.http요청.md](./12.http요청.md)

## 4. TCF ON일 때 MVC 안에서의 호출

```text
DispatcherServlet
  → ServicePreventionInterceptor.preHandle
  → OnlineTransactionController.handleByServiceId
        @RequestBody Map → dto 추출
        → TcfFacade.process(serviceId, dtoBody)
             → Handler → Facade(@Transactional) → Service → DAO
        ← 업무 DTOout
  → ResponseBodyAdvice.beforeBodyWrite
        → { hdr_nhnis, dto }
  → afterCompletion → ImageLog post
```

MVC “Controller”는 **공통 1개**이고, 업무 Controller 역할은 **Handler + Facade**가 이어받는다.

## 5. Filter vs Spring MVC

| | Servlet Filter | Spring MVC |
|--|----------------|------------|
| 시점 | DispatcherServlet **전** | 매핑·핸들러 실행 |
| PDMG 대표 | `DefaultFilter` | Interceptor · OnlineController · Advice |
| Context 생성 | O | 사용·보강 |
| ImageLog 선 | X | Interceptor.pre |
| URL → Bean | X | HandlerMapping |
| 응답 JSON 봉투 | X | ResponseBodyAdvice |

## 6. 설정 스위치

| 프로퍼티 | MVC 관련 효과 |
|----------|----------------|
| `nhnis.fw.tcf.enabled=true` | `OnlineTransactionController` 활성 |
| `nhnis.fw.commons.legacy-web.enabled=true` | Interceptor + Request/Response Body 처리 |
| `nhnis.fw.commons.filter.enabled=true` | Filter (MVC 앞단, 필수에 가깝다) |

Filter 없이 MVC만 켜면 Context·Body 캐시가 없어 Interceptor/전문 처리가 깨질 수 있다.

## 7. 하지 말 것

1. 거래마다 MVC Controller를 늘려 시스템 선후처리를 복사 (TCF ON에서는 Handler 추가)  
2. Interceptor/Advice에서 `@Transactional` 업무 TX  
3. Filter 일을 MVC로 옮기거나 그 반대 (JWT·Body 캐시 vs ImageLog)  
4. `postHandle`에만 응답 전문 의존  
5. DispatcherServlet 앞에서 ImageLog를 기대

## 9. 요약

```text
Spring MVC = DispatcherServlet 안에서
  Interceptor(시스템 선·후 ImageLog) +
  OnlineController(진입) +
  Advice(응답 봉투)

그 앞: DefaultFilter
그 안쪽 업무: Handler → Facade(TX) → Service → DAO
```
