# 07. 도메인 정의 및 호출방식 (PDMG)

기준일: 2026-08-09  
대상: `pdmg-service` + `pdmg-ui` + `pdmg-fw`  
관련: [05.전체 빅픽처 흐름.md](./05.전체%20빅픽처%20흐름.md) · [06.네이밍 형식.md](./06.네이밍%20형식.md) · [02.어플리케이션 컴포넌트 구조.md](./02.어플리케이션%20컴포넌트%20구조.md) · [MG-NAMING_CONVENTION.md](./MG-NAMING_CONVENTION.md)

## 1. 목적

PDMG에서 **도메인**이 무엇인지, **어디까지가 한 도메인 단위**인지,  
화면·중계·서비스가 **어떤 방식으로 그 도메인을 호출**하는지 정의한다.

| 용어 | 의미 |
|------|------|
| 애플리케이션 | `MG` (`nhnis.mg`, `pdmg-service`) |
| 업무 도메인 축 | 업무구분 + 세부업무 (`CO`+`A` → `co.a`) |
| 프로그램 도메인 | 식별번호 단위 (`8888` → `mgcoa8888*`) |
| 거래(서비스) | 서비스 ID 1건 (`mgcoa8888S0`) — 호출의 최소 단위 |

---

## 2. 도메인 계층 정의

```text
MG (애플리케이션)
 └─ CO / A (업무·세부 도메인 축)     ← 패키지 nhnis.mg.co.a , Mapper rdw.mg.co.a
      ├─ 프로그램 8888 (이미지로그)
      │    ├─ 거래 mgcoa8888S0 (조회)
      │    └─ 거래 mgcoa8888D0 (삭제)
      ├─ 프로그램 5530 (마케팅희망고객)
      │    └─ 거래 mgcoa5530S0
      ├─ 프로그램 9999 (영업팁 실적)
      │    └─ 거래 mgcoa9999S0
      └─ 프로그램 9000 (거래 파라미터)
           ├─ mgcoa9000S0 / C0 / U0 / D0
```

### 2.1 애플리케이션 (`MG`)

| 항목 | 값 |
|------|-----|
| 코드 | `MG` |
| Boot | `nhnis.mg.PdmgApplication` |
| UI | `pdmg-ui` (`nhnis.mg.ui.*`) |
| FW | `pdmg-fw` (`nhnis.fw.*`) — 도메인 로직 없음 |

### 2.2 업무·세부 도메인 축

| 코드 | 의미 | 패키지·Mapper |
|------|------|----------------|
| CO | 공통 | `…co…` / `rdw.mg.co…` |
| IC | 통합고객 | `…ic…` |
| MS | 미니 상품부 | `…ms…` |
| SA | 사업관리 | `…sa…` |
| + A | 상담 | `.a` |
| + B | 고객 | `.b` |

현재 샘플 전부 **`CO` + `A`** → Java `nhnis.mg.co.a.*`, 서비스 접두 `mgcoa`.

이 축이 같으면 **같은 업무 도메인 공간**을 공유한다 (Handler·Facade·Config 스캔 범위).

### 2.3 프로그램 도메인 (식별번호)

한 **프로그램** = 화면/기능 묶음 = 식별번호 4자리.

```text
프로그램 접두: mgcoa8888
포함 컴포넌트(각 1):
  Handler, Facade, Service, DAO, (Controller), Mapper XML
포함 거래(N):
  mgcoa8888S0, mgcoa8888D0, …
```

| 프로그램 | 도메인(업무) 요약 | 거래 |
|----------|-------------------|------|
| `mgcoa8888` | 이미지로그 조회·삭제 | S0, D0 |
| `mgcoa5530` | 마케팅희망고객 목록 | S0 |
| `mgcoa9999` | 영업팁 실적 목록 | S0 |
| `mgcoa9000` | 거래 파라미터 CRUD | S0, C0, U0, D0 |

**경계 규칙**

- 프로그램끼리 Service/DAO를 함부로 공유하지 않는다. 공유가 필요하면 `support`/`client` 또는 공통 업무 프로그램으로 승격한다.
- 동일 식별번호의 여러 거래는 **하나의 Handler·Facade·Service·DAO**에 메서드로 모은다.

### 2.4 거래 도메인 (서비스 ID)

호출·TX·DTO·SQL의 **최소 단위**.

```text
mgcoa8888S0  = 프로그램 8888의 조회 거래 0번
```

| 거래가 소유하는 것 | 예 |
|--------------------|----|
| URL | `POST /mgcoa8888S0` |
| Facade/Service 메서드 | `mgcoa8888S0(...)` |
| DTO | `mgcoa8888S0DTOin` / `out` |
| SQL ID | `mgcoa8888S0_S0`, `…_count` |
| UI catalog/relay id | `mgcoa8888S0` |

한 거래 ≈ Facade 메서드 1개 ≈ DB 트랜잭션 1건(쓰기 시).

---

## 3. 도메인 간 의존

```text
허용:
  거래(서비스) → 같은 프로그램의 DAO/SQL
  프로그램     → 같은 업무축(co.a)의 config/support
  업무축       → pdmg-fw (Filter, TCF, 예외)

지양:
  mgcoa8888Service → mgcoa9999DAO 직호출
  UI가 serviceId 없이 임의 REST path 호출
  Handler가 다른 프로그램 Facade를 한곳에 몰아넣기
```

외부 시스템 연동은 `client` 패키지의 `*Client`로 두고, 프로그램 Service가 Client를 호출한다.

---

## 4. 호출방식 개요

PDMG 호출은 **서비스 ID 기반 POST 전문**이다. REST 리소스 URL이 아니다.

```text
호출자 ──POST──► /{serviceId}
         body: { hdr_nhnis, dto }
```

| 호출 경로 | 언제 | 진입점 |
|-----------|------|--------|
| **A. TCF ON** | 기본 (`nhnis.fw.tcf.enabled=true`) | FW `OnlineTransactionController` → Handler |
| **B. TCF OFF** | 호환 | `application.controller` |
| **C. UI Relay** | 화면 | `pdmg-ui` `/api/relay/{id}` → A 또는 B |
| **D. 직접 HTTP** | 도구·연동 테스트 | `POST http://host:8080/{serviceId}` |

---

## 5. 호출방식 A — TCF ON (기본)

```text
Client/UI
  → POST /mgcoa8888S0  { hdr_nhnis, dto }
  → DefaultFilter
  → ServicePreventionInterceptor   (시스템 선처리·ImageLog)
  → OnlineTransactionController
  → TcfFacade / Dispatcher
  → mgcoa8888Handler.handle(dtoBody, context)
       serviceId == mgcoa8888S0
  → mgcoa8888Facade.mgcoa8888S0(dtoBody)   ★ @Transactional
       → [BizPrePost] mgcoa8888Service.mgcoa8888S0(DTOin)
            → mgcoa8888DAO.mgcoa8888S0_S0 …
  → 응답 { hdr_nhnis, dto } · ImageLog 후처리
```

**도메인 매핑**

| serviceId | Handler | Facade 메서드 |
|-----------|---------|----------------|
| `mgcoa5530S0` | `mgcoa5530Handler` | `mgcoa5530S0` |
| `mgcoa8888S0` | `mgcoa8888Handler` | `mgcoa8888S0` |
| `mgcoa8888D0` | `mgcoa8888Handler` | `mgcoa8888D0` |
| `mgcoa9999S0` | `mgcoa9999Handler` | `mgcoa9999S0` |
| `mgcoa9000S0`~`D0` | `mgcoa9000Handler` | 동명 메서드 |

Handler 등록: `serviceIds()`에 문자열을 넣으면 Dispatcher가 찾는다.  
미등록 serviceId → `ServiceHandlerNotFound` → `NH_NIS_ERR_DTO`.

---

## 6. 호출방식 B — TCF OFF (호환)

```text
Client
  → POST /mgcoa8888S0
  → (Interceptor)
  → mgcoa8888Controller.@PostMapping("/mgcoa8888S0")
  → Service (또는 Facade)
  → DAO
```

- Handler / `OnlineTransactionController`를 거치지 않는다.
- 프로그램당 Controller 1, 메서드(매핑)는 거래(서비스 ID)당 1.
- TX·업무 선후처리를 A와 맞추려면 **Controller → Facade → Service** 호출을 권장한다.

---

## 7. 호출방식 C — UI Relay

화면은 브라우저에서 service로 직접 치지 않고 **UI가 중계**한다.

```text
브라우저
  → pdmg-ui :8090
       POST /api/relay/{id}          id = serviceId (예 mgcoa8888S0)
       또는 catalog 전용 API
  → TransactionRelayService
       POST {baseUrl}/{serviceId}    기본 baseUrl → pdmg-service :8080
  → (방식 A 또는 B)
```

| UI 요소 | 역할 |
|---------|------|
| `TransactionCatalog` | 거래 목록·path·설명 메타 |
| `TransactionRelayService` | body 그대로 백엔드 POST |
| `PdmgUiApiController` | `/api/relay/{id}`, 일부 단축 API |

catalog에 등록된 path 예:

```text
/mgcoa8888S0, /mgcoa8888D0
/mgcoa5530S0, /mgcoa9999S0
/mgcoa9000S0, C0, U0, D0
```

**규칙:** UI id·catalog path·백엔드 serviceId·Handler 등록 문자열이 **동일**해야 한다.

---

## 8. 호출방식 D — 직접 HTTP

```http
POST /mgcoa9000S0 HTTP/1.1
Host: localhost:8080
Content-Type: application/json

{
  "hdr_nhnis": { ... },
  "dto": { ... }
}
```

성공: 동일 봉투 + 업무 `dto`.  
실패: `NH_NIS_ERR_DTO` (TCF ON + GlobalExceptionHandler).

Postman·연동 시스템·배치성 HTTP 클라이언트가 이 방식을 쓴다.  
인증은 `SecurityConfig` 정책을 따른다.

---

## 9. 프로그램 내부 호출 (도메인 안)

외부 호출이 거래(서비스 ID)로 들어오면, **프로그램 내부**는 고정 체인이다.

```text
Handler  ──►  Facade  ──►  Service  ──►  DAO  ──►  Mapper/DB
 라우팅       TX+변환       업무            SQL
```

| 호출 | 입력 | 출력 |
|------|------|------|
| Handler → Facade | `Object dtoBody` | `*DTOout` (Object로 반환) |
| Facade → Service | `*DTOin` | `*DTOout` |
| Service → DAO | `Map` 등 | `List`/`int` |

프로그램 밖에서 다른 프로그램 Service를 부를 때는:

1. **가능하면** 그 프로그램의 공개 거래(serviceId)를 HTTP/Client로 호출하거나  
2. 공통 로직을 `support`로 빼고 양쪽이 참조한다.

Handler끼리·Controller끼리 교차 호출하지 않는다.

---

## 10. 동기·트랜잭션 관점의 호출

| 호출 | 동기 | DB TX |
|------|------|-------|
| UI → service | 동기 HTTP | — |
| Handler → Facade | 동기 in-process | Facade에서 시작 |
| Service → DAO | 동기 | Facade TX 참여 |
| ImageLog INSERT/UPDATE | 동기(요청 전후) | **업무 TX 밖** |

비동기 도메인 이벤트 버스는 현재 기본 스택에 없다. 필요 시 별도 설계한다.

---

## 11. 새 도메인 추가 절차 (호출까지)

1. **축 확정** — 업무/세부 (`co.a` 유지 or `ic.b` 신설)  
2. **프로그램 식별번호** — 예 `9010` → 접두 `mgcoa9010`  
3. **거래 목록** — `S0`/`C0`/… 서비스 ID 확정  
4. **구현** — DTO → DAO/XML → Service → Facade → Handler (+ Controller)  
5. **등록** — Handler `serviceIds()`  
6. **UI** — `TransactionCatalog` + 필요 시 화면/relay  
7. **호출 검증** — `POST /mgcoa9010S0` 및 `/api/relay/mgcoa9010S0`

네이밍 형식은 [06](./06.네이밍%20형식.md), 패키지는 [04](./04.패키지구조.md).

|------|----|
| 도메인의 큰 단위는? | 업무축 `co.a` + 프로그램 `mgcoa8888` |
| 호출의 최소 단위는? | 서비스 ID (`mgcoa8888S0`) |
| 기본 호출 방식은? | `POST /{serviceId}` + `{ hdr_nhnis, dto }` (TCF ON) |
| 화면은? | UI `/api/relay/{serviceId}` → 백엔드 동일 ID |
| 프로그램 안 호출은? | Handler → Facade(TX) → Service → DAO |

```text
도메인 축(co.a) ⊃ 프로그램(8888) ⊃ 거래(S0/D0)
호출:  거래 ID로 들어와서  프로그램 체인으로 처리한다.
```
