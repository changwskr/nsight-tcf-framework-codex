## 1. 역할

TCF ON일 때 **모든 온라인 거래의 단일 HTTP 진입 Controller**다.  
거래마다 MVC Controller를 두지 않고, path·헤더의 **서비스 ID**로 `TcfFacade`에 위임한다.

| 한다 | 하지 않는다 |
|------|-------------|
| `POST` 매핑 수신 | `@Transactional` / SQL |
| serviceId 해석·헤더 보정 | 업무 검증·`BizException` 생성 |
| 전문에서 `dto` 추출 | ImageLog / 응답 봉투 조립 |
| `tcfFacade.process(serviceId, dtoBody)` | Handler 라우팅 세부분기 (TcfFacade/Dispatcher) |

```text
Filter → Interceptor.preHandle
  → OnlineTransactionController     ★ 본 문서
       → TcfFacade → Dispatcher → Handler
            → 업무 Facade(@Transactional) → Service → DAO
  → ResponseBodyAdvice → Interceptor.afterCompletion
```

시스템 선후처리는 Filter / Interceptor / Advice가 유지한다. Controller는 **연결점**만 담당한다.

---

## 2. 활성 조건

```java
@RestController
@ConditionalOnProperty(name = "nhnis.fw.tcf.enabled", havingValue = "true")
public class OnlineTransactionController { … }
```

```yaml
nhnis.fw.tcf.enabled: true   # pdmg-service application.yml
```

`false`이면 이 Controller는 빈으로 안 뜨고, 거래별 `application.controller.*Controller` 경로를 쓴다.

---

## 3. URL 매핑

| 메서드 | Path | 용도 |
|--------|------|------|
| `handleByServiceId` | `POST /{serviceId}` | **PDMG 기본** 예: `/mgcoa8888S0` |
| `handleRoot` | `POST /online` | tcf-web 호환 — serviceId는 헤더 |
| `handleWithBusinessCode` | `POST /{businessCode}/online` | tcf-web 호환 |

권장(화면·UI relay·연동):

```http
POST /mgcoa8888S0
Content-Type: application/json

{ "hdr_nhnis": { "sys_comm": { "rms_svc_c": "mgcoa8888S0", … } }, "dto": { … } }
```

세 진입점 모두 내부 `handle(pathServiceId, request, servletRequest)` 로 모인다.

---

## 4. 요청 Body

```java
@RequestBody Map<String, Object> request
```

| 키 | 사용 |
|----|------|
| `hdr_nhnis` | serviceId 해석 보조 (`sys_comm.rms_svc_c`) |
| `dto` | **`tcfFacade.process`에 넘기는 본문만** (`request.get("dto")`) |

헤더 전체는 이미 Filter가 `ServiceContext`에 넣었다. Controller는 **dto 노드**를 업무 쪽으로 전달한다.  
반환 `Object`는 업무 `*DTOout` (또는 예외 경로의 에러 DTO) → Advice가 `{ hdr_nhnis, dto }`로 감싼다.

---

## 5. `handle` 처리 순서

```text
1. enrichClientIp(servletRequest)
     sys_comm.tr_trm_ipadr 비어 있으면 X-Forwarded-For / remoteAddr

2. serviceId = resolveServiceId(pathServiceId, request)
     우선순위:
       ① ServiceContext.header.sys_comm.rms_svc_c
       ② Body hdr_nhnis.sys_comm.rms_svc_c
       ③ path 변수 (/{serviceId} 또는 businessCode)

3. ensureRmsSvcC(serviceId)
     Context 헤더에 rms_svc_c 가 비어 있으면 path에서 보정

4. dtoBody = request.get("dto")

5. return tcfFacade.process(serviceId, dtoBody)
```

표준 운영: **path = rms_svc_c = 동일 서비스 ID**.  
우선순위상 Context/Body 헤더가 path보다 앞서므로, 불일치 시 헤더 값이 이긴다 — 의도적 불일치를 만들지 말 것.

---

## 6. serviceId 해석 상세

```text
resolveServiceId
  Context.rms_svc_c  (Filter·Interceptor가 채운 헤더)
       ↓ 없으면
  JSON hdr_nhnis.sys_comm.rms_svc_c
       ↓ 없으면
  pathServiceId      (/mgcoa8888S0 의 path, 또는 /xxx/online 의 businessCode)
       ↓ 없으면
  null  → TcfFacade/Dispatcher 에서 Handler 미매칭 가능
```

`ensureRmsSvcC`: Context에만 채움(이미 값 있으면 유지). ImageLog·추적용.

---

## 7. 다음 단계 (`TcfFacade`)

```java
tcfFacade.process(serviceId, dtoBody);
```

- `TransactionContext.fromCurrent(serviceId)` 생성  
- `TransactionDispatcher.dispatch` → `*Handler.handle`  
- Handler → 업무 `*Facade`  

상세: [17.TCF-TcfFace-Dispatcher.md](./17.TCF-TcfFace-Dispatcher.md) · [18.Business-Handler.md](./18.Business-Handler.md)

Controller는 Handler를 직접 주입하지 않는다.

---

## 8. 로깅

```text
[OnlineTransactionController.handleByServiceId] 시작/종료
[OnlineTransactionController.handle] 시작/종료
[OnlineTransactionController] serviceId=mgcoa8888S0
```

업무 Start/End(`▷▷`/`▶▶`)·시스템 선후 배너는 Controller가 아니라 Interceptor/Service/Advice 쪽이다.

---

## 9. TCF OFF와의 관계

| | TCF ON (본 문서) | TCF OFF |
|--|------------------|---------|
| HTTP 진입 | `OnlineTransactionController` 1개 | `mgcoa*Controller` N개 |
| 라우팅 | serviceId → TcfFacade → Handler | Controller → Service(또는 Facade) |
| URL | 동일하게 `POST /{serviceId}` 권장 | `@PostMapping("/서비스ID")` |

신규 온라인 거래는 TCF ON 기준으로 **Handler + Facade** 추가가 원칙이다.

---

## 10. 하지 말 것

1. Controller에 업무 if·SQL·`@Transactional`  
2. 전문 전체를 Facade에 넘기고 dto만 써야 할 계약을 깨기  
3. path와 `rms_svc_c`를 다르게 넣어 해석 우선순위에 의존  
4. 거래마다 OnlineController를 복제  
5. 시스템 선후(Filter/Interceptor/Advice)를 Controller로 흡수
