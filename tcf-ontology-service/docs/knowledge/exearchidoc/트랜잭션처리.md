# 트랜잭션처리 (PDMG)

PDMG 온라인 거래에서 말하는 「트랜잭션」은 두 층이다.  
과거 TCF `@TcfTransaction`(요청 흐름 마커)와 혼동하지 않는다.

| 구분 | 무엇인지 | 어디에 |
|------|----------|--------|
| **요청(거래) 흐름** | Filter · 시스템 선후처리 · 단일 Controller · ImageLog | `pdmg-fw` commons + TCF web |
| **DB 트랜잭션** | commit / rollback | Business Facade `@Transactional` |

변경 요지(Service Pointcut): [01.트랜잭션처리 변경.md](./01.트랜잭션처리%20변경.md)  
전체 시퀀스: [pdmg-service 트랜잭션흐름.md](./pdmg-service%20트랜잭션흐름.md)  
컴포넌트↔패키지: [MG-NAMING_CONVENTION.md](./MG-NAMING_CONVENTION.md) §4

## 0. 패키지 역할 (요약)

| 관심사 | 컴포넌트 | 패키지 |
|--------|----------|--------|
| serviceId 라우팅 | Handler | `nhnis.mg.co.a.entry.handler` |
| 업무 선후처리 AOP | Aspect | `nhnis.mg.co.a.entry.aspect` |
| **DB TX** | Facade | `nhnis.mg.co.a.application.facade` |
| 업무 절차 | Service | `nhnis.mg.co.a.application.service` |
| TCF OFF HTTP | Controller | `nhnis.mg.co.a.application.controller` |
| SQL | DAO | `nhnis.mg.co.a.persistence.dao` |
| DTO | DTOin/out | `nhnis.mg.co.a.dto` |

## 1. 요청 흐름 (DB commit과 무관)

```text
요청
 → DefaultFilter (Body, ServiceContext, GUID)
 → ServicePreventionInterceptor (시스템 선처리, ImageLog INSERT)
 → OnlineTransactionController / TcfFacade / Handler
 → Business Facade (+ Service)
 → ResponseBodyAdvice (시스템 후처리)
 → ImageLog UPDATE
```

시스템 선후처리·ImageLog 실패는 업무 DB 롤백을 유발하지 않도록 분리되어 있다.

---

## 2. DB 트랜잭션 (`@Transactional`)

선언 위치: **`nhnis.mg.co.a.application.facade.*`**

```java
@Transactional(transactionManager = "rdwTransactionManager", readOnly = true)
public mgcoa5530S0DTOout mgcoa5530S0(Object dtoBody) { ... }
```

```text
Handler → Facade 호출
 → Spring TX 프록시: BEGIN
 → (Facade 본문) Service 호출
      → BizPrePostAspect 선처리
      → Service / DAO / SQL
      → BizPrePostAspect 후처리
 → Facade 반환: COMMIT (예외 시 ROLLBACK)
```

TM 빈: `rdwTransactionManager` (`nhnis.mg.co.a.config.RdwDataSourceConfig`).

**공통 온라인 타임아웃(1차):** `TcfFacade` → `OnlineTimeoutExecutor` 가 Worker에서 외부 TX를 열고 deadline을 건다.  
→ [20.타임아웃.md](./20.타임아웃.md)

Facade `@Transactional(timeout=…)` 는 보조(2차). 구 설명: [롤백아키텍처 4초지나면롤백되나.md](./롤백아키텍처%204초지나면롤백되나.md)

## 3. 업무 선후처리 (`BizPrePostAspect`)

```java
@Pointcut("execution(public * nhnis.mg.co.a.application.service..*(..))")
```

- Facade TX **안**에서 Service 전후에 실행
- 로그 확인: `[업무 선처리] 호출: …Service.…`

---

## 4. 공통 Controller vs 거래별 Controller

PDMG(TCF ON)는 **공통 `OnlineTransactionController` 1개**를 쓴다.

| | 공통 Controller (현재) | 거래별 Controller |
|--|------------------------|-------------------|
| 진입 | `POST /{serviceId}` | 거래마다 클래스 (`application.controller`) |
| 시스템 선후처리 | 한곳에 고정 | 반복·누락 위험 |
| 신규 거래 | Handler + Facade + Service | Controller 추가(TCF OFF 호환) |

온라인 전문(헤더+dto, GUID, ImageLog) 스타일에는 공통 Controller가 적합하다.

TCF OFF(`nhnis.fw.tcf.enabled=false`)일 때만 거래별 Controller가 HTTP 진입이 된다.  
현재 샘플 Controller는 Service를 직접 호출한다. TX·선후처리를 Facade와 맞추려면 Facade 경유가 더 일관적이다.
