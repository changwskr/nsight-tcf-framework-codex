# 업무도메인 개발방법론 샘플 프롬프트 모음

`2026-07-26-nsight-tcf-prompts.md`의 **7번 프롬프트(방법론 절차 실행 — Phase 0~6)**를
기반으로, 설계서 작성부터 구현·문서화까지 방법론 한 사이클을 그대로 실행할 수 있게
구성한 샘플 세트입니다.

앞서 만든 `업무도메인-샘플-프롬프트/`(명세 직접 지시형)와 달리,
이 폴더는 **설계서(문서)가 구현의 유일한 입력**이 되는 설계 우선(Design-First)
방법론을 따릅니다.

## 방법론 파이프라인

```text
[0단계] 설계서 작성                      [1단계] Phase 실행                [2단계] 역공학 문서화
6번 템플릿 → {업무코드}-프로그램-설계서    설계서 §3~§6 → Phase 0~6 구현      구현 코드 → 설계서 재생성
          → {업무코드}-UI-레이아웃-설계서   (Phase별 검증 게이트 통과)          (문서-코드 정합성 확보)
```

## 파일 목록 (실행 순서대로)

| 파일 | 역할 | 실행 대상 |
|---|---|---|
| `0-설계서-작성-프롬프트.md` | 템플릿 기반 설계서 2종 작성 지시 | 설계서가 없는 새 업무 |
| `LN-프로그램-설계서-예시.md` | 완성된 프로그램 설계서 예시 (9섹션) | 1단계의 입력 문서 |
| `LN-UI-레이아웃-설계서-예시.md` | 완성된 UI 레이아웃 설계서 예시 (6섹션) | 1단계의 입력 문서 |
| `1-Phase-실행-프롬프트-LN.md` | **Phase 0~6 구현 실행 프롬프트** (LN 완성본) | 위 설계서 2종을 입력으로 구현 |
| `2-역공학-문서화-프롬프트-AV.md` | 구현 완료 모듈 → 설계서 자동 생성 (8번 응용) | 이미 구현된 av-service |

## 사용 방법

1. **설계서가 이미 있는 경우**: `1-Phase-실행-프롬프트-LN.md`의 코드 블록에서
   업무코드·설계서 경로만 바꿔 채팅에 붙여넣습니다.
2. **설계서가 없는 새 업무**: `0-설계서-작성-프롬프트.md`로 설계서 2종을 먼저
   만들고(LN 예시 문서가 작성 기준), 검토·확정 후 1단계를 실행합니다.
3. **코드만 있고 설계서가 없는 기존 모듈**: `2-역공학-문서화-프롬프트-AV.md`로
   설계서부터 확보한 뒤, 보완 개발 시 1단계를 사용합니다.

## 원본(7번) 대비 보정 사항

이 폴더의 Phase 프롬프트에는 실제 구현 검증에서 확인된 사항이 반영되어 있습니다.

- **Phase 0에 tcf-ui 등록 추가**: `BusinessModuleDefinitions.ALL` 등록과
  `sample-requests/{코드소문자}-sample-inquiry.json` 생성(누락 시 tcf-ui 기동 실패)
- **포트**: `BusinessModuleDefinitions.java`가 포트 SoT — 8081~8097·8099~8101·8110은
  예약됨. LN 예시는 8103 사용
- **Phase 4 게이트 경로**: bootRun은 context-path가 `/`이므로 `POST /online`
  (또는 `/{코드소문자}/online`) 호출, Health는 `/actuator/health`
- **표준 전문 header**: 검증 호출 시 전체 필드 필수 (`eb-sample-inquiry.json` 기준)
- **Phase 6 OM 등록**: 저장소의 실제 OM 등록 방식을 확인 후 적용하고,
  적용 불가 시 '미실행'으로 구분 보고
