PDMG에서 JWT 토큰 검증은 `pdmg-fw`의 `DefaultFilter`와 `JwtProvider`가 담당합니다.

```text
클라이언트 요청
  → DefaultFilter
      → Authorization 헤더 추출
      → JwtProvider.validate()
      → JwtProvider.isAccessToken()
      → JwtProvider.getSsoId()
  → Controller
```

### 1. 검증 호출 위치

[DefaultFilter.java](<C:/Programming(23-08-15)/nsight-tcf-framework-codex/pdmg-fw/src/main/java/nhnis/fw/commons/filter/DefaultFilter.java>)

Non-local 환경에서 다음 순서로 검사합니다.

```java
String authorization = request.getHeader("Authorization");

if (authorization == null || !authorization.startsWith("Bearer ")) {
    response.sendError(
        HttpServletResponse.SC_UNAUTHORIZED,
        "Authorization Bearer Token이 필요합니다."
    );
    return;
}

String token = authorization.substring(7);

if (!jwtProvider.validate(token)) {
    response.sendError(
        HttpServletResponse.SC_UNAUTHORIZED,
        "유효하지 않은 Token입니다."
    );
    return;
}

if (!jwtProvider.isAccessToken(token)) {
    response.sendError(
        HttpServletResponse.SC_UNAUTHORIZED,
        "Access Token이 아닙니다."
    );
    return;
}

String ssoId = jwtProvider.getSsoId(token);
request.setAttribute("ssoId", ssoId);
```

### 2. 실제 JWT 서명 검증

[JwtProvider.java](<C:/Programming(23-08-15)/nsight-tcf-framework-codex/pdmg-fw/src/main/java/nhnis/fw/commons/jwt/JwtProvider.java>)

```java
public boolean validate(String token) {
    try {
        Jwts.parser()
            .verifyWith(key)
            .build()
            .parseSignedClaims(token);

        return true;
    } catch (Exception e) {
        return false;
    }
}
```

검증 키는 설정값으로 생성합니다.

```java
@Value("${jwt.secret}")
private String secret;

@PostConstruct
public void init() {
    key = Keys.hmacShaKeyFor(
        secret.getBytes(StandardCharsets.UTF_8)
    );
}
```

즉 다음 항목이 검증됩니다.

- JWT 구조
- HMAC 서명
- 만료시간 `exp`
- 토큰 Claims 파싱 가능 여부

그 후 `type` Claim도 검사합니다.

```java
return "ACCESS".equals(type);
```

### 3. 필터 등록 위치

[FilterConfiguration.java](<C:/Programming(23-08-15)/nsight-tcf-framework-codex/pdmg-fw/src/main/java/nhnis/fw/commons/configuration/FilterConfiguration.java>)

`DefaultFilter`는 다음 조건에서 등록됩니다.

```yaml
nhnis:
  fw:
    commons:
      filter:
        enabled: true
```

현재 PDMG 설정에서는 이 값이 `true`이므로 필터가 활성화됩니다.

### 4. 환경별 차이

`DefaultFilter`는 현재 `jwt.enabled`가 아니라 프로파일 이름을 직접 검사합니다.

```java
if (!"local".equals(active)) {
    // JWT 검증
}
```

따라서:

| 환경             | JWT 검증 |
| ---------------- | -------- |
| `local`          | 생략     |
| `dev`            | 수행     |
| `prod`           | 수행     |
| 그 밖의 프로파일 | 수행     |

`application.yml`에 `jwt.enabled: false`가 있더라도 `dev`라면 현재 코드상 JWT 검증을 수행합니다.

### 5. Spring Security의 역할

[SecurityConfig.java](<C:/Programming(23-08-15)/nsight-tcf-framework-codex/pdmg-service/src/main/java/nhnis/mk/config/SecurityConfig.java>)는 현재 요청을 허용하도록 설정되어 있습니다.

```java
.anyRequest().permitAll()
```

따라서 실제 JWT 인증 관문은 Spring Security가 아니라 `DefaultFilter`입니다.

정리하면:

```text
토큰 생성: 외부 인증 서비스 또는 tcf-jwt
토큰 전달: pdmg-ui → Authorization Bearer 헤더
토큰 검증 호출: pdmg-fw DefaultFilter
실제 서명 검증: pdmg-fw JwtProvider
사용자 ID 전달: request attribute의 ssoId
```
