현재 `pdmg-fw`, `pdmg-service`, `pdmg-ui` 안에서는 JWT를 생성하지 않습니다.

[JwtProvider.java](<C:/Programming(23-08-15)/nsight-tcf-framework-codex/pdmg-fw/src/main/java/nhnis/fw/commons/jwt/JwtProvider.java>)는 다음 기능만 제공하는 검증 전용 클래스입니다.

```java
validate(token)       // 서명, 만료 등 기본 유효성 검증
isAccessToken(token)  // type claim이 ACCESS인지 확인
getSsoId(token)       // subject에서 사용자 ID 추출
```

`Jwts.builder()`나 `createToken()`, `generateToken()` 같은 발급 코드는 PDMG 영역에서 발견되지 않았습니다.

현재 구조는 다음과 같습니다.

```text
외부 인증/SSO 서버
  → JWT Access Token 발급
  → pdmg-ui가 토큰 보관
  → Authorization: Bearer {JWT}
  → pdmg-service
  → DefaultFilter
  → JwtProvider로 검증
```

즉 PDMG는 외부 인증 시스템이 발급한 토큰을 전달받아 검증하는 Resource Server 역할로 설계된 것으로 보입니다.

저장소에는 별도의 JWT 서비스인 [tcf-jwt](<C:/Programming(23-08-15)/nsight-tcf-framework-codex/tcf-jwt>)가 있습니다. 여기에는 로그인과 토큰 발급 관련 구현이 있습니다.

- `JwtAuthLoginHandler`: 로그인 거래 진입점
- `JwtAuthSsoIssueHandler`: SSO 토큰 발급 진입점
- `JwtAuthService`: 인증 업무 처리
- `JwtTokenIssuer`: 실제 JWT 생성 담당

실제 생성 핵심 파일:

[JwtTokenIssuer.java](<C:/Programming(23-08-15)/nsight-tcf-framework-codex/tcf-jwt/src/main/java/com/nh/nsight/auth/jwt/support/JwtTokenIssuer.java>)

따라서 통합 구조는 일반적으로 다음과 같습니다.

```text
pdmg-ui
  ├─ 로그인 요청 → tcf-jwt
  │                  └─ JwtTokenIssuer가 JWT 생성
  │
  └─ 업무 요청 → pdmg-service
                   └─ DefaultFilter/JwtProvider가 JWT 검증
```

한 가지 중요한 조건이 있습니다. `tcf-jwt`가 발급한 토큰과 PDMG가 검증할 때 사용하는 키가 일치해야 합니다. 현재 PDMG `JwtProvider`는 `jwt.secret` 기반 HMAC 검증을 사용하므로, 발급 서비스가 다른 키나 RSA/JWK 방식으로 서명하면 검증되지 않습니다. 발급 주체를 확정한 다음 서명 알고리즘, 키 관리, issuer/audience 검증 정책을 맞춰야 합니다.
